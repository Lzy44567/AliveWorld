## 正式打包阻塞项

### P0：必须先解决

1. **没有生产运行模式**
   - `start_dev.bat` 启动 Vite 开发服务器和带 `--reload` 的 Uvicorn。
   - FastAPI 尚未托管前端 `dist`，玩家机器仍需要 Node。

2. **没有便携版或安装包工具链**
   - 当前没有 PyInstaller/Nuitka 配置、桌面启动器、单实例管理、构建脚本、Release CI 或安装程序。
   - 玩家必须预装 Python 3.12 和 Node.js 20+，已被真实非程序用户证明容易失败。

3. **用户数据路径不适合程序升级**
   - `data/`、`config.yml` 和日志仍以项目目录为中心。
   - 正式版必须迁移到稳定的用户数据目录，例如 `%LOCALAPPDATA%\\AliveWorld`，覆盖程序文件时不能覆盖个人资产。

4. **本地 API 安全边界需要收紧**
   - 当前 CORS 允许所有来源。
   - `/system_config` 会把完整 API Key 返回给前端。
   - 正式本地程序应采用同源前端、移除宽泛 CORS，并避免通过普通 GET 回传完整密钥。

5. **版本号与文档不一致**
   - 前端为 `v1.5.0-dev.7`，FastAPI 为 `1.0.0`，npm 包为 `0.0.0`。
   - README 仍把已经实现的快捷行动和偏好卡列为“正在开发”。
   - 发布前需要单一版本真源、更新安装说明、功能边界和截图。

6. **缺少干净电脑发行验收**
   - 必须在没有 Python、Node、项目缓存和开发环境的 Windows 10/11 环境测试。
   - 至少验证首次启动、API 配置、创建故事、完整回合、存档重启、工坊、可选 ComfyUI、升级保留数据和卸载不删个人资产。

### P1：首个 Beta 后、正式稳定版前解决或获得明确验收

- 用一个较完整模板完成真实游戏循环，不只测试单项接口。
- 长故事记忆压缩达到多个片段后继续游玩。
- 用户偏好从证据、分析、确认到正文消费的人工观察。
- 角色、文风、实体工坊各完成一次“讨论 → 草稿 → 发布 → 再进入恢复”的人工验收。
- 错误提示覆盖无网络、API 余额不足、模型拒绝、ComfyUI 未启动、端口占用和磁盘空间不足。

## 推荐的首个傻瓜版架构

首包以 Windows 10/11 为目标，采用“一目录便携版 + 单个启动程序”，暂不追求同时发布 Android/Linux。

1. Vite 只在构建机运行，生成静态 `dist`；玩家电脑不安装 Node。
2. FastAPI 同源托管静态前端和 `/api`。
3. 前端 API 地址改为相对路径，不写死 `127.0.0.1:8000`。
4. 使用 PyInstaller `onedir` 封装 Python、后端和依赖；首版不采用启动更慢、排错更难的单文件模式。
5. `AliveWorld.exe` 负责单实例、选择可用本地端口、启动服务、等待健康检查并打开窗口。
6. UI 优先使用 Windows WebView2；WebView2 不可用时回退系统浏览器。这样玩家只需双击，不接触命令行。
7. 配置、存档、资产、日志、图片和工坊草稿进入 `%LOCALAPPDATA%\\AliveWorld`。
8. 输出便携 ZIP；稳定后再用 Inno Setup 等生成安装程序。
9. 在干净 Windows 虚拟机执行发布验收并生成 SHA-256 校验值。

## API 与云生图判断

- 文本模型当前的 OpenAI-compatible `Base URL + API Key + Model` 足够首包使用；多配置档案和快速切换属于后续体验增强。
- 首个傻瓜版只宣传 ComfyUI 生图，不需要云生图。
- 云生图不能只保存 URL 和 Key 就宣称支持；每个真实服务商仍需要请求体、鉴权、异步任务、图片下载、错误映射和计费提示适配。
- 可以提前保留统一服务商接口和配置结构，但在适配完成前不显示可选服务商，避免产生假功能。
