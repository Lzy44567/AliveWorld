# AliveWorld界面设计评审准则

日期：2026-10-13。来源：用户列出的十一项原则。作为产品要求，不声称已实现或已通过可用性测试。用户引用的“24小时遗忘25%”没有核验，不作为科学结论或设计参数；采用“让用户看得见选择，减少依赖记忆”的定性原则。

| 原则 | 在AliveWorld中的具体检查 |
|---|---|
| 简易性 | 默认页突出当前任务；低频专业项折叠，不把所有内部阶段变成按钮 |
| 用户语言 | 使用故事、角色、世界设定等语言；避免宇宙主导向、内部协议缩写等含糊术语；必要专业词有简短解释 |
| 减少记忆负担 | 已载入资产、当前作用范围、待审改动、设置来源可见；选择优先可浏览卡片与搜索，不要求记住名称/ID |
| 一致性 | 同类资产的选择、编辑、保存、更多菜单位置一致；复用组件，但故事/角色/工坊不同任务不强行同构 |
| 清楚直觉 | 本故事设置在本局入口；接口凭据只有一个管理来源；相邻/同组操作语义相关；危险操作不紧贴常用动作 |
| 熟悉程度 | 角色模式参考熟悉的聊天列表与气泡；故事兼顾连续阅读；不把所有模式都做成聊天软件 |
| 用户视角 | 从“我要开始玩/修改这张卡/找到刚才的人”组织页面，而不是按后端模块组织导航 |
| 排列 | 清楚层级、稳定对齐、常用操作易找；用留白和分组表达关系，不靠堆边框和颜色区分一切 |
| 安全性 | 草稿、撤销、范围预览；删除存档/覆盖等有具体后果说明。收费请求、外部发布等不能承诺全可逆，应提前说明 |
| 灵活性 | 鼠标、键盘、触摸有等价主要路径；悬停内容可点击访问；窄屏可操作。手柄完整支持另排期，不冒充现状 |
| 人性化 | 简单默认＋高级总开关；保留偏好与布局选择。隐藏高级控件不偷偷停用功能；提供恢复默认而非无限自定义 |

## 关键页面走查

- 新建故事：不看教程能否知道选什么、自己扮演谁、从哪里开始？是否必须先懂资产分类？
- 故事页面：能否直接行动、看最新内容、知道是否保存？后台信息是否抢占阅读或剧透？
- 工坊：能否表达想法、看见草稿、只改一个条目、知道何时发布生效？
- 设置：能否知道当前值影响新故事还是本故事？隐藏高级后是否仍能找到故障处理？
- 通用：空态、加载、错误、长文本、窄屏、键盘输入、文字选择复制、未保存修改都要覆盖。

这些是后续信息架构和原型的检查表，不是再加一套玩家设置。不提前冻结配色与布局；原型集中审阅后再编码，测试观察任务能否完成及哪里困惑，而不只判断截图好不好看。
