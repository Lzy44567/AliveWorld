# 开局流程、界面重设计与人物消息表现

日期：2026-10-12。状态：用户需求与设计候选，未编码。关联09新手引导、25世界包创作、26角色提取、28剧情方向。

## 用户反馈与核验

- 新建故事后出现“时间线已建立／宇宙法则主导向／当前世界犹如一张白纸／万象资产”默认正文，不适合实际开局。
- api/v1/game_routes.py中_start_materialized_session的无opening分支直接构造上述文本并传入start_new_game。这是实际默认开场，不是placeholder；上一轮只解释输入框占位文字未涵盖该问题。
- 写好世界书与角色卡后仍不知从何处、以何种事件开始；需要作者预设开局与普通玩家辅助开局。
- 用户希望以后重新审视UI整体架构；“UI设计三原则”具体所指尚不明确，不代用户指定某一套定义。
- 用户要求头像＋消息，故事可区分角色台词与旁白，复用至私聊/群聊，并支持立绘、差分及悬停角色资料。

## 开局产品候选

“新建故事”提供使用现有世界包、选择资产开始、从简短灵感开始三条清晰路径。默认呈现卡片和当前配置摘要，不让玩家先掌握全部资产分类。

1. 作者开局：世界包携带主角创建选项、起点、初始资源/关系和开场事件；角色选项可改变开局状态与分支，不必数值化。亲密题材仅限明确成年角色，不设计未成年人性化选项。
2. 辅助开局：选择世界/人物后，工坊按需提出少量可行起点，每项简述地点、当前处境、近期目标；玩家选择或自行填写，预览后开始。不能为了帮助开始而自动决定玩家接下来要说什么或做什么。
3. 自由开始：允许只写概述与第一步行动，不强制向导；尚未开始时用界面空态提示如何载入/选起点，系统教程不保存成故事事实。

作者已提供适用开局时直接复用，不多花一次生成费用。AI起点建议由玩家主动选择后调用，不每次打开创建窗口就生成。开局应读取本次选中的资产，现有普通新建流程仅world_premise/设置，不能声称已支持完整资产先选流程。

“创建成功”属于系统通知；世界介绍和开场属于故事内容。内置默认开场后续移出故事历史。旧存档不批量删除历史消息；迁移策略在实施时另定。

## UI整体设计候选

围绕玩家任务重排：开始/续玩→行动与结果→按需看人物/世界→需要时创作。保留故事/角色/工坊顶部模式已确认结构，是否进一步调整须原型讨论。

先做信息架构和关键页面原型，再落实视觉样式：常用操作可见、低频配置收纳、相同控件一致、反馈清楚、隐藏信息不误泄漏。不能将某个样式修复当整体重设计完成。

优先原型：新建故事、故事主界面、角色会话、工坊审阅与世界包项目。桌面和窄屏同时考虑；无需现在重写所有页面。

## 头像与结构化消息候选

- 统一人物身份→显示名/头像/当前立绘映射，系统与旁白拥有明确身份；缺图用首字/中性图标，不强制生图。
- 故事一回合可含旁白及多个角色台词段，每段关联说话者身份，未知说话者允许未知。不能凭引号或同名字符串猜角色，也不为每段单独调用模型。
- 来源仍为一个正式回合/裁定结果；拆段仅呈现，不改变整回合撤回、状态提交和流式最终确认。可复用外观组件，但故事回合与角色消息组生命周期仍独立。
- 候选让现有GM输出携带精简说话者/段类型标记，按序流式呈现；增加输出/复杂度需和长文阅读效果一起评估，不本轮冻结JSON格式。
- 旁白可用连续阅读布局、对话可用头像气泡，给长篇正文保留阅读舒适度；默认样式先做原型，避免每段大头像碎片化文章。
- 立绘/差分引用已有资源；按已确认表情状态选择，无匹配则回退默认，不为换表情自动生图。头像与立绘可不同裁切。
- 悬停头像显示简明资料和立绘预览，点击展开完整详情；触屏/键盘可通过点击/聚焦访问，不依赖hover。只显示玩家获准知道的信息，隐藏身份/后台属性不因悬停泄漏。
- 历史消息固定说话者身份，当前资料与当时状态区分；不能把现在的受伤/改名误称为历史回合当时状态。是否冻结每条消息形象留后续设计。

## 待讨论与优先级

### 2026-10-12补充：故事内私聊与群聊的区别

用户明确：脱离剧情自由聊就是已有独立角色模式，不另造私聊类型。故事内“与角色私聊”目前价值假设是更明显的互动感；直接向正文说与某人互动也能完成，所以核心用途未定。世界时间/主场景暂停暂不设计，不能以尚未证明必要的入口推导一套复杂后台。

当前候选分三层：

1. 故事消息呈现：GM一次输出旁白与多角色台词，UI按说话者分段和头像展示。看起来有多人，但仍一份场景、一轮结算，不是独立群聊引擎，旁白也不是世界内第三个人。
2. 对象化互动入口：原建议撤回。用户指出，当前普通故事消息只有正文AI与玩家，不能把未来的NPC消息头像当作现有入口去验证私聊价值。不得以另一项尚未实现的呈现设计作为“低成本实验”的既有条件；是否需要专门互动入口仍未定。
3. 独立故事私聊：只有后续证明需要持续聚焦对话、隔离知情范围等价值，再决定是否另设视图以及时间与中断规则。当前后置，不阻塞头像或人物记忆。

用户进一步明确：目标群聊/跑团采用各角色独立AI调用，让模型分别扮演人物并互动，而不是由一个GM模拟全部发言。各角色知情范围、目标、发言机会与GM世界结算仍需设计；独立调用不等于已经确认每轮所有角色必须发言，发言调度与费用边界尚待设计。普通故事头像呈现不因此自动改为群聊引擎。

P1产品设计：资产到可玩开局、系统消息与故事分离、身份正确的头像消息。P2整体视觉更新/差分/资料卡精修，实际开发顺序仍由最终设计案确定。

先确认作者开局与AI辅助开局是否并存，以及故事默认偏连贯阅读还是逐角色聊天；再给出原型。已有白底输入框问题独立保留，当前不实施UI改造。
