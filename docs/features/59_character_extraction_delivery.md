# 59 故事人物提取与跨模式复用

2026-11-11；承接26的已确认产品目标。当前为工程范围冻结，尚未实现；不要求用户先验收rc.1才能继续。

## 完整交付目标

故事人物/局内角色→提取预览→确认人设与可选经历→保存独立全局角色卡→在新故事或独立聊天载入。原故事、源卡不被修改；角色无需先成为暗流实体。默认不携带经历，不新增自动后台模型调用。

## 本轮采用的具体方案

- 仅人设保留用户确认的当前人格、能力及表达习惯，不自动还原初始卡，不把伤势、地点或短期情绪写成永久性格。
- 提取预览选择携带经历；带经历卡载入时仍可忽略经历。旧世界经历明确标注来源，不视为目标世界历史，同名人物不自动继承关系。
- 能力与目标世界冲突时遵循目标世界规则；不自动生成能力转换体系。自定义适配可先编辑角色卡。
- 已有角色卡以局内副本为底稿；场景人物用稳定ID/别名获取资料。不能只按名字搜索就自动合并人物。
- 模型负责提炼候选人设与经历；程序负责选择来源、身份、保存及载入语义。调用由用户主动触发并提示费用；结果先预览，不直接写全局资产。
- 来源原文只供本次显式选择的整理请求使用；分享卡不夹带整份历史、幕后账本、私人偏好或密钥。无依据的角色知情不得作为已知事实导出。

## 工程顺序与完成证据

1. 核对局内卡、场景人物稳定身份及已有角色字段；确定最小提取资料结构，复用资产保存/重名处理，不新建资产数据库。
2. 提取请求与预览：复用模型接口和工坊整理能力，候选结果可编辑，失败保留用户输入，不修改源故事。
3. 全局保存与两种载入接通：故事/独立聊天均验证经历开关，世界包导出只含已确认卡片内容。
4. 界面完整路径与自动验收：匿名改名不重复、仅人设不泄漏经历、带经历不认识新世界同名人、取消/重名不覆盖、重启可用。最后统一升版、构建和发布，不逐内部切片发包。

## 范围限制与开发约束

不做完整群聊、角色长期人格演变、跨世界自动能力转换或任意分支树。只校验外部输入和明确数据不变量；新增恢复逻辑需记录具体故障证据。复用现有请求锁与资产生命周期，不追加通用事务平台。人工人物自然度测试统一留到核心功能基本完成后，自动测试不替代文学质量判断。
