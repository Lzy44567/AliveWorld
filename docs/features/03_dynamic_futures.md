# 03 动态未来候选

## 2026-10-12产品设计补充（尚未实现）

用户明确：AI结合各种状态提出几个实质不同方向的未来，以贝叶斯方式赋予概率，Python随机；考虑加入骰子＋属性判定，以及关键要素决定某方向是否能够产生。此处未来候选不是回溯存档的历史分支。

### 建议的职责与顺序（待讨论）

1. 根据世界规则、已成立事实、当前行动、角色/场景状态、实体影响生成本轮相关候选；不强凑某数量，不预写多层树或替玩家决定下一步行动。
2. 先排除不满足硬条件的候选。结构化条件由程序检查；自然语言条件由AI结合依据解释，未知不能自动当成否定。硬条件为零概率，不用概率更新把不可能事件重新救活。
3. 若启用骰子规则，程序按作者给定的属性、难度、加成和随机分布计算并投掷。没有明确规则时不能由AI每轮随意重定数值，规则配置需设计。
4. 对可行方向分配概率，再由Python抽取；骰子可以先决定行动结果，再对该结果下的叙事方向抽样，或直接用骰子规则计算结果概率后一次抽取。两种组织方式不能对同一成败重复随机。
5. 正文落实已选结果；已确认的剧情节点固定结果、世界事实不能被概率覆盖。随机种子/实际抽取/条件依据留回溯记录，不承诺LLM原文确定重现。

### 贝叶斯的适用边界

当前实现是AI给相对权重，程序归一化后抽取，不是严格贝叶斯。严格更新需候选假设、先验和新证据的似然或似然比；AI任意写百分比不能称客观统计概率。

建议区分：有明确骰子规则的结果概率直接计算；叙事候选采用有依据的主观先验和条件证据更新，标为估计。需防止相同事实既进先验又重复作证据、相关证据机械连乘、反复回合重复更新和候选集变化时错误继承概率。暂不冻结数学模型，不为每候选另开AI评估请求。

### 下一模块需决定

- 是否默认保留自由叙事，骰子由世界包/作者选择启用？
- 随机在重要不确定行动时触发，还是每轮均选叙事方向？平静回合能否只有一个方向？
- 默认候选关注多大时间范围，避免一次抽取跨过玩家的下一次重要选择？
- 贝叶斯采用可解释主观估计还是要求世界包提供可量化规则？展示概率如何避免伪精确？
- 固定剧情结果和玩家行动产生矛盾时如何处理，与25剧情节点设计一致。

以下为原实现基线，不把上述设计计为已实现。

## 当前决策

### 2026-10-12后续确认与候选方案

- 用户同意平静回合可只有一个未来，以及推进到当前行动直接后果、下一重要玩家选择前停下。用户要求提示词保持短小，考虑以后预设和多模型适配。
- 候选判定流程：未来AI在原有请求内选择已配置规则、提出难度/加成依据和结果档位对应的候选；Python在规则冻结后执行骰子与结果选择；正文接收确定结果再叙述。不默认另开一次“骰子AI”，不让正文先写结果再补投掷。
- 难度优先来自世界包/规则表；允许AI在预先约定档位中根据当前情境选择并留依据。新小游戏的规则在创作或进入玩法时建立并复用，不每轮临时重定义，不看见骰子结果后修改难度。
- 同次未来请求可输出有限成功/失败/部分成功方向，程序投掷后选择匹配档位；只有已选方向内确有独立叙事不确定性才额外抽取，不重复随机同一成功判定。自适应连续判定另设计，不预生成指数树。
- 无关确定行动不投骰子；已知不可能由硬条件排除，不通过高点数违背世界公理。规则未开启时保留原来的未来方向机制。
- 短提示词候选：“依据已知规则与当前行动，给出实质不同且可发生的近期结果；无实质不确定性时只给一个。不强造波折，不替玩家决定后续行动，在下次重要选择前停止。”结构输出契约单独维护；这不是完整系统提示词。
- 稳定引擎约束保持精简；骰子规则仅启用/相关时加入未来任务，正文只接已裁定结果及必要规则。截短输入不保证首字时间，需按任务观测输入/输出/推理与调用链耗时；禁用可选机制不得仍注入其提示词。

### 小游戏方向（用户灵感，未定稿）

AI创作抽奖、掷骰、简易博彩玩法、塔防等，让世界可玩；可先采用可配置规则与现成玩法组件，由程序结算，再探索生成独立可执行小游戏。后者涉及状态/渲染/存档/重玩和运行权限，不能当作“增加一种骰子”或默认让模型返回代码就在主进程执行，也不等于重启万物插件改造。

候选首期为有限规则的抽奖/骰子模板；塔防和任意Python/JS生成小游戏保留独立设计。需确定创作入口、玩法嵌入形式、规则预览、结果如何回写故事，不在当前捕获设计中扩展实现。

- 现有游戏本来就是单层候选。本阶段优化该核心闭环，不预生成多层 `N×n` 剧情树。
- 每回合根据世界书、角色状态、近期事实、实体与暗流因果生成若干近期未来。
- 先判断候选是否符合硬性事实，再为合格候选分配非负相对权重；权重无需合计 100。
- `eligible=false` 的候选权重归零，不进入 Python 随机池，但可保留在调试展示与日志中。
- `basis` 保存关键事实依据，用于调试模型判断；它不是客观概率证明。
- 候选必须实质不同，但不按改善、恶化、中立等主角中心类别硬凑。
- 重掷与正常回合复用同一候选领域逻辑。

## 当前实现边界

`core/future_candidates.py` 是候选清洗、资格过滤、相对权重与抽取的唯一领域入口。旧协议缺少 `eligible` 或 `basis` 时默认兼容。

本切片不做因素逐项计分、概率连乘、通用条件表达式或世界书演化。后续先依据真实日志验证候选事实性，再专项设计世界书的检索、冲突识别、演化草稿与玩家确认边界。
