# 更新与新手引导

## 目标

AliveWorld 面向没有编程基础的玩家。发行体验必须同时解决三件事：

1. 玩家能够知道有新版本，而不是依赖群消息或反复查看 GitHub。
2. 更新程序不能覆盖 `UserData/`，失败时不能让当前版本也无法启动。
3. 新玩家能够完成“配置模型 → 创建故事 → 载入资产 → 发送第一回合 → 重启读取”的最短闭环。

## P0：Beta 发行方式

- ZIP 文件名携带版本号，例如 `AliveWorld-1.5.0-beta.1-windows-x64.zip`。
- ZIP 内部根目录固定为 `AliveWorld/`，不再随版本变化。
- 玩家关闭游戏后，把新版 ZIP 解压到旧版所在位置并允许覆盖同名程序文件。
- 公开 ZIP 永远不包含 `UserData/`，因此覆盖解压不会删除配置、存档、资产、图片和日志。
- 构建脚本必须自动模拟一次覆盖升级，并用哨兵文件验证 `UserData/` 保留。
- 如果玩家选择全新目录，可在“设置 → 数据与迁移”手动选择旧版的 `UserData/`。

## P0：发布前检查更新（dev.12 已实现）

首个 Beta 不静默下载或安装更新。先实现安全、可解释的检查：

- 设置或“关于”页提供“检查更新”按钮。
- 请求必须异步执行，超时或 GitHub 不可达不能影响游戏。
- 只信任项目配置的官方 Release 地址。
- 显示当前版本、新版本、发布日期、更新摘要和下载入口。
- 默认不强制玩家更新；存档格式确实不兼容时才显示最低兼容版本警告。
- GitHub 网络异常只显示“暂时无法检查”，不能误报“已是最新版”。

实现位于独立的 `core/update_checker.py`、`api/v1/update_routes.py` 和前端 `UpdateSettings.vue`，不把网络请求塞入设置主组件或游戏会话。

## P1：自动下载与安装

自动更新不是简单下载 ZIP。实施前必须具备：

1. Release 清单：版本、平台、下载地址、SHA-256、最低兼容版本和更新说明。
2. 下载到 `UserData/update-cache/`，支持取消、重试和明确进度。
3. 下载完成后校验 SHA-256；不一致立即拒绝安装。
4. 单独更新进程等待 AliveWorld 退出，只替换程序文件，永不写入 `UserData/`。
5. 替换前保留可回滚程序备份；启动健康检查失败时恢复旧版本。
6. 未签名阶段明确显示来源和校验结果；商业发行前增加 Windows 代码签名。
7. 默认只提醒，不后台自动下载，避免网络、流量和隐私争议。

在以上条件满足前，不实现“点击后直接覆盖自身”的危险简版。

## 双层教程

### P0：随包图文教程

`docs/USER_GUIDE.md` 随 ZIP 一起分发，分成：

- 五分钟开始：配置 API、创建故事、发送第一回合、退出重进。
- 资产与世界：角色、世界书、文风、实体、本局/全局。
- 工坊：讨论、草稿、确认、发布。
- 高级玩法：暗流因果、记忆压缩、用户偏好、语义检索和 ComfyUI。
- 数据与更新：`UserData/`、备份、迁移和隐私。

正式截图必须使用全新的演示 `UserData`，不能包含作者 API Key、私人存档、R18 资产或日志。

### P1：游戏内聚焦式引导

游戏内引导不是不可关闭的遮罩动画。它需要：

- 首次启动可选择“开始引导 / 稍后 / 不再提示”。
- 每一步聚焦一个真实控件，并解释“为什么做”，不能只写“点击这里”。
- 允许跳过、返回、关闭，并可在设置中重新开始。
- 控件不存在、窗口过窄或玩家已经完成该步骤时自动跳过。
- 引导进度保存在本机，不进入故事存档。
- 首版步骤只覆盖 API、故事线、新建故事、发送、资产载入、日志和重启读取。
- 高级功能采用独立短教程，不在第一次启动时一次性灌输。

该功能依赖稳定的控件标识和响应式定位，安排在 Beta 收集真实新手反馈后实现。
