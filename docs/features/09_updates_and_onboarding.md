# 更新与新手引导

## 目标

AliveWorld 面向没有编程基础的玩家。发行体验必须同时解决三件事：

1. 玩家能够知道有新版本，而不是依赖群消息或反复查看 GitHub。
2. 更新程序不能覆盖 `UserData/`，失败时不能让当前版本也无法启动。
3. 新玩家能够完成“配置模型 → 创建故事 → 载入资产 → 发送第一回合 → 重启读取”的最短闭环。

## P0：Beta 发行方式

- ZIP 文件名携带版本号，例如 `AliveWorld-1.5.0-beta.1-windows-x64.zip`。
- ZIP 内部根目录固定为 `AliveWorld/`，不再随版本变化。
- 玩家关闭游戏后，把新版 ZIP 解压到旧版所在位置并允许覆盖同名程序文件。
- 公开 ZIP 永远不包含 `UserData/`，因此覆盖解压不会删除配置、存档、资产、图片和日志。
- 构建脚本必须自动模拟一次覆盖升级，并用哨兵文件验证 `UserData/` 保留。
- 如果玩家选择全新目录，可在“设置 → 数据与迁移”手动选择旧版的 `UserData/`。

## P0：发布前检查更新（dev.12 已实现）

首个 Beta 不静默下载或安装更新。先实现安全、可解释的检查：

- 设置或“关于”页提供“检查更新”按钮。
- 请求必须异步执行，超时或 GitHub 不可达不能影响游戏。
- 只信任项目配置的官方 Release 地址。
- 显示当前版本、新版本、发布日期、更新摘要和下载入口。
- 默认不强制玩家更新；存档格式确实不兼容时才显示最低兼容版本警告。
- GitHub 网络异常只显示“暂时无法检查”，不能误报“已是最新版”。

实现位于独立的 `core/update_checker.py`、`api/v1/update_routes.py` 和前端 `UpdateSettings.vue`，不把网络请求塞入设置主组件或游戏会话。

## P1：自动下载与安装

自动更新不是简单下载 ZIP。实施前必须具备：

1. Release 清单：版本、平台、下载地址、SHA-256、最低兼容版本和更新说明。
2. 下载到 `UserData/update-cache/`，支持取消、重试和明确进度。
3. 下载完成后校验 SHA-256；不一致立即拒绝安装。
4. 单独更新进程等待 AliveWorld 退出，只替换程序文件，永不写入 `UserData/`。
5. 替换前保留可回滚程序备份；启动健康检查失败时恢复旧版本。
6. 未签名阶段明确显示来源和校验结果；商业发行前增加 Windows 代码签名。
7. 默认只提醒，不后台自动下载，避免网络、流量和隐私争议。

在以上条件满足前，不实现“点击后直接覆盖自身”的危险简版。

### 私有源码仓库与公开发行仓库迁移

源码仓库即将私有化时，更新元数据和二进制附件必须迁移到独立的公开发行仓库，例如 `AliveWorld-Releases`。客户端不应为了检查更新持有 GitHub Token，也不能依赖访问私有源码仓库。

迁移采用“公开名称接管”，不要求客户端改 URL：

1. 当前公开 `AliveWorld` 源码仓库先发布 dev.20；dev.19 使用原地址即可发现并由玩家人工安装它。
2. 把已有 Release 的说明、ZIP 和摘要完整复制到临时公开发行仓库并核对。
3. 将源码仓库改名为 `AliveWorld-Source` 并转私有，再立即让发行仓库接管公开名称 `AliveWorld`。
4. dev.19、dev.20 和未来客户端始终优先请求 `/Lzy44567/AliveWorld/releases`；名称接管后 URL 不变，只是仓库内容由源码变为发行物。
5. `AliveWorld-Releases` 只作为迁移期间的临时回退名，接管完成后不应成为长期首选地址。

GitHub 没有可配置的 Release API 重定向，不能把仓库网页重定向当成客户端更新协议。发行仓库只保存公开 README、版本说明、更新清单、ZIP 和校验文件，不复制私有源码。

#### 建议的最终仓库拓扑（待桥接包完成后执行）

当前两个仓库均无 star、watcher 或 fork，可在桥接节点一次迁移：

1. 先把已有公开 Release 的说明、ZIP 和校验文件复制到 `AliveWorld-Releases`，核对摘要。
2. 将现有含完整 Git 历史的 `AliveWorld` 改名为 `AliveWorld-Source` 并转为私有；本地开发 remote 随后改指向它。
3. 将公开的 `AliveWorld-Releases` 改名为 `AliveWorld`，使项目主页、下载与 Issue 保持最容易搜索的名称。
4. GitHub 在旧名称被重新使用后不会继续把 `/AliveWorld` 重定向到改名后的源码仓库；这是本方案的预期行为：dev.14 等旧客户端仍请求 `/AliveWorld/releases`，但会进入新的公开发行仓库。
5. 客户端始终优先 `/AliveWorld`，迁移期兼容 `/AliveWorld-Releases` 回退；确认名称接管稳定后再移除回退。

不能通过在公开分支提交“删除所有源码”来隐藏历史；文件仍存在于旧提交。仓库改名、转私有和发行仓库接管旧名称必须作为同一迁移窗口执行，避免旧客户端在中间状态查不到版本。

### 一键更新实现切片

“一键更新”由主程序和独立更新助手协作：

1. 主程序读取公开发行清单，选择当前平台 ZIP 与可信摘要。
2. 下载到 `UserData/update-cache/<version>/`，前端轮询真实字节进度，支持取消和重试。
3. 校验 GitHub Release asset digest 与随包 SHA-256；任一不匹配都拒绝安装。
4. 解压到暂存目录并验证固定 `AliveWorld/` 根、EXE、运行时、版本和隐私清单。
5. 把更新助手复制到系统临时目录，传入当前 PID、安装目录、暂存目录和一次性随机令牌。
6. 玩家确认后主程序退出；助手等待文件锁释放，备份除 `UserData/` 外的旧程序，原子替换并启动新版。
7. 新版写入一次性健康确认；超时或版本不符时助手恢复旧程序并保留失败报告。
8. 成功后清理旧程序备份；更新缓存和失败报告可由玩家在设置中查看/清理。

源码运行模式只提供检查和下载，不自动覆盖 Git 工作区；只有 PyInstaller 便携版显示“一键更新”。

#### dev.20 实现状态

- 主程序通过后台线程下载官方 Windows ZIP，前端轮询真实字节进度；玩家可取消，失败后可重新开始。
- 必须同时匹配 GitHub Release asset digest 与 `.sha256` 附件；随后检查 ZIP 路径、固定根目录、EXE、运行环境、内部版本和 `UserData` 隐私边界。
- `AliveWorldUpdater.exe` 使用独立 PyInstaller onefile 构建。确认安装后复制到系统临时目录运行，主程序自动退出，不要求玩家打开网页、解压、选择目录或手工备份。
- 更新助手先完整复制旧程序，再替换除 `UserData` 外的文件；新版启动后用一次性令牌和版本号写入原子健康确认，失败则恢复并重启旧版。
- WebView 与系统浏览器回退启动方式都监听更新退出；更新过程写入本机日志。
- Python、API、前端生产构建、11 项 Edge 端到端验收和真实 PyInstaller 双 EXE 构建均已通过；便携 ZIP 已验证结构、隐私边界、SHA-256 和覆盖升级保留 `UserData`。dev.19 尚无更新助手，不能作为一键更新起点；最终实机验收应在玩家人工安装 dev.20 后，从 dev.20 一键更新到后续已发布版本。

## 双层教程

采用“首次快速闭环 + 随包完整文档”的混合方案，而不是在首次启动时播放一套很长的遮罩教程：

- 无 API Key：直接打开 API 配置，测试成功后结束本步骤。
- 尚无故事线：引导创建故事，可选择一个带游戏介绍的入门梗概，但不替玩家静默创建。
- 首个故事载入后：只提示输入框、资产栏和日志三个关键入口。
- 复杂工坊、暗流因果、记忆、偏好和 ComfyUI 进入图文指南及各自的短教程。

这样能让没有技术背景的玩家尽快开始第一回合，又不会让已经会用的玩家被长流程遮罩阻塞。

### P0：随包图文教程

`docs/USER_GUIDE.md` 随 ZIP 一起分发，分成：

- 五分钟开始：配置 API、创建故事、发送第一回合、退出重进。
- 资产与世界：角色、世界书、文风、实体、本局/全局。
- 工坊：讨论、草稿、确认、发布。
- 高级玩法：暗流因果、记忆压缩、用户偏好、语义检索和 ComfyUI。
- 数据与更新：`UserData/`、备份、迁移和隐私。

正式截图必须使用全新的演示 `UserData`，不能包含作者 API Key、私人存档、R18 资产或日志。

### P0：应用内快速开始（dev.14 已实现，不等同教程）

- 没有 API Key 时先进入模型配置；源码前后端并行启动时有限重试配置读取，不能把后端尚未就绪误判为缺少密钥。
- 没有故事且没有待处理旧资产迁移时，显示轻量快速开始，可选择可编辑的入门梗概或空白创世。
- 支持“稍后再说”和“不再提示”；设置中的“关于与更新”可以重新打开引导。
- 已有故事的玩家直接进入原界面，不显示新手弹窗。
- 旧资产迁移优先于新建故事，避免玩家先创建空故事后才发现旧存档。

设置中的重播入口应命名为“重新打开快速开始”。它目前只重新打开创世选择，不应称为“重新开始新手引导”。真正的新手教程属于下方的聚焦式引导。

### P1：游戏内聚焦式引导

游戏内引导不是不可关闭的遮罩动画。它需要：

- 首次启动可选择“开始引导 / 稍后 / 不再提示”。
- 每一步聚焦一个真实控件，并解释“为什么做”，不能只写“点击这里”。
- 允许跳过、返回、关闭，并可在设置中重新开始。
- 控件不存在、窗口过窄或玩家已经完成该步骤时自动跳过。
- 引导进度保存在本机，不进入故事存档。
- 首版步骤只覆盖 API、故事线、新建故事、发送、资产载入、日志和重启读取。
- 高级功能采用独立短教程，不在第一次启动时一次性灌输。

该功能依赖稳定的控件标识和响应式定位，安排在 Beta 收集真实新手反馈后实现。
