# 自动化验收与可观测性设计

## 目标

AliveWorld 已有大量领域和 API 自动测试，但完整玩家循环仍依赖人工逐页操作，容易漏测资产开关、异步任务、持久化和 UI 回归。本设计建立四层测试，不用一个万能调试接口替代真实代码路径，也不把可操纵私人数据的后门打进发行版。

## 四层测试

### 1. 领域与 API 回归

继续使用现有 Python 测试直接验证存档、资产、实体、账本、记忆、偏好、工坊和生图领域。新增场景驱动器应优先组合现有正式 API；只有正式 API 无法观测的内部状态才通过依赖注入或测试专用适配器读取。

测试数据必须使用临时 `UserData` 根目录，运行前后都不能扫描、修改或删除玩家真实数据。

### 2. 假模型服务

提供独立的本地 OpenAI-compatible 假服务，只在测试命令启动。不同任务路由使用不同测试模型名，例如 `fake-story`、`fake-overseer`、`fake-workshop`、`fake-memory`，从而稳定返回符合各自 JSON 协议的正文、实体行动、工坊提案或记忆摘要。

它的职责是验证请求是否发出、上下文是否包含或排除了指定资产、返回解析、异步状态和持久化，不评价文学质量。测试还应提供超时、空返回、审核拒绝、无效 JSON 和连接失败脚本。发行包默认不包含启用入口，生产配置也不能切换到测试管理 API。

ComfyUI 同样使用独立假服务验证提交、轮询、失败、取消和图片落盘；真实显卡与真实模型只留给少量人工兼容验收。

### 3. 浏览器端到端测试

使用 Playwright 或同类浏览器驱动按真实 UI 完成高价值路径：首次启动、配置测试接口、创建故事、载入/关闭资产、发送正文、撤回/重试、工坊草稿与发布、生图任务、重启恢复和删除确认。

浏览器测试同时断言 DOM 文本、控件状态、网络响应和后端文件结果，并在失败时自动保存截图、页面结构、控制台错误、网络摘要和相关日志。截图不需要新增游戏内接口；浏览器测试工具可以直接截取页面。视觉截图比较只覆盖少量稳定布局，避免字体和显卡差异制造大量假失败。

Codex 视觉/键鼠操作适合探索未知交互和发行前抽查，但速度慢、消耗上下文且不够确定，不能替代可重复的 Playwright 场景。

#### 可视化运行模式

浏览器验收增加可选的 headed/slow 模式，而不是另写一套“演示测试”：

- 默认 CI 模式继续无头、快速运行；`--headed` 打开真实 AliveWorld 页面，`slowMo` 在动作之间保留可观察间隔。
- 页面显示只读测试浮层：当前场景、步骤编号、正在执行的动作和最近断言；浮层由 Playwright 注入，不进入生产构建。
- 每个关键步骤完成后可选自动截图，并生成一份按场景排列的 HTML 报告。失败时仍强制保存截图、DOM、控制台和网络证据。
- 精确功能结果以 DOM、API、JSON 协议和磁盘状态断言为准；截图用于检查遮挡、跳动、溢出、视觉层级和异常空白，不能凭“看起来正常”替代断言。
- Codex 可在发行候选节点读取关键截图做视觉抽查；不要求每次单元测试都消耗视觉模型。

优先级为 P1。它能显著降低人工理解自动测试过程和 UI 抽查成本，但不阻塞一键更新桥接版；先复用现有 10 条 Playwright 场景实现命令行开关、慢速模式和 HTML/截图报告，再考虑游戏内测试入口。

### 4. 便携包冒烟与人工体验

便携包测试验证无 Python/Node 环境启动、数据目录、升级保留、端口、浏览器窗口和退出。真实 DeepSeek、真实 ComfyUI、长篇连贯性、提示词质量和手机布局仍需人工验收，因为固定假返回无法证明模型效果。

## 不建立“万能控制后门”

前端本身已经通过正式 API 操作大部分功能。测试客户端应复用这些路由，而不是新增一个可以任意执行命令、读取任意文件和截取桌面的 `/test/all` 接口。

确有需要的测试控制能力必须同时满足：

- 仅测试进程通过环境变量启用；生产启动器拒绝启用。
- 仅绑定回环地址并使用随机会话令牌。
- 只能访问隔离的临时测试目录。
- 使用白名单动作，不接受文件路径或任意代码。
- 构建检查证明发行包没有开启测试模式。

## 结构化日志

日志后端统一记录：时间、级别、分类、任务用途、trace ID、故事/任务 ID、短摘要和可展开详情。分类至少包括正文、动态未来、Overseer/暗流、世界书捕获、工坊、记忆、偏好、生图和系统。

前端日志页提供分类筛选和折叠行；默认只显示时间、来源、状态与安全摘要，展开后显示格式化请求/响应 JSON。API Key、自定义请求头、完整参考图和不必要的私人文件路径必须脱敏。日志用于可观测性，不成为第二套业务状态数据库。

### dev.18 实现状态

首版结构化投影已落地为与人类可读 `.log` 并行的 `.jsonl`。LLM 请求和响应具备稳定 trace ID、任务分类、阶段、状态、摘要与详情；其他 Python 日志通过统一分类器形成兼容事件。前端支持分类、摘要搜索、trace 过滤和逐条展开。结构化详情遮罩常见凭据与用户目录，但仍可能包含正文和私人卡片，因此只保存在本机，分享前仍需玩家检查。

故事/任务 ID 字段已经进入格式，但只有调用点明确提供时才记录；不能根据文本猜测业务对象。后续扩展生图任务和后台工坊 trace 时，应在调用边界显式传入 ID。日志不是存档、任务队列或审计数据库，不参与恢复业务状态。

### dev.19 实现状态

浏览器场景由 5 条扩展到 9 条。新增隔离假 ComfyUI，支持连接检查、模型列表、提交、失败、历史查询、成功图片下载和取消；第一次提交固定失败，重试创建的新任务固定成功，因此可以稳定验证正文失败卡、技术阶段说明、重试按钮、异步轮询和图片交付。

新增场景覆盖：正文同一行动重试后替换最后一回合并可撤回；世界书工坊编辑只进入草稿、发布后才改变正式资产且重进同步；生图首次执行失败后原位恢复；页面重载后重新唤醒故事并恢复正文与局内资产。测试仍通过正式 API 和玩家界面运行，没有新增生产测试路由。

### dev.20-a：声明式提示词契约

假模型不再只识别少数写死的中文卡名。任何测试资产、提示词片段或故事输入都可携带 `【AWTEST:名称】`；假服务记录该标记实际进入的任务类型，并通过 `/__test__/coverage` 汇总正文、动态未来、Overseer、工坊、记忆、偏好和生图提示词请求。关闭某项功能时，测试断言对应标记必须从指定请求消失，而不只检查界面开关颜色。

正文假模型从实际收到的历史中寻找 `自动测试正文 n` 并返回 `n+1`，用于证明上下文延续、撤回和压缩后的热历史，而不是依赖全局计数器伪造连续性。每种 AI 任务仍使用独立合法 JSON 适配器；不经过模型的存档、删除、克隆、账本生命周期和文件恢复继续使用领域/API/浏览器断言，不能为了统一而塞进提示词测试。

测试标记、假模型管理端点和固定返回只存在于隔离测试服务。生产包不暴露 `/__test__` 路由，也不读取玩家真实 `UserData`。

### dev.20-b：状态协议与更新提示

假结算返回动态状态条、文本状态和世界时间；Python 严格验证 JSON 字段，浏览器验证第 1/2 回合的可见变化及刷新持久化。启动更新提示同样进入浏览器场景，确保 GitHub 不可达或提示出现时均不阻塞玩家进入游戏。

## 场景清单与通过标准

每个场景用声明式清单描述前置资产、开关、玩家动作、假模型脚本和预期结果。至少覆盖：

1. 各类资产启用时进入对应上下文，关闭后明确不进入。
2. 无实体/全部封存时不请求 Overseer。
3. 账本触发、撤回恢复、实体记忆同步和删除生命周期。
4. 世界书工坊草稿隔离、发布、重进同步和冲突保护。
5. 记忆压缩后原文保留、工作上下文变化和失败回退。
6. 偏好学习关闭时不拼接提示词，候选不会直接污染正式偏好。
7. 生图提示词、ComfyUI 提交、占位、完成、失败、重试和删除。
8. 重启后故事、设置、任务和资产恢复。

## 开发顺序

1. P0：假 OpenAI-compatible/ComfyUI 服务与隔离测试数据根目录。
2. P0：一条“创建故事—载入资产—正文—撤回—重启”的 API 场景。
3. P0：浏览器基础场景与失败证据包。
4. P1：结构化日志分类、折叠详情和 trace 关联。
5. P1：逐步把现有人工验收清单转换为自动场景；文学质量与真实服务仍保留人工样本。
