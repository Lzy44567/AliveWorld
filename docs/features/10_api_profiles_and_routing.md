# 接口配置中心与任务路由

## 状态与优先级

- 状态：dev.15-a 至 dev.15-c 已实现；dev.15-d 的工坊待发布徽标与版本恢复仍待后续切片。
- 优先级：P0，作为 `v1.5.0-dev.15` 的核心开发线。
- 原始需求依据：`功能想法_原始手写版本.txt` 要求支持 DeepSeek、Gemini、ChatGPT、Claude、自定义文本接口，以及 ComfyUI、Stable Diffusion 和后续云生图接口。

本功能不是把现有三个 API 表单换成卡片皮肤。它要解决两件彼此独立的事：

1. **连接配置**：玩家有哪些可用的文本或生图服务。
2. **任务路由**：正文、记忆、工坊、偏好分析、图片提示词等任务分别使用哪个连接。

连接和用途不能绑死，否则每增加一个 AI 功能都要重复保存 Base URL、密钥和模型名。

## 当前代码事实

当前 `config.yml` 使用一组正文配置和两组可选覆盖：

- `api_key / base_url / model`
- `memory_api_key / memory_base_url / memory_model`
- `preference_api_key / preference_base_url / preference_model`
- `image_api_url` 与前端保存的 ComfyUI 工作流、模型和生成参数

`api/v1/game_routes.py` 同时承担配置读写、密钥显示、连接测试、运行时 AI 实例装配以及活动会话热更新。它在当前规模可运行，但继续增加任务和服务商会形成高耦合热点。生图领域已经具备独立服务商协议，应保留这一边界。

## 领域模型

### 连接配置 `ConnectionProfile`

每条连接使用稳定 UUID，不用显示名称充当引用：

- `id`
- `name`：玩家自定义名称，例如“DeepSeek 正文”“本地 ComfyUI”
- `category`：`text`、`image`；为未来 `audio/video` 预留枚举扩展
- `protocol`：首版只实现 `openai_compatible` 与 `comfyui`
- `provider_hint`：DeepSeek、OpenAI、Gemini、Anthropic、自定义等界面预设；预设只负责填充已验证的默认值，不冒充尚未实现的原生协议
- `base_url`
- `api_key`：只保存在本地私人配置，列表与普通查询只返回“已配置”
- `default_model`
- `enabled`
- `advanced_options`：超时、并发、RPM、思考参数等；默认折叠，只有协议支持时才显示
- `last_test`：最近测试时间、成功状态和可读错误；不把密钥或正文写入测试记录

首版一条文本连接保存一个默认模型。任务路由可以选择该连接并可选覆盖模型名，避免为了同一个密钥的不同模型复制整条连接。以后若真实需求证明有必要，再增加服务商模型列表发现和收藏。

### 任务路由 `TaskRoute`

首版任务槽位：

- `story`：正文与动态未来
- `overseer`：暗流实体统筹，默认继承正文
- `workshop`：全部工坊 Agent，默认继承正文
- `worldbook_capture`：世界书设定捕获，默认继承正文
- `memory`：记忆压缩，默认继承正文
- `preference`：偏好分析，默认继承正文
- `image_prompt`：把正文/角色资料整理为生图提示词，默认继承正文
- `image_generation`：ComfyUI 或未来云生图连接

每个文本任务只保存 `connection_id` 和可空的 `model_override`。`inherit` 表示继承主文本连接。删除正在使用的连接时必须阻止直接删除，先要求重新分配用途；禁用连接时显示受影响任务。

## 渐进式 UI

设置中的“API 配置”升级为“接口与模型”，但不把所有复杂度一次展开：

### 第一层：连接列表

- 顶部按“语言 / 生图”切换；视频等未实现类别不显示空标签。
- 卡片只显示名称、服务商/协议、地址摘要、默认模型、连接状态和“主接口”标识。
- `+` 新建连接。
- `…` 菜单包含编辑、测试、克隆、停用和删除。
- 删除采用统一的异位确认或模态确认，不能让确认按钮出现在原删除按钮位置。

### 第二层：新建与编辑

默认只显示：

1. 配置名称
2. 服务商预设
3. API Key
4. 接口地址
5. 默认模型
6. 保存并测试

并发、RPM、超时、思考模式、自定义请求头等进入“高级选项”。不支持的参数不显示，避免小白误以为每个服务商都需要配置。

### 第三层：用途分配

默认模式只有一个“主文本接口”，其他文本任务全部显示“继承主接口”。点击“高级任务分配”后，才允许分别覆盖记忆、偏好、工坊、Overseer、世界书捕获和图片提示词。该方案已由用户确认。

生图连接单独选择；ComfyUI 的模型、工作流和生成参数仍由生图模块管理，不塞入通用密钥表单。接口中心只管理服务连接和鉴权，生图模块管理服务商特有能力。

## 服务商与协议边界

- `OpenAI-compatible` 是首个完整文本协议，当前 DeepSeek 和大量中转/本地服务可直接使用。
- DeepSeek、OpenAI 等预设可以提供默认地址和帮助文字。
- Gemini、Anthropic 的“原生接口”必须各自实现适配器和测试，不能只更换图标就宣称支持。
- ComfyUI 是首个完整生图协议，通常不需要 API Key。
- 云生图必须按厂商逐个适配能力、鉴权、任务状态、取消和内容政策；不能假设“填写 URL 就兼容”。
- R18 内容不得在未明确提示时从本地 ComfyUI 自动回退到云端。

## 密钥与迁移

- 所有连接凭据仍只保存在本机 `UserData/config.yml`，不进入存档、日志、前端 localStorage、Git 或发行 ZIP。
- API 列表只返回遮罩状态；显式点击显示时才从本机后端短暂读取。
- 本地纯便携应用无法仅凭自身实现“绝对安全加密”：若密钥与解密程序放在同一目录，攻击者仍可读取。首版应诚实说明本机明文边界；系统凭据库属于后续跨平台专项。
- 首次升级时把旧的正文、记忆和偏好字段迁移为连接配置与任务路由。迁移先备份旧配置，原子写入，失败则继续使用旧结构。
- 迁移必须保持现有玩家的任务继承语义，不要求重新输入密钥。

## 高内聚、低耦合落点

后端建议拆分：

- `core/model_connections/models.py`：连接、能力和任务路由领域模型
- `core/model_connections/repository.py`：私人配置持久化、迁移和原子写入
- `core/model_connections/registry.py`：协议适配器注册和能力查询
- `core/model_connections/router.py`：按任务解析连接和模型
- `api/v1/model_connection_routes.py`：列表、创建、修改、测试、密钥显示和用途分配

`AIEngine` 继续只负责一次文本模型调用，不读取全局配置。`GameSession`、记忆、偏好、工坊和生图提示词只向任务路由请求所需引擎，不自行解析 `config.yml`。`game_routes.py` 最终移除模型配置管理职责，只处理游戏会话。

前端建议拆分：

- `stores/connectionStore.js`
- `api/connectionApi.js`
- `settings/connections/ConnectionList.vue`
- `settings/connections/ConnectionEditor.vue`
- `settings/connections/TaskRouting.vue`
- `settings/connections/ProviderHelp.vue`

设置主窗口只负责切换页面，不承载连接表单逻辑。

## 小白帮助

帮助采用三级信息，不在主界面堆长教程：

1. 字段旁简短问号：解释“到哪里获得、是否必填、会发送什么”。
2. 服务商预设内的“查看配置教程”：打开对应的短步骤页面。
3. 完整图文指南：提供 API 申请、余额、模型名、常见错误、ComfyUI 安装和模型放置说明。

第三方整合包与模型链接必须在发布前核对来源、许可、版本、文件大小和安全风险。不能把未经核验的网盘或视频链接硬编码成官方依赖；AliveWorld 也不静默安装 Torch、大模型或第三方节点。

## 工坊自动发布判断

草稿自动保存和正式资产自动发布不是同一件事。现有草稿隔离是防止 AI 错改正式资产的事务边界，直接增加“自动发布一切”会削弱撤销与审阅。

已确认采用以下顺序：

1. P0：离开工坊、切换资产或返回游戏时，若有未发布修改，显示持续可见但不阻断的“有草稿待发布”状态，并提供一键发布/继续保留。
2. P0：工坊入口和资产卡显示未发布草稿徽标，避免玩家忘记。
3. P1：先建立正式资产版本快照和“撤销最近一次发布”。
4. P1：再提供默认关闭的自动发布，并至少区分“玩家直接编辑”和“AI 修改”；高影响操作、删除、公理和绝对规则永不自动发布。

没有版本快照前，不实现不可逆的全量自动发布。

## 教程边界修正

`dev.14` 实现的是“快速创建故事”，不是完整新手教程。教程应分为：

- 快速开始：配置主接口并创建第一条故事线。
- 聚焦式基础引导：真实聚焦故事线、输入框、资产载入、日志和重启读取。
- 功能短教程：接口中心、工坊、记忆、偏好、因果账本和 ComfyUI 各自独立。
- 完整图文手册：供玩家随时查阅。

设置中的入口应准确命名为“重新打开快速开始”；等聚焦式引导实现后，再增加独立的“重新开始新手教程”。

## 验证

- 旧 `config.yml` 自动迁移且正文、记忆和偏好行为保持一致。
- 密钥不会出现在普通 GET、日志、localStorage、存档、Git 或 ZIP。
- 连接重名、删除正在使用的连接、停用连接和无效任务路由均有明确错误。
- 主连接切换后新会话与现有活动会话均使用新引擎。
- 单个高级任务覆盖不会影响其他任务。
- 文本接口和 ComfyUI 使用各自协议测试，不使用同一个假成功逻辑。
- Python 领域/API 测试、前端交互测试、生产构建和便携包迁移测试全部通过。

## dev.15 实现结果

- 后端按 `models / repository / router / runtime / API routes` 拆分；各业务只按任务用途请求引擎，不自行读取密钥。
- 前端按 `connectionApi / connectionStore / ConnectionCenter / ConnectionEditor / TaskRouting` 拆分；设置主窗口只负责页面切换。
- 旧配置首次读取时无损迁移并生成 `config.pre-model-connections.yml` 本机备份；备份和正式配置均被 Git 忽略。
- 现有正文、Overseer、世界书捕获、记忆、偏好、工坊及图片提示词调用已进入任务路由。
- 连接采用方案 A：一张卡保存账号、地址、密钥和默认模型，任务可覆盖模型名。
- “连接测试”和“任务分配”是两个概念：前者验证某条服务能否调用，后者决定某项功能实际使用哪条服务。

尚未在本切片实现：

- Gemini、Anthropic 原生协议和任何云生图厂商适配。
- 服务商模型列表自动发现、RPM/并发调度和系统凭据库。
- 运行日志中的连接名称与任务路由可视化；当前仍由既有 LLM trace 记录实际模型调用。
- 工坊自动发布；待发布徽标、正式资产版本快照与撤销最近发布仍按原优先级后置。

## 已确认

1. 普通模式采用“一条主文本接口，其他任务默认继承”；高级模式允许每项功能单独选择连接。
2. 首版只承诺 OpenAI-compatible 文本接口与 ComfyUI；其他服务商作为经过验证的兼容预设或后续原生适配。
3. 暂不开放“自动发布全部草稿”；先实现待发布提醒、徽标和版本快照。
4. 连接卡采用方案 A，避免重复保存同一密钥，同时允许任务覆盖模型。
5. 聚焦式新手教程排在接口中心稳定之后，避免教程锚定旧设置界面。
