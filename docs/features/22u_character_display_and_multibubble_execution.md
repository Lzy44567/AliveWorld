# C4 三态显示与多气泡：阶段实施合同

2026-10-06，Astra设计。承接22t并覆盖其显示组合、独立逐字动画及下一片建议。用户已授权沿明确显示方向编码；不是逐项批准所有工程细节。本文不改运行代码、不迁移真实会话、不Git。当前C4-0为7f5265e、版本dev.19；637 Python/116 Node/相关Edge2为历史证据，本轮无新运行验收。

## 1. 已确认玩法与范围

- 流式开启即在气泡中实时出现文字，两者绑定，不加逐字开关；不是等完整结果后假流式。
- 流式和气泡间隔二选一，或全关。无后续入场动画、逐字重播、速度滑块或模型秒数。
- 一次请求产出完整有界气泡组，不按标点机械拆分、不每气泡调用。
- 连续短批发完后统一回应期间玩家连发；真正等待只发当前话题，到追问才继续；新回复先回应再适当接回有来历旧话题。三者不再反复提问。
- 不用新停止按钮、关键词取消或额外分类API解决插话；不删除角色已有停止生成能力。
- 后台/重开接收已生成内容及未读；进程退出不假装运行。撤回/重生成按批。

不扩C5、容量、跨会话画像、心理学调用、人格演变、版本、打包、远程或付费实测。C4-0仍是single reply指导，不冒称C4完成。角色理由、人设差异、真实等待与自然接话仍须质量评价，假模型测试只证明工程。

## 2. 冻结三种显示状态

| 状态 | 请求/显示 | 正式提交 |
| --- | --- | --- |
| stream | 供应商流式返回，按到达顺序更新当前气泡；后续气泡也实时出现 | 全JSON、来源、账本验证成功后整组一次提交；预览原位转正式 |
| gaps | 一次非流式取得整组并验证；Python逐条安排间隔，整条气泡出现 | 每条到期事务提交；末条同时结算账本 |
| instant | 一次非流式取得整组并验证，直接显示所有气泡 | 整组一次提交 |

UI保留“流式输出”开关，增加“气泡间隔”开关，不用下拉。开启其一原子关闭另一个；两者关即instant，无第三逐字开关。文案明确“流式：收到文字即显示，完成验证后保存”“间隔：完整生成后按内容长度分条发送”。

内部可用display_mode三值避免非法组合；API现有delivery继续只表示stream/non_stream。旧设置stream映射stream，non_stream映射instant，不擅自给旧用户开启间隔。新设置验证拒绝矛盾payload；旧客户端缺新字段按旧delivery映射。新会话默认保持当前既有默认，不顺手改变。

每attempt保存显示快照；发送/送达中设置下一次生效，UI说明，不重排当前队列。重试可按玩家当前显示选择创建新attempt，但原输入、协议和来源快照不变；重载恢复已验证队列必须使用其保存快照。

## 3. 真实源码缺口与明确层次

stream_json.ReplyPreview目前只识别根reply字符串，保存有界原始JSON后仍由contract最终验证。transport.generate使用一次供应商请求、零自动重试，流式逐chunk喂lexer；新数组不能直接复用根reply识别。

characterChatStore当前preview是单字符串，reply_delta累加，终态清空后读权威记录；CharacterWorkspace只画一个未保存预览块，并在忙碌时禁用流式开关。必须改为按attempt+气泡ordinal的预览集合，不能只把一个大字符串换行。

三种身份严格分开：正在生成的预览可被玩家看见，但不是正式证据；已验证候选仅为待发草稿；正式消息由服务端提交，可进入历史/来源/未读。已读再由前台确认。玩家看见预览不使它自动成为正式经历。

## 4. 新输出协议和容量合同

新增明确character.reply.v3，旧v1/v2不加字段。根对象严格仅messages、ledger_ops、memory_annotations；messages必须先输出以便及时预览。messages为1–6项，每项仅{local_id,text}，local_id严格b0、b1……连续对应数组位置；text为非空字符串，整组最多8000 Unicode码点。总原始JSON仍≤65536 UTF-8字节，深度≤12；拒绝重复key、未知字段、非法Unicode、非有限数、截断、工具调用。

ledger_ops及memory_annotations沿用v2类型/权限/最多6项，不添加心理或策略字段。来源可引用本次提供的正式message_id，或候选本地引用b0等；解析后程序映射为本attempt预留的稳定UUID，禁止任意新全局ID。为免本地命名与正式ID混淆，bN只在v3来源解析分支接受，不影响旧协议。

dialogue_event只允许本次认领的正式玩家输入及本组气泡；历史原文保持M3权限，OOC仍不可作来源。不能为了多条输入放开来源类型或伪造拼接引文。supersede仍仅可选上下文提供的active旧entry，同组同目标最多一次，不允许引用同组新entry或链式操作。

程序在请求准备时预留最多6个气泡ID及group_id，输出只使用实际长度前缀。lexer事件使用ordinal，不等模型local_id才展示；最终local_id不符则整组失败。ID表既用于原位确认，又用于重放去重，不让模型决定身份。

不新增end/策略状态：真等待用当前组在互动点结束表达，组结束且无输入就不再调用。不强迫每组6条或所有角色短句；roleplay可单条。

## 5. v3实时预览lexer与确认

扩展或独立新增有界单遍lexer，仅抽取根messages数组直接子对象的text字符串；ledger.content、evidence.quote、卡片文本及其它同名键不显示。维护数组ordinal、容器路径、key去重、字符串escape和代理对状态，跨任意chunk切割都正确；不可用正则扫描text。

输出preview_start/preview_delta/preview_end（名称可沿既有事件封装规范），带session/action/request/group、ordinal及单调事件seq。delta解码JSON转义后立即送前台，后续气泡text到达即开始新预览气泡，不能等根对象结束。前台按到达内容立即追加，不人为固定每字延迟、不在完成后重播；供应商chunk可能带多个字，实时字显不等于人为匀速一字一帧。

lexer只提供预览，不证明协议完成；完整parse_result和账本/容量校验是唯一提交门。最终成功返回稳定ID映射及权威组，前台原位以正式内容覆盖对应预览，去掉“生成中·未保存”，不追加第二份，不重新播放。内容核对不一致时以权威结果为准并记录无正文诊断。

预览字符/数量/深度/原始字节均有界；重复/乱序事件不累计，旧request事件不能污染新attempt。断连后查询权威状态，不从preview构造正式历史；重连不自动再请求模型。

## 6. 流式失败的现行继承策略

推荐沿用当前失败语义：流式预览旁明确“生成中·未保存”；网络失败、截断、协议或账本验证失败时撤去临时气泡，显示“本批未保存，可重试”，保留正式玩家输入。预览正文不持久化、不入列表预览/未读/账本/下次上下文，重开只显示失败状态。这样不增加“失败台词档案”或半真经历。

这是已有预览生命周期的工程继承，不是新收费/数据留存选择，不需重问三种模式。若用户希望失败预览长期保留供复制，再作为独立UX选择讨论，不能默认保存。

玩家可能根据未验证预览发送新话：输入照常保存，但直到本组成功才自动认领下一组。若本组失败，待回应输入保留而不自动调用，界面提示“上一批未保存，先重试或继续发送”。显式继续发送可合并尚未回应输入进入一次新请求；不把失败预览注入该请求，不声称角色已经说过它。重试原组只认领原输入，成功后再回应队列，不重复玩家消息。

此限制必须在失败路径可见，不能因玩家已看见就把坏JSON补成正式消息。没有真实产品未知阻塞parser/lexer编码；若日后要求恢复失败台词，另过数据语义门。

## 7. gaps计时、正式事务和恢复

工程首版参数：首条验证保存后立即送达；后续delay=clamp(0.1秒×下一条非空白Unicode码点数,0.1秒,3秒)。0.1秒来自用户示例，3秒是避免长文过长等待的可逆工程上限，不标记用户确认；合成短/长/emoji例子验证，参数集中命名，不向模型索要、不加速度设置。

保存候选和第一条送达可一个事务；后续保存next_index和到期信息，timer仅唤醒执行，事务重验组有效性、next_index、截止时点。幂等键group_id+ordinal；重复timer/丢响应不重复。服务器本进程计时用单调时钟，持久时间保存UTC以供诊断/恢复，不伪造离线时点。

进程重启或长休眠：已正式部分立即还原，有效剩余从恢复时重新安排下一短间隔，不按过期时钟瞬间倾倒、不重播历史。程序退出期间没有送达。页面关闭但服务存活照常送达；UI不是唯一timer。stream/instant没有完成后的计时队列。

整组预校验并预留容量后才送首条；每次气泡提交与正式seq/列表预览/未读更新同事务，保存失败不广播。未发候选不进入上下文、世界书命中或来源索引。容量不足在首发前失败，不发一半才发现装不下。

## 8. 批末账本和异常结算

stream/instant整组消息和op/注解/inverse一次原子提交。gaps前缀先作为正式原文，最后一条与整批账本结算同事务；下一请求只在结算后认领，避免看到半套推断。不做每气泡op图、不每字保存。

依赖仍预先校验：op引用的候选都必须属于本组；最终正常完成时全满足。等待送达期间阻止手工账本/语境变更并给忙碌说明，普通玩家追加输入与已读不阻止。容量预留不可超卖，不能靠后续supersede提前腾位置；按op顺序检查总量和active峰值。

磁盘失败可恢复原候选，不自动丢弃尾部。必须终止的异常组只结算来源全部正式且目标仍有效的op子集，依赖未发气泡者废弃；op、注解、inverse和终止状态同事务。没有编造替代引文。该路径由故障恢复处理，不新增正常插话截断玩法。

## 9. 连发、CAS及请求认领

玩家输入独立正式保存，有ID、conversation_seq及本轮OOC；请求认领输入ID集合，不合成一条假消息。每会话最多一个生成或待送达组。批完成后在同一锁下认领当时全部未回应输入，一次正常调用；之后新输入留给下一批，不每条付费、不取消当前批。

建议首版待回应集合最多8条且总正式文字≤现有4000字符单请求预算；超过则明确拒绝新的发送、保留客户端草稿，不截断/丢消息。各OOC保持所属输入身份并计总预算，具体总长度沿C3现有上限而非8倍扩张。UI可显示“待回复N条”，不要求玩家管理队列。

保留session revision用于外部CAS，新attempt另保存context_epoch及claimed_input_ids/history_cutoff_seq。普通追加输入、已读、标题修改不改变epoch；撤回/重生成或影响上下文的变更改变epoch。生成提交检查attempt仍pending、epoch一致、认领输入未改、组身份及账本预留有效，而非简单删掉当前base_revision检查。每类操作列冲突测试。

并发两窗口输入可CAS冲突后取权威状态，用同client_action_id幂等重投，不自动创建第二动作。失败保存不宣布已发送。先后由服务端事务决定，不以浏览器显示顺序判断。预览不计正式seq。

旧批不能实时理解未来边界：A后收到更正，B/C仍按已确认连续批送完，下次回复必须理解更正；不以旧B/C证明玩家接受，不宣称即时边界处理已实现。不重问是否取消余量。

## 10. 批操作、已有停止及未读

整批撤回/重生成只作用最新已结算且未被后续正式输入依赖的组；送达中不开放批操作，不建部分截断入口。原始认领输入集合保持关联；不能误删送达期间追加的输入。重生成成功才原子替换旧组并逆转旧inverse，失败保留原正式组；旧替代分支不召回。

角色已有停止生成保持“取消尚未完成的生成请求”语义，不扩为停止气泡余量。候选进入送达后请求已生成完，不再显示生成取消；不新增按钮、不删旧能力。取消后认领输入及待回应集合保留，禁止自动重启付费，需显式重试/新发送。测试取消与最终提交竞争，先提交者决定结果。

每会话保存最新正式AI序号和单调已读游标；前台正式气泡确实显示后ack，预览不ack、不计未读，后台不自动读。stream成功原位确认后才ack已可见部分；旧ack不覆盖后到消息。列表头像未读/预览只取正式数据。

## 11. 迁移与真实会话写入门

新持久schema需容纳独立输入、组和attempt，不给旧turn偷偷塞数组。旧v1/v2以单气泡组适配读取，保持原消息/turn/action/request ID、inverse、来源、归档、OOC；不猜分句、不改旧attempt协议。先实现只读投影与合成迁移，未知更高版本只读拒写。

迁移保留原文件备份，全部验证后原子替换；失败留旧文件，不跨多个文件假称原子。旧pending按原协议恢复interrupted/retry，不用v3解析旧请求；新会话/已迁移会话的新请求才用v3。既有上限按逻辑组/输入/attempt计数明确保守映射，不把气泡当扩容理由。

真实会话迁移在全部合成/备份/恢复与旧版本拒写测试通过后，再由主代理说明范围并取得确认；当前不执行。精确存储schema由B片实现前形成字段表与校验器，本文不拿候选设计冒充已验证迁移。

## 12. 分阶段可立即编码出口

1. **A：v3 parser+实时lexer，立即可做**。新协议、local引用映射、分气泡事件、任意chunk切割与失败测试；保留旧v1/v2。只接合成数据、不启用真实会话，不用单reply动画替代这一片。
2. **B：后端组事务与兼容适配**。先字段表/操作冲突矩阵，再候选保存、三模式提交、批末账本、输入认领、CAS、恢复、容量及旧数据合成迁移；不提前开放半成品UI。
3. **C：前端与完整闭环**。两个互斥开关、数组实时预览、原位确认/失败、gaps通知、连发、未读、批操作及既有停止兼容；读权威状态而非从预览造历史。
4. **V：验收与迁移门**。窄测→全量Python/Node/build/Edge，宽窄截图及进程重启；更新当前证据，真实会话迁移未确认前不做。无版本/打包/远程。

最低场景：第一和后续气泡流式实时出现；转义/代理对跨chunk；坏ledger在已预览后失败；预览原位确认不重播；A/B/C期间X/Y只一次后续调用；真等待零自动续发；三开关状态/旧设置；首条无额外等候；后台/重开/退出；timer重复；CAS/停止/保存失败；批撤回逆账；旧pending/归档来源/OOC；容量拒绝无丢草稿。

## 13. 人类选择与结束条件

本轮无新增必须产品问题：三态互斥、真实流式、连续批接话均已明确，按上述已确认方向和工程继承策略推进A片，不再次问是否需要独立逐字或是否截断旧批。若未来要求永久保留失败预览才讨论其数据身份；不把这种未提出的偏好当当前阻塞。

仍需后续明确确认的是实际迁移范围，不是再讨论显示方向。可直接向用户说明：“新协议测试通过后，需要把现有角色会话备份并转换为消息组格式；在你确认前只验证合成会话，不转换你的真实记录。”

完成意味着完整多气泡闭环及恢复证据，不是只有parser、只有动画或只有设计文件；技术通过也不证明真实模型活人感。
