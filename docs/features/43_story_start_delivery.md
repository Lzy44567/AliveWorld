# 43 从设定到可玩开局

2026-10-20，用户授权下一大阶段。依据29、32及统一新建浮窗决定；P1，当前实施A。

## 目标与分期

- A：统一使用“故事名称／故事与世界概述／开场”用户语言。概述、开场均可空；教程只在UI显示，不入故事历史。手写开场无需模型请求，作为已发生的第0回合保存。保留旧存档，不清洗历史。
- B：在同一新建浮窗选择已有资产或世界包。复用现有卡片选择与世界包创建服务；先核对局内副本、角色归属及失败清理再实施，不先创建空档再逐项加载形成半成品。
- C：端到端验收创建、首次行动、存取、重名、无开场、作者开场和资产隔离。随后才判断版本交付；不自动发布。

## A 工程与界面边界

一个新建按钮打开浮窗：名称必填，概述说明世界前提，开场说明当前地点/处境；两者默认空。提交期间禁止重复提交及关闭；失败留在窗口保留输入。系统建立成功只toast。

API添加可选opening（上限20000字符），旧客户端不传时为空；不改description兼容字段。GameSession在空开场时保存空chat_messages/context_history/story_turns，非空仍第0回合。自动世界书继续创建，首次行动沿原流程，不额外初始化模型。UI空态只说明可以输入第一步、选择资产或选填初始化状态，说明不参与请求。

模型不负责判断开场有无；Python负责存储及边界。概述请求标签改为普通“故事与世界概述”，不再声称最高法则。已有世界书优先关系不在本片另建规则引擎。旧存档加载不删除旧系统开场。

验收：空/空白开场无历史污染；手写开场持久化及重载；首次行动与撤回；旧调用和世界包开场保留；前端暗色输入、可展开、窄屏可滚动、不自动收费。

## 非目标

AI辅助开局建议、作者可编程角色创建器、全NPC头像、故事私聊、群聊、角色自然感42及全面UI重写不在此阶段。无需新增通用框架；复用既有存储、资产生命周期和可展开输入组件。
