## 已确认需求与优先级

1. P1/体验与恢复：请求发出后，原发送位置切换停止按钮。待机纸飞机、处理中方形停止图标，配悬停文字/无障碍名称，不在每个气泡重复放停止按钮。本条替代2026-10-06“不新增停止”决定。
2. P1/体验与恢复：停止后可以修改原请求再发送。推荐首版保留原气泡及已停止标识，悬停/键盘聚焦显示铅笔；点击将原文和场外提示带回输入区。若已有新草稿，不自动覆盖；编辑不直接篡改已结算故事历史。
3. P1/功能升级：自动重试次数由玩家设定，明确是“首次请求失败后的额外尝试次数”，推荐默认0；须说明额外费用。不得把此前的手动重试冒称自动重试已实现。
4. P2/下一体验板块：角色聊天参照微信/QQ的操作与信息层级：左侧紧凑会话列表（头像、名称、末条摘要、时间、未读），中央头像/气泡/输入工具栏，右侧会话资料按需展开；保留既有会话数据、生成机制和设置。不整套重做故事/工坊。

## 请求生命周期设计约束（待工程细化）

2026-10-18代码核对：故事/工坊共用api/v1/streaming.py只放弃预览订阅，明确不会取消已执行事务；workshop_chat_transaction是副本→保存→回填。因此39-A必须接后台取消信号并在提交前检查，不能仅在发送按钮上调用浏览器abort。当前并未实现，40修复收口后开始此主线。

- UI停止必须提交到后台任务，不等于AbortController断开浏览器订阅。只停止当前会话任务，其他并发故事/工坊继续。
- 已经完成并入档的结果不能通过停止按钮抹掉；取消与提交冲突以后台权威结果显示。尚未完成的预览不冒充正式正文、资产或记忆。
- 玩家点击停止立即停止后续重试调度；提供“正在停止”直到服务端确认。供应商是否已计费不可保证，需诚实提示。
- 首版优先编辑本次失败/停止的请求。编辑历史成功消息涉及撤回后续状态，属于既有分支/撤回边界，不隐式实现。
- 自动重试仅明确可重试的暂时网络/限流/服务错误；认证、参数、额度不足、模型内容拒绝不循环撞接口。未知是否已经成功时先核对原任务，不盲发新收费请求。
- 明确重试次数、当前进度、等待倒计时及取消；退避并尊重服务端等待指示。模型结构错误的纠正重试另行设计，不混作网络重试。
- 连续消息聊天保留现有追加/排队能力；停止入口不得因直接替换发送而让正在输入的新消息无法发送。该交互在39-A编码前单独定稿。
- 多气泡已生成内容的显示节奏不等于模型正在请求；此时不能用“停止请求”误导玩家，也不重新增加逐气泡停止按钮。

## 验收

39-B实施规则（2026-10-19）：次数放在每个文本接口的高级设置，0–3次额外尝试，默认0。按单次模型请求而非整回合重跑；SDK内置重试及旧空白JSON额外调用关闭。仅连接建立失败、429（排除额度/余额错误）、502/503/504允许重试；Retry-After超过60秒则交还人工，不提前重试。读写超时或流式已开始后的断线、格式错误、过滤、token上限均不自动重试。主动联系规划仍0次，避免暗中扩张其独立费用预算。当前已接设置/同步与异步调用，状态通知/倒计时与真实HTTP故障验收待完成，不能宣称39-B完整交付。

## 39-A工程拆分（2026-10-18）

1. 独立请求控制模块：每次生成有UUID，按故事/工坊及对象ID隔离；取消只针对指定请求。请求状态由后台持有，取消标记与开始提交共用短锁，先提交则取消返回已结束/正在提交，不声称已取消。取消不排队等待长模型锁。
2. 同步生成借当前请求上下文在调用前、分片间及最终提交前检查；关闭供应商流尽力止费，不保证已发生费用退还。没有分片/同步非流式时可能需等供应商读超时，但最终结果不能落盘。状态显示“正在停止”直到工作线程退出。浏览器断开不自动取消。
3. 故事复用checkpoint回滚，工坊复用候选副本；取消不能在提交后反向撤销已经成功的内容。退出任务清理注册表，不积累永久请求档案。新请求不能被旧停止信号误伤。
4. 三类模式分别接按钮/失败原文编辑，角色沿用既有取消服务，不迁移其会话格式。忙碌且输入新文本时保留角色追加发送入口，停止放相邻紧凑按钮；其余模式原发送位显示停止。恢复输入需保护新草稿。
