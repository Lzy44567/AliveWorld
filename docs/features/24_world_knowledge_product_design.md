# 世界知识与变化：产品设计讨论稿

更新：2026-10-12。状态：第二轮讨论；只记录产品设计，不授权功能编码。关联总索引 WORLD、STORY、ENTITY、CARD。工程现状见04/18；本文件不将新需求描述为已实现。

## 已确认的产品定位

- 故事世界的连续性是主要特色；角色模式保留独立入口，工坊服务于两者。角色模式机制较少，但其体验达标和完成工期不能仅按机制数量判断。
- 分模块充分讨论与记录，随后汇总为完整游戏详细设计案，再按设计案分阶段实施。已完成实现保留，新问题不自动打断设计主线。

## 已确认的世界观语义

1. 世界书定义世界自身的规则，玩家控制主角。玩家在角色台词或行动中提出事情，不因此获得任意改写世界的作者权限。
2. 设定补全：初始世界书不可能涵盖所有场景。游玩中首次出现的新技能、功法、地区等可复用设定，应能被整理保存。这不必代表世界规则在该回合发生改变，也可能是原来就存在、此刻才被发现的内容。
3. 世界内改变：角色按世界设定拥有改变认知、制度或世界规律的能力，实际成功生效后产生相应变化。可以作用于状态，也可能需要对局内世界书直接新增、修改或废止内容；不是作者场外编辑的同义词。
4. 用户举例：持续生效的认知改变可在状态栏体现；改变世界底层规则的能力可能需要修改世界书。题材是说明例子，不是自动识别所依赖的关键词。

## 当前文档需要补齐的概念

旧18文档主要按“捕获、作者创作、场景演化”划分输入路径，还需独立区分“发现已有设定”和“世界本身发生变化”。捕获不应只识别新法律或规则改变而遗漏首次出现的既有功法。

候选原则（待确认）：按知识的作用范围、持续条件和用途决定保存位置，而不按题材名称分配；状态栏显示当前效果，世界书记录可复用机制，两处可引用同一来源，避免分别维护相互矛盾的副本。角色只学会一门功法属于角色变化，功法的通用机制属于世界知识。

世界真实成立、人物是否知道、玩家是否可见应分别考虑，避免“写入设定”导致人物突然知道秘密。

## 第一轮问题（历史，以下第二轮答复优先）

1. 补全时机：在正文自然出现后整理；还是对重要新区域/功法先补设定再写正文？候选默认前者，后者作为后续可选能力。
2. 可信度：传闻、角色自述可否以未证实知识保留？候选允许保留说法及来源，但不当作客观规则。
3. 保存分工：技能机制进世界书，谁学会/掌握程度进角色记录；组织制度进世界书，组织当前计划进实体。是否采用这种按内容分工？
4. 生效与确认：世界内已经成功发生的变化是否自动成为当前有效状态，仅通知并允许纠正；还是必须确认才持久生效？旧设计对修改一律待确认，可能与正文已生效产生矛盾，需要重新决定。
5. 原规则与当前规则：玩家看到当前有效版本，后台保留原版与变化原因；临时效果结束恢复，永久变化持续，来源不明时不猜时效。是否作为默认？
6. 冲突与权限：公理中哪些不可被世界内能力推翻，哪些只是当前有效规律？自由文本如何表达可改变条件，需要可选创作约定，不要求所有作者重做卡。

下一轮再细化：多书写入目标、关键词与语义召回、通知/纠错入口、导出基线或当前版本、世界包作者指导及验收案例。

## 第二轮已确认要求（2026-10-12）

- 默认正文自然推进，并行调用工坊补全场景；设置允许调整补全程度、是否等待补全再继续正文，以适配不同存档。具体档位、默认强度及生效方式仍待讨论。
- 长期传闻更接近线索，可记录在世界书或实体相关资料；必须能在证伪时准确定位并修改，不能成为不可纠正的客观事实。
- 接受按内容分工：技能机制属世界知识，掌握情况属角色，组织制度属世界知识，当前计划属实体；还要纳入状态栏，通常展示角色当前状态。
- 沉默、禁火技能或阵法的当前效果不因持续生效就进入世界书；道统、地区或世界底层规律的实际改变才作为规则变更。通用技能/阵法机制仍可作为知识条目，不能混同当前效果实例。
- 规则的持续性可能依赖来源：例如大能死亡后，其维持的道统消失。不得仅以“长期/永久”推断完全独立于来源。
- 同意保留原规则与变化原因，平时展示当前有效版本；按已知期限/条件处理结束，不猜测未说明的期限。
- 公理既可约束创作方向，也可规定世界事实，同一条还可能兼具二者。原文继续保留，不强迫作者拆卡。
- 对上一轮“已成立变更是否一律自动保存”的问题，本轮主要澄清收录边界，尚不能视为已确认所有自动修改权限。

## 候选方案：来源关联与精确更新（待确认）

每条被维护的知识、线索和效果拥有稳定身份及来源。名字、标题、关键词仅用于展示/检索，不能作为删除或合并身份依据。记录源回合、相关人物/组织身份、当前真假或有效状态，必要时关联被修订的规则和持续条件。

- 传闻保留“说法”与证据状态；证伪时更新同一条记录，保留曾经传播的历史。客观上为假，不代表每个NPC已经知道它为假。证伪也不能自动证明相反命题。
- 已有明确来源ID时直接定位；没有ID时按主体、来源、内容寻找候选。无法唯一确定时保留待处理，不按模糊名称批量删改。ID解决定位稳定性，不能保证AI语义匹配必然正确。
- 人物/组织持有计划与动机，世界书持有知识规则；同一传闻若两处需要，使用关联或只读展示，不保存两个可独立修改的“真相”。首期只需要明确引用关系，无需通用图数据库。
- 规则可以关联“由某人维持”“依赖阵眼存在”“至某条件成立”等已确认条件。代码检查明确状态条件；自然语言条件由AI提出有来源判断。不因为来源死亡就自动取消其创造的所有结果。
- 若规则成立后、后台整理结束前又发生死亡/证伪，迟到结果不得重新启用旧状态；按提交时当前事实检查。这是并行补全必须保证的产品行为。
- 效果结束时重新计算剩余有效规则；不能直接覆盖回最早版本而抹去期间其他独立变化。具体冲突优先级后续设计。

## 候选方案：后台补全与状态展示（待确认）

- 工坊以当前正文已成立事实为约束补细节；尚未完成的草稿不作为正文已知事实。正文继续期间产生的新事实优先保留，冲突补全需修正或待处理。
- 设置分为补全程度与等待方式，按全局默认/本局覆盖。候选程度：关闭、必要补全、丰富补全；候选等待：后台进行、等待完成。程度描述补什么，不用模糊数量冒充质量。预算/频率作为高级项后续决定。
- 状态栏是展示入口，不是每条知识的独立副本。角色状态展示于人物状态栏，地区效果可显示在场景状态；结束隐藏当前效果但保留历史来源。

## 候选方案：公理具有两种职责（待确认）

创作约束用于限制AI怎样创作；世界规律描述世界内部怎样运转，是否可改变取决于世界已有机制。允许一条公理同时承担两种职责，用两个可并选的用途标记表达，保存作者原文。既有自由文本不自动重写或自动授予改变权限，工坊可建议用途供作者调整。

仍需决定：改变世界规律时怎样保护同条公理中的创作约束；冲突说明对玩家如何呈现；确认自动修改权限的默认方式。

## 完成本模块设计的标准

用新场景、首次发现功法、能力造成局部临时变化、世界规则永久改变、传闻被证伪、效果恢复六类例子，说明何时成立、记录在哪里、谁能知道、如何继续影响正文、如何纠正与导出。产品行为明确后再补最小工程方案，不以新增字段数量代表完成。
