# 世界知识与变化：产品设计讨论稿

更新：2026-10-11。状态：第一轮讨论；只记录产品设计，不授权功能编码。关联总索引 WORLD、STORY、ENTITY、CARD。工程现状见04/18；本文件不将新需求描述为已实现。

## 已确认的产品定位

- 故事世界的连续性是主要特色；角色模式保留独立入口，工坊服务于两者。角色模式机制较少，但其体验达标和完成工期不能仅按机制数量判断。
- 分模块充分讨论与记录，随后汇总为完整游戏详细设计案，再按设计案分阶段实施。已完成实现保留，新问题不自动打断设计主线。

## 已确认的世界观语义

1. 世界书定义世界自身的规则，玩家控制主角。玩家在角色台词或行动中提出事情，不因此获得任意改写世界的作者权限。
2. 设定补全：初始世界书不可能涵盖所有场景。游玩中首次出现的新技能、功法、地区等可复用设定，应能被整理保存。这不必代表世界规则在该回合发生改变，也可能是原来就存在、此刻才被发现的内容。
3. 世界内改变：角色按世界设定拥有改变认知、制度或世界规律的能力，实际成功生效后产生相应变化。可以作用于状态，也可能需要对局内世界书直接新增、修改或废止内容；不是作者场外编辑的同义词。
4. 用户举例：持续生效的认知改变可在状态栏体现；改变世界底层规则的能力可能需要修改世界书。题材是说明例子，不是自动识别所依赖的关键词。

## 当前文档需要补齐的概念

旧18文档主要按“捕获、作者创作、场景演化”划分输入路径，还需独立区分“发现已有设定”和“世界本身发生变化”。捕获不应只识别新法律或规则改变而遗漏首次出现的既有功法。

候选原则（待确认）：按知识的作用范围、持续条件和用途决定保存位置，而不按题材名称分配；状态栏显示当前效果，世界书记录可复用机制，两处可引用同一来源，避免分别维护相互矛盾的副本。角色只学会一门功法属于角色变化，功法的通用机制属于世界知识。

世界真实成立、人物是否知道、玩家是否可见应分别考虑，避免“写入设定”导致人物突然知道秘密。

## 第一轮待确认问题

1. 补全时机：在正文自然出现后整理；还是对重要新区域/功法先补设定再写正文？候选默认前者，后者作为后续可选能力。
2. 可信度：传闻、角色自述可否以未证实知识保留？候选允许保留说法及来源，但不当作客观规则。
3. 保存分工：技能机制进世界书，谁学会/掌握程度进角色记录；组织制度进世界书，组织当前计划进实体。是否采用这种按内容分工？
4. 生效与确认：世界内已经成功发生的变化是否自动成为当前有效状态，仅通知并允许纠正；还是必须确认才持久生效？旧设计对修改一律待确认，可能与正文已生效产生矛盾，需要重新决定。
5. 原规则与当前规则：玩家看到当前有效版本，后台保留原版与变化原因；临时效果结束恢复，永久变化持续，来源不明时不猜时效。是否作为默认？
6. 冲突与权限：公理中哪些不可被世界内能力推翻，哪些只是当前有效规律？自由文本如何表达可改变条件，需要可选创作约定，不要求所有作者重做卡。

## 完成本模块设计的标准

用新场景、首次发现功法、能力造成局部临时变化、世界规则永久改变、传闻被证伪、效果恢复六类例子，说明何时成立、记录在哪里、谁能知道、如何继续影响正文、如何纠正与导出。产品行为明确后再补最小工程方案，不以新增字段数量代表完成。
