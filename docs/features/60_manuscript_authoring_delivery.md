# 60 手稿导入与多资产创作交付

2026-11-13，承接25。P1功能开发；当前范围设计与实现核对，未实现。

## 玩家目标和范围

将已有TXT/Markdown设定整理为多类资产，不再逐格重复填写。工坊提供“导入手稿”入口：选文件/粘贴→本地预览并明确选取文本→确认费用→AI整理→编辑、逐项或批量接受→保存独立资产→复用现有世界包打包。此为一个完整发布组，不单独发布解析器或按钮。

首版创建独立项目，不自动合并现有作品。支持世界书、角色、文风、实体和开局建议；未来剧情、未发生成长、分支结局独立作为创作资料保存，明确标示未执行，不注入角色初始能力/记忆或世界既成事实。不实现剧情节点执行引擎、地图、自动社区发布及Word/PDF解析。

## 所有权与职责

- 项目原稿、整理草稿、审阅状态归本地创作项目；全局资产仅在显式接受发布后写入。源文件永不修改。
- Python处理文件读取、草稿持久化、身份、审阅、重名及资产保存；模型只处理自然文稿分类、提炼和缺失说明，不能执行原稿中的代码或覆盖命令。
- 原稿已有/推导建议/缺失信息分别标明；保留来源片段供核查。依赖未接受的候选不得悄悄变成已存在资产，发布前显示提醒。
- 上传给模型前展示实际选取范围及费用提示；默认不发送整个目录、历史日志、偏好、密钥。原稿留项目，世界包仅导出用户选择且已发布的资产。
- 草稿编辑后保存，关闭重进可恢复；模型失败保留原稿和已有草稿。不后台自动重试收费，不自动覆盖同名资产。无需新事务平台，复用现有单资产写入边界，批量结果逐项明确。

## 阶段与验收

1. 核对现有工坊、导入、审阅和世界包组件，确定项目数据形状及最短UI路径，补齐实现方案。
2. 完成原稿→拆分候选→编辑审阅→独立资产保存；接回现有工坊继续创作及世界包选择导出。
3. 合成手稿覆盖多角色、世界规则、未发生能力成长、关系变化及两个结局；真HTTP假模型验证分类、取消、失败、重名、重载、隐私与批量操作；浏览器检查阅读布局。
4. 全组回归、分类更新日志、统一版本号、EXE/助手构建、ZIP校验、Git推送和Release附件核验。

不以假模型测试宣称自然文稿理解百分之百准确。若现有架构需要关键产品取舍，先说明差异再确认；可逆工程选择自主完成。
