## A 自然表达

目标是按人设和语境选择简短回应、自有行动、具体邀请、表态、拒绝或必要提问，而不是客服式征询，也不是强制每轮推进或永不提问。主动性不等于代写玩家反应、忽略拒绝或越过边界。

- 一条短回复是完整合法结果；不能最低三气泡，也不将长回复机械切成三份。
- 先核对会话快照、实际请求、模式及提示词覆盖，再改提示词；不靠追加越来越长的场景禁令。
- 不额外串行调用“人格审核AI”。采用少量中性对照场景：问候、事实短答、已有明确安排、角色主动提议、需澄清的信息、意见不同、用户明确拒绝。
- 假模型验证1条/多条均能呈现；真实模型质量评估分别看是否回应上下文、符合人设、擅自代写、重复征询与不必要扩写。不能以问号数量单独判定人格质量，也不能将随机输出当精确单测。

## B 消息状态与操作

- 正常聊天弱化工程词。等待显示“对方正在输入”；错误附着相关消息，红色感叹号可点击且有文字提示、键盘焦点，不只靠颜色传达。
- 区分“消息未提交”“消息已保存但回复失败”“保存结果待确认”。后两种不能伪装成消息未发送；待确认先查询状态，不直接再次扣费请求。
- 自动重试倒计时中不显示终局失败；最终失败才提供重试。重试沿用现有批次边界、场外提示及去重机制。
- 桌面右键、移动端长按提供操作菜单，另保留可发现的辅助入口。撤回/修改明确作用于整批及其关联回复，不静默改历史事实；新输入草稿不能被覆盖。
- 流式预览未提交的事实仍需可见，但使用小型状态，不把长篇“未保存/编辑并重试”说明堆在消息正文旁。
- 验收：真实HTTP失败、自动重试、停止、保存结果未知、重载恢复、已有新草稿、跨会话切换以及键盘/触屏操作。复用现有状态服务，不重建请求框架。

## C 会话资料

拟采用与故事模式一致的侧栏容器和分类导航，但保留聊天专属内容：人物、世界与偏好、记忆与关系、会话设置。容量/请求诊断放高级区；内部记录保留明确剧透入口，不能因换页自动暴露。

人物页用头像、简要资料、分区详情；设置按功能成组，长文本允许展开。窄屏采用可关闭抽屉，不压缩聊天到不可阅读。切换分类保留未保存编辑，源卡与会话快照的区别明确显示。正式开发前补一张布局草图和常见操作路径，不能只把原长列表换成多个折叠框。

## D 从聊天记录制作角色卡

玩家导入有权使用的记录→预览参与者→选定需要提炼的一方→选择范围并脱敏→确认发送模型→生成可逐项审阅的角色卡草稿。

- 首期候选TXT/结构化JSON，具体格式需样本后确定；不直接读取微信数据库，不自动采集联系人或其他聊天。
- 提炼措辞、句长、标点、幽默、回应习惯、少量行为示例；区分原文证据与模型推测，不由语言习惯诊断心理疾病或断言真实人格。
- 不自动把其他参与者的隐私、生平、关系写入卡片；不声称卡片等同真实本人。保留人工修改与删除入口。
- 调用前说明内容将发往所选API及可能费用；默认不上传原始文件、不保存长期原文，不自动发布或覆盖已有卡片。证据引用只在本地审阅，导出另行预览。
- 大文件分批提炼的上下文预算、临时文件生命周期、撤销与删除，在实施前冻结；本轮不创建导入接口。
