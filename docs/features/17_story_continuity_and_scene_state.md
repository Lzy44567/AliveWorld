# 剧情连续性、场景 NPC 与世界常识变更

## 真实游玩证据

2026-08-24 对游玩区“现实世界”“园区求生”及“园区”世界书、运行日志进行只读核验后，确认三个相互放大的问题：

1. 模型会为了维持戏剧冲突，忽略已建立的信息封锁，反复凭空加入路人、物业、警方、对讲机或临时设备故障；
2. 左侧 NPC 卡是当前场景状态，却只有模型显式返回 `status_deletions` 才会消失，离场人物会持续积累并污染后续上下文；
3. 世界书自动捕获已经能新增长期规则，但缺少“修改/废止既有世界常识”的安全提案协议，不能用一次模型判断直接覆盖玩家世界。
4. 世界书条目召回过去扫描整份工作上下文，早期出现过一次的关键词会在许多后续回合重复触发，稀释当前场景事实并增加请求长度。

## 已确认边界

- 正文历史、角色卡和暗流实体负责长期记录；左侧 NPC 卡只表示当前场景，不是人物档案。
- 后端按正文/玩家行动中的实际提及维护 NPC 在场性；显式“已离开、未出现、死亡”等立即退出，连续三回合未提及则从雷达隐藏。隐藏不删除人物资料或历史。
- 外部介入必须拥有已建立的信息通道。局部搜索失败不能升级为全局不存在；已确认的信号屏蔽不能被无依据的电话、对讲机、网络或临时过热绕过。违法性和道德评价不是信息通道，不能自动生成警方、保安或投降结局。
- 未来推演与行动裁定属于同一次模型返回，但后端不再盲信其内部一致性。每个候选必须逐字覆盖全部 `accepted_facts` 并给出 `fact_checks`；缺项或 `compatible=false` 的候选强制退出随机池，全体失效时使用“按当前事实继续”的保守候选。
- 世界书捕获支持 `add/update/retire` 三种提案。低风险、高置信的新增长期规则可按局内设置自动加入；修改和废止永远先进入“待确认”，原条目在玩家接受前继续有效。
- 世界书概述、公理和“常驻”条目不受压缩；普通触发条目只检索近期正文窗口与当前行动，不再扫描整段长篇历史。完整原文仍永久保存在存档中。
- “常识改变”是色情漫画等作品中的特定题材能力，不代表所有玩家天然拥有世界改写权。显式 `常识改变：……` 命令在正文确认生效后可新增或修改条目；`常识恢复……` 只能修改或废止对应改变。普通讨论、愿望、谎言或失败尝试不得触发。该题材用于同时压力测试新增、替换、恢复、精准定位和后续召回。
- 上述命令不是常驻 GM 提示词。Python 只识别明确的命令格式，命中时才为该回合动态附加短裁定协议；普通故事和普通回合的 token 成本为零。核心捕获提示词始终只描述可泛化的长期世界规则与 add/update/retire 契约。
- 新建故事若没有任何启用世界书，会在该存档中创建“本局自动设定”。它可见、可编辑、随存档迁移和删除，不进入全局资产；后来载入真实世界书后，真实世界书优先接收新捕获。

## 数据与恢复

NPC 在场计数保存为独立 `state_meta.npc_presence`，与可见 `state.npcs` 分离；快照、撤回、重掷和存档加载一起恢复。旧存档没有该字段时安全从空计数开始，不迁移或重写玩家原文件。

世界书修改提案保留 `pending_operation` 与 `replaces_entry_id`。接受修改时以原 ID 原位替换；接受废止时删除原条目和提案；拒绝只删除提案。模型不能直接执行既有规则删除。

## 世界包与个人资产

官方世界包模板仍保存在可提交的模板文件中并供打包器解析，但普通全局资产接口默认只列个人资产。玩家通过“资源库 → 世界包”管理世界；开始世界后只获得局内独立副本和不可编辑来源元数据，不把包模板伪装成个人全局卡片。

## 后置

- 不实现全量 NPC 社会模拟、自动角色卡提取或长期人物关系图。
- 不用固定回合删除角色卡/实体卡/历史正文。
- 世界公理级改写、批量冲突合并和可视化版本差异留给世界书工坊后续迭代。
