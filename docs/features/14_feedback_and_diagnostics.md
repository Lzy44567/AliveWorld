# 游戏内反馈与诊断

## 目标

在公开测试前，让非技术玩家无需理解日志目录，也能把“发生了什么、如何复现、对应哪个版本”整理成可发送的反馈；同时避免把 API Key、私人故事和个人资产默认上传到任何服务器。

该功能不是社区中心，也不是远程遥测。首版只在本机生成玩家可预览的反馈摘要和诊断包，由玩家自行选择复制到 QQ/Discord、保存文件，或打开预填的 GitHub Issue。

## 玩家流程

1. 从顶部帮助入口或“设置 → 关于与反馈”打开反馈面板。
2. 选择分类：功能错误、界面与交互、模型/网络、生图、内容建议或其他。
3. 填写标题、实际表现、期望表现和可选复现步骤。
4. 面板自动附带版本、操作系统、运行模式、最近一次相关 trace ID 和安全的错误摘要。
5. 玩家按需勾选截图、选定日志详情、当前故事名称或正文片段；默认全部不勾选。
6. 提交前显示完整预览和隐私提醒。
7. 玩家选择“复制反馈摘要”“导出诊断包”或“打开 GitHub Issue”。网络不可用时，前两种方式仍可正常工作。

## 数据边界

### 默认包含

- AliveWorld 版本、发行渠道和便携/源码运行模式。
- Windows 版本、Python 打包运行标记、前后端健康状态。
- 反馈分类、玩家填写文本、发生时间。
- 最近错误的分类、阶段、状态、trace ID 和已脱敏摘要。

### 必须主动授权才包含

- 截图。
- 完整结构化日志详情。
- 故事名称、正文、世界书、角色卡、文风、实体或偏好内容。
- 本地文件路径；即使授权，也应把用户目录替换为占位符。

### 永不包含

- API Key、Authorization、自定义密钥请求头和连接配置中的秘密值。
- 浏览器凭据、GitHub Token、系统环境变量全集。
- 未被玩家选中的其他故事、资产、存档或图片。

导出前后均运行脱敏器。若内容仍疑似包含密钥格式，阻止直接打开 GitHub Issue并要求玩家检查，而不是静默上传。

## 输出方式

### 复制反馈摘要

生成适合 QQ、Discord 或 Issue 的 Markdown 文本，包含版本、分类、复现、预期/实际和 trace ID。它是国内网络不稳定时的默认可靠路径。

### 诊断包

输出 `.zip`，包含 `feedback.md`、`environment.json`、玩家明确选择的 `logs.jsonl` 和可选截图。清单记录每个文件及其是否含故事内容；不写入游戏安装目录之外的随机位置，由玩家选择保存位置。

### GitHub Issue

首版只打开带标题和正文参数的官方 Issue 页面，不在客户端嵌入仓库 Token，也不承诺匿名代发。附件仍由玩家在 GitHub 页面手工确认上传。未来如建设官方服务，再单独设计认证、限流、删除和隐私协议。

## 架构边界

- `core/feedback/`：反馈模型、脱敏、摘要和诊断包构建；不依赖 Vue。
- `api/v1/feedback_routes.py`：只暴露预览和本地导出所需的窄接口；不能接受任意文件路径或读取任意日志。
- 前端反馈面板：表单、数据授权、预览和输出动作；不自行拼接秘密配置。
- 复用结构化日志查询与 trace 分类，不复制日志存储。
- 生产包不提供“上传所有数据”或万能测试接口。

## dev.20 范围与验收

P0：

1. 反馈摘要预览、复制与脱敏单测。
2. 诊断包只收集白名单字段和玩家选中的日志事件。
3. API Key、自定义请求头、用户目录和未授权正文的泄漏回归测试。
4. 从错误提示/日志条目一键带入 trace ID。
5. GitHub 不可达时仍能复制摘要和导出本地包。

P1（可延后）：

- 自动截图；首版允许玩家手工附图也可成立。
- 直接创建 GitHub Issue；首版打开预填页面即可。
- 反馈状态跟踪、评论同步、远程上传和社区账号。

dev.20 同时补三条高价值自动回归：暗流账本触发后撤回恢复、记忆压缩失败回退、非世界书工坊的正式资产并发冲突。真实 DeepSeek/ComfyUI 的文学和画面质量仍需人工抽查，不能用固定假响应证明。
