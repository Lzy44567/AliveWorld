## 3. 核心决策

### D1：分开三个维度，不把层级当作拼接顺序

- **权限/职责**：引擎、玩法、体验、资料。
- **变化频率**：版本、配置、资产修订、记忆段、回合。
- **发送位置**：system静态区、system配置区、user资料区、user回合区。

例如世界书条目是资料，有的常驻、有的每回合检索；不能全部标成“稳定资产”。状态输出schema是引擎，启用的可选字段组合则随配置变化。模型适配属于运输与能力边界，不额外建立一份庞大“所有供应商规则”提示词。

### D2：两条消息作为首个兼容目标

保留现有 `system + user` 的可执行格式。内部新增请求计划，返回 system/user、contract_id、参数、完整manifest。将来供应商支持独立schema/多消息时，由适配器降级或映射；本轮不引入任意消息数组编辑、assistant prefill或新供应商。

```text
领域模块提供只读输入 → 任务构建器选择贡献与输出字段
→ 装配器验证/预算/确定性渲染 → 模型适配器发送
→ 领域结果校验器 → 原有游戏编排与持久化
```

装配器不读资产文件、不检索世界书、不决定暗流触发、不修改状态。先在已有文件边界演进；仅当职责实际独立时抽取 `prompt_composer`、`story_prompt_builder`，不创建空壳包装层。

### D3：规则权力与故事事实分别裁定

- 输出结构、数据可见范围、模块写权限由代码保护，内容预设无权改写。
- 玩家控制自身选择；是否允许创作世界事实，沿用行动裁定与世界规则契约。自由创作权限不等于任意角色对白都成为新公理。
- 场景事实、已批准世界规则、玩家主张、NPC认知、记忆摘要分别标明来源；NPC怀疑不升级为客观事实，搜索未发现不等于不存在。
- 事实发生冲突时引用已有裁定/修订，不能简单采用“文本最后出现者胜出”。引擎优先级也不能被误用成具体世界观价值判断。
- “不得替玩家选择重大行动”属于稳定权限；“外部角色必须有合理知情途径”属于通用因果规则；警方/保安专项案例留作评测，体验默认只写通用反复/强制剧情约束。
- 内容预设能修改表达和节奏，不能覆盖JSON协议。提示词优先级只能降低冲突概率；Python无法证明任意自然语言正文从未替玩家决定，仍需语义评测。

## 4. 注册表与请求快照

扩展现有 PromptSlice，而不平行创建第二份注册源。首期字段：

```text
id, task, owner, layer, slot, priority, source_version
variables, enabled_by, required_when, output_fragment
editable, override_policy, cache_class
budget_group, overflow_policy
```

启用规则来自受控设置/任务布尔值，不执行用户表达式。首期依赖是有限任务模板内的显式依赖，不建设通用依赖图执行器。
排序固定 `(slot_order, priority, id)`；同一id重复贡献报错。必需切片为空、未知/越权变量、重复输出字段或相互矛盾的结构参数必须在发请求前报错，指出切片来源。
可选模块关闭：规则、数据、输出字段、额外调用全部按执行开关移除。显示开关只影响UI，不能顺手关闭未来推演。当前暂不存在的玩法执行开关不在本轮扩张设置UI。

每次请求固定一份 `RequestContextSnapshot`：故事ID、源回合/修订、设置、资产修订、提示词覆盖修订、契约版本。来源元数据尽量留在本地manifest，只有模型需要引用的ID才进入请求。中途切换故事或编辑提示词不改变在途请求。后续回合使用新修订。

变量沿用现有ID，避免改名迁移。逐步新增：

| 变量组（目标） | 来源/允许任务 | 空值处理 |
| --- | --- | --- |
| `context.world.base` / `context.world.retrieved` | 世界书只读投影；未来/GM | 无资产为空，不自动造设定 |
| `context.history` / `context.memory` | 原文热窗口/现有记忆索引；故事任务 | 无历史合法 |
| `runtime.state` / `story.player_action` | 本局状态快照/行动；未来/GM | 状态结构无效或空行动拒绝 |
| `runtime.causal_candidates` | 账本活跃影响及条件；仅未来 | 空集合合法 |
| `runtime.triggered_influences` | 已验证ID与效应；仅GM | 空集合合法 |
| `runtime.adjudication` / `runtime.selected_future` | 本次未来结果与Python选择；GM | 该模式必需 |
| `player.preferences.confirmed` | 已允许类别的确认偏好；GM | 关闭即不注入 |

`context.world` 保持旧模板兼容，标明“旧版聚合变量”；现代任务使用具体投影。中文短名、悬停/点击说明和插入沿用当前UI。资料只渲染一次，资料内部类似 `{{...}}` 的文字不递归执行为变量。

## 5. 装配表、缓存与注意力

### 默认布局（目标）

| 顺序 | 内容 | 稳定范围 |
| --- | --- | --- |
| S1 | 本任务职责、权限与通用因果规则 | 程序/提示词修订 |
| S2 | 本任务输出契约、状态字段语义 | 契约与功能配置 |
| S3 | 启用的玩法说明、篇幅、体验预设、必要模型兼容说明 | 配置修订 |
| U1 | 常驻世界规则、玩家角色、文风等本任务需要的固定资料 | 资产修订 |
| U2 | 当前记忆摘要 + 按时间追加的近期完整回合 | 记忆段/历史前缀 |
| U3 | 本回合检索条目、相关NPC/实体、当前状态、任务数据 | 回合 |
| U4 | 当前行动；GM另含既定裁定、选中未来、已触发影响 | 回合 |

任务规则不能为了共享缓存而携带其他任务的全部规则。固定文风资料可留有清楚的“按此风格渲染”引用；资料进入user区不等于撤掉功能，system负责说明其作用和边界。迁移这一位置属于语义变化，必须单独评测。

前缀缓存优化关注**实际发送消息和序列化结果**。现有system切片prefixHash不足以解释user资料或适配器变更；扩展为每消息/每段的哈希与整个有序消息前缀哈希。应用哈希用于变化定位，不等于供应商token缓存键。

稳定区禁止动态时间、日志ID、随机排序；字典序列化规则固定，语义有序数组保留原序，检索候选先选定再稳定排序。不能为了缓存保留已失效世界规则，也不能把所有世界书塞进前缀。旧历史追加时能复用的部分尽量保持；摘要更新/世界修订改变前缀是合理失效。

DeepSeek官方资料说明相同前缀可以复用上下文缓存，并提供 `prompt_cache_hit_tokens` 等统计。本设计仅据此采用稳定前缀，不写死最小块长、TTL或命中率。2026-09-15官方页面直连超时，核对范围为官方搜索索引摘要：[上下文缓存](https://api-docs.deepseek.com/guides/kv_cache/)、[接口字段](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)。供应商细则在适配实施时再次核实。

| 连接类型 | 首期行为 |
| --- | --- |
| DeepSeek官方兼容接口 | 稳定两消息；从usage读取实际缓存统计，保留原始字段 |
| 其他OpenAI兼容/本地接口 | 相同语义请求；缓存能力unknown，未报告统计显示“不可得” |
| 需要显式缓存、其他消息角色或schema的原生协议 | 后续适配；未验证前不发送专用缓存参数 |

缓存命中仍占模型上下文并参与注意力，不能解决长提示词的全部问题。主要观测：输入/输出/缓存token、请求总耗时、模型调用数。当前非流式链路不能把总耗时标成首token延迟。没有为了保温而自动付费发请求。

注意力策略：关键规则一处定义，裁定与本轮状态靠近行动；只交付已选择未来，不再把候选全集给GM。默认不新增尾部重复检查表。仅在实测改善遵循度时启用短摘要变体，记录额外token和重复规则来源。提示词更短不保证模型回答更快，要同时测输出长度和端到端耗时。

## 6. 上下文预算

不采用跨模型统一的5000/10000阈值。每条路由配置有效上下文窗口C、输出预留O与token估算误差余量M：`输入上限 B = C - O - M`。O包含正文及全部结构字段，必要时也遵循供应商的推理预算规则；不能只按中文字数乘3推断所有任务。

窗口已知时采用已验证能力配置；未知兼容端采用明确标注的保守配置并允许高级用户修正，不宣称自动知道真实窗口。token优先用供应商匹配的计数方法；否则显示估算，M取可配置的窗口比例（初始10%，需测量），不把估算当作精确计费。

预算优先顺序：
1. 必需：引擎、所需输出契约、行动、既定裁定/未来、已触发影响、相关当前状态和强制世界约束。
2. 保留最近完整回合；其余历史交现有记忆模块处理，不在装配器新增一次总结调用。
3. 相关检索条目按已有召回规则选取，固定/常驻项不静默压缩；超限首先省略可选低相关项并记录ID。
4. 可选说明、非必要例子、低相关旧资料按显式策略省略。切片与JSON字段不从字符串中间截断。

预算器不改写世界书、角色、账本原文；也不静默删除已确认规则。必需集合仍超限时，返回可理解的超限原因及各组占用，提供增大上下文/调整载入资产的路径，禁止发送缺失契约的请求。普通模式不增加一排预算滑块；开发者预览中显示占用与省略原因。

## 7. 状态结果契约：沿用字段，补足语义

首期沿用 `story_text/new_buffs/remove_buffs/dynamic_bars/status_updates/npc_states/status_deletions/resolved_influences`。不立即替换为Sol举例的通用路径StatePatch，不强制NPC/条目一次性改用新ID。既有字段与存档兼容风险更小。

在请求外部携带契约版本；schema由领域定义生成给校验器和提示词的简短字段说明，避免两个手抄schema漂移。新版只对启用模块增加可选字段；省略可选字段意味着无操作，必需字段缺失不得默认为成功。

明确状态语义：
- 空对象=不变；删除必须显式。验证对象/列表类型、长度上限、数值有限性、颜色值和NPC结构。
- 已有条只提交 `current`（结算后绝对值）或 `change`（直接变化量）之一；两者同时出现返回契约错误。新条用current/max，change必须缺省。
- 延续现有Buff阶段顺序并写入示例：新增/删除Buff→本轮持续效果→AI直接变化→定界。AI用change时不重复计算代码持续效果；用current则代表全部效果后的最终值。新增Buff是否当轮生效先保持旧行为。
- 新版status_deletions名称若同时命中多个组，拒绝歧义删除；明确作用域的删除协议留作以后版本，不默默改变旧存档结构。
- JSON object模式仅保证输出形式的意图。可解析JSON、schema合法、状态数值合理、与正文语义一致，是四种不同验收。

实施目标：在副本校验并计算状态、NPC元数据、账本变更，再由游戏会话提交；失败不留下半更新。两条结算路径复用校验器。原有快照保留；磁盘失败也应恢复内存或标记未提交，不能展示已保存。

初版不自动增加“状态修复AI”请求：错误保留为未提交诊断，玩家可重试；如后续引入一次定向修复，必须单独设计费用、原正文保留和防重复提交。自然语言中替玩家决定或事实矛盾不能仅靠字段校验判定，另列模型质量用例。

| workshop.* | 对应资产草稿、会话、允许操作、编辑模式 | 草稿操作/讨论；对应工坊领域 | 独立会话 |
| image.prompt | 选定角色/场景的视觉投影 | 图片提示词；生图领域 | 手动/现有任务调度 |

后四类不是本轮深度代码审计结论；具体字段和预算须在迁移该任务时核对，不先为它们发明统一输出格式。实体当前由一个Overseer统筹，不新增每个实体一个AI线程。

交接原则：保留正式正文这一必要叙事来源，同时传结构化裁定/ID；不要求AI只读字段而丢失剧情，也不传推理链和完整内部日志。未来负责评估条件，代码负责ID/状态/消费政策，GM只报告实际兑现；代码补出的“已兑现”不能替代模型报告。

缺失必需的兑现报告时拒绝本次提交，保留账本；重复/未知ID过滤并记录。合法报告也不能保证正文确已呈现，需语义用例验证；后续可加简短正文证据引用以便核查，但不新增每回合独立审核AI。

并发沿用同故事串行、不同故事/工坊独立。请求结果归属于源故事和源回合。异步世界捕获/偏好提交需要校验源回合仍有效、目标修订未变化；旧回合被撤回则弃用或进入待确认，不能污染新状态。这是后续跨领域生命周期补强，不在纯布局迁移中同时实施。

调度改造顺序单独验证：目标先准备有效状态/账本副本，再供Overseer读取一致投影，最后统一提交必要结果与调度后置任务；Overseer失败沿用现有“正文可成功、暗流有诊断”的策略，不能因重试重复执行玩家状态。何时提前展示正文涉及UI持久化，不在此轮扩张。

## 9. 预设与编辑最短路径

- 普通玩家沿用默认体验。高级设置选择任务体验预设；开发者模式沿用密码保护的提示词工作台。
- 工作台按任务→职责展示切片；展开编辑、变量说明、覆盖/恢复沿用已有UI；增加最终请求预览、来源与预算即可。
- 同一体验槽位：官方默认 < 已确认的世界包建议 < 全局用户选择 < 本局覆盖。用户行动是回合数据，不直接成为可覆盖引擎的“最高优先级预设”。同层互斥配置在保存时解决。
- 原文预设存在自然语言冲突时只能提示和评测，不能宣称解析器能自动理解全部矛盾。
- 内建只读；覆盖按切片ID、基线哈希、修订保存于现有UserData开发者目录；体验预设独立于密钥与连接，引用用ID而非名称。卸载预设不改既有历史或状态。
- 用户覆盖含旧聚合变量/无法可靠拆分时维持 legacy 布局，显示迁移待处理；自动迁移只接受确定性的转换并保留原始副本。不用模型自动重写玩家覆盖。
- 世界包只能携带声明式体验建议，经过既有导入确认，不能携带密码/密钥或静默启用引擎覆盖。默认日志manifest不复制私人正文；完整预览仍在现有开发者访问边界内。

### 首个可执行切片 M1

1. 先捕获双路径现有请求，包含无资产、有资料、偏好/建议开关、有/无暗流、旧覆盖和重掷。
2. 新builder接收只读快照与mode，不在内部读取当前活动会话或执行模型请求。
3. 输出system/user、manifest、generation参数；mode保留旧路径差异并明确记录，不能借抽取顺手改字序/3000上限。
4. 两条调用路径接入；请求体逐字等价、调用次数不变、覆写不串故事后提交。

### 验收层次

- 确定性测试：变量任务边界、启停、顺序、数据投影、schema、状态变化、事务失败、回合归属。假模型必须检查真正收到的请求与返回后的磁盘/UI状态。
- 浏览器：切片编辑/恢复、展开、预算来源、任务切换不串结果；只有涉及UI的阶段运行相应浏览器回归。
- 小型真实模型语料：封闭场景信息隔绝、NPC怀疑与客观事实、玩家重大决定、日常无事件、多轮规则修订、Buff叠加、NPC退场、暗流触发/未触发。只使用合成非敏感场景，不读取玩家私人存档。
- 真实模型对照计划：先8个场景，每场景3次，旧/新共48次单任务请求；只运行本阶段受影响任务。固定模型、参数、资料与未来输入，人工/模型辅助阅读判定，保留失败样本。需在实施阶段告知调用费用范围；本轮不调用付费游戏API。
- 质量门槛：确定性测试全过；真实模型结构/玩家权限等硬性用例出现失败则先定位，不能以平均文学评分抵消。48次只是初步筛查，不证明所有模型/长故事都可靠。
- 缓存对照另测：重复前缀请求，记录usage/耗时，报告样本和不可得字段。不能用字符串哈希或假API证明供应商命中。
