## 已确认需求

1. 暂不做故事内私聊；未来该功能依赖独立角色对话能力，不能另建一套角色引擎。
2. 顶部改为「故事—角色—工坊」：故事为RPG，角色为独立一对一聊天式扮演，工坊用于制卡。未来群聊需要单独讨论，不改变当前三入口定位。
3. 全局角色卡是可复用资产；会话内角色副本可变化，默认不反写全局。角色账本记录知识、经历等局内信息。
4. 重设计 NPC/玩家角色的控制身份分配，不能未经迁移直接删除旧开关。
5. 角色卡结构预留演进空间，保留自由文本能力，不强迫玩家填写复杂心理表格。
6. 提示词管理页顶部按模式切换对应列表，不把所有提示词纵向混排。
7. 反馈入口/标题标记“已实装”，同时明确“需手动发送，不会自动提交”，避免填写但未送达。
8. 兼容酒馆及用户称为“类脑”的来源中的角色卡、世界书；格式和运行行为分别验收，不承诺所有社区扩展天然兼容。
9. 2026-10-01 用户澄清“链式输出”是流式输出：单次请求逐步显示可见正文，不是无限续写、多次调用链或内部思维链。
10. 2026-10-03 用户确认即时聊天与情景扮演两种都提供，由会话设置选择；共用身份、历史与账本，切换不重置人格/关系。首版详情以22b为准。

## 建议：身份归会话，资料归卡片

本节保留设计方向，首版具体冻结见22b；仍不是当前存储格式。

- 拆分角色资产（是谁）、会话实例（本次经历/状态）、控制分配（谁扮演）。界面使用“我扮演的角色”“AI 扮演的角色”，NPC不是卡片永久属性。
- 首版一个AI+一个user，可不选玩家卡直接以“我”说话；身份在创建时确定，开聊后不原地换人，换卡新建会话。
- 相同资产可进入多个独立会话，名称不是唯一标识；实例、消息、账本使用稳定 ID 关联。
- 旧 `is_player` 映射为原故事的控制分配，不改变旧正文/主角或其他故事。多张旧玩家卡不能静默任选一张；保留备份并明确兼容规则。
- 局内变化经显式提取/另存才进入全局资产，默认排除私聊记录、隐藏知识与私人关系历史。

## 角色账本与本回合行为

- 区分稳定描述、当前目标、个人边界、具体对象关系、已知信息、猜测、实际经历、未落实意图。
- 关键变化带来源消息/回合和证据；未知不补成事实，模型推断不等同作者声明，避免一次错误反应被固化成人格。
- 逻辑顺序：读取状态→形成意图→生成回应→提交实际变化。不要求重写整张卡、不要求输出内部思维链、不规定每步独立模型调用。
- 原文保留，工作上下文使用有界相关投影；不每回合完整注入所有角色账本。
- 失败/取消不提交虚构经历；重试、撤回、分支同时处理消息和状态。快照/补丁格式及事务边界需先冻结。
- 无卡片 NPC 可使用轻量实例，不必升级为暗流实体，不默认持续模拟全部路人。

## 模式与提示词界面

- 模式切换只换视图，不清空会话；沿用按会话隔离的并发原则，迟到结果不能写入错误会话。
- 独立角色会话拥有消息、参与者和世界书绑定，不自动读写游戏存档历史；首版不设计跨模式时间同步。
- 群聊需明确发言顺序、最大回应数量、停止/取消与可见消息范围，不默认人人每轮回复；调用策略通过成本/质量对照确定。
- 提示词列表建议「游戏｜角色｜工坊｜通用」分类。分类只改变导航，不复制切片、不改权限和运行组装顺序。
- 跨模式切片保持单一注册定义，显示适用模式；未接入的角色提示词显示空态/待接入，不提供“可编辑但不生效”的假入口。
- 保留搜索、变量说明、扩大编辑、恢复默认和未保存保护；通用后台切片不因分类失去入口。

## 可演进结构与职责

- 候选模块：资产模型/迁移、局内状态仓储、上下文投影、对话调度、外部适配、API与UI。复用稳定的连接/日志/事务能力，不复制整套故事 GM。
- 少量稳定核心字段 + schema_version + 稳定 ID + 命名空间扩展；缺失可选字段可读，未知字段保留但不自动执行。
- 外部原始载荷与内部归一化表示分开，不把所有外部字段压进 description 冒充兼容。
- 迁移前备份、失败不覆盖、迁移幂等；较新未知结构不能静默降级重写。编辑与模型返回竞争需要修订校验。
- 删除会话清除其内容，不连带删除全局卡；22b规定原卡删除不影响既有快照，仅保留无内容删除ID墓碑防旧创建请求复活。撤回/重生成归档由生成原回合的action持有，不覆盖旧尝试。

## 流式输出：需求已确认，首版执行契约见22b

- P1角色私聊基础交互，非F1/U1工作。输出分临时预览与正式结果：增量仅显示白名单正文文本，不展示JSON、账本补丁、诊断或内部思维链；未完成/非法JSON不进入历史或局内知识。
- 首版建议单次模型调用返回最终JSON（reply与受限state_changes）；适配层增量解析reply字符串，正确处理UTF-8、转义、跨chunk边界。不用正则截取JSON。最终必须重新完整解析、领域校验、来源校验和expected_revision检查，持久化成功后才发送committed。
- 预览状态 proposed → streaming → validating → committed；取消/断流/超时/格式错误/冲突到 aborted/failed，不能悄悄转正式消息。重试生成新request_id、引用原操作，但不能重复提交同一client_action_id。取消与提交竞争以同一会话锁内的最终状态为准：已提交则返回已完成，未提交则置取消且禁止迟到写入。
- 会话/请求身份必须贯穿每个事件；切视图不能改结果归属。同会话只允许一个未完成写操作，其他会话可独立运行；模型网络等待不持有全局锁。编辑/删除与回复的revision冲突拒绝迟到结果，不猜测合并。
- 断线默认取消未完成请求；若最终提交已完成但终态丢失，重连先查询request/client_action状态及会话revision，不自动重新调用模型。需要服务端幂等记录随正式回合原子持久化，进程重启后的in-flight任务标记中断，不自动付费续跑。
- 22b已明确现有OpenAI兼容调用边界、支持/降级矩阵、事件schema与限额、增量状态机/最终解析测试、取消传播、幂等查询和原子存盘故障矩阵。R2包含流式与双模式UI，是首个可玩发行闭环必要项；R1B非流式后端仅为工程切片。非流式供应商允许完整校验后一次显示，不伪造逐字流。

## 角色底座：已确定边界与待冻结协议

首版仅独立一对一私聊；顶层游戏—角色—工坊的实际导航改动与R2一并交付，不在U1提前放空壳角色引擎。默认一个AI角色，可不选玩家卡（普通“我”参与者）；选择玩家卡只复制资料，不将is_player写回全局。身份切换限定空会话/新会话，已有回合的会话不原地换人，避免历史归属变化。多AI群聊后置。

数据方向确定为 `global asset → session-local snapshot → local ledger`，无反向自动写入。会话拥有session_id、revision、参与者instance_id、controller=user/ai、原资产引用与来源修订；实例保存完整创建快照，原卡后续修改/删除均不改变已有会话。删除会话只删自身消息/账本/请求记录，不能删全局卡。卡片自由文本继续可用，少量稳定字段加schema_version与命名空间extensions；未知更高版本只读/拒写，不能降级覆盖。

局内账本条目至少表达稳定entry_id、主体instance_id、kind（knowledge/belief/experience/intent）、内容、来源类型（作者/玩家陈述/模型提案/实际对话事件）、source_message_ids、证据与可见性。玩家声称不自动成为客观事实；belief更正与knowledge获取需要保留来源而非覆盖成无来源结论。模型负责提出reply和允许的变化，确定性代码负责字段/身份/来源/可见性与事务；不持久化内部推理。首版只投影当前AI有权看到的有界条目，原文保留；预算不足拒绝或明确压缩策略，不静默将其他角色私密信息带入。

最终消息、状态、账本、幂等记录必须作为同一会话聚合文件原子替换；API不逐条先写消息后写账本。回合撤回与重试采用前态快照/受限补丁并撤销相应来源，禁止只删气泡。具体字段、限额、操作集、目录schema、历史策略、重试/撤回UI、错误码和迁移已在22b冻结，实施不能自行扩张到全域资产迁移。模式/会话切换只换视图，store持有的流不得因Workspace卸载而取消。

旧故事继续原读取路径和is_player逻辑；新独立会话先采用新控制分配，不批量改写旧卡/旧存档。后续故事适配器需要显式识别旧多玩家卡、稳定ID冲突、迁移备份与幂等测试；不得“任选一张”改变旧主角。无卡NPC复用发生在R4，不自动将路人升级为全局卡或长期模拟对象。
