# 角色模式、局内角色状态与外部资产兼容

更新：2026-10-01。状态：需求确认与设计草案，未实装；不是已冻结的完整架构。

## 目标与授权

- 独立私聊、小规模群聊作为角色行为实验场，研究目标、表达、知识边界和关系，再将有效机制验证到故事中的无卡片 NPC。
- 本轮仅设计、记录优先级，不修改功能代码，不升级版本、打包或发布。
- 用户指定 Astra 负责设计，6.1 Sol 中/高思考负责后续编码。本文是设计交接输入，不宣称所有未决协议已经由 Astra 冻结。
- 原 M1–M5、W1a/W1b 到达已批准工程边界；完整世界规则修订历史、已提交变更撤回及创作收件箱仍未完成，暂存后续设计池。

## 已确认需求

1. 暂不做故事内私聊；未来该功能依赖独立角色对话能力，不能另建一套角色引擎。
2. 顶部「游戏—工坊」改为「游戏—角色—工坊」。私聊/群聊在角色模式内部安排，不再增加顶层入口。
3. 全局角色卡是可复用资产；会话内角色副本可变化，默认不反写全局。角色账本记录知识、经历等局内信息。
4. 重设计 NPC/玩家角色的控制身份分配，不能未经迁移直接删除旧开关。
5. 角色卡结构预留演进空间，保留自由文本能力，不强迫玩家填写复杂心理表格。
6. 提示词管理页顶部按模式切换对应列表，不把所有提示词纵向混排。
7. 反馈入口/标题标记“已实装”，同时明确“需手动发送，不会自动提交”，避免填写但未送达。
8. 兼容酒馆及用户称为“类脑”的来源中的角色卡、世界书；格式和运行行为分别验收，不承诺所有社区扩展天然兼容。
9. 2026-10-01 新增“链式输出模式”需求，含义待确认，不能自动解释为流式输出或连续多次模型调用。

## 建议：身份归会话，资料归卡片

本节是待冻结方案，不是当前存储格式。

- 拆分角色资产（是谁）、会话实例（本次经历/状态）、控制分配（谁扮演）。界面使用“我扮演的角色”“AI 扮演的角色”，NPC不是卡片永久属性。
- 私聊可考虑不选身份卡直接说话；默认方式、控制人数和切换时点待定。
- 相同资产可进入多个独立会话，名称不是唯一标识；实例、消息、账本使用稳定 ID 关联。
- 旧 `is_player` 映射为原故事的控制分配，不改变旧正文/主角或其他故事。多张旧玩家卡不能静默任选一张；保留备份并明确兼容规则。
- 局内变化经显式提取/另存才进入全局资产，默认排除私聊记录、隐藏知识与私人关系历史。

## 角色账本与本回合行为

- 区分稳定描述、当前目标、个人边界、具体对象关系、已知信息、猜测、实际经历、未落实意图。
- 关键变化带来源消息/回合和证据；未知不补成事实，模型推断不等同作者声明，避免一次错误反应被固化成人格。
- 逻辑顺序：读取状态→形成意图→生成回应→提交实际变化。不要求重写整张卡、不要求输出内部思维链、不规定每步独立模型调用。
- 原文保留，工作上下文使用有界相关投影；不每回合完整注入所有角色账本。
- 失败/取消不提交虚构经历；重试、撤回、分支同时处理消息和状态。快照/补丁格式及事务边界需先冻结。
- 无卡片 NPC 可使用轻量实例，不必升级为暗流实体，不默认持续模拟全部路人。

## 模式与提示词界面

- 模式切换只换视图，不清空会话；沿用按会话隔离的并发原则，迟到结果不能写入错误会话。
- 独立角色会话拥有消息、参与者和世界书绑定，不自动读写游戏存档历史；首版不设计跨模式时间同步。
- 群聊需明确发言顺序、最大回应数量、停止/取消与可见消息范围，不默认人人每轮回复；调用策略通过成本/质量对照确定。
- 提示词列表建议「游戏｜角色｜工坊｜通用」分类。分类只改变导航，不复制切片、不改权限和运行组装顺序。
- 跨模式切片保持单一注册定义，显示适用模式；未接入的角色提示词显示空态/待接入，不提供“可编辑但不生效”的假入口。
- 保留搜索、变量说明、扩大编辑、恢复默认和未保存保护；通用后台切片不因分类失去入口。

## 可演进结构与职责

- 候选模块：资产模型/迁移、局内状态仓储、上下文投影、对话调度、外部适配、API与UI。复用稳定的连接/日志/事务能力，不复制整套故事 GM。
- 少量稳定核心字段 + schema_version + 稳定 ID + 命名空间扩展；缺失可选字段可读，未知字段保留但不自动执行。
- 外部原始载荷与内部归一化表示分开，不把所有外部字段压进 description 冒充兼容。
- 迁移前备份、失败不覆盖、迁移幂等；较新未知结构不能静默降级重写。编辑与模型返回竞争需要修订校验。
- 删除会话明确关联数据范围，不连带删除全局卡；原卡删除后会话副本的处理规则待冻结。

## 外部兼容：文件、内容、行为分层

2026-10-01 查阅的规范入口；实施时锁定版本和合法测试样本：

- https://docs.sillytavern.app/usage/characters/
- https://docs.sillytavern.app/usage/core-concepts/worldinfo/
- https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md

候选范围为旧式/V2/V3 角色 JSON、PNG 内嵌卡、附带世界书及独立世界书 JSON。先做识别/映射矩阵，再冻结首版子集；这是计划，不是当前支持声明。

1. 文件层：识别、校验、读取、保留原始字段和未知扩展。
2. 内容层：描述、开场白及备选、示例对话、场景、世界书等逐项映射。
3. 行为层：宏、消息位置、触发顺序、递归/概率/时效、正则和脚本等标记“等价支持/有限转换/仅保留/不支持”。导入成功不等于行为等价。

- “类脑”目前是来源称呼，缺具体版本与样本，不能假定存在统一专有格式。需要去隐私且有权使用的代表样本，尤其是特殊状态栏和扩展依赖。
- 导入必须预览缺失/降级、冲突和取消选项，不能悄悄丢字段或宣称未支持的行为已生效。
- 外部提示词不能覆盖引擎权限/安全协议；宏白名单解释，默认不执行脚本、不自动访问外部链接。HTML与正则另设安全边界。
- 限制载荷、图片元数据、嵌套深度和处理成本；拒绝路径穿越。保留署名、许可与隐私边界，导入不等于获得再分发许可。
- 导出与无损往返另立验收，不纳入首版默认承诺。

## 反馈小修，不替换主线

- 2026-09-30 检查：本机预览、复制、ZIP导出、预填 Issue 已有实现；4项专项测试通过。没有自动发送、回执、状态跟踪；未验证真实 GitHub 提交。
- 建议标题“反馈与诊断 · 已实装”，辅助说明“仅在本机整理，需手动发送给开发者”。填写/预览不能显示已提交，复制/导出不能声称开发者已收到。
- 修复陈旧预览：表单变化后复制/打开 Issue 必须刷新预览或明确失效；失败不能沿用旧结果。保留日志主动选择、脱敏和人工检查提示。

## 链式输出：待确认，不立即实现

- 需确认是流式输出（单次请求边生成边显示），还是链式生成（分段续写/多次请求衔接），或其他含义。
- 若为流式：先核查各请求当前实现；设计结构化结果与可见正文分离、增量解析、断流/取消/重连及最终提交。未完成文本不能污染正式历史或角色账本，不能把内部 JSON 原样展示给玩家。
- 若为连续调用：先定义停止条件、调用/token上限、失败恢复及玩家确认，不默认无限自动续写。
- 优先级暂 P2 待澄清；若确认为角色模式基础交互，再在 R0 冻结前评估是否提升为 P1。未审计现有能力，不能仅据用户描述断言完全未做。
