# 世界包创作、外部资产与文稿导入

更新：2026-10-12。状态：需求记录与候选产品方案，未授权编码。

## 用户需求

- 明确可见的酒馆角色卡导入入口，兼容常见角色卡/世界书；类脑按实际文件格式判断。
- TXT手稿可能同时含主角、配角、剧情节点、世界规则、能力成长、关系变化，需要拆解整理为可玩内容。
- 候选在工坊中增加与单资产并列的世界包创作入口，用于跨资产共同开发；与现有仅选择资产导出打包区别。
- 工坊审阅需逐条、勾选批量、全部操作，允许编辑和带描述重写，界面简洁。

## 本轮源码核对事实

- WorldPackageManagerModal.vue已有“导入角色卡”“导入世界书”，ExternalAssetImportModal.vue先预览映射再确认写个人资产库，不自动加入故事。
- core/external_formats/adapters.py支持Character Card V2/V3及部分旧格式JSON、PNG角色卡和常见Lorebook JSON；独立性格、场景、示例字段有映射。
- 内嵌character_book保留但尚未自动载入；外部system等字段不自动取得引擎权限。导入格式支持不等于宏/脚本/插件/预设行为全部兼容。
- 工坊资产浏览器现有“打包”打开WorldPackageBuilderModal，主要选择已有资产导出，不是复杂文稿自动拆分生产线。
- 当前所查入口不支持TXT综合设定拆解；本次为定向代码检查，未实测每种来源文件或用户正在运行的包。

## 候选产品流程

工坊选择“世界包”→新建创作项目→添加文稿或现有卡片→AI整理目录与问题→逐项/批量审阅→发布资产及可玩起点→导出包。

- 复用当前工坊三栏：左侧作品结构与资产卡，中央协作对话，右侧当前资料/来源。原始手稿保留可追溯片段，不直接整篇当正文系统提示词。
- 支持先TXT/Markdown及现有JSON/PNG导入；更多文档格式另排优先级，不承诺首版全部解析。
- 标准格式确定性解析；自然文稿由AI按需拆分，呈现原稿已有、推导建议、缺失待补，不能擅自补齐当成作者原意。
- 内容分类包括世界规则、人物底稿/关系初态、实体动机/计划、风格、开局与剧情方案。跨资产引用保留，批量接受时提示未接收的必要依赖。
- 特别区分初始事实、未来计划、条件触发变化、不同结局分支。女主未来能力成长或关系变化不写成开局已经掌握或发生，不提前泄漏给角色。
- 故事节点需要额外产品能力：候选“剧情计划”，提供条件/事件/成长建议。自由发展、条件引导或严格按剧本的取舍尚未确定；不能把全部未来剧情塞进世界书就声称剧本可玩。
- 世界包创作项目可先用已支持资产形成草稿；尚无执行能力的剧情结构标明仅创作资料，不伪装成已生效功能。
- 发布前预览资产、起点和推荐设置；本地导出与社区上传分开。长文按章节/对象分段整理，先结构后细节，保留人工修正，后续确认调用预算与规模。

## 待讨论

### 2026-10-12已确认：触发与结果分开

- 玩家未到目标地图，节点保持未触发。引导候选包括地图标记、线索、资源需求等；用户丧尸高中原稿用食物和材料需求促使探索，不强迫主角自动前往。
- 创作者可在世界书中描述节点结果约束：结局可变但能力固定、能力可变但结局固定、二者都可变；不能在引擎中写死一种。
- 候选整理方式：保留世界书作者原文，将地点/前置条件/触发事件/固定结果/可变结果关联为运行节点；同一设定只保留一个编辑来源，运行记录保存触发状态，不另造必须手工重复维护的卡。
- 固定结果仍需解释因果及适用前提，不替玩家决定台词与行动。若人物死亡或前置条件不成立导致固定结果无法发生，应报告节点无法按原设定执行，不擅自复活人物或强迫玩家行为。此异常产品处理待剧情模块设计。
- 地图功能、迷雾、可见标记/线索与知情范围为关联灵感，未核实当前地图能力，不将地图开发设为首期导入必需条件。

### 2026-10-12补充：用户手稿的剧情节点

用户说明原稿面向线性小说生成：探索具体地图→触发事件→刺激某角色能力变化，小说中原本必经。此为原稿意图，不自动代表AliveWorld玩家必须被强迫走完该路线。

候选导入为独立剧情节点：触发地点及条件、应发生的事件、受影响角色、能力/关系变化、前置节点、是否已触发。能力变化要区分事件必然后果与需要玩家行动才可能达成的结果，不能仅凭进入地图就跳过事件完成成长。未来节点不给角色当作已知经历。

地点与角色引用使用稳定身份；重访不重复发放成长，撤回/分支恢复节点状态。具体实现与调用策略后置，不因此新增每节点独立AI。

待确认：玩家不去该地图时是否让节点保持未触发？进入地图是否仅保证事件开始，结局/成长允许因行动变化？原稿必经可保留为创作者意图，严格线性玩法另作为可选模式，不静默替用户选定。

1. 世界包作为工坊创作项目入口是否采用？
2. 手稿剧情节点是可偏离的引导、条件触发事件，还是必须发生的剧本？允许不同节点单独指定，但首版默认需确认。
3. 导入后默认建立全新草稿还是允许合并既有项目？候选新草稿，合并须展示差异。

验收应包含一份合成手稿，覆盖多角色、尚未发生的成长、关系变化、世界规则和两个可选结局，确保各内容归类及起始状态正确。此处只规划测试，不执行付费调用。
