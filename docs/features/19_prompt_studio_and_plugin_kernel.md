# 提示词工作台、内容预设与插件内核

## 状态与本轮结论

- 状态：设计门已完成，尚未授权进入整体插件实现。
- 当前主线：先把散落的提示词变成可追踪、可组合、可测试的切片，再用它修复玩家行动权、信息通道和通用世界变化捕获。
- 插件方向：成立，但采用“协议优先、声明式优先、逐个内建系统迁移”，不把任意 Python/JavaScript 执行器直接交给工坊 AI。
- UI 原则：普通玩家只看必要开关和当前预设；提示词正文、插件权限、组装预览与诊断属于密码保护的开发者模式。

下一轮的重点确实包含提示词工程，但不是只改一段正文提示词。AliveWorld 已经同时拥有正文、未来推演、状态结算、世界书捕获、记忆、偏好、暗流、多个工坊和生图提示词任务；如果仍让各模块自行拼字符串，新增编辑器只会制造一个看似可控、实际遗漏大半内容的入口。

## 当前代码事实

截至 2026-09-06：

1. `system_prompts.yml` 只保存动态未来、剧情结算、世界创建和 Overseer 四组提示词。
2. 玩家行动权、剧情连续性、正文长度、快捷行动、世界规则命令和偏好注入在 `resolution_engine.py` / `game_session.py` 中通过字符串依次追加。
3. 世界书捕获、故事记忆、偏好分析、世界书工坊、通用资产工坊、偏好工坊和生图提示词各自在所属 Python 模块中硬编码系统提示词。
4. `/api/v1/lobby/prompts` 已能直接读写 `system_prompts.yml`，但没有开发者鉴权、版本历史、字段校验、作用域或前端入口，而且无法覆盖其余硬编码提示词。
5. LLM trace 会记录最终 system/user 文本，却没有记录每一段来自哪个切片、版本、开关、预设或插件。

因此旧提示词接口不能直接作为正式“提示词编辑器”。首个实现切片应先把它降为兼容层，待新注册表接管后删除或限制。

## 目标与非目标

### 目标

1. 每一次模型请求都能回答：调用哪个任务、由哪些提示词切片组成、每片来自哪里、为何启用、估算消耗多少 token。
2. 内建提示词可查看、克隆、覆盖、恢复默认和版本回退，不直接破坏发行包中的基线。
3. 内容预设（包括玩家俗称的“预设/破限”）按任务和槽位显式注入；关闭后不再发送任何相关文本、prefill 或参数覆盖。
4. 插件可通过受限协议贡献提示词、状态字段、规则和生命周期钩子；关闭插件后停止运行但不删除其历史状态。
5. 默认游戏体验无需玩家进入开发者模式修提示词；警察强行介入、替玩家投降等问题仍由官方基线与确定性校验修复。

### 非目标

- 不承诺绕过模型服务商的审核或风险策略。
- 不允许世界包静默替换核心系统提示词或启用高权限插件。
- 不在第一版运行工坊 AI 任意生成的 Python、PowerShell、Node.js 或浏览器脚本。
- 不一次性把所有现有系统重写成外部插件。
- 本地开发者密码不是 DRM，也不能阻止拥有本机文件修改权限的人逆向或篡改程序。

## 提示词切片模型

每个 `PromptSlice` 至少包含：

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定机器 ID，例如 `story.player_agency.v1` |
| `owner` | `builtin`、`user_override`、`preset`、`world_package` 或 `plugin:<id>` |
| `task` | `story_future`、`story_settlement`、`worldbook_capture`、`overseer`、`memory`、`workshop.*`、`image_prompt` 等 |
| `slot` | `system_prefix`、`core`、`system_suffix`、`context`、`user_prefix`、`user_suffix`、`assistant_prefill` |
| `priority` | 同槽位内的稳定排序；不能只依赖导入顺序 |
| `required` | 是否属于不可缺失的协议、结构或权限边界 |
| `enabled_by` | 全局设置、局内设置、请求条件或插件开关 |
| `template` | 提示词模板，不保存运行时私人上下文 |
| `variables` | 允许使用的变量及类型 |
| `output_contract` | 可选 JSON Schema / 文本协议引用 |
| `dependencies` / `conflicts` | 前置切片和互斥关系 |
| `version` / `content_hash` | 审计、迁移和回退依据 |

内建基线不可被原地覆盖。玩家编辑时创建 `user_override`，记录所覆盖的内建 ID 和基线哈希；升级后若基线变化，显示三方差异并让玩家选择沿用、合并或恢复。这样既能自由调试，也不会让更新静默毁掉玩家版本。

## 任务与首批切片

第一阶段至少登记以下切片，而不是只登记文件里的四个大提示词：

| 任务 | 首批切片 |
| --- | --- |
| 动态未来 | 角色职责、玩家事实裁定、信息通道/因果连续性、候选差异、物理权重、暗流条件检查、输出结构 |
| 剧情结算 | GM 职责、文风、玩家行动权、所选未来、暗流兑现、正文长度、状态栏结构、世界变化短信号、快捷行动、偏好上下文 |
| 世界书 | 通用变化捕获、目标匹配、时间/范围语义、风险与审阅、操作结构 |
| 暗流 | 实体职责、信息权限、行动/账本、输出结构 |
| 记忆与偏好 | 各自的分析职责、隐私边界、输出结构 |
| 工坊 | 通用协作阶段 + 世界书/角色/文风/实体/偏好的领域切片与操作权限 |
| 生图 | 上下文选择、视觉转译、内容尺度、角色立绘/CG 差异、输出结构 |

状态栏虽然当前和正文结算使用同一次请求，仍应是独立切片；“独立切片”不等于“增加一次模型调用”。将来若插件提供新状态栏，只贡献 schema、说明和经过校验的更新提案，不复制整个正文提示词。

## `PromptAssembler` 与来源诊断

所有文本模型调用逐步改为请求 `PromptAssembler.compose(task, runtime_context)`，返回消息列表和 `PromptManifest`：

```json
{
  "task": "story_settlement",
  "slices": [
    {"id": "story.gm_role.v2", "owner": "builtin", "version": 2, "enabled_reason": "required"},
    {"id": "story.player_agency.v1", "owner": "builtin", "version": 1, "enabled_reason": "required"},
    {"id": "story.action_suggestions.v1", "owner": "builtin", "version": 1, "enabled_reason": "story.aiSuggestions=true"}
  ],
  "estimated_tokens": 2380
}
```

组装器负责稳定顺序、变量验证、必需切片、依赖冲突、任务作用域和 token 估算；`AIEngine` 只发送已经组装好的消息。日志默认只显示 manifest 摘要，开发者解锁后才可查看包含故事私密内容的最终请求。

重要边界：输出 JSON Schema、玩家行动权等后端依赖的核心契约不能被普通内容预设关闭。即使开发者强制覆盖文本，Python 侧仍须验证候选、状态更新、世界书操作和插件权限，不能把安全性寄托在提示词上。

## 开发者模式与提示词工作台

### 入口

设置新增“开发者模式”。普通状态只显示说明和“解锁”按钮；成功解锁后出现：

- 提示词工作台
- 请求组装预览与来源
- 插件权限/诊断（插件阶段）
- 高风险日志正文查看

普通高级设置与开发者模式分开：配置 API、选择预设、打开玩法插件不要求密码；修改核心提示词和查看完整上下文才要求。

### 密码边界

- 首次启用时由玩家设置本地密码，只保存随机盐和 PBKDF2 哈希，不保存明文。
- 解锁状态只存在当前进程或短时会话，支持立即锁定和超时锁定；连续失败限速。
- 密码、哈希和恢复材料不进入存档、世界包、诊断包、日志或 Git。
- 忘记密码可在本机执行重置；重置只会封存开发者覆盖并恢复官方提示词，不删除故事资产。
- 必须在 UI 明示：本地密码主要防误操作、共享电脑窥看和普通玩家进入，不等同系统级加密。

### 工作台最短路径

1. 左侧按任务分类，显示切片数量、覆盖数量和错误徽标。
2. 中部显示切片列表、来源、启用条件、版本、token 估算；内建文本默认只读。
3. 点击“克隆为覆盖”后编辑，实时验证变量、依赖、JSON 契约和长度。
4. 右侧或弹窗提供“使用当前存档预览组装结果”“查看与官方版本差异”“试运行但不写入游戏”。
5. 保存前创建版本快照；支持撤销、恢复官方、导入/导出。导出默认不含故事上下文和密钥。

## 内容预设与俗称“破限”

沿用 `15_prompt_presets.md` 已确认的双层设计：

- 模型适配预设：解决 system 消息、JSON mode、prefill、stop、温度等兼容问题，绑定连接或任务路由。
- 内容提示词预设：承载创作边界、表达倾向和玩家自定义文本，按任务启用。

内容预设可使用受限槽位，但不能替换核心 schema、权限或确定性校验。世界包可以声明推荐预设，导入时必须展示内容、任务范围和影响并让玩家选择，不能携带密钥或静默启用。“破限”只是玩家可以自定义的预设名称；AliveWorld 不承诺绕过供应商审核。

后续可做 SillyTavern 预设适配器，但必须生成字段映射/丢失报告，未知脚本、宏和扩展字段不自动执行。

## 生图提示词转写开关

生图新增统一 `prompt_mode`，由全局默认、工作流覆盖和本次生成选择按优先级解析：

| 模式 | 行为 |
| --- | --- |
| `auto` | 根据生图连接/工作流声明的 `natural_language_prompt` 能力选择直送或 AI 转写 |
| `rewrite` | 调用 `image_prompt` 路由，将正文与玩家要求整理为 `ImagePromptSpec` |
| `direct` | 不调用提示词 LLM，将本次自然语言场景作为玩家层提示直接交给工作流/服务商 |

`direct` 必须在日志和任务状态中明确显示“未调用提示词模型”。自动剧情 CG 使用玩家可见的场景正文与本次补充要求；手动生图使用玩家输入。最终提示仍保留三层来源：工作流基础词（默认只读）→ AI 场景词或直送文本 → 玩家固定补充。

关闭转写不代表跳过工作流映射、尺寸校验、内容政策或服务商错误。错误仍按“上下文准备 / 提示词转写 / 工作流提交 / 运行 / 取回”分阶段报告。

## 插件内核

### 为什么可行但不能一步到位

物理随机、实体推演、实时状态栏、偏好、世界书捕获、记忆和生图都具有“读取特定上下文 → 在特定时机提出结构化变化 → 由核心校验并提交”的共同形态，适合协议化。但存档身份、事务、回滚、模型路由、提示词组装、日志和权限必须留在可信核心，否则插件关闭、升级或失败后无法恢复一致状态。

### 核心保留职责

- 存档/故事线/回合与分支身份
- 事件总线、事务提交、撤回和失败回滚
- 模型连接、任务路由、预算和超时
- 提示词注册、组装和输出契约验证
- 插件权限、依赖、版本、签名/哈希和生命周期
- 日志、诊断、迁移与兼容检查

### 插件类型与权限

第一版只支持声明式插件包：manifest、设置 schema、提示词切片、状态 schema、安全规则 DSL 和测试夹具。候选权限包括：

- `prompt.contribute:<task>`
- `state.read:public`、`state.write:own`
- `future.propose`、`status.propose`、`entity.propose`
- `ui.widget:declared`
- `asset.read:<type>`、`asset.write:own`
- `network:none`（默认）；未来按域名授权
- `files:own_data`（默认）；不得读取密钥和任意文件

插件只返回“提案”，由核心按 schema、权限和当前回合版本校验后提交。外部可执行插件后置；若未来确有必要，优先独立进程/WASM、资源限额、域名白名单和显式权限，不复用主进程 Python 环境。

### 生命周期事件

候选钩子为：

- `before_context`
- `before_future_candidates`
- `after_future_candidates`
- `before_settlement`
- `after_settlement`
- `on_state_update`
- `on_turn_commit`
- `on_rollback`
- `on_asset_loaded`

每个钩子都必须声明输入、输出、是否允许模型调用、预算、超时和失败策略。非关键插件失败默认隔离并继续正文；会影响状态一致性的插件必须在回合事务内失败回滚。

### 开关语义

插件分别有全局默认和本局覆盖。关闭时：

1. 不贡献提示词；
2. 不执行钩子或模型请求；
3. 不显示运行中组件（管理页仍可见）；
4. 已有插件私有状态进入 dormant，不删除；
5. 显示依赖、冲突和关闭后影响，确认后再切换。

必须区分“运行”和“显示”。例如当前“显示未来可能性”只隐藏候选，不停止未来推演；插件化后的随机未来需要单独的运行模式：物理随机、固定/锁定候选、直接叙事或关闭。不能通过隐藏 UI 假装节省 token 或改变玩法。

### 插件工坊

插件工坊的最小安全闭环：

1. 玩家自然语言描述目标；
2. AI 将需求映射到已有安全原语和权限；
3. 生成声明式 manifest、设置、提示词切片、规则和自动测试；
4. 静态检查、假模型 dry-run、权限预览和冲突检查；
5. 安装为默认关闭的草稿插件；
6. 玩家确认后启用，并可随时停用、回退版本或卸载。

若需求超出安全原语，工坊应明确报告“当前协议不能实现”，生成插件协议扩展提案，而不是偷偷产生可执行代码。

## 玩家行动权与“警察剧情”回归

提示词工作台不是把修复责任交给玩家。官方基线必须同时做到：

1. 玩家明确的自身事实与动作不会被旧正文错误判定为撒谎或幻想。
2. “没搜到 / 没观察到”只是局部负面证据，不能升级为绝对不存在。
3. 警察、保安、监控、邻居或通信介入必须指出可验证的信息通道；违法或冒犯本身不是信息通道。
4. 候选不能全部换措辞导向同一个惩罚、投降或正义介入结局。
5. 正文不得替玩家新增投降、认罪、逃跑、攻击、原谅或崩溃等重大决定。

首批回归语料至少包括：屏蔽全部信号后外部无法收到对讲机消息、住所未搜到设备但设备可位于其他地点、玩家拒绝投降、玩家用括号补充自身设定、封闭现场不存在新目击者。测试既检查提示词 manifest，也用假模型和真实模型抽样检查输出契约；文学质量仍由人工评价。

## 数据所有权与恢复

- 官方切片随程序版本发布，只读。
- 用户覆盖、预设、插件与密码哈希保存在 `UserData`，不进入源码和发行 ZIP。
- 局内选择保存在故事设置中，引用稳定 ID；内容资产本体不复制进每个回合。
- 世界包只携带声明式推荐项和插件依赖，不携带凭据，不静默启用。
- 删除预设/插件前列出被哪些故事引用；默认停用/封存，确认后才删除本体。
- 每次组装保存可复现 manifest；不永久重复保存全部动态上下文正文。

## 实施优先级与设计门

### P0：可观察、可组合的提示词内核

1. 建立 `PromptSliceRegistry`、`PromptAssembler`、任务/槽位枚举和 manifest。
2. 先迁移动态未来与剧情结算，保持输出结构和模型调用次数不变。
3. trace 记录切片来源、版本、启用原因与 token 估算。
4. 将旧 `/prompts` 写接口限制为开发兼容或移除，避免绕过新版本/校验。
5. 用警察介入、玩家投降和世界变化捕获语料做契约回归。

完成证据：同一输入的新旧组装结果语义等价；关闭快捷行动等功能后对应切片完全消失；玩家行动权与信息通道测试通过；Python 全量测试、前端构建和浏览器主循环通过。

### P0：通用世界变化捕获

在组装器上实现 `18_play_to_author_world.md` 的题材无关短信号与按需详细捕获，不依赖“常识改变”固定词。它仍是当前玩法主线的一部分，不被插件构想挤掉。

### P1：提示词工作台、开发者锁与内容预设

提供只读查看、克隆覆盖、差异、恢复、试运行、任务作用域、导入导出和密码保护；接入模型适配/内容预设。没有版本快照和变量校验前，不开放直接改核心提示词。

### P1：生图三态策略与真正的系统运行开关

加入 `auto/rewrite/direct`，并把“显示未来”与“执行随机未来”分离。此阶段先用内建设置实现，不等待插件内核完成。

### P2：声明式插件内核与第一个垂直切片

先用“提示词贡献插件”验证 manifest、权限、开关、依赖、升级和回滚，再选择状态栏或随机未来之一迁移。不要同时迁移实体、记忆、世界书和生图。

### P2/P3：插件工坊与可执行扩展

插件工坊先生成声明式插件。可执行插件只在沙箱、签名、资源限制、迁移和崩溃隔离完成设计与原型验证后考虑。

## 尚未确认、实现前再决定
