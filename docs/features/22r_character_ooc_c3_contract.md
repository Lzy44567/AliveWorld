# C3：结构化场外提示与角色单步自主契约

日期：2026-10-06。状态：最小 C3 工程切片已实施并完成隔离工程验收；不是完整角色模式或真实模型质量证明。设计基准提交 `3c5e5c0`，公开版本仍 `1.6.0-dev.19`。承接 22m/22n，保留已完成 M3 的来源、预算与兼容约束。只实施、测试、更新文档和本地 Git；不改公开版本、不打包、不发布、不访问玩家数据、不付费调用。

## 1. 主线、玩家结果和停止门

最终方向是有来源记忆、保持玩家行动权的一对一角色交流。本阶段只交付：玩家点击小按钮，在台词输入框上方展开“场外提示”，随非空台词提交一次；程序把两种身份分开保存和投影，失败可核对、重试，历史可查看。角色在现有一次回应中依人设迈出一个有限小步，不代写玩家。

M3 已有源码与 Python606/Node109/Edge38 的历史验收记录，当前不是重做 M3。下一可验证片是 C3 的双输入事务→同次请求投影→双草稿 UI→隔离验收。C3 达到本文件验收且无 P0/P1 后停止，C4 消息组送达与 C5 主动联系仍是独立未冻结工程门。

已确认：独立折叠文本框、位于台词框上方；普通括号仍是角色动作；不用 `[[...]]` 标记解析。以下为保守首片工程取舍，不冒称用户逐项选择：仅本轮作用、1000 字符上限、必须同时有台词、无持久控制状态。

非目标：纯 OOC 发送、持续会话规则、暂停扮演状态、独立 OOC 模型回复、心理分析、自动改卡/写全局偏好、重新标注旧消息、多气泡、后台联系、扩容/归档迁移。不把自然语言“以后都……”解释为持久授权。

## 2. 输入与存储

- `send` 请求增加可选 `ooc_note`。缺失、`null`、空串或去首尾空白后为空统一视为无场外提示；非字符串非空值拒绝。规范化为去首尾空白后的字符串，最多 1000 Unicode code points（前端使用 `Array.from` 计数，不能只靠 UTF-16 `maxlength`）；超限拒绝而不截断。台词既有 4000 字符和非空规则不变。
- 字段由可信 API/UI 传递；不解析台词中的括号、标签、JSON、引用或模型输出赋予控制身份。作者卡、开场、世界书、偏好内容不能创建 OOC 字段。
- 非空 `ooc_note` 原子写入 `attempt.pending_input` 与 action 的 `retry_input`，成功时复制为 `turn.ooc_note`；不拼进 `user_message.content`，不创建 message ID、turn ID、ledger 条目或额外正式消息。无 OOC 时可以完全省略字段，旧数据不写空值迁移。
- `turn.ooc_note` 是玩家可核对的生成说明，不是角色说过/听见的消息。当前会话详情、分页历史及动作结果可以白名单公开此字段；列表摘要、未读消息标识、公开来源端点、容量统计不把它作为额外消息或经历。
- 存储校验覆盖正式 turn、archived_turn、pending_input、retry_input 的可选字段，拒绝非法型和超长值；未知上下文协议继续 fail closed。不得只在路由验证而信任磁盘数据。
- 来源身份一致性：非空 OOC 的 pending/retry/正式及归档 turn 必须对应 C3 owning attempt；C3 pending/retry 必须有非空规范化 OOC。拒绝 M3/legacy 搭配 OOC 或 C3 输入缺 OOC 的损坏存储，不静默忽略说明。2026-10-06 独立 Astra 审阅补强；未增加产品范围。
- 保留 session schema 1，依赖已有独立上下文协议识别 C3 请求。新版本读取旧会话不重写/猜测历史；旧程序遇到未知 C3 attempt 协议应拒绝写入，不声称旧二进制可安全编辑新 C3 文件。无需批量迁移。

## 3. 事务、身份与恢复

复用既有 action/attempt、每会话 pending、revision/CAS、原子 repository transaction 和取消/提交互斥。不新增并行 OOC 请求或第二份控制文件。

| 路径 | 冻结规则 |
| --- | --- |
| 新 send | 冻结台词和规范化 OOC；同一动作指纹仅在 OOC 非空时增加该键，保持所有旧无 OOC 指纹一致 |
| 同 action 重复请求 | 相同输入返回既有状态、不再次调用；相同台词但 OOC 不同为 `IDEMPOTENCY_MISMATCH`；省略/null/空白 OOC 等价 |
| 显式 retry | 从服务器保存的 retry_input 取原台词和 OOC，不从现有编辑框取；新的尝试仍重检当前 revision、偏好授权和预算，不能借 OOC 恢复已撤销授权 |
| regenerate | 只接受末轮 target，不接受客户端替换 content/ooc_note；复用目标 turn 原台词和 OOC。旧回复及 OOC 在新结果成功原子提交前保持有效 |
| undo | 整轮撤回既有消息与账本逆操作；原 OOC 随 archived_turn 保留作技术档案，不再进入模型。没有持久授权可被撤回复活 |
| failed/cancelled/interrupted | 不产生正式 OOC 或半回合；retry_input 留存原双输入，终结时清理 pending_input，重启恢复沿既有 interrupted 路径 |
| 丢响应/状态未知 | 只查询 action 状态，不自动重发或调用模型；查明已提交后加载权威历史；不存在时保留草稿供显式发送 |

`regenerate`/`undo` 请求不接受 OOC（即使试图注入其它内容也拒绝），retry API 白名单不接收替换输入。动作结果保留既有字符串 `retry_input` 兼容前端，非空时并列提供 `retry_ooc_note`，不要把原字段改为对象。请求正文不写日志/错误文本。

新 OOC attempt 冻结 `context_contract_id = character.context.c3.v1`；没有 OOC 的新请求保留 M3。duplicate 不改原 attempt 身份。显式新 retry 按已保存输入选择当前支持的相应协议，保持既有显式重试重检语境机制，不把旧 pending 原地升级。reply contract 仍按既有 v1/v2 规则，与 context 版本独立。

取消与提交的竞态仍以先成功的权威事务为准：取消获胜不能留下正式回合，提交获胜返回已提交，不能向玩家谎报“撤掉已提交结果”。不新增持久暂停按钮，也不把本轮 OOC 文本作为停止 API。

## 4. 当前请求投影、证据隔离与预算

采用独立 C3 上下文/提示词身份，保留 M3 与 legacy 的注册和本地覆盖身份，不默默把旧覆盖解释为理解新字段。C3 继承 M3 的近期历史、局内索引相关取材、4 条/4000 字符关联原文及最终来源闭包；不能因为增加新 context id 而退回旧版、关闭 source recall 或漏掉报告。

C3 context 明确包含 `context_contract_id` 和顶层 `current_ooc_note` 字符串；该字段只来自冻结 pending_input。`current_user_message` 仍只含正式台词。输出继续使用严格 `character.reply.v1` 或 `character.reply.v2`；不增加回复 JSON 键，不复制 OOC 至输出协议。

- OOC 不进入下一轮 `history`、recalled_sources、allowed_messages、source 的 message_ids/evidence、世界书触发文本、记忆词法取材、认知索引、重要/高光自动输入或偏好写回。重生成/显式重试原动作是本轮重新执行，可重新投影原 OOC，不算持续会话规则。
- 当前 OOC 不分配 message ID；伪造 OOC ID 或以当前台词 ID 引用仅出现在 OOC 的文字必须被现有精确引文校验拒绝。历史分页展示 OOC 不扩大模型证据权限。
- 当前 OOC 为本轮必需输入，计入同一总预算；不能默默裁去、截断或拼入台词。按既有顺序裁剪可选内容后仍超限则 `CONTEXT_LIMIT`、零 provider 调用；同样不得裁掉其身份/行动权说明。不要提高 token、消息、账本或文件硬限额。
- 代码保证身份与来源集合，不能证明自然语言语义蕴含：若模型把 OOC 内容改写到正式 AI 回复，该回复仍是既有合法消息，无法只靠 message ID 判定文字是否来自 OOC。提示词明确禁止复述 OOC 为剧情事实，人工质量验收单列；不宣称完全消除语义泄漏，也不用关键词黑名单伪造保证。

## 5. 角色自主表达与职责

稳定提示词说明：角色根据已提供的人设、事实和边界选择一个小步（回应、表态、自有行动、具体邀请、退让、拒绝或等待），到需要玩家选择处停止；不强迫每轮反问，不代写玩家感受、动作或答应，不把始终反对当人格。

当前 OOC 只作本轮表达/节奏说明，不是双方经历、人物天然知识、修改冻结人设或同意证明。角色台词中的拒绝仍有效；历史偏好、人设、作者资料和 OOC 均不能把拒绝改判为同意。歧义时停止相关动作并作必要短确认，不需要冻结所有正常交流。

可对当前新请求使用的 M3/C3 核心自主表达切片补充以上规则；不要重写 legacy reply.v1/v2 协议或更改原 prompt slice ID。C3 对新字段的身份说明必须独立注册，旧覆盖不自动覆盖新说明。模型仅负责语言与合法账本提议，不要求输出思维链，不增加分析、修复或重试调用。

## 6. 最短 UI 与双草稿

每会话内存 context 增加 `oocDraft` 与 `oocOpen`，不复用全局角色设置，不把未提交正文写 localStorage。切会话/模式保留各自双草稿；删除会话清理该 context。完整浏览器重载不保证恢复从未提交的草稿，需在帮助说明如实写明；已被服务器接受的失败输入可恢复。

- 小按钮“场外提示”在 composer 附近，展开的小 textarea 必须在台词框上方；辅助文字为“仅本轮，随台词发送；不作为角色经历保存”。准确表述为不作为经历，不声称不存储。首片必须有台词，OOC-only 时发送禁用并提示“请同时输入角色台词；暂不支持仅发送场外提示”。
- 收起不清空；有非空 OOC 时按钮/紧邻提示始终显示“本次含场外提示 · N 字”并能一击展开查看，不能让隐藏字段静默发送。提供显式“清空场外提示”。展开/清空按钮必须 type=button，不能误触 submit。
- OOC textarea 的 Enter 仅换行，不复用台词 Enter 发送处理；台词原 Enter/Shift/Ctrl/IME 规则不变。发送按钮提交一份双输入快照，无额外确认弹窗。
- 在途可继续编辑草稿，但 flight 保存发送时原始双草稿与实际规范化 payload；之后的编辑不影响已发送输入。成功仅当两个草稿都仍等于该 flight 的原始快照时成对清空，任一已变则全部保留；不会擦掉新编辑内容。失败/停止不清空任何草稿。
- retry 明示“重试原台词及场外提示”，不发送用户刚改的双草稿。新双草稿可由普通发送创建新 action；不能把“重试”改成重新提交编辑内容。
- failed/reload 和 undo 的自动回填只有在两个当前草稿都为空时才成对执行，不混合新台词和旧 OOC；任一非空则均不覆盖。undo 只回填刚撤回原输入，不自动发送。必要时错误提示指向原记录，不强制覆盖。
- regenerate 使用末轮保存的 OOC，不读取新草稿且不清空新草稿；确认文案说明“沿用该轮台词及场外提示”。历史回合在台词附近单独显示可折叠“本轮场外提示（非角色台词）”，使用普通转义文本，不当作气泡或来源链接。
- session/action/request/sequence 归属与 store 异步隔离沿既有门；迟到结果只能作用发起会话，不把 A 会话的 OOC 回填或显示在 B 会话。无未提交 OOC 上传/后台分析。

## 7. 实现边界与隐私

小型纯 OOC 规范化/校验模块可共享 API、模型和 context 使用；service 持有状态转换，contract 持有成功 turn 构造，context 持有预算/投影，prompts 注册协议身份。API 仅映射/白名单；store 持有双草稿、flight 与恢复，独立轻量 composer 子组件可承载输入 UI。不要将全部事务塞进 Vue 或增加通用插件框架。

OOC 只属于当前会话，和现有会话正文一样被本地会话仓储保存；生成时发送到玩家已配置的角色回复供应商。清空草稿只清草稿，不删除历史。撤回/重生成保留技术档案，不冒称物理擦除；删除会话沿现有删除/墓碑规则清理该会话数据，不增加全局 OOC 副本。诊断和列表默认不导出正文，错误和安全报告不回显 OOC。

## 8. 必须通过的验收

所有自动验收使用隔离合成数据/假供应商，禁止真实 API 费用和玩家目录。代码变更后窄测、完整 Python/Node/visibility/build、完整 Edge、宽1600×1000/窄520×900截图检查；更新 ACTIVE、路线图、总设计/相关功能状态、分类 CHANGELOG、TESTING 与本文件实施证据。

1. 输入：缺失/null/空白等价；1000 Unicode 边界与 emoji；1001 拒绝；非法类型拒绝；台词仅括号/伪 OOC 标签保持原文；OOC-only 零调用；regenerate/undo/retry 替换字段拒绝。
2. 身份：旧无 OOC 指纹不变；相同 action 同输入幂等一次调用，不同 OOC mismatch；旧数据读取不重写；未知 C3 协议拒写；reply.v1/v2 与 legacy/M3/C3 的独立身份和覆盖行为可查。
3. 生命周期：流式和非流式成功成对保存；失败/取消/服务端重启后重试原双输入；在途编辑、切会话、丢响应恢复；取消先赢/提交先赢；原子持久失败无半回合；重生成失败保留原 OOC，成功替换并归档；撤回后重载不再投影。
4. 隔离：本轮 request 有 OOC，下一轮历史/召回无 OOC；只存在 OOC 中的关键词不触发世界书/记忆/来源；伪造 ID 与引文拒绝，source 端点不展示 OOC；认知/容量/未读不增假消息；提示词明确角色自主、玩家行动权与拒绝规则。
5. 预算与调用：C3 保留 M3 来源报告及最终证据闭包；OOC 全量计费预算，不被可选裁剪静默丢失；必需超限零调用；每次合法生成只有现有一次调用，无语义分析、后台轮询或自动付费重试。
6. UI：小框位置、按钮收起后非空提示、清空、字符计数、OOC Enter 换行、台词 IME/发送；history 标签、重载、失败 retry 提示、双草稿全空回填及编辑保护；宽窄可用无横向溢出。

自动测试只证明协议、状态和可见性。具体人物是否主动自然、是否将 OOC 语义泄漏进剧情、是否误代写，需要后续用户明确授权的真实模型验收；此轮不以工程通过冒称质量结论。
