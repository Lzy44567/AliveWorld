# 设置中心信息架构

## 为什么现在需要整理

当前全局设置已经分为体验、接口、偏好、生图、数据和更新，局内设置也具备分类折叠。这套组件基础仍可复用，但功能数量继续增加后，出现了三个结构问题：

1. 同一数据存在多个编辑入口，例如 ComfyUI 地址同时出现在接口中心和生图配置。
2. 全局默认、当前故事覆盖和运行时实际值没有始终明确标注来源。
3. 专业能力与日常开关混在同一层级，小白玩家会误以为每项都必须配置。

因此不重写整个界面，而是在新增更多设置前调整信息架构和数据所有权。

## 全局设置结构

1. **体验默认值**：正文长度、未来可能性、快捷行动、实体可见性等；说明只影响以后新建的故事，或提供“应用到当前故事”的明确动作。
2. **接口与模型**：连接档案、启用状态、测试、主文本接口、模型发现和高级任务路由。它是地址、鉴权与模型路由的唯一来源。
3. **生图**：当前生图连接的只读摘要、工作流、工作流配置档案、默认提示词层、尺寸和高级采样参数。这里不再重复编辑 ComfyUI 地址。
4. **用户偏好**：偏好卡管理、学习与敏感分析的全局默认；复杂证据与后验继续留在偏好专页。
5. **数据与安全**：个人数据位置、旧资产同步、导入导出和未来的局域网访问安全。
6. **关于、教程与更新**：版本、玩家指南、聚焦式教程入口、检查更新和诊断信息。

记忆压缩、世界书捕获、偏好分析等低频能力在体验页中归入默认折叠的“高级 AI 功能”，其模型选择仍统一进入接口中心的高级任务路由。

## 当前故事设置结构

局内设置只放会改变当前故事体验的内容，不复制 API Key、Base URL 或连接管理：

1. 故事基础：宇宙主导向简述、世界时间显示等。
2. 正文与交互：目标正文长度、未来可能性、投掷结果、快捷行动。
3. 活世界：实体推演、显示权限、世界书捕获。
4. 记忆与偏好（高级）：自动压缩、偏好学习、正文参考偏好等。
5. 生图覆盖（高级，可后置）：默认继承全局工作流和风格；只有开启本故事覆盖后才显示不同工作流或玩家固定补充词。

当前代码在创建故事时复制全局默认值。首轮整理保持这种“创建时快照”语义，避免全局设置变化后静默改变旧故事；界面必须明确写成“新故事默认值”，并可提供“恢复为当前全局默认”。未来若改成实时继承，需要单独的数据迁移与覆盖标记设计。

## 交互与组件规则

- 设置窗口升级为接近全屏的工作区仍可使用现有侧栏，不需要另造一套顶层模式。
- 每个选项使用统一的 `SettingRow + FieldHelp`，高级组默认折叠；只有接口列表、工作流映射等复杂对象使用独立编辑页或弹窗。
- 当前值旁显示来源：`全局默认`、`本故事覆盖`、`工作流默认` 或 `玩家覆盖`。
- 开关、连接测试和保存必须有即时反馈；耗时热重载不能让按钮看起来失灵。
- 一项配置只能有一个写入所有者。其他页面显示摘要并提供“前往设置”，不复制第二份表单。
- 当选项继续增长时优先增加分类内搜索，而不是无限增加左侧一级栏目。

## 开发顺序

1. P0：消除 ComfyUI 地址双写，接口中心成为连接唯一来源，生图模块只读取已路由连接。
2. P0：补齐正文目标长度的全局默认、局内覆盖、存档恢复和提示词约束。
3. P0：接口卡片直接显示启用开关；优化设为主接口与普通按钮的响应等待。
4. P0：文本接口模型列表发现、缓存和可输入检索下拉；不支持 `/models` 时允许手填。
5. P1：按本文件重新分组全局/局内设置，增加值来源标识和恢复默认。
6. P1：工作流配置档案、映射检查与三层提示词，详见 `05_image_generation.md`。
7. P1：完成访问鉴权和移动正文布局后，再提供手机局域网访问。
