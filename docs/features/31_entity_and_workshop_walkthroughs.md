# 实体推演与工坊：完整流程设计推演

日期：2026-10-13。状态：产品设计候选，未编码、未运行模型实验。继承30的已确认原则；下文新增流程及默认值均为建议，不自动视为用户批准。用途是检验玩法是否自洽，而非替代真实测试。

## 一、实体系统的完整玩家体验

### 场景基础

某城遭遇连续降雨。商会有交付药材的合同，车队负责运输，桥梁管理处负责道路安全。玩家在城中旅馆活动，未必会参与运输。实体拥有各自知识、资源和目的，不共享全知信息。

| 故事时间 | 世界实际变化 | 实体卡/账本职责 | 玩家角色可知内容 |
|---|---|---|---|
| 第一天上午 | 商会决定次日出货，已付订金；车队收到订单 | 商会卡保留目标和资源现状；账本记录订单、参与者和出发窗口 | 默认不知道，除非得到消息 |
| 第一天下午 | 管理处检查桥梁，决定次日封桥；通知商会的信使已出发 | 管理处卡有检修判断；账本记录封桥安排与通知进度 | 可在实际可见的公告处得知；不能自动知道检查内部细节 |
| 第二天清晨 | 车队在收到改道消息前已出发 | 出发成为已发生事实；资源与位置同步变化 | 上帝视角玩家可看见，角色仍未必知道 |
| 第二天上午 | 玩家选择去东路；到达时间与车队经过重叠 | 依现有路线和时间裁定相遇，不移动车队迎合玩家 | 角色看到车辆；与领队交谈后才可能知道货物与委托 |
| 第二天稍后 | 玩家若告知封桥，领队依据可信度、时限和成本作决定 | 更新领队认知与运输计划；改变未来路线，不改写过去出发事实 | 玩家可见领队回应，但不自动知道其所有顾虑 |
| 第二天下午 | 若无人提醒，车队可在桥前受阻，再根据现场信息决定等待或改道 | 实体不为玩家缺席而冻结；结算后保存延误等后果 | 玩家未到场则不强行插入全知旁白 |
| 第三天 | 商会根据到货情况处理履约，玩家稍后可能听见相关消息 | 事实与传播记录分开；再次接触不重复执行运输 | 得知的是当时能获知的消息，可能不完整 |

该表是用于设计验证的一条假设路径，不预先强制所有存档出现相同剧情。

### 变体：检验是否真在模拟世界

- 玩家完全不介入：运输和检修仍按条件推进，不要求与主角扯上关系。
- 玩家只是去东路但迟到：可能遇不到车队；不能因玩家意图而回放出发事件。
- 商会负责人死亡：已出发车队继续；未下达的新计划不会自动执行；授权继任者可改变后续决策。
- 信使没能送达：车队不能根据管理处秘密决定提前改道；收到不实传闻也可形成有根据的误判。
- 玩家连续发十条短对话：不能按十回合强制经过十天；信息变化仍可能触发决定。
- 玩家等待三天：处理期间关键事件与依赖，不只在第三天一次性把所有计划判成成功，也不逐分钟请求AI。
- 玩家中途撤回告知封桥的回合：恢复此前认知与计划；从该告知派生的新路线不能残留在分支。旧分支历史可保留，但不能污染当前世界。

### 交互与信息组织建议

默认故事界面只显示主角可感知的变化，不弹出幕后流水账。开启既有上帝视角权限后，另显示清楚标注“幕后／角色未必知情”的摘要，不当成主角亲历的消息。

实体详情呈现“当前状态—目标—相关计划与影响—已知信息”，不是把全部账本JSON摊开。计划条目可展开看到依据、参与者和变化记录。全局账本按时间和实体过滤，用于跨实体追踪；无需增加一个常驻抢占故事空间的侧栏。

短期NPC记忆、场上人物展示、活跃实体推演是不同层次：人物离场可退出左侧列表，身份及已发生经历仍保留；不需要为了记住一句对话而把所有路人升级成后台实体。

## 二、后台与正文的协作：不重复裁定同一件事

建议由后台决定和记录离场实体行动，正文处理当前场景中玩家行动及可见互动；同一事件进入当前场景后应由一个流程完成本次结算，不让后台同时给出另一个结果。

| 责任 | 输入与产出 | 调用原则 |
|---|---|---|
| 程序筛选 | 故事时间、已明确条件、当前相关实体和待处理事项 | 没有工作则不调用；不把复杂语义条件硬编码成题材规则 |
| 暗流AI | 相关实体知识/目标/资源、世界约束、必要账本 → 行动或保持不动及依据 | 可批量处理相关实体，不默认每人一次；新请求是实际额外费用 |
| 程序保存 | 已接受的变化与来源、资源、分支归属 | 一次执行不重复扣资源，不让迟到结果覆盖更新后的事件 |
| 未来/正文AI | 当前行动与已发生后果、当前场景必要的隐藏事实、角色已知边界 | 复用现有职责，不额外增加通用导演调用；不能重新抽签推翻既成事实 |

上述是职责建议，不是预定实现字段或大型任务框架。

### 异步存在的真实取舍

后台结果与当前行动无关时，不阻塞正文。若玩家恰好进入仍在计算的运输事件，不能一边宣称世界已独立结算，一边让正文随意另编结果。

建议先完成与当前场景相关的最小事件结算，必要时短暂等待；其余后台任务继续。等待或失败使用中性“正在整理当前场景”提示，不泄漏隐藏事件。失败时保留输入并可重试，不自动制造成功结果，也不重复收费重试到无上限。具体超时与预算在实现阶段确定。

所以“后台异步”不是保证所有情况下零等待。设计优先减少无关等待，并保证当前场景只有一份成立的事实。

### 重要事件的介入机会

候选：不保证玩家总能挽救所有离场人物，也不为了让玩家介入而暂停整个世界。能够影响玩家、且世界内存在传播途径的变化，可通过消息、线索和可见后果提供机会；不能凭空给主角预知。

“重要同伴可能在完全不知情时永久死亡”等体验边界仍需集中审阅；本轮不添加一套未经确认的保护开关。固定剧情节点的保障需求与实体自由行动冲突时，应回到作者约束解决，不能暗中替换玩家选择。

## 三、工坊完整创作流程

### 起始输入示例

玩家：“我想做一个海上浮岛世界，主角经营一家小店，与各岛居民交朋友。轻松、有秘密可以探索，但不要总变成战争与经营压力。”

这是体验目标，不意味着世界里不能有经济或冲突。工坊不应一上来扩写税制、劳动制度、战争史，忽略玩家想玩的内容。

### 1. 先理解，不先发长问卷

工坊从输入中提取已经明确的基调与重点，只询问影响开局的少量缺口，例如：“你更想从已有熟客的小店开始，还是刚到陌生岛屿开店？”“经营更偏轻量背景，还是想参与进货与定价？”

建议一次优先问1–3个关键问题，作为会话指导而非硬性每轮规则。玩家说“你来决定”时先给可修改草案；不得无限提问或反复要求重填已知设定。

### 2. 简短复述创作目标

展示可修改的创作目标摘要：“轻松交往与探索为主；经营提供互动契机，不以财务压力驱动；岛屿秘密形成长期兴趣。”与世界内规则分开保存，并在后续创作中持续参考，不只第一轮使用。

不用增加一次专门的LLM调用来生成这个摘要，也不要求玩家额外点击一次确认才能聊天。

### 3. 给少量有区别的方向，再批量创作

例如起点可以是熟客介绍委托、漂流物引出岛屿秘密、邻岛节庆促成首次出行。每个方向说明能玩什么，而非仅给三个不同标题。

按选定方向组成一个可玩小集合：起始岛与小店、少量可互动人物、一个近期需求、一条可探索线索、必要世界规则及开场。数量是例子而非固定模板。更大的历史与地理可后续展开，不用先填满世界百科。

单资产创作沿用现有工坊入口；涉及多资产共同创作时采用25的世界包项目候选。不得把“选资产导出”当作“跨资产AI创作”已经实现。

### 4. 审阅按成果，而不是按长JSON

候选界面复用草稿结构和中央对话：结构中按世界设定、人物、开局等分组展示有摘要的条目卡；点击查看内容与改动。卡上提供接受/拒绝，重写放在更多操作中；勾选后才出现批量工具条，避免每张卡堆满按钮。

举例：玩家喜欢岛屿和店主设定，不喜欢某位商人。可以只重写该人物，并附“更内向，但不是冷漠”的说明，无需整批重做。若其他条目依赖这个人物，标出受影响项；不自动连带删除或悄悄用替代品覆盖。

“接受草稿”与“发布生效”保持区分。编辑当前故事副本时不改变全局资产；批量操作范围要显示清楚。保留既有草稿/发布机制，不因新工坊设计另造一套资产真相。

### 5. 可选小范围试演与发布

试演是P2候选：创建与真实游玩隔离的临时场景，调用当前相关角色/规则观察一小段效果，明确会消耗API；不改正式存档，不自动累计为人物真实记忆。其目的不是证明所有模型都能忠实执行，而是帮助作者发现提示和设定歧义。

发布前展示资产范围、可玩起点与推荐设置。尚未实现的剧情能力必须标为创作资料，不能伪称会自动触发。先本地发布/导出，社区上传不纳入本轮。

世界包完成度可提示“已有开局／缺少可扮演角色等必要内容”，但不要求所有世界包都包含固定数量或种类的资产；例如世界书扩展包不必有独立开局。

## 四、优先级与有限范围

| 类别 | 优先级 | 设计内容 | 当前状态 |
|---|---|---|---|
| 核心功能 | P1 | 实体独立行动、知识边界、世界级账本、死亡后的布置持续 | 原则已确认，流程候选已写 |
| 核心功能 | P1 | 正文/后台同事件责任、关键时间处理、回溯一致性 | 详细职责候选，未实施验证 |
| 核心功能 | P1 | 工坊先定位意图、持续参考创作目标、批量起草和部分审阅 | 目标已确认，交互候选已写 |
| 功能升级 | P2 | 多资产创作项目、导入拆解、可玩起点与依赖审阅 | 关联25/29，整体入口待原型审阅 |
| 体验优化 | P2 | 实体详情和账本总览、试演及改动对比 | 候选，未制作视觉原型 |
| 玩法扩展 | P3 | 普通路人离场经历补全 | 默认关闭已确认，延后 |

先将以上流程纳入完整故事和创作设计案，再划编码版本范围。本轮不建新引擎、不发布、不增加付费实验。

## 五、后续验证清单（尚未执行）

实体：身份改名不重复、行动依据受限、条件满足不等于成功、消息延迟影响认知、时间跳跃不重复执行、死亡影响按依赖处理、迟到结果不串分支、上帝视角不改世界事实。

工坊：用户已给内容不重复询问、目标在多轮后仍保留、补充不偏离体验、用户原文与推导区分、仅重写选中项、依赖未接受时提示、发布与全局/本局范围清楚、试演不污染真实数据。

程序测试验证状态与交互；模型评估另验证推演动机和创作契合度。不把设计走读当作自动化测试通过，也不把“质量”完全归咎于模型而忽略提示词与取材。
