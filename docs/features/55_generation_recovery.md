# 55 故事与工坊生成失败恢复功能组

2026-10-24 / P1 / 已获继续开发授权。本组完整交付后统一发布，不按内部切片发版。

## 玩家流程
生成失败后，在原阅读区附近看到“未完成内容”；打开残稿记录，查看正文、失败原因及下一步建议，复制或导出文本，必要时将原请求放回输入框修改并明确发送。刷新或重启后仍可读取。旧残稿不因下一次成功而自动删除，玩家可逐条删除。

## 边界和所有权
- 故事与五类工坊，覆盖流式/非流式截断、格式错误、已收到内容后的传输失败。只提取已有公共正文/工坊解释字段，不猜测缺失字符，不修复或执行JSON操作。
- 失败残稿是独立本地文件，不进入正式对话、提示词、记忆、状态或资产。无额外模型调用。过滤与主动取消的本次内容不保留；模型推理、密钥、原始JSON和内部操作不提供给恢复界面。
- 故事残稿放在存档内，随存档改名/删除。工坊残稿附属现有工坊记录，按目标资产聚合，跨新轮/发布可见，保留规则与既有工坊历史一致；玩家可以显式删除残稿。不会迁移或扫描私人旧日志。
- 每次失败按请求ID独立记录，重试不覆盖旧残稿。并发对象不串内容；正文事务成功不生成残稿，保存失败不冒称成功。残稿存储失败必须提示，且不得改变原事务的失败结果。
- 原请求恢复只填入输入框，有新草稿时不覆盖；不会自动重放撤回/重掷。显式发送是新的当前操作，UI说明可能产生费用。
- 断网未确认服务器结果时不直接重试，先重新加载核对。停止/重试沿用39，不增加另一套调度。

## 分层及阶段
1. 独立恢复领域：公共字段提取、请求内捕获、失败分类、独立持久文件；生成边界负责失败才落盘，AI适配器提供收到的内容。
2. API按现有会话定位数据，返回记录和显式删除；UI公共恢复面板负责列表/展开/复制/导出/恢复请求，故事与工坊只传身份和填入动作。
3. 中性测试覆盖流式/非流式、五类工坊、保存重载、失败不结算、过滤/取消、隔离与并发、新草稿保护、成功后保留旧残稿、删除以及浏览器真实请求。最后全量回归、构建和发布核验。

非目标：自动续写、把残稿一键结算为正式回合、替供应商规避过滤、角色聊天迁移、全软件日志重构。历史53/54完成不等于本组完成。
