# 回合回溯、重演与时间线分支（设计草案）

## 来源与目标

原始手稿已经提出“重新生成/撤回本回合”“读取故事时间点，并以额外存档保留后续”。2026-08-18 的讨论进一步补充了两个不同需求：

1. 玩家想回到任意较早回合，保留原故事，并从该节点尝试另一条发展路径。
2. 玩家在 Boss 战、解谜或关键选择中只想微调操作，不希望每次回退都重新随机出完全不同的未来；被撤回的内容可以作为一次临时参考，但不能继续冒充正式历史。

这不是一个“多次撤回按钮”。它同时涉及故事事实、Python 随机、LLM 非确定性、状态栏、暗流因果、实体、记忆、异步任务和存档空间，必须先定义语义再实现。

## 当前基准

当前每次正文前保存一份内存快照，最多保留 20 份；撤回只弹出最后一份。快照已经覆盖正文、状态、暗流账本、故事回合和行动建议，因此最后一回合撤回具备基本一致性。

当前结构的限制：

- 没有稳定的时间点 ID、标签、父节点或分支 ID。
- 不能直接跳到任意较早回合，也不能保留被覆盖的旧路线。
- `retry` 会重新运行未来推演和正文，不能保证同一关卡条件或相同结果。
- 被撤回正文不再进入正式上下文；系统没有“仅供下一次重演参考”的非正式上下文层。
- 快照重复保存完整聊天与回合历史。真实 18 回合存档已约 1.5 MB，不能把现有整份快照无限延伸为时间线。

## 三种操作必须区分

### 撤回

回到上一正式回合开始前，删除本回合对正式世界状态的影响。原先已触发的账单、状态、实体、回合计数和故事证据必须恢复。它是快速纠错，不自动创建长期分支。

### 重演

从同一个回合起点再次执行。重演提供三种明确意图：

1. **原样回放**：起点、玩家输入和所有依赖均未改变时，直接复用已保存的完整结果，不调用模型。这是唯一能够保证完全相同的模式。
2. **微调重演**：玩家修改行动，但希望关卡条件和主要未来保持一致。复用旧候选集合、选中候选和必要的裁定依据，只重新生成正文；目标是高度相似而非逐字确定。
3. **重新推演**：从相同起点重新生成候选并重新进行 Python 随机，允许进入不同未来。现有“重试/重掷”可归入这一模式。

不能声称通过固定 temperature 或 seed 就能让任意服务商的 LLM 完全复现。完全一致必须使用缓存结果；有输入改动时只能锁定可控条件。

### 时间线分支

从指定回合创建新的故事头，默认保留原分支。分支用于尝试不同角色扮演、结局或路线，不等于覆盖原存档，也不等于复制所有全局资产。

## 临时重演上下文

被撤回内容不得重新进入正式历史，否则模型会把已经取消的结果当成既成事实。微调重演使用独立的 `replay_capsule`：

- 起点回合 ID、来源分支 ID。
- 上次玩家行动。
- 上次候选集合、Python 抽样记录和选中候选。
- 上次正文的短摘要与关键状态变化，而不是无条件拼接整篇正文。
- 玩家本次修改点；未修改的关卡条件要求尽量保持。
- 有效期默认仅下一次重演；重复尝试时覆盖为玩家选定的参考尝试，不能把所有失败路线累计进上下文。

`replay_capsule` 是非正式、可见、可取消的参考层：

- 不进入世界书捕获、记忆压缩、实体记忆或偏好事实。
- 不增加世界时间和暗流回合数。
- 新回合成功提交后立即销毁，除非玩家把该次结果保存成分支。
- 日志必须标明“重演参考”，方便判断模型是否遵守。

## 确定性边界

一次回合至少包含三个随机来源：未来候选 LLM、Python 加权抽样、正文 LLM。分别处理：

| 层 | 原样回放 | 微调重演 | 重新推演 |
| --- | --- | --- | --- |
| 候选集合 | 复用 | 复用 | 重新调用 |
| Python 抽样 | 复用选中项与抽样记录 | 默认复用，可手动解锁 | 重新抽样 |
| 正文 | 复用缓存 | 重新调用并携带重演胶囊 | 重新调用 |
| 正式状态 | 恢复起点后应用原结果 | 恢复起点后应用新结果 | 恢复起点后应用新结果 |

如果世界书、角色卡、本局设置或模型路由在两次尝试之间改变，系统必须提示“依赖已变化，无法保证相似”，不能静默宣称确定性。

## 时间线数据模型草案

### `TimelineNode`

- `node_id`：稳定 UUID。
- `turn_id`：玩家可读回合序号，不作为全局唯一键。
- `parent_node_id`：上一正式节点。
- `branch_id`：所属分支。
- `player_action`、`story_text`。
- 候选集合、选中候选、抽样记录。
- 本回合状态/账本/实体变化摘要。
- `created_at`、可选标签、内容摘要和兼容版本。

### `TimelineBranch`

- `branch_id`、显示名称。
- `fork_node_id`、`head_node_id`。
- 创建时间、最后游玩时间。
- 是否为当前分支、是否归档。

### 状态存储

不继续把整份聊天历史复制进每个节点。推荐：

1. 回合正文和操作记录使用不可变节点保存。
2. 可变游戏状态采用“周期性完整检查点 + 中间回合增量”或内容寻址快照。
3. 分支共享分叉前的不可变节点，避免复制全部历史。
4. 图片文件不复制，只记录分支/回合引用；删除分支不能误删仍被其他分支或画廊引用的图片。

首版若增量状态过于复杂，可以先在“玩家主动创建节点”时保存压缩完整检查点，而不是每回合永久保存整份存档；但必须先测量存档体积和恢复时间。

## 跨系统恢复边界

回到节点时必须一致恢复：

- 正文消息、行动建议、玩家/NPC 状态和世界时间。
- 暗流实体、因果账本状态、尝试/触发次数和因果回合计数。
- 故事记忆索引、活动事件和被回溯回合产生的偏好证据。
- 本局 AI 捕获的世界书内容及其来源回合；玩家手写和分叉前共享设定不能被误删。
- 与被回溯回合关联、仍在执行的异步生图/世界书捕获任务必须取消或标记为过期。

全局资产、API 配置和玩家明确保存的偏好不是故事时间的一部分，不随时间线回退。已经生成的图片可保留在画廊，但要显示其来源分支已归档或已废弃。

## UI 草案

- 正文消息旁提供“从这里开始”入口，打开时间线面板并聚焦当前节点，不在聊天列表顶端插入大型编辑器。
- 时间线默认只显示当前分支：回合号、玩家行动首行、正文摘要、时间和标签。
- “回到这里”默认创建新分支；覆盖当前后续属于危险操作，必须二次确认。
- 分支可重命名、归档和对比；删除分支前显示其独占图片、捕获设定和节点数量。
- 重演弹窗明确选择“原样回放 / 微调重演 / 重新推演”，并显示是否能保证完全相同。
- 不首版绘制复杂思维导图；树形列表足以验证玩法。

## 优先级与切片

### P0：当前版本之后的回合语义修复

- 先修复玩家代理权和事实裁定，避免把错误正文稳定重演。
- 为已生成候选、选中候选和 Python 抽样增加可持久化记录。
- 将现有“重试、重掷、撤回”的名称和结果语义统一，补齐账本与记忆失败回退测试。

### P1：微调重演 MVP

- 仅支持最近一个回合。
- 原样回放使用缓存；微调重演复用候选和选中未来。
- 临时 `replay_capsule` 默认只生效一次，并可在发送前关闭。
- 验证同一输入零模型调用复现、微调输入保持主要条件、正式上下文不包含已撤销结果。

### P1：任意节点与分支

- 稳定节点/分支模型、时间线列表、从节点创建新分支、切换与持久化。
- 先支持玩家主动保存的重要节点，再根据体积数据决定是否每回合自动保留。

### P2

- 分支对比、结局图谱、复杂树状可视化、分支合并。
- 跨分支自动归纳“哪一步导致差异”。

## 待确认问题

1. “回到某回合”默认一定创建分支，还是提供“覆盖当前后续”但默认选分支？当前建议前者。
2. 微调重演默认锁定选中未来，还是每次弹窗询问？当前建议默认锁定并提供“重新随机”按钮。
3. 玩家希望连续尝试 Boss 战时，参考最近一次失败还是可以手选某次尝试？当前建议首版只保留最近一次，分支版再允许选择。
4. 玩家主动载入/修改世界书或角色卡后回溯，分支是否继续使用修改后的资产？当前建议按依赖版本提示玩家选择，不能静默决定。
