## 1. 主线、确认与停止门

最终目标仍是忠于人设、知情边界和共同经历的独立一对一角色对话。最简闭环、共享可搜索选卡器和创建时世界书快照已完成；真实模型质量、桌面验收不能用这些工程证据代替。

用户已接受的产品方向：左侧是类似通讯软件的**会话列表**，不是角色资产列表；同一卡可以有多段独立会话。右侧只服务**当前会话**：人物资料、共同经历、会话设置；内部记录必须显式剧透查看。资产选择使用已有卡片视图，不退回下拉框，不堆复制按钮。既有会话不默认更换参与者或世界书。

下一可独立验收片 **UX-S1（P1体验）**：让玩家找回、区分、置顶和继续会话，且不会误认临时输出为已收到消息。只有这个切片的工程契约在本文冻结；I1字段/开场语义是下一设计门，不夹带实现。UX-S1无必须等待玩家回答的问题。

达到本文验收、无P0/P1后停止侧栏扩展，返回22d角色质量基线及I1讨论。演变、内核提炼、群聊、故事NPC、语音图片、完整长期记忆继续后置；不增加每轮第二次LLM调用。本片不改版本、不重打包、不访问私人玩家资料、不付费调用、不发布。

## 2. 核查到的实际边界

- `CharacterWorkspace.vue`已有左右栏、创建卡片选择、公开账本和显式剧透；不是从零另建聊天引擎。
- `GET /api/v1/character-sessions`当前按UUID字典序分页，每页最多50；`session_view(detail=False)`仍包含人物description/starting_scene，没有末条摘要或turn_count。仅把首页50条在前端排序不能声称全局最近会话。
- 仓储`updated_at`也随pending/失败等写入变化，不能直接等同最后聊天时间。
- store已经按session/request保有草稿、预览和在途操作。切视图不取消请求；摘要不能取预览、失败输入、归档回合或私有账本。
- `models.profile_projection`只投影name/description/starting_scene。外部适配器把personality/scenario/mes_example拼入description，把first_mes写入starting_scene，同时保留原始source。信息并非全丢，但没有独立语义。

## 3. UX-S1领域与API：新增投影，不改聚合

领域会话schema仍为1；无迁移、无源卡回写、无新LLM路径。给现有列表增加显式`view=summary`参数，默认旧投影保持兼容。新投影由服务层纯函数产生；路由只做参数/分页映射，仓储只读权威聚合。

每行只返回以下白名单：

| 字段 | 约束/来源 |
| --- | --- |
| session_id/title/revision/presentation_mode | 原有字段；标题仍≤80字符 |
| ai_name | AI参与者冻结display_name；不读取当前全局卡 |
| created_at/last_activity_at | 最后正式turn.created_at；无正式回合则created_at。不以改名、切模式、失败、pending时间排序 |
| last_message_preview | 当前末尾正式AI消息content折叠空白并截取160码点，纯文本；无回合为空。不是语义总结，不单独读私有记录 |
| latest_ai_message_id/latest_ai_committed_revision | 当前末尾正式AI消息ID和所属turn.committed_revision；无回合为null |
| pending | 既有安全action/request身份及状态；不含pending_input |
| schema_read_only/read_error | 既有安全只读/损坏标记；未知格式不用猜测字段 |

列表不得返回profile_snapshot、world快照、turns、ledger、requests全文、归档、失败输入、source、文件路径、任意外部图片URL。预览属于玩家已可见的公开消息，不等于公开发布；不写日志、不写浏览器持久缓存，不自动解析HTML/Markdown/远程图片。

头像第一片使用冻结AI名字生成的本地字形/颜色占位（无外部请求）；这是可用头像位，不承诺已冻结图片。若后续要复用真实立绘，应另核对现有图片生命周期与删除行为，不为了头像把可变资产库当会话权威、复制大图进聚合或新增远程抓取。

### 完整列表和查询的有界契约

复用现有UUID游标，每次最多50条；前端连续枚举summary投影并按ID去重，再在完整集合执行搜索/排序。首片不建设全文索引或服务端快照分页系统。

- 一次枚举最多40页/2,000行；游标重复、不推进、超限、单页失败均结束枚举并标记“不完整”，不静默继续无限请求。达到第40页且next_cursor为空仍为完整。
- 完整时按“置顶优先→last_activity_at降序→session_id升序”排序；搜索trim后按大小写无关的会话标题/AI名字子串匹配，不承诺正文或私有记忆搜索；搜索词≤80字符，不持久化。
- 不完整时可以继续显示已读行并开聊，但醒目标“列表未完整加载；搜索和排序仅覆盖已加载会话”，空结果不得写“没有此会话”。保留刷新入口，不假报全局查询。大于2,000会话的全局检索是明确后续容量门，不删除任何会话。
- 获取期间可显示上一成功列表和“正在刷新”；首次获取显示加载态，不能闪成空库。一次完整结果原子替换；失败保留旧列表并注明过期。新一轮刷新有generation token，旧请求不得覆盖新结果。
- 这是逐页当前数据，不承诺跨会话事务快照。当前窗口创建/删除/提交期间使枚举失效并合并权威事件或安排一次合并刷新；不逐delta刷新。其他窗口改变通过下一次显式刷新/回到角色页面刷新发现；无永久后台轮询或请求循环。跨页新增UUID落在旧cursor前，需下一轮刷新才能发现，不能宣称实时多端同步。
- 墓碑不显示；损坏/未来schema保留安全占位，排序尾部，不能当空会话或清除文件。

## 4. 本机置顶与未读，不参与领域revision

可逆的UI偏好由独立小工具/store管理，不写会话聚合，不触发模型、CAS冲突或updated_at变化。浏览器同源localStorage仅保存版本号、session_id、pinned、已读水位及最后触达时间；不保存名字、正文、角色资料、草稿、预览或私有记录。说明“置顶/未读仅保存在此浏览器”，清缓存后不影响聊天数据。

存储schema明确版本1；总编码≤256KiB、最多2,000会话，ID校验UUID，revision校验非负安全整数，pin必须boolean，拒绝原型键。损坏、未知版本、权限/配额失败时降级本次内存偏好，不覆盖未知版本数据、不阻断发送，并一次性提示偏好未保存。容量淘汰最久未触达的非置顶条目；无可淘汰项时拒绝新增持久偏好并提示，不静默取消已有置顶。成功删除此会话立即移除对应偏好；部分列表缺席不能视作删除。

未读采用**圆点**，不是虚构精确条数。按最新正式AI ID和提交revision判断，不能用session.revision或turn_count单独判断：

- 首次见到无本机记录的既有会话，以当前latest AI提交revision建立已读基线，不把全部旧历史刷成未读；此次运行中自己发起的在途请求须在发起前建立旧基线。
- 新正式AI提交revision高于已读水位且消息ID不同→未读；预览/validating/失败/取消/改名/模式变化/空会话都不产生未读。
- 只有角色页面可见、该会话当前打开、权威详情成功载入并呈现时清点，记录实际所呈现最新AI ID/提交revision；不因后台store刷新或仅activeId残留而标已读。页面隐藏/切故事后提交应保留未读。
- 撤回使末条恢复更早回合，不重亮已读旧回复；已读水位不因撤回降低。重生成产生更高提交revision的新AI ID，可重新未读。没有新正式AI消息的undo不制造通知。
- 本机偏好允许其他tab的storage事件刷新，但不承诺多端强一致。不得因偏好同步修改聊天数据。

## 5. UI和生命周期

左栏：标题“对话”、一个新对话入口、搜索框、会话行。行内头像位、标题、末条纯文本、时间；运行中用现有busy/pending独立状态，不拿“正在输入”覆盖持久预览。置顶操作用轻量独立按钮，键盘可达、有aria-label，不嵌套button；未读圆点带可访问文字。无消息显示“尚未开始对话”。同卡两会话按各自session_id独立选择/草稿/运行/未读。不默认自动改标题、不新增AI命名费用。

右栏：标题“当前对话”；依次是参与者资料（默认简洁、长description按需展开）、只读世界书名称及创建快照说明、“共同经历”公开记录、会话设置。共同经历是友好栏目名，不把belief/用户陈述都改称客观事实：保留kind、来源类型及展开的逐字证据；仅公开active条目。设置保留现有表现方式与删除，回应方式可保留输入区原入口，不增加第二份开关。资产管理仍在工坊，不在右栏重放全局资产库；没有换AI/换世界书按钮。

内部记录默认未请求；明确点击“查看角色内部记录（剧透）”才GET spoiler，不称之为思维链。关闭、切会话、离开角色模式时清除可见剧透及此次查看授权。异步请求捕获session_id和查看token，迟到结果不得重新展开、写入当前另一会话或在未经再次点击时恢复。公开账本接口继续由服务端过滤，不能下载全量后仅CSS隐藏。

宽屏保留三栏；窄屏列表和资料抽屉一次只开一个，关闭/选择后焦点回合理入口。搜索无结果、列表加载/失败、空对话、只读/损坏、状态待确认都有具体文案。资料区错误不清聊天/草稿；搜索和pin不停止流；切会话仍由store持有请求。所有全文可正常选择，不能为此增加逐条复制按钮。

模型与账本事务完全沿22b：同一次reply产生受校验ledger_ops，正式提交后才进入摘要/未读；regenerate失败保原回合；undo按inverse撤销来源状态。UI不新建/编辑经历，不把列表摘要当模型输入或来源证据。

## 6. UX-S1实现边界和验收

建议只改service安全摘要函数、列表route参数、client API、store和局部侧栏/偏好工具；Workspace只组合和展示，不承载存储协议或模型逻辑。无需通用聊天平台、数据库、后台索引、通知服务或新包依赖。

必须用隔离合成数据验证：

1. 超过50条会话、UUID顺序与聊天时间相反、同时间并列；第2页命中搜索和置顶；删除墓碑、损坏、未知schema、分页失败/重复cursor/40页上限、旧刷新迟到。确认不完整提示真实。
2. 摘要含且仅含白名单；私有独特字串、source、完整profile、失败输入、archived_turn、预览均不出现。长Unicode预览合法，HTML/链接当普通文本，不发外部网络请求。
3. pending到commit与失败/cancel、跨会话/跨模式/隐藏页面完成、回到可见详情、首次基线、连续regenerate→undo。未读圆点、水位和最后消息同时符合正式历史；不增加供应商调用数。
4. localStorage坏JSON/未知版本/超限/拒绝写入/非法UUID；聊天仍可用，未知内容不覆盖，成功删除清偏好、部分列表不误清。

## 7. I1下一门：可选role_fields候选，不随UX-S1编码

以下是供下一轮讨论的工程建议，不是用户批准了开场玩法或自动升级：

```text
role_fields?: {
  version: 1,
  description: string,
  personality: string,
  scenario: string,
  dialogue_examples: string,
  first_message: string
}
```

角色name仍沿用原字段；普通自由文本卡无需role_fields或精神内核。明确版本白名单验证；五项都显式存在（可空），避免“缺省字段”重新拼回合并后的description造成重复。没有role_fields时旧name/description/starting_scene投影逐字保持，不从_external_import猜测升级、也不解析描述中的【性格】标题。存在但版本未知/结构非法时不能部分激活；导入/创建预览明确报告，保原件且不进入新语义运行。

建议外部字段精确映射为description/personality/scenario/mes_example→dialogue_examples/first_mes→first_message；导入时同时保留旧description合并结果和starting_scene用于故事/旧读取方兼容，原始source继续保存。新角色投影只使用role_fields结构，不再重复注入兼容合并文本。工坊编辑须同步维护结构或明确退出结构模式，不能偷偷保留过时的role_fields盖过作者后来编辑的description；发布前需专项设计这一编辑权威路径。

建议限额：description≤16,000、personality≤8,000、scenario≤8,000、dialogue_examples≤8,000、first_message≤8,000字符，总投影文本≤32,000字符；这是待I1审阅的保护候选，不是现有卡自动截断/拒绝读取政策。导入预览标超限字段，用户编辑后方可新建结构语义会话；旧资产/旧快照不改。

- description/personality是冻结作者人设资料；不自动生成心理内核、不推断缺失性格、不宣称外观必然推出性格。
- scenario是创建场景资料，不是已经发生的对话，也不等于first_message。first_message只是作者提供的开场候选；UI-S1仍保留现行starting_scene表现，不能悄悄塞入history。
- dialogue_examples是表达参考，独立标明“非本次历史/非共同经历”，不赋正式message_id，不作为ledger_ops可引用来源，不建立玩家已做过的行动/关系。
- 外部system_prompt、post_history_instructions、脚本、未知宏和内嵌世界书继续只保留、不执行、不提升系统权限。第一片I1建议不做宏替换；若以后做，仅另冻结明确白名单的纯文本替换，绝不执行任意表达式或递归展开。
- 稳定引擎职责/权限/JSON契约留system；卡片/世界资料以有来源的用户数据投影，不能为了缓存把外部作者文本抬成引擎指令。输入顺序稳定，人设资料在动态历史之前；动态账本/历史/本轮输入在后，关键信息避免重复。字段hash/来源元数据不复制原文到诊断。
- 人设和场景属于必需集合；示例是可选参考，按完整字段/未来明确分段裁剪，不能截断半个JSON或把样例拆成真实轮次。先权限过滤再检索/预算；必需集合超限零调用，保留现行至少近期2完整回合的保护。不承诺供应商缓存命中或“更多字段必然更忠于人设”，用实际token、cache usage和人工质量评估验证。
- 会话继续创建快照，旧会话永久沿旧语义；本片不批量重写资产或迁移旧会话。用户若要升级旧会话，应在独立设计中讨论预览、备份、历史含义与失败回退；不能因新代码识别到source就改变旧对话。

### 真正待问的I1产品问题（不阻塞UX-S1）

**导入卡的原开场是否要成为可选的正式聊天开场？** 建议默认仍由玩家先发言，提供创建时预览和显式“采用原开场”；但这将新增单条作者开场的身份/撤回/来源语义，不能装成既有双消息turn或假定用户已经做了原开场里的行为。若玩家选择采用，需要另冻结“作者设定展示”还是“AI正式已发消息”、如何编辑越权玩家动作、如何撤回和是否允许产生账本；不能只补一个first_message字段就宣称问题解决。无需在UX-S1之前追问。

人物字段之间冲突先在预览可见、不由LLM改写原卡；人格演变/自由文本提炼等仍不在此门。I1独立验收应含旧卡/旧会话字节不变、纯字段映射、示例不入历史/来源、恶意系统文本不提权、预算与编辑一致性；内容质量仍需明确授权的真实评估。

## 8. 长期记忆另过门
