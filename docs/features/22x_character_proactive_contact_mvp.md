# C5：有限主动联系最小交付设计

2026-10-09；承接22n§6–7、22w和已完成的C4。本文是实施提案，不冒充已实现或全部参数已由玩家确认。
当前主线仍为角色基本完成；交付片A已实施（2026-10-09），B仍为下一阶段设计。真实玩家数据及公开版本未修改。

实施状态：A提供当前会话授权/费用、编辑租约、一次规划、持久次数额度、无玩家输入的正式主动组、未读/撤回及取消/重启停止。813 Python、144 Node、生产构建、C4+C5 Edge6项通过；假模型和20倍测试时钟只在隔离测试服务，不入生产。首版仍不支持关机后台、批量启停、每日免打扰、主动组重生成或逐气泡动画；额度是次数而非金额。

## 1. 玩家闭环与范围

- P2玩法升级：当前会话设置→阅读额外调用费用说明→开启→正常聊天→闲置→角色有理由时主动发有限消息组→玩家回复即结束旧计划。
- 默认关闭，授权只属于当前会话；新建/复制不继承。首次开启不凭旧聊天立即收费，下一条正式玩家消息开始周期。
- 一次空闲周期最多一次模型规划；一次返回0至N个未来联系组，每组沿用C4的1–6气泡/8000字符上限。不用LLM轮询。
- 模型只决定“是否联系、说什么、有限相对延时”；授权、计时、次数、取消、正式送达由程序控制。
- 首版限schema2；旧会话显示需升级，不自动迁移。只在本地服务运行时工作，不承诺关机、退出软件或云端后台联系。
- 首个交付片必须有UI开关和真实完整调度路径，不能把配置接口或quota模块单独宣称C5完成。

## 2. 冻结为可编码的最小规则

- 工程默认值（可逆，不是已获用户逐项确认）：连续闲置10分钟；编辑租约30秒，心跳最多每5秒一次；每周期最多2组（设置1–5）。
- 全局每日主动规划调用默认5次、联系组默认10组，设置分别1–100；只是次数硬限制，不声称精确金额/token上限。正常聊天调用不计入这两个C5限额。
- 首版预算日固定UTC，UI显示下次重置的本地时间；计划最晚在预算日结束或规划后2小时过期，取较早者，不跨预算日发送。
- 只允许真实文本编辑续租，含台词/OOC；焦点、鼠标、非空草稿不续租。客户端只上传临时client_id与活动信号，不上传草稿。
- 服务端按接收时间维护各client_id租约；任何有效租约都阻止规划/联系。普通生成、待回复输入、C4送达未结束时同样不开始闲置计时。
- 上述阻挡消失后重等完整闲置阈值。编辑覆盖计划期限时先等，过TTL直接丢弃；不补发积压。
- 新正式玩家输入在`accept_input`同一会话事务内递增`interaction_epoch`、清除旧计划并开启新周期；正常回复失败不复活旧计划。
- 关闭、撤回/重生成、语境或记忆修改、删除会话取消旧计划；只有下一条正式玩家消息才能重新开启周期。改标题/已读不取消。
- 开关反复切换、重启、失败、空计划和额度恢复都不自动开新周期；已开始调用不自动重试，也不提供主动规划的收费重试按钮。
- 服务重启/退出后所有未送达计划停止，授权设置保留，但等下一条玩家消息；休眠造成定时器明显迟到（建议60秒）也停止该周期，不补发。
- 免打扰首版仅一项“暂停主动联系”：立即取消计划，恢复后等待新消息。每日时段免打扰属于第二片，不假称已有该功能。

## 3. 核心loop（一个协调器，无通用调度平台）

1. 玩家消息保存→取消旧计划、epoch++→正常C4回复→无忙碌/无编辑后启动本地idle timer。
2. 到点检查开启、周期未规划、无编辑/忙碌、未暂停以及容量→取得共享provider slot→再检查条件。
3. 同步写全局quota预占“一次调用+最多N组”→会话标记本周期已规划和plan_id→释放会话锁后调用模型一次。
4. 验证独立`character.contact_plan.v1`输出：`contacts:[{delay_seconds,reply}]`，reply使用既有V3结构；delay非负递增，所有时间相对规划保存时点，超界整份拒绝。
5. 返回后重验epoch/授权revision/语境epoch；失效即丢弃。保存预写计划，不放入`groups`、历史、未读或账本；空计划直接耗尽。
6. 本地timer到期重验同一组条件及TTL/额度凭据→同一会话事务把该预写组转为C4正式组并标记该索引已送达→发布既有group/state事件。
7. 后续只等本地timer；计划耗尽则停。玩家消息取消的旧worker即使迟到返回，也不能提交或再计费。

首片到期采用`instant`原子送达整组，所有气泡仍各有ID与seq；不伪装实时流式，不新造半组恢复协议。
这是主动联系的明确MVP显示限制，不改变普通聊天C4显示模式；主动组逐气泡服务端间隔后置。

## 4. 数据与持久化：会话正文仍只在原会话文件

- 会话`extensions.proactive_contact`存设置`enabled,authorization_revision,idle_seconds,max_contacts,paused`，以及`interaction_epoch,cycle_state,plan`；缺省视为关闭。
- plan只存`plan_id,interaction_epoch,authorization_revision,context_epoch,history_cutoff_seq,quota_day,expires_at,contacts,next_index`和规划状态。
- contacts保存有界预写V3内容、delay与预分配group/action/request/AI IDs；不复制全对话。允许引用的历史message/entry IDs只保留有界ID集合，到送达时从正式记录解析。
- 模型不许引用其他尚未送达联系组；每组账本只引用规划时已正式来源和本组气泡。到期走现有来源/账本校验，冲突就取消剩余计划，无额外模型调用。
- 计划成功/取消后清掉未送达正文，只留当前周期的最小终态。会话删除移除计划；公共GET只给授权、状态、额度与下一到期提示，不能泄漏预写正文。
- 小独立`proactive_quota.json`只存预算日、上限、plan_id预占调用/组数及已释放数，无对话正文。原子replace持久化，单进程事件循环短同步更新，沿用当前运行边界。
- 所有规划先预占最多N组，额度不足可缩小N；不足1组则不调用。一次联系按组占用，不能用气泡数量绕限。
- quota落盘先于会话标记与provider调用；任何中途失败只会保守多占，不会超卖。启动时一律停止旧周期，所以不会重复调用。
- 成功/取消可在会话计划已落盘失效后，按plan_id幂等释放明确未送达组数；释放失败保守占用至当日结束。调用预占不返还，包括超时或未知供应商结果。
- 到期送达不再写第二个消费文件：已预占组数就是硬占用，会话中的plan索引与正式group原子保存。重放同一plan/index只返回已有结果。
- quota不读得懂/写不成就停用C5并提示，不阻塞正常聊天、不重置成空预算。预算日只向前推进，时钟回拨不清零；不承诺抵抗用户修改系统文件/时钟。
- 这不是跨文件原子事务；有意以小额保守占用换最小可靠实现，不建全局会话镜像、WAL补偿平台或账单结算系统。

## 5. C4必须改的最小契约，不能伪造玩家输入

- `group_schema.py`：group新增可选`origin='proactive'`及`contact_ref={plan_id,index}`；旧组缺省为reply。仅主动组允许`input_ids=[]`，普通组仍1–8。
- request的`operation`增加内部`proactive`，无`input_id`，保留真实action/request/group映射；每个已送达联系各建一个committed attempt，不能把一次模型调用伪装成多个真实API调用。
- 主动送达attempt沿用V3回复与C4证据语义；独立contact_plan协议用于一次规划，不偷改普通reply.v3输出。实际规划调用唯一记录在plan/quota中。
- `group_lifecycle.py`：新增小入口`commit_proactive_contact`，创建无玩家输入组后复用`prepare_candidate/commit_generated/deliver/settle_ledger`；整组一次会话事务，不暴露generating中间态。
- `settle_ledger`明确主动owner的`result_state='active'`；不给主动组附加依赖玩家本轮输入的memory_notice。消息/未读/来源/ledger_inverse继续共用。
- `latest_batch`不能对空input集合`max()`：主动组以对应attempt的`history_cutoff_seq`做后来玩家输入屏障，仍仅允许最近完整组撤回。
- `batch_action`复用整组undo与账本回滚，主动组无玩家输入可撤；主动组regenerate首版明确拒绝，不能落进`create_group([])`的普通付费路径。
- `require_group_retry`和公共retryable对`operation=proactive`恒拒绝；UI显示“主动联系”标识、允许符合屏障的撤回、不显示重生成/重试。
- `group_views.py`输出origin用于UI，其余分页/正式消息/未读沿用`group_records.py`；不另建第二套聊天列表。
- 旧schema2文件缺省关闭无需转换；一旦保存主动字段，旧构建可能拒读，发布需说明不可用旧程序写回，不做隐式降级。旧schema1保持原样。

## 6. 代码职责与集成位置

| 模块 | 唯一职责 |
| --- | --- |
| `proactive_contact.py` | 周期/授权/计划领域变更、到期判定；外部设置/模型输出在边界校验一次，内部信任契约 |
| `proactive_quota.py` | 小型次数预占/幂等释放持久化；不放会话文本，不管UI/timer |
| `proactive_service.py` | 每会话timer、编辑租约、一次规划worker；使用既有transport和共享slots，调用会话事务入口 |
| 现有C4/service/runtime/API | 接入生命周期和少量send/语境变更通知，复用投影与事件；不把全部新逻辑塞进group_service |
| 客户端API/store/UI | 当前会话设置/费用提示、编辑节流心跳、暂停/关闭、状态与额度；不拥有送达权威 |

规划提示复用现有角色/正式历史/记忆上下文的投影部件，新增单一规划输出说明；不调用要求当前用户input的普通`build_group_context`假造消息。
没有真实新玩家输入，不自动把“经过10分钟”写成故事推进，也不推测玩家为什么离开。

## 7. 两个实际交付片与验收

**A：当前会话可开启并实际收到有限联系（首先编码，完整闭环）。**
一次实现UI开关/费用说明、租约+闲置、有限列表规划、持久quota、无输入主动组、原子送达、未读/撤回、取消和重启停止。
设置可先用上述默认值，但显示清楚上限；支持单会话修改idle/N及全局次数。开发假provider可缩短时钟，不需要付费实测授权才能验工程链路。
针对性验收：默认关零调用；编辑续租/草稿不续租；0/1/N组一次调用；到期产生真实无input组、未读和账本；玩家回复/关闭取消；重复timer不重复；重启不补发/重试。
再验两个会话抢最后配额只准一个、quota落盘后崩溃保守占用、送达后崩溃不重复、主动撤回来源逆转、普通C4输入/批撤回回归。
交付门为相关Python+Node测试、一次前端build和宽窄浏览器端到端；不在每个helper后跑全suite，不把假provider通过当文学质量通过。

**B：多会话易用性补齐。**
会话列表明确勾选/全选现有会话批量开启、逐项结果与对称一键关闭；每日免打扰时段、可见预算重置说明。
批开不授权未来会话，不回滚成隐性开启；免打扰结束重等完整idle、不补积压；批量失败可逐项核对。A仍是可玩的首交付片，B完成22n批量承诺。

## 8. 后置与真正未决项

- 非阻塞产品提案：10分钟/2组/每日5调用10组、2小时TTL、固定UTC预算日；实施可采用明示默认值，用户之后调整，无须逐项微审批。
- 主动联系首片整组原子送达、暂停代替时段免打扰、主动组只撤回不重生成，是为最快闭环明确收窄；若要求首发与普通聊天逐气泡间隔完全一致，需先扩展半组取消/恢复契约。
- 真实关机后台、微信、精确全局token/金额计费、长期容量、跨进程调度和通用任务平台全部后置；不需要为C5首片先建设它们。
- 当前设计没有必须等待用户回答才能写A的技术阻塞；是否启动编码由主代理依据用户实际实施授权判断。真实付费质量测试和发布仍分别需要授权。
