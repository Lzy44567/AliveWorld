## 1. 现状与主线

dev.18的I1工程与包验收已完成，用户现已真实打开角色页。当前目标从兼容性转向容易上手的一对一角色聊天，而非立即扩充群聊、媒体或心理模拟。先解释玩法、冻结产品交互，再实施；角色长期记忆M的基础设施复用仍保留独立设计门。

实查：流式选择常驻输入框上方；Enter换行/Ctrl+Enter发送；会话列表为卡片式；messenger/roleplay只有下拉名称。外部卡示例可导入并进入模型，但原生编辑只读结构/转自由文本，不是独立示例编辑器。作者first_message只资料预览，创建无正式开场。世界书绑定创建快照：概述/公理及常驻/绝对规则常驻，普通条目仅匹配本次玩家输入，最多16项；不读取近期AI文本匹配。角色请求无用户偏好字段。此现状不是理想最终设计。

## 2. 用户确认与候选UI（P1体验）

用户要求参考微信的会话列表/聊天区，减少输入区工程选项。候选：保留AliveWorld三模式与主题，左侧紧凑会话行（头像、标题、末条摘要、时间、未读），搜索与新建置于上端；中间双方头像/左右消息气泡与时间分隔；右侧资料按需打开。只借用信息结构，不照抄商标或加入无作用装饰工具按钮。

流式默认开，移入“会话资料→会话设置”的开关，解释“收到内容时逐步显示”；关闭解释“完整回复后显示”。不是每次发言都需选择的聊天操作；设置持久化范围/旧会话默认值在工程门确认。正在输入、停止、失败重试保留，但临时文本不伪装为已保存消息。

候选快捷键：角色页默认Enter发送、Shift+Enter换行，兼容Ctrl+Enter发送；中文IME合成中Enter仅确认候选，不发送。长文本用户可在会话设置切回Enter换行/Ctrl+Enter发送。故事和工坊暂不跟着修改。键盘、触屏、忙碌/失败、跨页后台接收及小屏抽屉均需验收。

双表现不是两种引擎：即时聊天以角色发来的消息为主；情景扮演允许动作/环境旁白，但不替玩家行动。候选用两个带一行说明的选择卡替代下拉。切换只影响新回复，不改写历史、清空关系或重置记忆。

## 3. 创建开场（P1玩法）

用户确认：创建会话可编辑角色第一句话，默认留空。候选新增可展开文本框；可显式“使用角色卡开场”，但不自动填入。留空依然等待玩家先发言；填写则创建时直接显示，不额外请求LLM。只属于新会话，不回写全局角色卡，重开软件保留。

工程门必须区分作者预置开场与模型正式回合：独立ID、author_opening来源、预算、摘要/未读规则、撤回及重生成边界、旧会话缺字段兼容。开场可作为后续回应的语境，但不能当作真实玩家已经同意/行动的证据，不能凭预置文本生成关系或知识账本。不能简单伪造一轮用户/AI对话塞入turns；不得直接放宽现有ledger证据契约。

## 4. 可编辑行为/对话示例（P1核心）

用户确认：作者可描述“何种情景→角色如何行动/说话”，无需提炼抽象性格。候选原生角色卡提供可折叠“行为与对话示例”，自由文本一等支持；可辅助显示情景/行为/台词条目，但不要求每项全填，不自动推断精神内核。

复用I1独立示例语义及酒馆mes_example映射；是否增设行为字段或升级role_fields版本须工程门，不能无声给v1严格字段增键。源卡编辑只影响新会话，已有快照不追随；工坊同样支持独立修改与撤销，不因编辑一个示例把整张结构卡降级。

示例指导在相似情景下的倾向，不是动作脚本或每次复制的模板；人设与当下处境优先，不把样例当亲历，不制造用户动作、承诺、消息ID。沿用整字段预算裁剪，必须显示省略原因而不暴露私密内容。

## 5. 世界书与偏好（P1纠偏/P2核心接入）

世界书已接入；需要在UI解释真实触发范围。候选后续扩成“本次输入+有限近期双方正式消息”的匹配窗口，排除临时预览和未公开记录；不得直接遍历全历史造成关键词永久激活。先明确窗口、预算、权重和可观察命中报告，再复用故事条目选择逻辑，不新增LLM调用。创作者设定作为世界约束不意味着角色知道所有秘密；公开规则与角色知识范围的冲突须明确权限协议，现有全文书快照不是完美知情过滤器。中途换书/多书/自动捕获后置。

用户偏好尚未接入。候选会话设置提供“启用用户偏好卡”，默认策略待确认；复用已确认偏好、分类开关、敏感内容授权和长度预算的读取投影，按会话请求冻结快照，不把整份分析证据或推断档案塞进上下文。偏好影响话题/节奏/描写倾向，不能使所有角色趋同或无条件顺从；不得覆盖人设、知情范围、用户控制权与引擎约束。禁用后完全不拼接提示段。角色聊天自动分析偏好不随读取功能一起启用，另过证据/隐私/费用设计门。

## 6. 顺序、边界与验收

建议顺序：A通讯式交互/模式解释/快捷键（P1体验）→B预置开场与独立示例编辑（P1玩法/核心，先数据契约）→C世界书触发改进与偏好投影（P1/P2）→回M长期记忆设计。用户确认前这是建议，不自动启动开发或换包。

架构：表现设置/键盘在UI与会话设置层；资料示例在角色卡领域协调器；开场在会话模型与证据协议；世界书/偏好在纯上下文投影层。不要让CharacterWorkspace吸收所有业务，不新增每轮第二模型调用。未知用户文件保持不动。

验收分层：合成接口验证字段、预算、知识可见性、禁用零拼接、开场非玩家证据、新旧会话隔离及保存失败原子性；真实浏览器验证IME、Enter/Shift+Enter、模式说明、左右气泡、紧凑行、流式开关隐藏于设置、开场重载及宽窄屏；真实模型的角色独立性/示例模仿/偏好不顺从属于人工质量评价。无需重打包来证明只完成设计。
