## 玩家闭环与范围

- 故事右侧「世界书 → 本局」直接选择主世界书（卡片按钮，不用下拉框）。其他已启用书提供补充知识。
- 发现实际冲突时，正文采用主书；默认轻提示并停用本局次书的具体条目。详情显示来源、原因、适用范围，可恢复；高级选项可关闭自动停用或改为逐条人工确认。
- 不因题材不同认定冲突。同书的区域差异不自动停用；主书概述/公理可作为依据，但自动操作仅针对次书具体条目。
- 不扩展工坊融合、世界补全归属重构、玩家意图分类、群聊、角色存储。没有冲突信号不增加模型调用。

## 实现职责与数据

| 层 | 责任 |
| --- | --- |
| 提示词 | 在现有正文结算请求中，基于本次实际提供的书和条目，报告同一适用范围内互斥规则、双方原文证据及原因；不是额外审计调用 |
| Python 领域模块 | 为检索结果保留书/条目来源；校验本轮引用及原文证据、主次关系；保存本局冲突记录，投影停用状态 |
| 存档/API | `session_state.json` 中独立 `worldbook_collaboration`；沿用故事短事务锁与原子保存，不写全局资产、不物理删除条目 |
| UI | 同一世界书面板的主书选择、轻提示、折叠详情/逐条处理；显示模型判断不等于确定事实 |

书身份首版采用局内文件名（非显示名称）与条目 ID 的组合；内容指纹防止旧判断停用改写后的条目。检索 ID 使用带书来源的唯一引用，避免两本导入书中同名/同 ID 条目碰撞。文件改名或删除会使旧引用失效，不猜测匹配；主书失效时提示重新选择，不自动换主书。普通内容编辑不改变书身份。

旧存档没有配置时：只有一本启用书可推定为主书；多本不擅自确定优先级，保留原行为并提示选择。GET 不迁移或写文件。切换主书后旧冲突不再自动生效；全局原版不变。设置和人工恢复不随正文撤回丢失；自动冲突以 `capture_source.turn_identity` 绑定来源回合，撤回/重演后失效，不只比较回合数。

停用是读取时的覆盖，不改条目原有启用值；记录双方内容指纹。任一依据改动/删除/封存、主书切换、来源回合失效均不再停用。玩家恢复后同一对相同内容不反复停用。记录随存档生命周期删除。未确认记录不阻塞正文；人工确认只影响后续取材，不改写历史正文。详情由玩家主动打开，角落只显示数量，不泄露隐藏设定。

## 并发、失败和边界

- 模型输出一次在领域边界校验；引用不存在、证据不匹配或范围缺失的信号忽略并记录诊断，不让附属冲突信号导致整轮正文丢失。
- 正文保存失败/取消不提交冲突；配置修改与故事执行共用存档锁。API 使用版本摘要拒绝覆盖新状态。
- 提示词中声明只对本次提供资料判断；未检索条目无法检测，模型语义判断需要玩家反馈。不声称彻底解决世界观一致性。
- 单次最多处理少量冲突；不建设通用规则引擎、不增加常态审计调用、不添加题材关键词特判。
