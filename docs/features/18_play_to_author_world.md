# 边玩边创作：正文设定捕获、世界书演化与世界包提取

## 设计来源与目标

玩家最初提出“常识改变”题材，不是要求 AliveWorld 内置一个只服务该题材的玩法，而是把它作为世界书自动维护的压力测试：同一段长期世界规则会在正文中被建立、修改、撤销并再次触发。系统若能正确处理这一过程，就具备更普遍的“正文产生新设定后如何进入世界书”的能力。

最终目标是形成一条连续创作链：玩家只需建立一个小型世界观或空白故事即可开始游玩；故事中已经成立的新规则进入本局自动世界书；玩家与 AI 可以继续补充、修改、删除和演化设定；长期游玩后，再把稳定的世界书、角色卡、实体、文风和体验预设整理为可复用世界包。

这项能力暂称为 **边玩边创作（Play-to-Author）**。它不是每回合让 AI 随意改写整本世界书，也不等于把剧情摘要塞进世界书。

## 当前实现事实：v1.6.0-dev.9

### 2026-09-24 未发布进展：W1a 通用信号

- 默认正文协议改为 `world_change_events`；独立只读切片 `story.world_changes` 仅随捕获开关启用。最多8项，校验状态/操作/范围/时效枚举及摘要、证据长度；重复项去重。
- 正文提供的 confirmed 事件还必须含有能在本回合正文中逐字找到的证据。空数组、未确认事件或不匹配的证据不启动捕获，即使同时返回旧布尔值true或输入题材命令。
- 缺少新字段的旧开发者提示词仍使用旧布尔值/显式别名降级；这是兼容路径，不代表新协议需要固定关键词。详细捕获收到已校验事件后再次核对，并用通用现实层、范围、时效和事实状态指导整理。
- 维持现有add/update/retire条目提案；临时、恢复/暂停/到期和个体例外信号强制待确认，不伪称已经有精确历史恢复。没有新增自动发布权限。
- 确定性测试只证明结构与数据流、引用存在性，不能证明引用在语义上真的支持规则；分类质量仍需真实模型评测。
- 后续W1b必须解决正文存盘后才调度、源回合与目标修订检查、重掷与撤回竞态。完整修订账本、公理/概述提案和创作收件箱仍属于后续P1，不计入本切片完成。

以下为dev.9历史基线：

已经具备：

- 正文结算用通用字段 `worldbook_capture_needed` 标记本回合是否出现值得长期保存的世界规则；只有严格布尔值 `true` 才启动异步捕获模型。
- 捕获器读取玩家行动、已完成正文与目标世界书，可对**条目**提出 `add/update/retire`；修改和废止必须指向稳定条目 ID，并先进入待确认状态。
- 新故事没有世界书时会建立只属于存档的“本局自动设定”；玩家后来载入正式世界书后，正式世界书优先接收新捕获。
- `常识改变/恢复` 目前只是 Python 中的显式命令别名和专项测试适配器。普通回合不携带题材专属提示词；命中时才动态加入短约束。
- 普通世界书条目支持关键词、常驻标签和可选语义召回；待确认与待删除内容不进入正文。

尚未具备：

- 捕获器不能新增或修改概述、公理，只能操作条目。
- 没有完整的规则版本账本，无法天然知道一项规则“改变前是什么”；恢复主要依赖模型找到准确目标，不足以保证还原正确版本。
- AI 返回的关键词、标签和适用范围尚未经过面向召回质量的专门协议与确定性检查。
- 没有根据“进入尚未定义的新场景”主动提出设定演化的调度器。
- 没有把本局长期积累的资产清理、提取并交给世界包工坊的流程。

因此，dev.9 不是完整的通用边玩边创作系统，而是它的两个基础设施切片：**始终存在的本局写入目标**和**不污染普通提示词的按需命令适配器**。

## 三条输入路径必须分开

### 1. 正文事实捕获

适用于故事自然产生、且正文已经确认成立的长期事实，例如新法律正式颁布、魔法体系被证明具有稳定限制、学校长期采用新的制服制度。

- 触发者：正文结算模型的结构化信号。
- 可信度：正文已发生，但仍要判断是否长期、是否重复、是否属于世界书。
- 默认动作：低风险新增可按玩家设置自动写入；冲突、修改、废止、公理变更必须确认。
- 调用频率：事件驱动，不能每回合固定调用捕获模型。

### 2. 玩家主动创作指令

适用于玩家明确以作者身份补充或改变世界，例如“设定：该学校的女生制服上衣统一为半透明材质”。角色台词、谎言、愿望和普通行动不能自动获得作者权限。

- 触发者：明确的创作入口、轻量命令或跳出正文标记，而不是模型猜测玩家语气。
- 可信度：玩家意图是高可信创作证据；它是否已经在故事内生效，仍由正文与当前权限决定。
- 默认动作：生成可预览的结构化变更；涉及替换、删除、公理和大范围冲突时要求确认。
- 题材命令：`常识改变/恢复` 可以继续作为可选别名，但不能成为领域内核。它最终只应被翻译为通用的 `rule.add/rule.update/rule.restore` 意图。

### 3. 新场景设定演化

适用于玩家进入世界书覆盖不足的新区域、组织、文化或制度时，让工坊基于现有公理推导候选内容。

- 触发者：场景变化且检索覆盖不足，并满足冷却、预算和玩家开关；不能仅因“本回合很平静”就强行扩写。
- 可信度：这是创作建议，不是已经发生的客观事实。
- 默认动作：进入工坊收件箱或草稿，绝不直接进入正文上下文。
- 调用频率：低频、去重、可暂停；同一主题已有未处理提案时不重复请求。

三条路径共享世界书操作与版本内核，但使用不同的提示词、风险等级和发布权限。

## 最高优先级：通用世界观捕获提示词

正式捕获不能依赖 `常识改变`、`修改世界规则`、`言出法随` 等固定词。玩家可能用任何叙述表达同一件事，世界也可能通过法令、神迹、科技、集体认知、时间线重写或其他未知机制发生变化。专用检测只能作为快捷命令或测试入口，不能决定功能是否生效。

通用方案采用两层提示词，而不是把一份长说明永久塞给正文模型：

### 第一层：正文结算中的短判定协议

正文模型每回合只回答一个与题材无关的问题：**本回合是否确认产生了会在未来继续约束世界的新增、修改、暂停、恢复或终止事实？**

短协议要求区分：

- 已在正文中成立的事实，与尝试、愿望、谎言、传闻、梦境和假设；
- 世界规则，与单次事件、人物状态、临时物品位置和普通剧情结果；
- 客观规律、制度规范、群体认知、局部领域和个体能力造成的例外；
- 新增长期事实、修改已有事实、使规则暂时失效、恢复旧状态和规则自然到期。

它只返回短结构化信号和必要证据，不负责编辑世界书，也不包含任何题材示例列表。普通回合返回空事件，不启动额外模型。

建议输出契约：

```json
{
  "world_change_events": [
    {
      "summary": "本回合确认成立的变化",
      "fact_status": "confirmed | attempted | reported | uncertain",
      "change_kind": "add | update | suspend | restore | expire",
      "scope_hint": "global | region | organization | group | location | individual_exception",
      "time_hint": "persistent | until_condition | fixed_duration | uncertain",
      "evidence": "正文中确认其成立的简短依据"
    }
  ]
}
```

只有 `fact_status=confirmed` 且不是单次状态的事件进入第二层。Python 校验枚举、数量和证据，不能让模型仅凭强烈措辞强制写书。

建议常驻短提示词草案：

```text
【世界变化信号】
只报告本回合正文已经确认成立、并会继续影响未来场景理解或规则的世界事实变化。
变化可以来自自然演化、制度决定、能力、科技、灾难或任何世界内原因，不依赖固定关键词。
区分客观事实与尝试、愿望、对白、谎言、传闻、梦境、假设；区分长期或有持续期的世界规则与单次剧情结果、人物当前状态、物品位置。
若规则被新增、修改、暂停、恢复或终止，在 world_change_events 返回简短证据、范围和时间提示；否则返回空数组。不要为了产生设定而虚构变化。
```

### 第二层：按需调用的详细捕获协议

捕获模型只在第一层发现候选后运行。它读取当前有效世界书、相关历史修订、玩家行动和本回合正文，然后完成：

1. 判断变化属于条目、公理、概述建议，还是根本不应进入世界书；
2. 定位已有目标及冲突，不能伪造条目 ID；
3. 判断变化作用于客观现实、社会制度、群体认知、信息记忆或局部例外；
4. 判断适用范围、开始时间、结束条件、是否追溯性改写过去；
5. 生成克制的关键词主题簇和语义范围；
6. 返回新增、修改、暂停、恢复或到期提案及风险，不直接越过确认规则。

这份详细提示词可以很完整，因为它不是每回合常驻。它必须使用通用概念与反例测试，不把任何题材名称写成必要触发条件。

建议详细捕获系统提示词草案：

```text
你是通用世界观变更整理器。输入包括当前有效世界书、可选历史修订、玩家行动、已经完成的正文和正文模型报告的世界变化事件。

目标：只把正文已经确认成立、会跨越当前瞬间继续约束未来内容的世界事实整理为可审阅变更。变化的成因和题材不重要；不要依赖任何固定命令词。

依次判断：
1. 事实状态：confirmed 才能继续。尝试、愿望、角色对白、谎言、传闻、梦境、推测和失败结果不写入正式世界书。
2. 资料归属：法律、制度、社会规范、群体认知、自然规律、通用技术/魔法规则及有持续期的领域规则属于候选；单次动作、伤势、物品位置、角色计划、普通剧情摘要和幕后行动不属于世界书。
3. 现实层：区分客观现实、制度规范、群体认知、记忆/档案、传闻，不把“大家相信”自动写成“客观上真实”。
4. 范围与时间：判断全局、地区、组织、群体、地点或个体例外；判断持续、固定时长、直到条件或未知；判断是否追溯修改过去、记忆与档案。
5. 操作：新事实 add；替换已有事实 update；预计恢复但当前失效 suspend；不再有效 retire；回到某个历史修订 restore；持续期结束 expire。非 add 操作必须引用输入中真实存在的 target_id；不确定目标时返回 needs_review，不得猜造 ID。
6. 结构位置：有明确主题或场景的规则写 entry；几乎约束整个世界的底层规律才可提议 axiom；overview 只提出整理建议。axiom、overview、冲突覆盖、非 add 操作和不确定内容一律高风险待确认。
7. 召回：为 entry 生成 3-8 个克制的主题词，覆盖地点、制度、身份、活动或专用术语；不得使用过泛词凑数。重复或语义相同且未变化时不输出。

你只提出结构化变更，不直接发布，不删除历史，不改变未被本回合影响的设定。没有合格候选时返回空数组。
```

最终 JSON Schema 以 `WorldRuleChange` 领域契约为准，由 Python 校验；提示词不能自行扩大字段权限。

### 通用能力验收语料

同一协议至少要正确区分以下情况，避免只对某个关键词过拟合：

- 修仙最强者成功让某片天地从此禁止飞行；
- 最强者尝试修改规则但被世界意志阻止；
- 城邦通过并正式执行新的婚姻法律；
- 魔法在结界范围内让重力倒转，离开范围后失效；
- 群体开始相信一项从未发生的历史，但客观历史没有改变；
- 时间线被重写，所有人的记忆与档案一起变化；
- 角色撒谎称皇帝已经废法；
- 玩家只讨论一个“常识改变”题材；
- 某人短暂中毒、房门被炸毁或一件特殊道具出现。

测试目标不是让模型永不出错，而是证明它不依赖固定词、能输出可校验结构，并在不确定时进入提案而不是静默改写正式世界。

## 通用世界书变更模型

所有来源最终转换为统一的 `WorldRuleChange`，而不是在代码里继续增加题材判断：

```json
{
  "change_id": "稳定变更ID",
  "source": "story_capture | player_authoring | scene_evolution",
  "operation": "add | update | suspend | retire | restore | expire",
  "target_kind": "entry | axiom | overview",
  "target_id": "修改、废止或恢复时必填",
  "before_revision": "目标修改前的修订ID",
  "name": "可读名称",
  "content": "变更后的内容",
  "keys": ["学校", "校园", "校服", "女生校服", "学生", "上学"],
  "scope": "global | region | organization | group | location | individual_exception",
  "scope_detail": ["学校场景", "学生身份", "校服话题"],
  "reality_layer": "objective | institution | collective_belief | memory_record | rumor",
  "duration_mode": "persistent | until_condition | fixed_duration | uncertain",
  "effective_from": "故事时间、回合或条件",
  "effective_until": "可空的故事时间、时长或结束条件",
  "retroactive": false,
  "confidence": "high | medium | low",
  "risk": "low | high",
  "reason": "为什么属于长期世界设定",
  "source_turn_ids": [12],
  "status": "proposed | accepted | rejected | retired"
}
```

Python 负责 ID、目标存在性、修订匹配、重复检测、允许操作、原子写入和恢复；模型负责从自然语言理解候选内容、分类、关联词和冲突。模型不能自行伪造目标 ID，也不能绕过玩家确认门槛。

## 临时、永久、原始与当前必须是不同维度

“临时规则”也必须记录，否则它生效期间无法稳定约束后续正文；“永久规则”也不是永不可改，而是没有预设到期条件。每次变更至少分开记录：

- `validity`：当前是否生效；
- `duration_mode`：持续生效、固定时长、直到条件、未知；
- `effective_from` / `effective_until`：故事时间或条件；
- `scope`：全世界、地区、组织、群体、地点或个体例外；
- `reality_layer`：客观现实、制度规范、群体认知、记忆/档案、传闻；
- `retroactive`：只从现在起变化，还是连过去、记忆与记录一起重写；
- `base_revision`：改变前的稳定修订；
- `current_revision`：当前故事实际采用的修订。

例如修仙最强者修改世界规则时，不能根据“最强者”三个字判断永久性：

- “从此天地永远禁飞”且正文确认成功：`persistent`，直到未来再次被改变；
- “禁飞直到他离开此界”：`until_condition`；
- “一炷香内禁飞”：`fixed_duration`；
- 正文只说规则开始扭曲、没有说明持续多久：`uncertain`，先作为待确认或短期有效规则，后续再补充。

到期不物理删除规则，而是结束当前修订的有效期；这既保留因果历史，也允许回溯和再次恢复。

## 世界书提取时选择哪一个世界

提取不能只有“修改后”或“修改前”一个固定答案。世界包工坊应让创作者选择导出视图：

| 导出视图 | 用途 |
| --- | --- |
| 当前世界快照（默认） | 把玩家此刻正在游玩的有效设定制作成新世界 |
| 原始基线 | 从游戏最初世界出发，让新玩家重新经历变化 |
| 指定修订/时间点 | 制作某条分支或某个历史阶段 |
| 基线 + 演化规则 | 保留“谁能怎样改变世界”的机制，但不携带本次游玩形成的具体结果 |
| 当前快照 + 公开演化史 | 用于确实希望展示世界历史的创作者；默认关闭，需隐私与剧透检查 |

世界包默认不包含玩家原文、私人偏好和完整修订日志。若导出当前快照，规则内容可以保留，但来源存档名与回合号只保存在本机溯源中。这样同一存档可以分别提取“改变前世界”“改变后世界”和“允许重新演化的基础世界”。

## 每本世界书的可选捕获协议

通用提示词必须开箱可用，不能要求普通玩家或所有创作者先写协议。世界书可以额外提供高级 `capture_policy`，用于描述该世界特有的变更机制，例如：

- 哪些角色、神器或系统有权改变哪一层现实；
- 修改默认是局部还是全局、临时还是持续；
- 是否同时改写记忆、档案和历史；
- 哪些公理绝不能由正文自动修改；
- 世界专用术语、同义命令和恢复方式；
- 提取世界包时推荐使用基线还是当前快照。

首选结构化字段而不是一整段无限权限的自由提示词。高级自由说明只能追加给按需捕获/工坊模型，不能进入每回合正文，也不能覆盖系统的 ID 校验、确认、隐私和原子写入规则。

因此正确降级关系是：**通用协议负责绝大多数题材；世界书捕获协议补充特殊机制；固定词检测只提供便利，绝不作为唯一入口。**

## 条目、公理与概述的分流

- **条目**：有明确适用主题或场景的规则。大多数正文捕获进入这里。例如“该学校女生校服上衣为半透明材质”应成为社会制度/服饰条目，而不是世界公理。
- **公理**：几乎影响所有场景、难以由局部例外推翻的底层规律。它始终进入正文上下文，自动写入风险最高；任何新增、修改、恢复和删除都必须由玩家确认。
- **概述**：帮助理解世界整体方向的简明摘要，不承担精确触发。正文捕获不应频繁改写概述；由工坊在积累多个稳定变更后提出“重新整理概述”建议。

一个事实只因重要或题材强烈，不自动升格为公理。作用范围决定结构位置。

## 关键词与语义召回

捕获 AI 不应只复述玩家句子，还要给出能在未来自然召回该规则的主题簇。以制服规则为例，候选可包含“学校、校园、校服、女生校服、学生、上学”，但不能无限扩张到“衣服、女性、人类”等高噪声词。

写入前由 Python 执行：

1. 统一全半角、大小写和重复词；
2. 拒绝过短、过泛或与正文无关的关键词；
3. 合并已有同义主题，避免一条规则被拆成多个近似条目；
4. 保留 AI 给出的适用范围供语义检索和工坊检查；
5. 召回仍受当前行动、近期正文和上下文预算约束。

关键词负责强触发和无嵌入降级，语义检索负责“校园生活”与“上学”等非字面关联。二者都不能让已退休或待确认规则进入正文。

## 精确修改、删除与恢复

“恢复常识”不能被实现为按相似名称删除。每次接受变更时必须记录不可变的修订历史：目标 ID、变更前内容、变更后内容、来源回合和前一修订 ID。

- `update`：原条目身份不变，产生新修订。
- `suspend`：规则暂时不参与检索，但保留预期恢复条件。
- `retire`：当前修订停止参与检索，但历史不物理删除。
- `restore`：指向某个历史修订，生成一个新的当前修订；也可结束 suspend 后恢复其指定修订。它不是删除历史，也不是凭模型重新编写旧内容。
- `expire`：固定时长或结束条件已满足时关闭当前有效期，必须能追溯到产生该有效期的变更。
- 目标不唯一：显示候选差异并让玩家选择，不猜测批量操作。
- 回合撤回：是否连带撤销已经接受的世界书变更必须走同一修订账本；不能只恢复正文而留下未来世界规则。

这个设计既支持题材中的“改回去”，也支持普通游戏中的废法、制度改革、灾难后自然规律变化和创作者反复试验。

## 本局自动世界书的生命周期

- 创建：新故事没有启用世界书时自动建立；世界包已经提供主世界书时不额外创建空书。
- 所有者：当前存档。它随存档复制、迁移和删除，不进入全局个人资产。
- 可见性：在本局资源中正常显示、编辑和停用，明确标记“自动记录”。
- 写入目标：有明确主世界书时写入主书；否则写入自动书。多本启用世界书需要后续主书/参考书协议，不能永久依赖文件名排序。
- 内容：只保存稳定世界设定及变更修订，不保存普通剧情摘要、临时伤势、NPC 当前状态或幕后账本。
- 提取：玩家可从本局自动书创建全局世界书分支，来源存档与私人回合引用默认不随资产公开。

这里的“本局”表示归属范围，不表示内容会按回合自动过期。临时规则通过有效期或 `retire` 管理，不靠删除整个自动世界书管理。

## 从游玩资产到世界包

“边玩边创作”的最终产物不能一键原样公开，需要一个提取工坊：

1. 扫描本局自动世界书、已升格角色、实体、文风和体验设置；
2. 区分稳定资产、未确认提案、剧情专属状态和隐私内容；
3. 合并重复条目、检查冲突、补充触发词并整理概述；
4. 让玩家选择哪些角色/实体保留开局状态，哪些仅作为创作资料；
5. 克隆为新的全局资产，保留内部来源但默认移除存档名、回合原文和玩家偏好；
6. 交给现有世界包工坊选择资产、体验预设和起点，再执行依赖与隐私扫描。

同一份长期存档可以提取多个不同世界包分支；提取不能反向锁定或覆盖仍在游玩的存档。

## UI 最短路径

游戏模式不增加常驻复杂面板：

- 新建故事后自动书无需额外确认。
- 捕获到低风险新增时，以轻量消息或工坊小红点提示“新增 1 条设定”；玩家可稍后处理。
- 修改、删除、公理和冲突提案进入“创作收件箱”，不以系统弹窗打断正文。
- 玩家可从回合气泡或输入区使用“作为设定补充”快捷动作，避免记忆命令格式。
- 工坊模式集中展示待确认变更、版本差异、演化建议和提取世界包；游戏右栏只显示必要摘要。

建议提供三个自动化档位，但不能只用模糊名称控制未知行为：

| 档位 | 行为 |
| --- | --- |
| 关闭 | 不调用捕获/演化模型；玩家仍可手动送入工坊 |
| 保守（默认） | 只捕获正文明确成立的长期事实和显式玩家创作；不主动扩写新场景 |
| 协作创作 | 在保守模式上，低频提出新场景演化草稿；永不自动发布高风险内容 |

## Token、噪声与异步边界

- 正文结算保留一个短的通用判断字段，不增加独立的每回合分析线程。
- 捕获模型只在结构化信号或显式创作动作出现时调用。
- 场景演化使用独立任务路由、冷却和预算上限；同一场景覆盖充分时不调用。
- 捕获与演化都不能阻塞正文保存。失败只记录可重试任务，不影响本回合。
- 新规则在捕获完成前仍可从近期正文被下一回合看到；正式跨场景生效以世界书接受状态为准。

## 分阶段优先级

### P0：dev.9 已完成的基础

- 本局自动世界书；
- 条目 `add/update/retire` 安全提案；
- 题材命令按需注入而非常驻提示词；
- 普通回合零专项 token。

### P0：下一开发切片——通用捕获提示词与结构化信号

1. 用题材无关的 `world_change_events` 替代对固定命令的功能依赖；
2. 完成短结算判定提示词与按需详细捕获提示词；
3. 建立覆盖成功/失败、客观/认知、全局/局部、临时/持续、追溯/非追溯的评测语料；
4. Python 严格校验结构，普通回合不启动第二次请求；
5. 保留 `常识改变/恢复` 作为测试和快捷别名，但即使玩家不使用这些词也能捕获变化。

这是最高优先级。没有通用识别层，后续版本历史、自动演化和世界包提取都会建立在题材特例上。

### P1：通用变更、时间语义与精确恢复

1. 冻结 `WorldRuleChange`、时间/范围维度与不可变修订历史契约；
2. 让正文捕获、玩家主动创作和现有题材别名统一进入该契约；
3. 补齐关键词主题簇、重复/冲突检测和目标精确解析；
4. 实现真正的 `suspend/restore/expire`，退休而非物理删除；
5. 在工坊提供待确认收件箱和前后差异；
6. 公理/概述只先支持提案，不自动发布；
7. 提供可选的结构化世界书 `capture_policy`，没有它时仍使用通用默认协议。

### P2：场景驱动的世界书演化

- 检测新场景与设定覆盖缺口；
- 低频调用工坊模型生成候选，不写入正式世界；
- 冷却、去重、预算、失败重试和小红点；
- 玩家可以对某条灵感继续讨论、修改或丢弃。

### P2：游玩成果提取

- 本局自动世界书另存为全局世界书；
- NPC/实体/文风的候选提取与隐私清理；
- 一键送入现有世界包工坊，支持分支和多包输出。

### P3：多资产持续协同演化

- 世界设定改变后，自动提出受影响角色、实体和体验预设的迁移建议；
- 大规模依赖图、跨资产批量差异和世界版本分支；
- 不在缺少真实长期游玩证据时提前实现。

## 设计门与验收

进入 UI 与自动发布编码前仍需确认两个产品选择：玩家主动创作的默认入口形式，以及低风险新增是否默认自动接受。它们不阻塞 P0 通用提示词、结构化信号和评测语料先行实现。

P0/P1 验收至少覆盖：

1. 没有预建世界书也能捕获新规则；
2. 普通自然产生的新设定与题材命令走同一操作内核；
3. 制服规则能由学校、校服、校园、学生等合理主题召回，但不会在无关场景常驻；
4. 修改同一规则不会制造两条同时生效的冲突事实；
5. 恢复精确回到指定历史修订，其他相似规则不受影响；
6. 待确认、公理提案和已退休内容不进入正文；
7. 普通回合不增加题材专属提示词或固定模型调用；
8. 撤回、重启、存档迁移和异步失败不会损坏世界书。

真实模型还要人工观察：分类是否合理、关键词是否过宽、是否把剧情细节错误升格为世界设定，以及长期游玩后世界书是否更完整而不是更混乱。
