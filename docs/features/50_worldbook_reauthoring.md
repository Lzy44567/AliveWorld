# 50 世界书再创作整合阶段

2026-10-23，承接24确认的重写与工坊融合需求。dev.31完成；本轮按完整玩家流程交付dev.32，小步骤仅测试/提交，不分别打包。

## 玩家目标与产品边界

玩家可从工坊某一条目选择“请AI重写”，输入要求、讨论方案；也可选择同一资产范围的其他世界书作参考，比较差异并形成适配后的目标书。结果经过逐条/批量接受、撤销、发布，发布前原书不变。希望保留目标原本时先使用既有克隆入口。

融合是创作当前目标书，不是自动融合正在运行的整个故事。参考书永不被本功能改写，不自动停用故事中原书或条目。提示玩家不要将互斥原书与融合结果同时启用。跨书移动与回溯归属、自动替换冲突引用、世界包联动均后置。

## 分阶段实现

1. P1定向改写：草稿条目旁的小按钮选择稳定ID，中央显示目标并可清除。要求仍输入现有聊天框，不重复聊天引擎。定向期间只接受对该ID的update_entry操作，所有结果必须审阅，不能因“允许修改草稿”开关跳过确认；无关操作整轮不提交。原有效内容到发布才改变。
2. P1参考资料：工坊顶部折叠的“参考世界书”，卡片多选同范围书，最多3本；局内仅本存档目录，全局仅当前世界书目录，不跨故事自动读取。显示选择范围、内容字符数及会增加请求token的提示。用户保存选择时捕获快照，不随源书暗中变化；刷新快照需再次保存。清空立即停止后续取材。
3. P1参考创作：同一次工坊请求携带概述、公理、条目与来源标识，不带capture历史、聊天、账号或路径。总参考JSON不超过60000字符，超出明确拒绝，用户减少选择；不截断成貌似完整的书。指导模型区分兼容/冲突/范围差异/不确定，提出保留/适配理由，不宣称完整审计或已经改源书。不会后台收费检查。
4. P1连续审阅发布：快照与定向目标属于工坊会话，不进入发布的世界书。未发布重开保留；新发布轮次不自动延续参考授权或定向目标。使用既有会话锁、候选副本、保存后提交、发布源版本检查；读来源用已有文件短读锁。换资产或迟到请求不得串线。
5. 交付门：领域/HTTP/假模型实际请求与浏览器覆盖选择、重开、清空、定向不越界、审阅撤销、发布且源书不变；回归后一次升版打包发布及附件核对。

## 实现职责与优先级

独立reference模块负责允许目录的读取、快照和内容预算；workshop领域持久化与定向权限；Agent负责取材与创作提示；API只装配合法目录和会话事务；前端独立参考组件与定向操作复用现有store/API。不要把全部逻辑塞入正文或资产编辑器。

入口首版在工坊条目清单，不强行跨越有未保存内容的资产编辑弹窗。已有卡片/资产/历史不迁移。模型质量需人工阅读，不以假回复测试承诺文学或语义准确度。
