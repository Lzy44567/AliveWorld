# 按故事与工坊身份隔离的后台并发

状态：首版已实现并通过确定性浏览器验收（2026-09-12）。

## 玩家目标

玩家发出一个耗时请求后，可以切换到另一条故事或另一个工坊对象继续操作。第一个请求不因界面切换而取消，完成或失败后只更新它自己的对象，并在列表上留下状态。

这不是同一条故事的多人并行写作，也不承诺模型供应商允许无限并发。

## 所有权与一致性

- 故事任务键：后端使用规范化存档目录，前端使用后端 `session_id` 并维护存档名映射。
- 工坊任务键：`type + scope + story session + asset name` 对应一份前端上下文，后端最终以 `workshop_id` 锁定可变草稿。
- 不同键可以进入不同线程等待模型；同一键已有写操作时，后端立即返回 HTTP 409，不排队、不重入，也不让两个旧内存副本覆盖同一存档。
- 同一存档重复载入复用已有 `GameSession`。重命名会同步更新会话索引；克隆、重命名、删除在故事推演期间拒绝执行。
- 页面内切换不会取消 `fetch`。调用方在发起时捕获来源上下文，响应到达后按原 session/workshop 写回；只有来源仍是当前界面时才刷新局内资产或滚动位置。

## 前端状态

每个故事和工坊上下文独立保存：

- 当前消息、状态栏、快捷行动和未发送输入；
- `idle / running / completed / failed` 任务状态、任务种类和错误；
- 工坊草稿、聊天、历史、提案、待确认项、模式和输入。

存档卡与工坊资产卡显示“推演中/处理中、已完成、失败”；顶部在多个故事同时运行时显示额外任务数量。失败只污染来源任务，不会清空或标错其他故事。

## 设置自动保存

单局设置的延迟保存会在编辑时捕获 session 与设置快照，而不是定时器触发时读取“当前故事”。若该故事正在推演，保存会延后重试，从而避免把故事 A 的设置写到刚切换的故事 B。

## 重启边界

运行中的 HTTP 请求是进程内临时工作，不能跨应用退出恢复。已经提交到磁盘的结果仍可载入；若浏览器重载时后端仍在完成同一故事，载入返回 409 和明确提示，完成后再次载入即可获得已提交结果。首版不把未完成的模型连接序列化成可恢复作业。

## 验收证据

- 单元测试：相同键冲突、不同键同时进入、重复载入复用 session、故事路由 409 映射。
- Playwright：两个故事先后完成但响应各归其主；一个故事失败、另一个成功；两个工坊资产切换后各自收回回复；正文与工坊同时运行。
- 仍需在发布门执行完整 Python、前端构建和全部浏览器回归。
