# C4 多气泡与间隔送达：设计入口与停止门

2026-10-06。状态：需求与代码基准已核对，工程契约尚未冻结，未实现。
承接22m、22n、已完成22r；用户允许按阶段推进至设计或打包边界。本记录不把候选方案当作用户确认，也不将文档提交称为功能完成。

## 1. 玩家目标与已确认范围

角色聊天要接近微信/QQ：一次回应可以只有一个气泡，也可以有多个自然短消息，程序间隔显示。不是机械按标点拆句，更不是每个气泡调用一次模型。间隔可关闭，不强制所有角色采用短句网聊腔。玩家能在后续消息尚未送达时插话，不被整个表演队列阻塞。

主线是角色聊天，不是故事模式、插件平台或主动联系调度。C5主动联系依赖这里的送达底座，但不得顺手实施。权限仍按当前会话隔离，OOC保持当前回合说明，不能变为角色经历。

## 2. 真实源码基准与必要性

本地提交a5d202e；版本1.6.0-dev.19。C3历史验收Python630、Node116、Edge39；本轮仅核对源码与文档，没有重跑或新增运行验收。

- `core/character_chat/contract.py`：输出`reply`是单字符串，最多8000字符；`plan_turn`创建一条`ai_message`，一次提交全部账本操作和整轮inverse。
- `core/character_chat/models.py`：正式回合校验`user_message`/`ai_message`及整轮inverse，不能直接增加数组而保持旧校验不变。
- `core/character_chat/service.py`：最新预览及AI消息ID基于单条消息；撤回倒转整轮账本。当前`delivery=stream/non_stream`是传输方式，不是多消息送达状态。

因此前端拆分不能兑现“未送达内容不是经历”；也不能将完整候选回复先写入上下文，再只隐藏其后半部分。流式token是预览，不等于正式消息。

## 3. 冻结前必须闭合的约束

| 领域 | 必须明确的契约 | 不可采用的捷径 |
| --- | --- | --- |
| 身份/协议 | 新输出协议、存储版本、组ID、稳定气泡ID与顺序；旧v1/v2读取与旧pending恢复 | 给旧v2偷偷增加messages字段或猜分句迁移 |
| 生命周期 | 生成候选、待送达、已送达、取消/中断；第一条何时正式提交 | 把浏览器已显示等同服务端送达 |
| 插话 | 新玩家行动和送达竞争在同会话锁/CAS下排序；已送达保留，余下不再进入新请求 | 客户端先隐藏再异步取消，迟到timer复活旧队列 |
| 账本/高光 | 每个op依赖的气泡来源、提交时刻、supersede前置依赖、inverse与容量预留 | 仅检查引用ID后逐条执行，忽略操作之间的依赖 |
| 恢复 | 保存失败、丢响应、崩溃、重启、页面重载分别处理；服务端权威与幂等 | 页面每次打开重播或自行补送积压 |
| 撤回/重生成 | 整组作为操作单位，只逆转实际送达及已应用op；后续玩家已回应的组不可任意替换 | 把未送达草稿归档成正式经历 |
| 输入/输出预算 | 气泡数、总字符、间隔范围及关闭方式；原文召回按整条来源处理 | 增大硬容量或把每个气泡当额外免费回合 |
| UI/并发 | 会话设置入口、送达中提示、插话、取消、未读、后台切换；流式预览不重复最终气泡 | 前端定时器拥有唯一权威或依赖当前显示会话 |

此前1–6气泡/整组8000字符是候选参数，尚非冻结值。用户已确认的大方向不重复询问；可逆工程参数由契约设计论证。只有改变核心玩法/数据生命周期的取舍才需要用户选择。

## 4. 关键场景：A/B/C中途插话

模型一次生成A、B、C以及来源账本提议。A正式送达后，玩家在B之前发送X：

1. 以服务端同会话事务顺序确定B与X谁先发生，不能用浏览器看到的顺序裁决。
2. X接受后取消所有尚未送达项；A保留，B若已先提交也保留，C不再正式送达。
3. 只把实际送达内容放入下一次上下文、世界书匹配、来源索引与记忆取材。
4. 依赖取消消息的账本操作不可应用；已应用操作的逆操作必须准确。跨操作依赖不能被部分应用破坏。
5. 正常回复失败不得恢复旧队列；重启也不补发。保存失败不能让UI宣布已送达。

这是C4的核心验收，不是更漂亮的气泡动画。

## 6. 验收清单与停止边界

假模型一次调用产生多气泡；1条/最大条数/超长/坏协议；流式不产生提前经历；开关间隔不改正式内容；A/B/C插话两种锁顺序；重复送达事件；切换会话；丢响应/保存失败/崩溃；重新加载不重播；撤回和重生成准确逆转；OOC不入经历；未送达不入记忆/世界书/召回；旧v1/v2/pending无猜测迁移；未知新版本拒写。

本轮到达设计边界：只完成入口核对与本记录，不开发C4、不宣称聊天基本完成、不打包、不新增付费调用。下一可验证产物是C4-D的完整冻结工程契约，而不是C5或界面延时原型。
