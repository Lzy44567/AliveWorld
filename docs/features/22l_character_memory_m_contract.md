## 1. 目的、确认与保守范围

最终功能目的：角色在合适话题自然想起共同经历，持续尊重明确偏好/边界，能解释承诺和关系变化；玩家能知道记忆从何而来，纠正错误，而不用管理每轮摘要。记住承诺不等于必须履约，仍受人设、立场及情境约束。

用户已确认稳定陪伴优先、不故意制造遗忘；自动高光与非阻塞通知，可标重要、撤销和纠错；重要喜好、边界、承诺及关系转折优先保护。最新授权允许Astra补齐设计并推进开发，覆盖本M1工程片；22k较早的“仅讨论/不编码”描述是历史，不抹去其中尚未冻结的产品机制。

本片采用保守范围：**当前会话内，该角色对当前扮演者的有来源认知**。这不是用户明确选择了所有侧写细节，不自动等同真实玩家属性。全局实际用户档案、跨角色学习/共享、私聊写回偏好库后置；C2只读授权边界不变。人格演变、故意遗忘、离线心理模拟不进入M1。

优先级：

- P1核心：来源/权限/撤回正确；旧话题有效召回；明确重要项可保护；纠错可用且不会篡改原文；容量和省略可解释。
- P1后续主线：自动高光及其撤销/修正、明确偏好/边界结构化保护。用户已确认产品方向，但字段和提取机制须M2门，不能因M1完成称已交付。
- P2：情境/例外更细的局内认知索引、原文检索及分段归档扩容；真实语义效果与容量证据可提升优先级。
- P2/独立授权门：真实玩家全局侧写；P3：复杂心理模型、跨角色共享。写实淡化是以后可选策略，不作为容量清理借口。

## 2. 实际基线与不作出的承诺

已核对`core/character_chat/models.py`、`contract.py`、`context.py`及`service.py`动作路径：

- 单文件32MiB；最多512个当前正式回合、2048个actions（requests）、4096个attempts；归档回合仍占文件空间。
- ledger总2048条、active最多128条；每条content最多400字符、来源1至2条消息、引文每条最多240字符；每次模型最多6个ops。
- 当前最多20个近期完整回合和32个ledger项，intent最多8；统一token预算还能继续整条裁剪。128不是可无限复用的池，supersede会增加总条数，现无自动容量回收。
- reply.v1严格为`reply`和`ledger_ops`；ops只有add/supersede。五种kind仍为knowledge/belief/experience/intent/relationship，不能偷偷加入highlight或preference。
- 当前允许新账本引用的历史消息只来自**最终投影的history**，外加本次正式user/reply；ledger内旧引文不自动扩张该集合。dialogue_event仍只能引用本回合双方消息。

M1不是无限长记忆，不是全部原文每轮常驻，不解锁512回合以上续聊。到达限额沿用安全失败并明确说明限制；不删原文、不丢正式回合、不偷偷缩写账本来换取继续发送。已保存的原文在会话存续期间不被本片改写，但“永久保留”不等于无限容量或备份保证。

## 3. M1最小可验证切片（已冻结，可实施）

玩家路径：角色会话→正常聊天→右侧“共同经历/记忆”中看到公开账本、来源类型及可用引文→标为重要→远离近期20回合后重提旧话题→本次取材说明能解释该项是否被送入。取消重要标记立即恢复普通优先级。无需首次配置，不新增模型调用。

M1包含：确定性可测试的中英文相关取材；当前会话持久化的重要标记；公开来源查看；非剧透的本次记忆取材报告；纠错草稿入口及既有末轮撤回/重生成联动。**不包含**自动高光新字段、自动扫描全历史、原文额外召回、摘要合并、隐性全局画像。只增加后端工具而没有这条UI路径，不算M1完成。

### 3.1 所有权、来源和权限

- 单一session_id和AI instance_id拥有局内ledger；同卡多会话绝不共享。卡片快照/作者开场/示例/世界资料/C2偏好是各自类型的上下文，不是共同经历证据。
- 先过滤active、主体正确、AI可见且created_turn_id仍在当前正式turns；引用非author来源还须可追到当前正式消息，不把archived_turn、失败preview、取消attempt纳入召回。
- player_statement是“玩家/扮演者明确说过”，不是世界绝对事实；model_inference仍为信念/意图/关系解释。标重要仅改变取材优先级，不升级来源可信度、不改变visibility。
- M1标记入口只接受对双方公开的active账本；私有记录仍走现有显式剧透路径，不允许公共标记接口探测私有ID。私有AI可见记忆照常可用于模型，但公开报告不返回其ID、文本、关键词、条数或被省略信息。
- 来源查看优先显示已经校验的短引文和来源标签；必要时用独立只读白名单投影查询该entry引用的当前正式消息。验证entry公开且source/消息当前有效后才返回，最多2条；不是通用任意message_id读取接口。不得将整个session/archived_turn/ledger_inverse回传浏览器。
- M1不扩展`allowed_messages`：取材报告和来源查看不成为LLM证据。模型要纠正旧账本可引用当前玩家纠正消息并supersede已投影目标；不能用旧引文再造dialogue_event。以非法旧来源生成op继续整轮拒绝，不能静默删除坏op后提交正文。

### 3.2 重要标记的持久化与兼容

建议在会话`extensions.character_memory`保存严格版本化、可选的对象：`{version: 1, important_entry_ids: [UUID, ...]}`。这是M1冻结的数据语义；具体API路由命名可按项目习惯。只允许这两个键、整数版本1、去重合法UUID；最多8个标记根。缺失等价空集合，读取不补写，不重写旧会话、角色快照或ledger。继续遵守extensions整体32KiB限制。

选择8是可逆工程预算，不是心理学参数。第9条不静默挤掉旧标记，UI提示先取消一条。标记不新增ledger条目、不占模型ops、不伪装成玩家曾说过；只保存ID，不存文本副本。写接口接受`expected_revision`、`entry_id`、布尔`important`，采用显式设值而不是toggle；白名单、类型、目标权限、CAS和pending busy先校验，成功原子写且revision增加1。相同状态可无变化返回；过期修订先冲突，客户端重载核对，不盲目重试翻转。

标记根必须在写入时指向当前公开active条目。之后不靠复制metadata修改原ledger：从active entry沿`supersedes_entry_id`回溯到已标根，决定有效重要性；只允许同会话、同subject、同kind/about的合法链，有界遍历、循环拒绝。**不自动增加新的标记根**。新版条目可继续受保护，旧事实不会重新active；保护链若转为私有，公开UI不泄露后继，模型保护仍不改变权限。

撤回创建该根的回合后，根ID可作为失效用户标记保留但不产生召回；撤回supersede后原active项恢复，原标记自然恢复，不需改ledger_inverse。界面给公开且安全的“已失效，可取消”状态及取消入口；总计仍最多8，玩家可以释放槽位。删除session按现有墓碑流程清除全部标记，不能孤立残留到全局设置。

未知memory.version拒绝相关写入/生成并给可理解兼容错误，不抹掉扩展，不默认当空。损坏对象失败关闭；其它未知extensions保持原样。旧二进制可能忽略新扩展，不能承诺降级版仍执行保护；文档注明保护需M1源码版，旧dev.19包不修改。无需整批迁移，首次显式标记才建立该扩展。

### 3.3 取材、排序与budget

输入仍仅本次pending.content，不扫描全会话寻找新事实。候选最多128条active账本。稳定排序按：有效玩家保护优先→相关性降序→created_turn在正式历史中的次序降序→entry_id稳定破同分。

相关性用归一化casefold/NFKC的确定性词法：英文/数字完整token；中文连续文本拆相邻双字词；输入单位去重且最多128个。一个单位重复出现不反复加分；长度1的汉字不单独计分。规则与边界放纯函数测试，不宣称同义/指代或语义理解已解决；未来语义检索必须另有费用与权限门。

最多32条仍含最多8条intent。重要项先占对应名额，其余按相关性和新近填充；只改变顺序，不增加硬限额。不得通过把所有knowledge机械标重要或关键词“爱/恨”命中来宣称自动保护了所有偏好边界。M1手动保护补足可控性，自动语义分类属M2。

统一预算仍先裁可选C2偏好、世界普通条目、对白示例，再裁至至少两个近期完整回合，再从ledger低优先尾部整条裁剪。重要项尽量最后裁，但不是不可裁：若token预算仍不足，可省略并明确报告；必需部分仍超限则CONTEXT_LIMIT、零provider调用。不截引文、不留下半个消息/半条来源，也不降低安全规则来保记忆。实际projected_entry_ids、history允许证据集、报告必须来自最终裁剪结果，同一个冻结request。

公开报告只对本次候选中的公开项返回安全的entry_id、枚举原因（玩家重要/话题相关/近期补充）、是否实际入选/因预算省略；不含原文、私有聚合数、排名分值、绝对“模型已记住”结论。普通容量未选可概括为“本次未取用”，不等于删除。所有文本字段限长、ID与枚举白名单；可采用C1现有请求报告传输方式，但不能复制私有原始budget_report到前端。重载无报告显示“尚无本次取材信息”，不伪造持久成功记录。

### 3.4 纠错、撤销和竞态

- 点击“纠正这条记忆”只将玩家可编辑的纠正草稿放入输入框，例如“关于……，我要更正：”；不得自动发送，不覆盖未发送草稿，冲突时让玩家选择/复制。重要标记不是正确性确认。
- 玩家发送后是正常正式回合，模型按现有op执行有来源supersede；当前纠正来源优先于旧结论，提示词要求不要把相互矛盾条目都当当前事实。仅生成回复没有supersede不标“纠错成功”，UI仍显示实际ledger。此处模型语义成功需要真实体验验收，不以按钮点击替代。
- M1不提供无来源的文本直改/删除ledger，不承诺一键语义修复；自动高光的“撤销选取”和“纠正内容”在M2分别建模。M1已有取消重要标记，错误最近回合可用既有撤回/重生成。
- 请求开始时冻结重要设置/取材；pending期间标记写与其它变更一样返回SESSION_BUSY。显式retry/regenerate按当前会话重新组装上下文，重生成先在副本上撤旧回合，旧来源不可继续命中。生成失败不改变原回合、ledger或标记；成功通过同一原子事务替换。
- CAS冲突、持久化失败、丢响应均保持服务端权威。前端不提前显示成功、不跨session应用迟到响应；切换、删除或新request清除旧报告，流式/非流式共用同一取材数据。任何来源缺失默认不召回，不借恢复扫描读取真实其它会话。

## 4. AI与确定性代码职责

AI：在既有一次reply调用中组织自然回复、提出有来源ledger变化；保持自身立场、陈述/推断差异。提示词可说明优先尊重当前明确纠正与标记取材，不增加reply.v1字段。不把高情绪分数当事实，不生成绝对用户心理诊断。

代码：身份、可见性、合法来源、引文子串、正式状态、版本、上限、排序、请求冻结、CAS、撤回/重生成、报告白名单及标记生命周期。引文校验只证明出处存在，不能证明自然语言蕴含；不宣称程序已经证明模型总结正确。M1无额外每轮分析调用、无后台任务、无向量服务、无全知故事摘要复制。

## 5. M1验收与停止门

使用隔离合成会话和假供应商，禁止读取玩家私聊。至少覆盖：

1. 超过20回合、超过32个候选的旧公开偏好/承诺，中文和英文重提正确排序；8个标记、取消、第9个拒绝、重载一致。
2. supersede继承保护但旧内容不active；撤回恢复前项；撤根失效；重生成成功/失败、取消、重试不借旧来源；循环/非法链不扩大权限。
3. 私有项、作者开场、示例、C2偏好、跨会话ID、archived消息无法从公开接口/报告泄露或成为新合法证据；未知版本、坏扩展、旧会话读不写。
4. 低预算真正裁剪后IDs/允许消息/报告一致，重要被裁可见；极低预算零调用；32/8/128/2048及512/4096/32MiB限制不变。
5. CAS/busy、atomic replace失败、迟到响应、会话切换、恢复和删除；标记设值的丢响应核对，不出现双toggle。
6. 真UI公开经历→来源→标重要→重载→旧话题新请求→取材报告→取消；纠正保留草稿且明确发送；宽窄布局、键盘/流式回归。工程测试只证明被发送/事务，不证明“被在乎感”。

实施保持模块边界：独立纯记忆策略/设置验证模块；context负责拼装，service负责事务，API负责白名单，前端api/store/面板分离。不要把全部规则塞入路由或大组件。更新ACTIVE/VERSION_ROADMAP/DECISIONS/CHANGELOG/TESTING记录实际验证；不改版本、不重打dev.19、不新增发布。

M1所有上述玩家路径及P0/P1守卫完成后停止本片，报告“有界账本取材与玩家保护已实现”，不报告完整长期记忆完成。下一片按下节设计门推进，不用无止境UI润色替代M2。

## 6. 后续slices和未冻结部分

**M2 自动高光与明确重要项保护**：复用一次回复的提议，AI提出离散原因（明确边界/承诺/关系转折等）、来源、角色意义；程序校验、去重和分档，非阻塞通知并允许取消选取/纠正。情绪波动仅辅助信号，不采用“97分真实情绪”。需要先冻结highlight与player_statement区别、纠错版本链、取消语义、通知去重及保护容量；不让重复重生成累计为独立证据。若加严格JSON字段必须注册reply.v2/新版提示词及对应解析器，按请求固定协议，保留v1会话/测试路径；不能直接给v1增加可选未知键，也不能自动把旧普通ledger迁成高光。具体阈值与分类结构尚未冻结。

**M3 有界原文召回与情境认知**：若需要旧消息的新证据用途，明确新增独立`recalled_sources`投影、消息/字符/token上限及最终裁剪后同步允许证据集；只从当前正式、权限允许原文取材。继续保留dialogue_event仅本回合规则，若改变需独立协议门；旧source引文不是任意消息访问权。局内喜欢/讨厌/情境/例外/当前或被纠正索引从可追溯来源派生，可重建，不复制第二份权威自由文本。不默认为真实玩家画像。

**M4 容量与长期档案**：512/2048/4096/32MiB、active128的解除需要完整原文归档、工作集/索引分离、恢复/删除/撤回/重生成事务、版本化迁移与备份验收；不只是提高常量或删除旧actions。总结是有来源、角色可知、可废弃重建的派生物，不是故事全知摘要。触发阈值、异步与费用尚未冻结；无新增调用默许。若M1实际限额先阻塞常用玩法，优先把本门前移，不能假装已支持长年无限聊天。

剩余真实模型质量验收：旧话题自然重提、偏好变化、安静重要边界、承诺冲突、误会修正及不确定表达；用户可在现有包/后续获准包人工验证。付费模型评测、桌面EXE打包以及远程交付均需对应授权，自动化通过不替代这部分证据。
