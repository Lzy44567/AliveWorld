# 57 故事回溯与重演：交付规划

2026-10-28，状态：范围规划与实现核对，尚未完成功能。承接15/32及用户继续开发授权，56已发布不重开。

## A段核对与第一项实现

- 普通快照与失败事务检查点不同：前者保存状态、聊天、上下文、故事回合、暗流、建议、人物元数据；后者还保存偏好、设置、待捕获任务等。不能把二者当同一种完整时间线。
- 捕获来源使用core/capture_source.py的turn_identity（回合号、行动、正文、消息ID摘要），source_is_current读取已保存的session_state验证，不是仅凭回合数字。后续继续复用此边界。
- 已补is_game_over进普通快照及存档，撤回恢复旧状态；旧快照没有此字段时恢复为可继续回合，空撤回不改变状态。失败事务仍恢复其原始终局标记。此为状态完整性补齐，不宣称已复现玩家实际终局故障。
- 4项新回归和9项故事设置测试通过（13合计）。旧尝试档案、重演UI、任意分支仍未实现；不打包独立发布此内部修复。

## 玩家目标

撤回后能查看一次或多次旧尝试，选择作为再次行动的参考；旧尝试不冒充正式历史。重演保留原起点及未变条件，新行动影响的结果重新判断，不锁死旧成功或失败。不承诺任意模型逐字复现。

## 先核实再冻结的数据边界

1. 现有GameSession快照包含哪些内存状态，哪些世界书/实体/记忆仍由独立文件持有；失败恢复和撤回是否同一事务。
2. 使用稳定起点身份关联旧尝试，不仅用会重复的回合数字；回溯后的后台捕获不得迟到写入新路径。
3. 原文存储与请求预算分离，完整保存不等于全部常驻上下文。默认旧尝试不进入模型，用户显式选择后才作为非正式参考。
4. 删除故事时随之删除档案，删除单条档案不修改正式故事；导出/分享不得隐式带上废弃尝试或私人信息。

## 交付顺序

- A：核对快照/持久化/后台任务，补齐最小工程方案和验收场景。
- B：旧尝试档案、稳定起点、列出/读取/删除API；复用故事锁，不造通用数据库框架。
- C：撤回保留、选择旧尝试、修改行动重演；提示词独立标注非正式资料，正式记忆/捕获不得读取旧尝试作为事实。
- D：重启、连续撤回、失败重试、并发迟到、不同故事隔离、假模型真HTTP与浏览器验证；完成整个已冻结范围后统一打包，不单独发布档案工具。

任意历史节点分支、无请求原样回放、完整随机参数配对是同一板块后续能力，但当前尚不能宣称工程契约冻结。A完成后明确哪些可纳入同一发布，涉及用户体验取舍才集中询问，不暗中缩减为一个撤回按钮。

## 实现责任

Python负责身份、存储、恢复、任务归属与预算；LLM负责依据新行动重新判断，不能自行将旧尝试变为正式事实。UI负责用户选择和状态说明。不新增默认逐回合分析调用。
