# M：角色长期记忆的产品讨论（未冻结）

日期2026-10-05；基准C2提交d9b3d4a。只讨论、记录，不授权运行代码、版本、打包或远程动作。承接22c/22d的来源记忆方向，不将本文件当作完整工程契约。

## 已确认的产品选择（2026-10-05追加）

用户已逐项确认：首版稳定陪伴优先，不故意制造遗忘，写实淡化作为后续可选；高光AI自动挑选、非阻塞通知，玩家可标重要/撤销/纠错，不要求逐条确认；明确的重要喜好、边界、承诺及关系转折优先保护，普通闲聊可不主动召回。这是产品方向确认，不代表摘要触发、评分或存储协议已冻结，也不是开始编码的指令。

用户新方向：情绪重大波动可作为高光候选信号；提出更细致的“用户侧写”，记录喜欢与讨厌，作为用户偏好卡的扩展。具体适用身份和自动学习授权尚未确认。

## 用户本轮提出的方向

- 最终目标是角色“活人感”，可探索模糊、遗忘与总结偏差的表现价值；不是要求立刻实现随机记错。
- RPG对世界实际事件/后果的一致性要求更强；个人记忆与世界事实不应混为一个权威。
- 需要考虑“高光”经历，某些事件及体验能长期清楚记住。
- 陪伴可能更重视被在乎、关键喜好被记住，而不一定需要写实遗忘。“用户普遍更想要完美伴侣”属于待验证的产品假设，不作为人群事实或心理学结论。

## 建议的核心卖点与玩家循环（候选）

角色不仅复述聊天，而是能在合适时机自然想起共同经历、兑现或解释承诺、记住玩家明确表达的重要偏好，同时仍有自身性格与立场。

循环：正常聊天→后台形成有来源的记忆→相关话题或关系节点自然调用→玩家可查看、标为重要、纠正或移除。无需管理每条记忆，不每轮弹确认；主动关怀是体验目标，不等于频繁提旧事。

## 建议分工

1. **来源档案/世界事实**：保留正式原文与回合身份，不为了表现遗忘而改写或删掉证据。RPG的客观后果由世界状态与来源档案维护；NPC个人可以不知道、误解，但不得倒过来修改世界事实。
2. **角色个人记忆**：记录它知道的陈述、共同经历、信念、关系意义和承诺，保留来源与可见性。摘要或检索可以省略细节，不能悄悄把推断升级成已发生事实。
3. **回忆表现**：根据相关性与重要性分配预算，普通细节可不主动想起；证据不足可以说不确定，而不是补造细节。是否模拟遗忘、采用何种默认仍待用户选择。

不建议直接依赖模型注意力稀释或随机摘要偏差：程序不能保证只模糊无关细节而保留重要边界，也难重现和纠错。应把“取材不足”“允许的表现性淡化”“摘要错误”分开评估。原文保留不保证每轮都能全部送给模型，更不能承诺永不忘记。

## 高光、稳定事实与偏好的区别（候选）

- 高光同时包含来源事实、角色当时的体验/意义和关系影响；如首次建立信任、重要冲突修复、共同承诺。意义属于角色解释，不是客观世界真相，不以露骨程度或情绪强词自动判重要。
- 玩家可将某段标为“重要”；AI可以自动挑选，但不能把每件事都升级为永恒高光，也不能自动制造对等情感。永久存储不等于永远常驻全文，优先保护核心并按需检索细节。
- 玩家明确说出的重要喜好/边界作为有来源的局内陈述，与“AI推测玩家喜欢什么”分开。角色记得某个承诺，不等于必须履行；履行与否仍受人设/处境约束，并保持连续解释。
- 全局用户偏好卡是授权的体验指导；不能默认把它灌成角色“我知道你”的私人知识。玩家扮演者与实际用户也不自动等同。当前C2不分析私聊，本轮讨论不撤销该边界。
- 用户后续纠正喜好应保留变化来源，不沿用过时结论压过新声明。撤回/重生成/删除使相关来源与派生记忆失效；跨会话共享需单独授权，不能凭同一张角色卡自动共享私聊。

## 高光识别：工程候选，不是人类情绪量表

高光重要性与来源可信度必须分开。角色显著情绪变化是辅助信号，不能证明事件真实、用户同意或双方关系已经改变。Talarico与Rubin（2003）的54名参与者研究中，闪光灯记忆的一致性并未比日常记忆更稳定，鲜明度与准确性信念却保持较高；这提示不能把“强烈/确信”当作准确性的替代。它不提供游戏权重，也不能概括全部情绪记忆。[原论文摘要](https://www.psychologicalscience.org/journals/psychological-science/1467-9280.02453/)

候选采用离散信号与可解释等级，不直接让模型给“情绪97分”或“高光概率90%”：

- 优先保护：玩家明确标重要、明确重要边界/承诺。表达平淡也可重要；保护取材优先级不改变事实判定。
- 自动高光候选：有来源的关系/目标重大转折，加上显著情绪变化、超出角色预期、双方后续自主重提等辅助信号。安静建立信任也可以重要，不只有激烈场面。
- 普通或待观察：仅有强烈修辞、感叹号、露骨内容、模型自称激动或同一事件反复生成。模型复述不能累计成多条独立用户证据。
- 模型提议原因类型、角色意义及来源引用；程序验证来源存在、可见性、引文、重复事件/撤回失效，再按透明规则分档。代码验证引用不等于理解并证明其语义，错误关联仍需玩家可纠正。
- 首版拟用普通/重要/高光/玩家保护等级。具体升级阈值、情绪标签和权重待合成案例校准；不是已经科学验证的心理参数。暂不每回合加独立情绪分析调用，提取时机/协议另过工程门。
- 高光级别只影响保存/取材优先级，不要求角色每次提起，更不强制原文全文常驻；主观意义和确证事实各自保留。

## 用户侧写：细化偏好，而不是新增绝对心理定论

建议基于现有来源记录与偏好库做结构化索引，不再另建一份与二者竞争的自由文本“真相”。条目可包含喜欢/讨厌的对象、适用场景、例外/边界、明确声明或推断、来源回合、当前/被纠正状态；未确认推断不升级为已知事实，不用人格诊断标签。

例如“喜欢甜食，但睡前不想吃太甜”不能只总结成“喜欢甜食”；实际游戏游玩选择也不能直接推断真实生活喜好。上下文只取当前相关条目，不把详细档案每次整份发送。

建议分两个隔离范围（产品选择待答复）：

1. **会话内认知档案**：角色通过当前聊天知道的、关于当前聊天对象/扮演身份的信息。来自明确声明的陈述可自然生效，纠正保留来源；不能跨角色共享，也不自动证明真实用户属性。
2. **全局用户偏好扩展**：真实玩家的体验偏好，可跨模式/角色参考，但须明确授权；角色表演语言不直接写入。沿用敏感分类和候选确认，不自动将全局档案变成所有角色知道的秘密。

同一声明可经授权产生关联索引，但身份、授权、生命周期必须独立。当前C2只是读取，仍不分析私聊；本轮新灵感不默默开启全局分析。侧写自动更新、详细心理推断、跨会话共享单独设计。建议先做会话内明确喜好/边界的连续记忆，全局深度侧写后置P2；待用户明确目标范围。

## 剩余讨论与设计门

三项产品方向已确认。下一需确定用户侧写先服务于当前角色对聊天对象的认知，还是跨角色的真实玩家偏好；这决定权限与纠错语义。之后冻结高光提取时机、规则级别、记忆检索/合并/预算与失败恢复，而不是从已确认的方向直接跳到编码。

选择后再冻结触发时机、费用、检索预算、模型与代码职责、原文引用校验、隐私与失败降级、迁移与验收。先测旧话题重提/偏好改变/承诺/误会纠正/撤回/无来源不编造；真实自然度与被在乎感单独评价，不以字符串命中或“记忆条数多”当体验证明。
