# 实体独立推演与工坊创作意图

日期：2026-10-12。产品设计讨论；不代表新增功能已实现。关联01活的世界、02因果账本、08工坊、24世界知识、28叙事设计。

## 用户本轮确认与重申

- 实体库的核心是模拟玩家视野外的世界变化，而非只给正文提供素材。推演根据实体拥有的信息、知识、能力、资源、性格、目的，保留依据和可追查来源。
- 使用故事时间和事件作为推演依据，这是旧方向的重申，不是本轮发明；现实等待和操作回合数不能直接冒充世界时间。
- 有持续计划、承诺、冲突的实体提前推演；普通离场人物可按需补全。特别普通路人的经历补全默认关闭，作为未来可选能力。
- 幕后可见性与编辑开关沿用既有设计；推演气泡默认关闭。用户确认可开关不等于授权把全部秘密默认送入正文或人物认知。
- 工坊先帮助玩家减少逐项构思和按格式填写的劳动，其次提供灵感。先问少量问题定位意图，再成组补全相关内容。
- 工坊不得默认把创意扩展为全面现实主义社会分析。用户所举创作经历用于说明类型、体验和推演重点错位，不作为特定题材硬编码提示词。

## 旧文档与本轮设计的关系

01已记载实体动机、资源相关状态、计划、近期行动、触发器、关系与后台推演；02已有中心因果账本、实体引用和来源死亡策略；08已有理解目标到草稿发布的流程。保留其历史实现说明，不把旧MVP限制当最终产品规则。02的“世界时间只保存文本、不计算”是历史实现边界，本轮没有验证代码是否变化。

## 实体账本优化候选：计划不是事实

沿用现有中心账本与实体关联，不另造重复存储体系。产品上区分：

1. 意图/计划：目标、拟采取的行动、起因、已知信息和错误信念、时间窗口与资源需求；不是必定兑现的未来。
2. 已执行的布置：实际投入的资源、已完成的准备、作用对象、触发/失效条件；与计划关联。
3. 已发生事实与持续后果：执行结果、时间地点、依据、影响与谁获知。实体相信的内容与世界事实分开。

实体可以改变主意、放弃、失败、等待或不行动。条件满足仅代表可以开始或进入结算，不自动意味着成功。世界规则、对手行动与资源约束共同决定结果；正文不为迎合玩家或制造冲突推翻已经成立的幕后事实。

例如组织计划次日收购物资→今日已付订金并安排车辆→次日因道路封闭未按时到货。三段信息分别记录，不能把“计划收购”直接当作市场必然缺货。

## 生命周期与因果传播候选

- 引用稳定实体/事件/计划ID而非名称，人物改名不新建人格；事实来源、故事时间和提交回合/分支分别保存，回合编号用于追踪与回溯，不充当世界时钟。
- 更新计划保留变更缘由，旧计划不是删除后失忆；来源死亡/资源丢失根据实际依赖判断，不一刀切清除：本人施法可能终止，已派出的信使可继续行动。
- “发生”与“被玩家发现”是不同节点。玩家不去现场也可能发生；未来接触时显示可感知的后果，不在发现时重复执行事件或扣资源。
- 长时间跳跃按重要时间点和依赖处理，不逐分钟调用。互相影响的事件按因果顺序结算，不能独立并行后强行拼成矛盾事实。具体调度后续设计。
- 保存长期记录不等于全部进入每次请求；推演读取当前相关状态、待处理计划和所需依据，正文只获得当前场景必要的信息，角色仅拥有自己的认知。
- 群聊中角色独立调用的决定，不自动扩展成所有后台实体各调用一次。后台批量推演沿用既有方向，后续按质量/预算设计；不静默扩大调用成本。

## 2026-10-13：实体卡与账本、玩家与角色知情边界

用户提出：全部写在实体卡虽直观，但实体消失后仍可生效的布置不应随卡消失；上帝视角下玩家可利用幕后消息指挥角色去现场，角色却不自动获得这些知识。

### 存储职责建议（未实现）

- 实体卡保存“这个实体现在是什么样”：身份、认知/信念、能力、资源、性格、目标及当前计划摘要。尚未付诸行动、没有跨实体影响的普通念头不必全建账本事件。
- 世界级因果账本保存需要跨实体、跨时间持续追踪的计划、已执行布置及后果。关联参与者而非归某张卡独占；来源ID用于追溯，不代表生命周期依赖。
- 已进入账本的计划/事件以账本为唯一完整记录；卡内显示关联摘要和入口，不独立维护第二份可冲突的计划正文。计划取消、执行和资源变动须对应同一次状态变化，防止双重执行。
- 死亡、退场、停用与删除不同：死亡/退场不是擦除身份与历史。后台停止该实体主动决策，已派出车队、信件等按实际依赖继续；仍需本人持续维持的影响则按规则终止。
- 用户显式删除实体时，区分“停止/移除这个实体”与“同时撤销其关联布置”；不得默认连带删除其他参与者或已发生事实。具体删除交互尚待设计，保留最小来源档案/名称快照是实现候选。
- UI不必让玩家来回维护两套表：实体详情可展示关联计划和影响；全局账本用于跨实体总览，底层分责不等于增加填写负担。

### 已确认的体验方向与执行建议

- 上帝视角改变玩家可见范围，不自动改变玩家角色的知识。玩家可以据此选择移动、等待、观察或偷听，不强制为每个行动补造角色早已知情的理由，也不因属于元信息就拒绝行动。
- 相遇由已经成立的路线、位置、故事时间和可感知条件决定。到达合适地点且时间重叠，可自然碰上；不为迎合玩家把车队传送到场或重置时间。
- 潜入商会偷听时，只能听到当时实际进行且能被听见的交流。派遣会议已经结束，就不能因为玩家来了而重演；可见到已有的后续安排或线索，也可能一无所获。
- 一旦角色真正观察/听见，才记录其获得的信息与来源。看到车队不等于知道秘密货物、真实目的或完整计划。
- GM为裁定场景可获得必要隐藏事实，但必须与“角色已知”分开；角色的叙述和其他NPC认知不能泄漏GM隐藏材料。上帝视角信息不混入角色对话历史充当亲历事实。
- 玩家直接把幕后秘密说出口时，保留其自主台词，视为角色的断言/猜测；不自动补造可靠来源或保证其他角色相信。显式修改世界/授权角色知情属于另一种操作，不能与普通行动混淆。

验收候选：同一幕后事件在开关上帝视角时世界事实一致；正确时空可相遇、迟到可错过；偷听不会重演旧会议；角色死亡不抹去已派出的车队；角色看到车辆后仍不自动知道秘密货物。

## 贝叶斯推理的表述边界

用户要的是依据角色条件判断行动倾向并随新信息更新，而不是任意百分比。候选方案先明确可行行动及证据，再给相对倾向；只有定义先验、证据与更新方式时才称严格贝叶斯。是否每次都随机抽样、如何校准尚未确认。实体行动倾向与行动成功率分开，不能用“他很想做”代替“他做得到”。

## 工坊：先对齐创作目标，再展开

候选最小创作简报：玩家想体验什么、偏好类型/基调、现实约束强度、重点展开与避免偏离的方向。已有输入能回答就不重复询问；意图模糊时先问少量关键问题，也可给少量方向供选择。玩家仍只需自然表达，不增加必填表单。

流程：读取想法和已有资产→澄清决定方向的问题→简短复述创作目标→提出少量不同方向→按选中方向批量起草相关条目→逐项/批量审阅修改→发布。复述不必单独增加一次LLM请求或强制确认弹窗。

区分创作指导与世界内事实：前者规定应该重点设计什么，后者规定世界中真实成立什么。用户此前已经认可公理可同时具有两种作用，允许兼有，但不得为了约束写作而把全部偏好伪装成自然法则。工坊读取两者，故事人物不自动知道作者的创作指导。

创作质量按“符合目标、内部一致、可游玩、少让玩家重复劳动”评估，而非条目越多越好或现实后果越全面越好。建议中有偏离创作方向但必要的规则冲突时，简明说明并给适配方案，不擅自换题材。创作指导遵守内容安全边界。

## 优先级与后续设计

- P1 核心设计：计划/布置/事实区分、时间与因果依赖、认知隔离、与正文权责；工坊创作意图对齐与批量起草审阅。
- P2 体验优化：账本默认简明时间线，展开看来源/变化；丰富工坊方案比较和小范围试演。
- P3 玩法扩展：普通路人离场经历补全，默认关闭；不作为当前完整世界设计的必需成本。
