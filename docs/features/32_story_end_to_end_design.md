# 故事模式：从开局到回溯的完整产品流程

日期：2026-10-13。状态：跨模块设计整合稿，未编码、未实测。已有用户决定沿用03、24–31；本文新增默认和交互均为候选。15时间线与06记忆中的“当前实现”是历史快照，本轮不视作已重新核验。

## 一、玩家看到的最短流程

选择/续玩故事 → 确认角色与开局 → 输入行动 → 看到推进中的正文 → 本回合保存 → 继续行动。世界维护默认后台进行；不要求玩家逐步点击未来、捕获、实体和记忆模块。

复杂性在需要时展开：本局配置决定可选机制；日志解释发生了什么；世界书、人物与账本允许查看修正；撤回和分支提供试错。默认界面不把所有内部阶段都呈现为操作按钮。

## 二、开局：玩家必须知道自己能从哪里开始

沿用29的三个候选路径：世界包提供作者开局；选择已有资产后自行写或请求起点建议；只有一句概述也能自由开始。辅助生成由用户触发，不打开窗口就收费。

开始前用一张摘要确认扮演对象、世界/知识书、开局地点或处境与重要可选机制。不存在的配置允许留空或由作者开局提供，不能把所有项都设成必填。剧情发展方向与世界概述分开，未接线字段不能假装生效。

新故事建立局内副本及自动世界书；故事专属修改不污染全局。系统“创建成功/如何操作”留在界面说明，不能作为故事事实保存。作者未来剧情节点、秘密身份、后台计划不能写成角色开局已经经历或知道的内容。

## 三、一个回合内，谁先做什么

| 阶段 | 玩家体验 | 责任与边界 |
|---|---|---|
| 接收行动 | 保留输入，显示正在处理；切换故事不取消任务 | 当前请求固定其所属故事/分支和起点，不能把结果送入后来切换的会话 |
| 整理当前场景 | 无关后台不阻塞；必要时短暂等待 | 读取已保存状态、角色所知、相关世界规则和已发生实体后果；新建档任务未完成不等于有未决世界事件 |
| 判定近期结果 | 按当前设置显示或隐藏候选，不要求玩家强制选择 | 若启用未来机制，在已有未来请求内提出可行方向及必要判定依据；Python按规则抽取，不另设默认骰子AI |
| 正文推进 | 流式开启时渐进显示内容，直到下次重要选择前停下 | GM落实已裁定结果并处理当前场景；不替玩家决定后续言行，不修改既成后台事实 |
| 回合保存 | 完成后可继续；失败有明确提示而不是假装成功 | 正文及必要世界状态一起成为正式回合，资源/节点/状态变化只应用一次 |
| 按需后台整理 | 默认轻提示，不强制确认每件事 | 捕获、补全、实体整理、压缩各按实际需要运行，不默认每轮全部调用 |

未启用未来机制时不偷偷执行它，普通结果由GM根据同样事实约束推进。未来关闭但单独启用程序骰子/属性判定的组合尚未完整设计：不得为了实现简单而默默强制打开未来；在可选规则方案中解决或明确首期组合限制。

## 四、事实、内容选择与呈现不可混为一谈

先遵守世界事实、角色能力和已成立的行动结果；再在可行空间内落实剧情节点、发展方向与偏好，最后以文风呈现。不是把所有提示词机械堆叠，也不由某个长文本标签获得无限优先权。

- 世界规则决定可行性；剧情节点需实际触发，固定结果仍受已确认前提约束。
- 发展方向决定长期重心，不让未来目标提前成为历史。
- 偏好影响合适内容的机会与重心，不修改物理胜率或人物核心人格。
- 文风改变表达，不偷改裁定。
- 候选未来与未执行计划不是历史；上帝视角信息也不是角色亲历。

例如：玩家求生故事中偏好轻松同伴互动，仍需解决资源问题；同行与休整可以增加交流，不能因为偏好而自动获得物资或提前觉醒能力。

## 五、后台补全与当前事实的衔接

### 新事实不能等整理完成才存在

正文已经确认某条通行规则或NPC承诺，该事实先随回合保存在可供后续取材的简短记录中。后台再将其整理到世界书/实体，不应导致“下一回合因还没写书而忘掉”。该简短记录是原事实的过渡引用，不是第二份独立设定；整理完成后转为正式记录引用。

后台补全只能扩展尚未确定的空间，不得反向改写正文已发生事实。例如正文已写“只有一条可走路线”，工坊不能事后无提示补出第二条路来解释刚才的结果。

### 不同工作分开触发

- 正文同请求报告少量维护信号，不要求每轮写完整角色档案或整本书。
- 短期效果和场景状态直接更新本局状态；值得复用的机制和真正的规则变动按需整理到世界书。
- NPC身份、关键经历可留局内人物记录；有持续独立目标者才进入暗流整理候选。计数只是提醒整理的依据，不是记忆或重要性的替代品。
- 捕获与主动补全若能同批处理则合并，暗流建档与推演也尽量合并，但不能把权限或语境不同的任务硬塞进一次请求。
- 用户关闭暗流，不意味着自动忘掉普通NPC；关闭主动补全，不意味着拒绝保存已发生的状态。

### 人工审阅与“拒绝”语义

未发生的补全建议被拒绝：不加入世界设定。已在正文发生的事实，其整理条目被拒绝：仅表示不接受这个整理版本，不自动使故事事实消失。可改写条目、暂不收录；若要改变已发生内容，需显式编辑事实或撤回对应回合。

“暂不收录”不永久强迫整条内容常驻提示词；按正常记忆与相关性处理，保留原文来源。该区别在审阅界面用一句说明表达，不另加一套繁琐工作流。默认自动加入与可选逐项人工审阅沿用既有方向。

## 六、流式展示、并发与保存

流式显示的是正在生成的本轮内容，不代表已提交完所有状态。成功后成为正式回合；失败时保留可辨识的未完成草稿和玩家输入，不能让半条结构指令修改世界。

后台任务、生成回复归属于启动它的故事/分支；切换界面不停止接收。不同故事可独立推进；同一故事的连续操作有因果顺序，候选首期在本轮结束前保留草稿，不同时启动两个争抢同一起点的正式回合。

模型输出/网络失败的处理聚焦保存完整性，不为所有内部函数增加防御框架。本节为产品要求，具体协议沿用已有流式与任务基础，不宣称现已全部满足。

## 七、记忆：压缩文字，不抹掉有效世界状态

故事历史可分层压缩，但活跃状态、未完成承诺、已掌握能力和有效因果关系不应仅靠模糊摘要维持。原文保留，摘要与关键记录带来源，取材只读当前相关部分。

规则有权威条目、人物有当前记录、事件有因果记录，摘要不能另造一份相互矛盾的“真相”。摘要出错时从原文/当前有效记录修正；旧摘要中的已废止规则不覆盖新修订。

压缩通常后台进行。若下一次发送已经超过模型实际上下文容量，不能承诺永不等待或静默删掉重要规则；应先形成可用上下文，失败给出明确重试提示。不同模式复用压缩基础设施，内容重点与事实边界分别定义。

## 八、撤回、重演与分支：发现并修正一个旧设计矛盾

15的旧“微调重演”建议默认复用选中未来、只重写正文。若玩家修改了影响成败的行动，这会把结果锁死，违背“通过微调改变闯关结果”的原意。

本轮修订候选：微调重演优先保持起点世界状态、已固定参数、对手既有目标/布置和未被行动改变的外部条件；因新行动改变的判定与未来应重新评估。旧候选只有仍适用时才能参考，不能为了相似而保留不可能结果。不保证LLM逐字重复；完全相同只有在依赖不变且直接复用完整已保存结果时成立。

随机是否复用按判定对象和语义判断，不全局复用一个顺序随机流就宣称公平。例如玩家改用钥匙而非撬锁，不再复用撬锁失败；改变与掷骰无关的描写也不应重置锁难度。具体随机配对规则在回溯模块工程设计时收敛，不新增复杂通用模拟器。

撤回恢复本局状态、世界书修订、实体与账本、节点进度和取材记忆边界。已完成但晚回来的旧后台结果不得写入新分支；仍保留的旧尝试仅供玩家选作非正式参考，不进入角色记忆或捕获。

分叉后世界分别演变。用户在全局偏好/接口中作出的独立设置变化，不应随故事撤回一起消失。对局内手工编辑与自动回合变化的冲突需可见说明，不能仅用一个回合号粗暴删除一切后续文件。

## 九、成本与等待清单

| 工作 | 是否默认每轮新增调用 | 可能等待的位置 |
|---|---|---|
| GM正文 | 必需的主请求 | 首字与完整生成 |
| 未来推演 | 仅启用时，沿用该机制调用 | 正文开始前 |
| 骰子与规则计算 | 明确规则的计算由程序完成 | 不因掷骰单独调用AI |
| 世界书捕获/补全 | 有值得处理内容且设置允许时 | 默认后台，人工/等待模式按选择 |
| 实体整理/推演 | 有相关候选或待处理事件时 | 默认后台，当前场景依赖未决事件时例外 |
| 记忆压缩 | 按容量需要 | 通常后台，容量不足时例外 |
| 生图 | 按现有触发设置独立处理 | 不让生图失败撤销成功故事 |

这里只给调用位置和条件，不在未验证模型/数据规模前承诺固定延迟或token数。精简取材与稳定任务前缀是目标，不能用缓存掩盖不必要的长输出或多次串行推理。

## 十、本轮范围与下一步

P1设计：跨模块回合职责、已发生事实与后台整理一致性、玩家控制、知情边界、保存和回溯。P2设计：开局摘要、审阅说明、任务可见性与日志解释。暂不扩大到完整群聊、独立私聊或任意代码小游戏。

待集中审阅的真正取舍：重要离场人物的不可逆遭遇是否需要保障玩家介入机会；可选未来与数值机制组合；冲突无法裁定时的暂停边界；微调重演的条件保留方案。其余实现细节可继续自主整理。

下一步将各类设置收成“简单默认—高级展开—作者配置”一份表，并准备新建故事/故事主界面/工坊审阅的信息架构草图，再汇入总设计案。当前没有完成整款游戏设计，也没有执行代码/模型测试。
