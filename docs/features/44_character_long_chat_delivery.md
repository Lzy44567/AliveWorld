# 44 角色长聊上下文压缩交付

2026-10-21。P1 / 功能升级。承接22y-B，用户已确认默认关闭、逐会话授权额外费用。现进入实施；dev.25已收口，不回头扩写42。

## 玩家目标及范围

让较早的共同经历在超出近期聊天窗口后仍能被参考，而不是把聊天摘要称为完整、精确的记忆。现有原文、来源账本、原文召回保留，摘要只补充覆盖面。不做人设演变、跨角色画像、群聊、存储扩容或旧格式强制转换。

入口：会话资料 → 记忆与关系 → 长聊整理。建议每个schema2会话默认关闭；主动开启时说明会额外调用所选模型并消耗token。显示开关、最近整理结果、覆盖范围、来源及停用/重新整理操作。旧格式显示当前暂不支持，不改其文件。

## 当前代码证据

- `core/compaction_plan.py`已有纯规划函数，复用完整单元切片，不复制故事线程或另建通用框架。
- `group_context.py`当前取最后20个完成/部分送达组，并按预算删减；账本与召回不是完整聊天摘要。
- `CharacterGroupService._transaction`通过已有repository提交短事务，模型请求在事务外；摘要必须沿同一存储所有权接线。
- `context_contract.py`当前没有摘要输入版本；输出仍保持reply.v3，不通过改输出协议搭售功能。

## 模块分工与实施顺序

1. **派生摘要与取材（Python）**：独立角色摘要模块负责完整已送达组筛选、来源指纹、共享水位规划、大小边界与失效。只读取角色可见正式内容，排除OOC、未送达气泡、失败预览和撤回归档。
2. **后台整理（Python＋提示词）**：角色服务在玩家发起的正常回复正式结束后检查是否需要整理；同会话不并行重复整理，不阻塞本轮气泡。使用独立摘要任务与提示词身份，记录调用类别和费用来源。GET、启动、开启面板和主动联系不得触发新整理费用。
3. **下一轮参考（Python＋提示词）**：新增输入契约版本，保留旧请求重试按原契约执行。有效摘要作为派生资料，不进入可引用message_id集合；近期原文、账本与M3仍按原权限参考。报告与最终预算裁剪一致。
4. **玩家闭环（UI）**：开关确认费用 → 继续聊天 → 查看状态/来源 → 停用或显式重建 → 关闭。无需复制一份复杂设置页。
5. **验收与发行**：假模型真HTTP、浏览器/截图及必要回归；分类更新日志、Git提交、dev.26真实EXE/ZIP构建、推送与Release核对。用户明确的交付终点是实际发布。

## 必须在编码前冻结的数值与接线

- 触发不能仅按token水位：短聊天也可能超过20组，应同时考虑即将离开近期窗口的完整组，避免永久漏掉短但重要的对话。保留近期原文的最低组数、单次处理量与摘要总预算在专项用例中明确。
- 摘要存于会话内独立派生字段；使用原文组/消息身份和内容指纹，不把“任何新消息导致revision变化”误判成整个旧摘要失效。
- 撤回/重生成改变来源时立即停止参考；原文追加不应无端丢弃已有有效片段。迟到提交核对来源与当前授权，关闭或删除后不得写入；不能保存一份已失效结果再依赖UI隐藏。
- 整理失败保留原文与有效旧摘要，不推进处理位置；同一失败片段不因打开界面、重启或每次闲聊无限自动重试。显式重试/重建需说明费用。
- 不在摘要之上无限递归总结。首期的分段上限、选择和淘汰仅影响派生摘要；不得删除原文或谎称无限记忆。达到边界须向用户解释。
- 关闭后的既有摘要是否继续参与请求需在UI清楚说明；推荐关闭即停止整理并停止参考，保留本地派生数据供重新开启，用户可另行清除。
- 主动联系若本期不接摘要读取，界面和发布说明须明确，不声称所有入口记忆已扩展。

## 验收清单

- 超过20组的合成聊天中，较早经历通过有效摘要进入真实最终请求；短消息与长消息均覆盖。
- 只整理完整已送达内容；私密内部记录/OOC/撤回/预览/未送达尾部不泄漏。
- 原文证据集合不因摘要扩大；纠正/撤回/重生成、关闭、删除与迟到结果不污染后续请求。
- 默认关闭零额外请求；开启后按水位/窗口低频执行；失败、GET、重启及主动联系不循环收费。
- 来源可查看，摘要可停用和显式重建；有新草稿/切换会话不串写。
- 真实模型的记忆质量独立评价，不以固定假回复证明语义准确，不自动读取或上传玩家私聊作测试。
