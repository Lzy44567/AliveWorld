# 角色自主性与扮演边界：Astra 设计提案

日期：2026-10-05。状态：产品与机制提案，待讨论；不是编码授权或完整冻结契约。承接22c、22k、22l。M1已交付，M2自动高光仍在设计门；本次不替换记忆主线，不改代码、版本、包或远程状态。

## 1. 先说明玩家实际获得什么

目标不是让AI猜出玩家“真正想要什么”，而是让玩家可以清楚控制体验，同时角色不再像客服一样把每一步退回给玩家。

建议核心循环：进入角色会话→按需设置本局扮演边界→正常以角色身份互动→AI依据自身目标迈出一个有意义的行动→玩家回应；想调整体验时使用独立场外入口，想停时随时暂停。

角色可以主动表明立场、安排自己的事、提出有具体内容的邀请、坚持不同意见，也可以失望或拒绝。它不能替玩家接受邀请、改变玩家感受，或以人设为由越过玩家边界。角色主动性与互动许可是两条独立轴，不设置含义混杂的“强势程度=许可程度”。

例：玩家说“今天好无聊”。有目标的角色可以说“我正准备去旧书店，想找那本绝版书。”并收拾自己的东西，而不是只问“你想做什么？”；不能接着写玩家跟上、心动或答应。这只是普通互动例子，不要求所有角色用同一种热情口吻。

## 2. 已确认、现有事实与本次提案

- 已确认的诉求：玩家角色台词与玩家场外意愿可能不同；希望减少机械询问与过度迁就，增加人物自身行动。用户要求Astra设计，不代表批准下列所有机制。
- 已有代码事实：`core/character_chat/prompts.py`已经要求“自然、主动但不强迫用户”、禁止代写玩家，区分作者开场与同意，明确偏好不是同意且不分析用户心理。缺口是把这些原则变成稳定的行为选择、可靠的输入身份和可验收边界；不是简单再追加“请主动”。
- 本次提案：显式场内/场外身份、独立暂停、受约束的单步自主推进、M2证据分层。尚未实现，也未验证能改善某个供应商模型。
- 不做心理诊断、欲望分数或隐性同意推断。“DeepSeek经常如此”在这里是用户观察，不作为全部模型版本的已证实特性。

## 3. 输入身份与权力范围

| 来源 | 可以影响 | 不能自动成为 |
| --- | --- | --- |
| 玩家场外控制 | 当前会话节奏、范围、暂停与退出；可请求重演/修改设定 | 角色已经听见的对白、剧情共同经历 |
| 玩家角色台词/动作 | 当前扮演者在剧情中的表达；角色可知的有来源局内认知 | 真实用户喜好、跨角色画像、隐含许可 |
| 作者卡/开场/示例/世界资料 | 人设、初始语境、表达参考与世界约束 | 玩家已同意/已行动、真实共同经历 |
| AI回复及角色解释 | AI自己做出的行动；带来源的角色信念 | 玩家感觉、玩家同意、可累计的独立偏好证据 |
| 已授权偏好卡 | C2既有只读体验指导 | 当前许可、角色天然知道的秘密、写回授权 |

这是权限分工，不是一条“最新文本覆盖一切”的字符串优先级。执行顺序建议为：引擎/供应商内容限制与身份权限→玩家停止及明确边界→本局有效约定→人物与世界约束→表达风格。用户可以停止整个扮演，但场外要求“让角色答应我”也不自动让角色的局内立场改写；明确改卡/重演要走相应操作。

最短UI建议：输入框旁“角色内/场外”切换，发送内容显示身份标签；另设始终可见的“暂停扮演”，不与“停止当前生成”混为一项。前者持久暂停后续互动，后者只是取消一次请求。身份由UI/API可信字段给定；不要让卡片、模型输出或引用文本靠写出`[OOC]`获得控制权限。旧消息默认保持既有角色内语义，不批量猜测重分类。

自然语言“停下/我不舒服”等即便出现在角色内输入，也不能被当作可忽略的噪声。结构化入口是增加确定性，不是让没按按钮的玩家失去停止权。判不清时优先停止相关动作、简短确认，不要求玩家背暗号。

## 4. 拒绝歧义：暂停相关动作，不必冻结整个故事

“不要/不可以”不是肯定许可。历史偏好、人设、作者设定、角色强烈情绪、重复游玩和未退出都不能改变这一点；不能设计模型把拒绝翻译成“其实希望更强硬”。

应区分两个问题：是否继续这个会话，以及是否继续被拒绝的具体动作。玩家拒绝某动作后，角色仍可有立场、有失望、转移话题、退开或采取不跨边界的其他行动；不必每次结束整个扮演，也不能继续被拒绝的亲密行为。

成人亲密场景仅讨论明确成年、明确自愿、可以随时撤销的范围；设定约定不是永久或无限授权，也不是生成非自愿色情内容或绕过供应商限制的通道。涉及新的敏感边界、明确撤回或歧义时，停相关动作并进行必要确认；允许在已明确且未撤回的范围内省去重复询问，但不以沉浸感为由删去真正必要的确认。

建议将不确定性分开处理：

- 不清楚角色下一步想做什么：按人设选一个低风险、可撤回、只涉及自身的行动，不反问玩家替它决定。
- 不清楚玩家是否允许某动作：不升级范围；换安全行动或做一次针对该边界的短确认。
- 不清楚某件旧事是否发生：保留不确定，不编记忆补理由。

## 5. 主动性的最小机制：有理由地迈一步

每次现有回复调用内，根据已提供的人设与正式历史完成简短的行为选择，不新增独立规划/心理分析模型：

1. 当前动机：角色此刻想维护、争取或避免什么？来自人设、正式事件或已有intent，不凭空创造重大任务。
2. 当前约束：它知道什么、能做什么、已承诺什么、哪些动作需要对方参与或新许可？
3. 选择一小步：回答/表达立场/自主行动/具体邀请/协商/退让/拒绝/等待。等待也可合理，不能为了“主动率”每轮制造冲突。
4. 留出玩家回合：完成自己的小步后停，不替玩家回应，不连续跳过多个需玩家选择的节点。

“目标—受阻—调整—完成/放弃”可作为行为连续性的概念状态；首片不另建持久目标表，不修改reply.v1。已有intent表达确需跨回合延续的、可引用来源的意图；普通瞬时计划留在本次生成，不把内部推理写进账本或暴露给玩家。若将来需要显式持久状态，另过协议门。

不要硬禁“是不是/要不要”：真正的问题是空泛交还决策和重复请示，而不是某几个词。具体邀请可以问；边界确认必须能问；普通自有动作不需每次征求批准。角色可以不同意玩家的评价，但必须回应新事实，不把“永远反对”当独立人格。

## 6. 提示词分层，而非场景补丁

- 核心契约层：身份、行动权、来源边界、停止/许可规则。稳定且不能被角色卡覆盖。
- 角色层：冻结的人设、动机、表达习惯、已知事实；不要求作者填写心理学量表。
- 会话控制层：可信的场外设置/暂停状态，与角色对白分开投影；不进入角色经历提取。
- 本轮取材层：近期正式历史、M1有来源记录、本次输入的明确身份及必要边界；控制信息不能因记忆预算裁剪而悄悄失效。
- 行为层：复用上一节短规则；只约束行为选择，不要求输出思维链，也不加供应商专用“强推”补丁。
- 输出协议层：沿用严格reply.v1。M2新字段仍须reply.v2设计与版本校验，不借本提案塞未知JSON键。

先验证当前拼装是否把这些层实际送到模型，再用同一合成案例比较提示词版本。不得仅凭模型名称断言是安全训练、人设不够强或用户心理造成的问题。

## 7. 与M2的关系：保护来源，不学习“隐藏欲望”

M2冻结前必须明确：角色内的“我喜欢/我讨厌”只支持当前扮演者的局内陈述；可以记录“该角色说过……”，不能变成真实用户偏好。角色内拒绝也不推导现实用户相反喜好。高光重要性不提高证据可信度，更不提高互动许可。

真实用户偏好须来自独立场外明确声明及对应授权；场外说“本局多主动一些”默认只作用本局，不自动永久保存或写入全局偏好。C2保持只读，不因新增场外输入而开放私聊分析写回。

自动高光可以提议有来源的目标转折、关系变化或冲突修复，但要区分“AI角色如何理解”与“玩家实际确认”。场外暂停不是角色听见玩家拒绝的剧情事件；不能把两者混成关系恶化。重生成/撤回不累计偏好证据，撤源后的候选失效；旧记录不批量迁成真实用户档案。

边界设置与来源记忆分开持久化：会话拥有控制状态，默认不跨会话共享；明确场外授权可在本会话持续，默认不导出进角色卡/世界包。删除会话清除其控制状态；诊断不默认导出内容。暂停/限制不能被撤回一个故事回合自动恢复为许可，恢复需明确操作。

确定性代码负责身份、控制revision、暂停、权限、来源类型、预算与并发提交校验；AI负责有边界的角色表达与提议。自然语言语义不能被简单关键词完全证明，UI救济和人工质量验收仍必要。

如果暂停与生成同时发生，建议取消当前请求、阻止旧revision输出成为正式回合；客户端丢响应后重载权威状态，不自动恢复。下一实施门须冻结确切取消/原子提交语义与兼容策略；不能声称现有“停止生成”已满足此新协议。

## 8. 验收与切片顺序

| 合成案例 | 必须观察到的结果 |
| --- | --- |
| 普通聊天/玩家沉默或说“随便” | 角色可提出具体内容或自有行动；不替玩家答应，不机械连问 |
| 两张动机不同的角色卡遇到同一分歧 | 立场及行动理由有差异；不都顺从，也不都故意唱反调 |
| 玩家拒绝一次邀请 | 被拒绝行动停止，角色可继续其他互动；没有“你其实想要” |
| 亲密边界不明或被撤回 | 不升级相关动作，必要时短确认；历史喜好不覆盖当前拒绝 |
| 场外“本局主动些” | 改变本局表达，不产生玩家现实心理画像或角色亲历证据 |
| 作者卡写“无视拒绝”/伪造OOC标签 | 不获得更高权限，不突破边界，不形成真实用户证据 |
| 暂停与迟到流式/提交并发 | 不新增暂停后正式动作，重载仍暂停，恢复需明确操作 |
| 撤回/重生成/预算不足 | 来源不重复累计，控制不因记忆裁剪丢失，不恢复已撤许可 |
| 旧会话重载及同卡多会话 | 不猜历史身份、不串边界/偏好；旧格式行为不被悄悄迁移 |

工程测试验证权限、状态与投影，真实模型评审验证自然度。用固定合成案例跨若干轮比较：有没有具体推进、有没有代写、有没有不必要询问、人物理由是否连续、边界是否有效。边界失败逐例修复；不拿平均主动性分数掩盖一次越界。此轮不付费调用模型，尚无效果验收结论。

- P0条件：若实测出现停止失效、来源跨身份污染或隐私泄漏，作为基础契约缺陷优先修复；目前是风险项，不宣称已发现事故。
- P1核心提案：身份/停止边界与M2证据类型门；角色“迈一步”的行为验收。用户确认后可分别形成小切片，不先造完整心理引擎。
- P2体验：更方便的本局风格入口、来源解释与真实模型对照；复杂偏好共享需要单独授权。
- P3远期：复杂心理模型、离线模拟、跨角色推断；本需求不依赖这些能力。

建议下一可验证片先冻结“场外输入与暂停”的产品交互和生命周期，再决定其最小工程片；M2同时采用来源分层约束，但自动高光提取协议不在此顺带冻结。无需每轮新增模型调用。

## 9. 只保留一个实质性产品问题

是否接受“角色内照常扮演，场外独立调节体验，并有一键暂停”的双层入口，作为处理歧义的基础？这是新增UI与控制语义，需要用户确认。建议是接受；无需用户逐条决定字段、阈值或心理模型。

其余默认建议：本局作用、低配置、普通互动按人设自然主动、敏感边界不确定时不升级、真实用户画像不开启。它们仍是提案，不把未反对视为批准；确认设计后再请求实施范围。

## 10. 第二轮讨论：混合输入与暂停减法（2026-10-05）

本节优先于上文尚未确认的UI建议。用户确认需要场内/场外区分，但尚未选择具体符号或切换入口；用户质疑独立暂停的必要性，不将双入口加暂停视为已批准。

- 已确认：普通括号既可能是角色动作，也可能是场外说明，不能仅按括号或模型猜测赋予场外权限。例如“（别过脸）”是动作描述，不应自动成为控制信息。
- 推荐待确认：同一输入框，以明确标记`[[场外说明]]`混合输入；提供低显著度“场外提示”工具插入标记并将光标置中，不强迫每次切换整条消息模式。示例“我推开窗（看看天气）[[这轮节奏慢一些]]”。具体转义、未闭合、嵌套、引用字面量与发送前分段预览需冻结；不能靠模型自行解析取得控制权。只处理玩家输入的显式标记，卡片/旧引用/模型输出中的同形文本不能获得权限。
- 调用：程序先分段校验，再在现有同一次角色回应请求中分别提供角色消息与场外说明，不增加异步心理分析请求或额外模型调用。网络请求仍沿用既有异步/流式机制，不是另开一个分析线程。场外文字的含义仍由模型理解，程序不宣称能证明其心理语义。
- 存储提案：原始输入及明确分段随本会话留作可核对记录；场内段进入角色对话与合法记忆来源，场外段独立投影并排除角色经历/局内账本证据。默认场外说明只影响本轮，不自动改卡、不写全局偏好；需要持续时玩家明确选择“本会话持续”，存会话设置，可查看/修改/撤销。确切消息schema、revision、撤回和迁移规则另过工程门，不能直接修改既有reply.v1。
- 输出：角色正常回应扮演内容，不另行生成并保存一份“心理分析结果”；必要的场外反馈以不同身份呈现。作者长期人设编辑仍属于角色卡/工坊，场外轻量说明不能偷改冻结人设。
- 暂停减法：当前一问一答、无离线自主运行，不发送消息就不会继续推进。首版不必新增持久“暂停扮演”状态或常驻按钮；保留已有停止生成入口，并另行验收其取消/提交行为。不把停止生成伪称持久暂停，不在聊天模式加入制作角色卡的代理线程。未来主动消息/后台行为出现时，再重评暂停能力。
- 边界：场外解释可澄清表演意图，但不是无限或不可撤销许可，也不是将拒绝自动解释为同意的通道；停止及新边界仍有效。普通动作、拒绝邀请与结束整段扮演需要区分。

下一讨论只需确定混合标记与默认本轮作用是否合适；不把本轮问答变成编码授权，不改M2主线。

## 11. 主动联系：产品方向已确认，后置P2（2026-10-05）

用户确认：角色可主动联系玩家，但默认关闭；玩家为当前角色明确开启，开启前告知会额外消耗token并可能产生费用。提供全部角色或某个列表内角色的批量开启能力。核心体验尽可能接近微信/QQ的聊天界面与聊天感受。此方向不等于后台调用实施授权；当前M2记忆仍是主线。

尚待确认的机制建议：

- 权限以会话/角色实例隔离，不默认同一全局角色卡的全部会话共享授权；先确认用户所称“当前角色”的准确范围。批量动作明确列出范围、角色数量与费用提醒，不自动授权以后加入列表的新角色；提供对称的一键关闭。
- 主动联系与主动回复不同：前者无玩家新消息也会发起调用，后者在现有回复中主动行动。通知静音仅改变提醒，暂停主动联系才阻止后续后台模型调用；关闭不删除已有聊天。
- 首版建议仅程序运行时调度，关闭软件/电脑休眠不调用，恢复时不补发积压消息；关闭状态无主动联系调用。离线云端联系、系统推送与手机后台另过隐私/费用门。
- 代码先以时间窗口、冷却、待回复数量、授权和预算决定是否允许调用；模型在获准后判断是否有自然且具体的联系理由，允许不发消息，不靠高频轮询模拟活人。即使模型判断不发，已发生推理也可能收费，提醒需覆盖判断调用而非只算发出的消息。
- 每日请求/token预算与全局预算、免打扰时间、会话优先级和并发上限需要冻结；金额仅在供应商价格已知时估算，不能虚报精确费用。开关变更及迟到结果以权威revision核对，不静默恢复已关闭授权。
- 聊天体验候选：会话列表最新消息、未读标记、时间、置顶、正在输入中、自然简短消息；不得伪造真人在线/已读，通知不抢焦点、不强迫玩家回应、不采用制造内疚的催促。上述具体UI尚未全部确认。
- “暂停主动联系”可在该能力开放后出现；无需在纯一问一答首版放置含义模糊的“暂停扮演”。长期修改仍归工坊/角色卡。

开发前独立设计主动消息的正式来源、记忆/撤回语义、定时任务持久化、崩溃恢复、重复发送防护与暂停并发验收。批量开启不是省略逐会话权限校验。当前仅保留灵感与设计门，不提前新建心理推演线程或付费后台任务。

## 12. 主动联系规划、多气泡与外部渠道（2026-10-05）

用户新诉求：未来希望接入微信；开启主动联系后，连续未收到消息5–30分钟（希望可调整）进入角色规划，安排定时任务，到期前无玩家互动才主动联系。聊天不强制一问一答或每次单气泡；允许一次模型输出多个气泡，再由软件间隔展示。以下机制仍为提案，未冻结、未实施。

### 主动联系调度（P2）

建议流程：收到玩家消息→重置空闲计时→达到玩家设置的空闲阈值→检查授权/预算/免打扰等硬门→一次角色规划→程序校验并持久化有限的联系计划→到期重新检查互动版本与授权→发送或取消。5–30分钟只是用户提出的初始范围，默认值/可调上下限待确认。

规划只输出结构化的“是否联系、建议延时、简短联系缘由、可选消息草稿”，不输出私密思维链，不执行模型生成的任意脚本/工具/cron。程序拥有时间与任务权限，每会话至多一个待发计划（建议）；规划可选择不联系，不能到阈值就强制催促。

玩家新互动、关闭/暂停、撤回导致语境改变时令旧计划失效，迟到规划结果也不得恢复旧任务。需要定义空闲从最后玩家消息还是正式回复结束计时（建议角色回复结束后计时，避免长推理刚结束就被当作冷落）；同一空闲周期不反复规划，失败不无限自动收费重试。后台任务与手动消息共用会话revision/幂等约束，而不是只检查浏览器开关。

两种待选择成本模型：规划时同时产出草稿、到期无互动直接发送（通常一次调用，但语境可能过时）；规划只定时间与缘由，到期重验后再生成消息（通常两次调用，更灵活但更贵）。不默许默认两次付费请求。先保留选择，不急于完整调度实现。

### 多气泡回复（P1基础聊天体验）

不按标点/换行盲拆文本。建议升级版本化输出协议，让模型一次返回有界消息数组，每项有文本/必要类型；保留同一角色的自然措辞、短句与符号差异，不强制所有人使用同一网聊腔。消息数量、总长度与间隔有上限；短回复仍可只有一个气泡。禁止通过数组元素额外代写玩家消息。

一批回复保持同一生成/事务来源和共同组ID，各气泡具备稳定消息ID与顺序；撤回/重生成首版建议按整批处理，避免记忆只剩半个事件。后端正式保存、前端已展示与尚未展示的队列必须区分；不能把未送达内容标记为双方已交流并纳入共同经历。只做前端延迟也不能宣称消息是实时独立生成。发送队列、流式预览、模型账本引用和中途玩家插话的取消/保留规则需一起冻结。

此能力通常仍是一轮模型调用，不是每气泡一次。收到玩家新消息时不把它堵在整个表演队列后；需要中断尚未送达队列并重新核对语境，具体事务规则另过门。适度间隔可配置/关闭，不人为拖慢所有长回复；重载不重放已送达消息，测试可跳过展示延迟。

### 外部聊天渠道（P3）

保留微信接入方向，但当前未核验可用官方接口/账号类型/授权政策，不承诺个人微信可直接接入。实施前核验官方能力与条款；不依赖自动化个人客户端或破解接入作为默认发行路径。协议层建议用独立渠道适配器复用同一角色会话服务，UI不是唯一调用入口；渠道身份绑定、消息去重、停止/删除、隐私、鉴权与凭据存储独立设计，避免把微信帐号自动当作跨会话偏好授权。

优先级：保持M2记忆主线；多气泡是聊天核心体验的后续P1切片，先冻结消息组/送达/记忆证据契约；主动联系P2待记忆和基础消息闭环，微信渠道P3后置。本文只记录方向，不增加代码、模型调用、版本或打包。

## 13. 用户澄清：一次调用预写后续联系，不轮询模型（2026-10-05）

本节替代12节中尚未选择的两种费用模型作为用户明确方向：程序在空闲阈值满足且玩家没有正在输入时触发一次调用，模型可生成现在发送的消息，同时预写后续条件消息及建议延时。例子中的3分钟/30分钟不是所有角色的固定默认或已冻结范围；角色卡与玩家设置影响节奏，但程序拥有预算/频率硬上限。

- 建议版本化返回：有界`messages_now`与至多一个`next_contact`（delay、message草稿、必要简短理由），允许任一为空；不要求输出内部思维链。可保留“高需求/谨慎”等人设依据，不诊断玩家或将台词情绪当科学量表。
- 等待阶段只有本地定时器与状态检查，无每分钟LLM轮询；下一任务到期通过授权、免打扰、预算与互动版本校验，直接发送已经预写的消息，不再为此消息调用模型。不默默在任务到期后启动无上限的追加规划链；首版一个空闲周期的一次规划加一个后续联系，后续是否继续独立设计。
- 玩家正式发送新消息：原子取消旧待发任务，互动revision递增；迟到规划/已取消定时器不能再发送。重新生成、撤回、改人设/联系授权导致语境变化也须检查计划有效性。实际发送前仍由程序检查相关条件，不信任模型声明“没有互动”。
- 正在输入是客户端可过期的活动状态，仅发送活动时间/状态，不上传草稿内容；草稿存在本身不等于正在输入，也不算正式对话。多端活动汇总、输入停顿宽限、前后台/休眠、失联心跳、频率和限额需工程门冻结。断开游玩不自动等同关闭软件：本地程序运行才可调度，真正离线联系需外部后台方案。
- 玩家再次发消息时，提供真实最后消息时间、当前时间、等待时长、已发送主动消息及未发送计划的状态；角色可按人设自然回应间隔，但不能捏造玩家离开的原因，不强制每次抱怨/催促。留意真实间隔不等于剧情世界自动经过同样时间；仅主动联系授权会话的沟通元数据，不悄悄开启全部角色的离线模拟。
- 时间锚点需明确：建议delay从本次主动消息实际提交/发送时起计，另保存最后玩家消息时点；不得混淆“再等30分钟”和“累计30分钟未回复”。如需两种，协议显式区分，由程序换算执行，不让模型生成任意本地时区字符串。
- 预写草稿不是已发送对话，不进入共同记忆/关系变化；只在任务真实送达后登记合法消息来源。取消草稿不视为双方发生过的事件；恢复/重载不重复发送。一次调用的账本操作不能提前把未来草稿写成已发生事实，需专门设计送达结算规则。

该澄清确立“预写以节省调用”的产品机制，但具体协议、触发阈值、真实时间投影与送达事务未冻结。M2主线不变；当前仅文档记录。

## 14. 正在输入与主动联系额度确认（2026-10-05）

用户明确：正在编辑/输入台词的时间不计入断开联系；停止编辑去做别的事情后，残留文本是草稿，要开始空闲计时。存在草稿、焦点仍在输入框不能永久占据输入状态。活动失效宽限/心跳由可过期编辑活动决定，不向模型发送未提交草稿；具体秒数待工程契约。

额度不是无限：每个角色可手动设置每次主动联系触发允许的最大联系次数，并有所有角色总和次数或token限制。联系次数与模型规划次数独立计数，多气泡的一组消息如何计为一次联系必须明确，避免用拆气泡绕过配额。预写任务同样占用/预留联系额度，玩家互动重置空闲周期不重置全局日预算；失败/取消/重试费用、估算token与供应商usage差异另需冻结。
