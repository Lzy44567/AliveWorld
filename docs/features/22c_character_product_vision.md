# 角色模式：活人感产品设计与灵感池

> dev.17首版状态：用户最终选择先做最简角色载入/一对一对话，已实现双表现、冻结人设、来源账本、会话保存切换与真实流式及安全撤回。工程验收通过，当前本地EXE交付；下方价值假设仍需真实模型评价。性格演变默认关闭且未开放，内核提炼不开发；语音/图片/群聊/真实离线时间、完整长期记忆保留为未来分类灵感，不是首版承诺。

更新：2026-10-03。状态：用户需求已记录；下文建议仍待讨论，不是全部获准实施。工程草案见[22b](22b_character_private_chat_r0_contract.md)，它只回答如何安全运行，不能代替本产品设计。

## 1. 已确认定位与主线

- 顶部模式为 **故事—角色—工坊**。故事是RPG；角色是独立一对一聊天式扮演；工坊用于制卡。未来故事内私聊依赖角色能力，但不是独立角色模式的同义词。
- 用户此前选择同时提供即时聊天与情景扮演表现。本次进一步明确：二者都是一对一角色扮演的表达方式，不把叙事表现扩成第二个RPG模式。
- 用户要求先完成流式输出。此前R1A→R1B→R2实施排期暂停；22b作为工程候选保留，不再称为整个角色产品已经设计完成。流式交付后，先继续讨论本产品目标和最小闭环，再安排角色代码。
- 角色语音、图片属于未来升级，当前闭环不引入这些复杂模块。等待期间显示“对方正在输入中”，不暴露内部推理。

## 2. 核心玩法与价值假设（建议，待讨论）

核心不是“另一种聊天框”，而是与一个有身份、有个人立场、记得共同经历的人建立持续互动。用户行动会改变对方的信任、目标与表达，但对方不因一次请求就丢掉人设，也不会永远锁死在初始卡片上。

活人感的三条价值假设：

1. **此人性**：换一张卡，面对相同事情有不同理由、选择和表达；不是只换名字和口癖。
2. **连续性**：共同经历会影响之后的反应；误会能被纠正，承诺能被记住，未亲历的信息不会自动变成知识。
3. **可变化性**：关系、情绪、能力和性格有因果变化；既不是无条件顺从，也不是为了表现自主而机械拒绝。

这是产品目标，不是已证明的独特卖点。只有同场景对照和真实长期互动评测能判断是否优于普通角色卡聊天；更多后台调用/更多字段本身不是效果证据。

## 4. 人设、记忆与变化的分工（建议）

### 人设不是每轮重写的数据库

原始角色卡保存创作者底稿；会话实例保存当前情绪、关系、目标和能力状态。临时紧张不应立即改写成“胆小性格”；一次友善不应立即升级成深度信任。稳定性格变化需连续、有因果的证据，不简单固定每N轮变化，也不让模型自己编造过去。

### 记忆不是“把更多文本塞进上下文”

建议区分：近期原文、可检索经历、重要关系/承诺、稳定个人事实。记忆携带来源与认知类型；摘要用于取材，不取代永久原文。检索和摘要可复用现有基础能力，但故事摘要不自动等同角色个人记忆。未知信息、错误信念和被纠正的记忆需分别表达。

首版账本可先证明“会话外仍记得且能纠错”，但22b的最近回合+有限账本不代表长期记忆产品完整。自动提取时机、遗忘/淡化、重要度和记忆合并仍需讨论，并单独评估token与噪声。

### 变化必须影响后续行为

情绪是短期、目标是中期、关系/能力是累积、性格是较慢变化；这只是设计框架，不预先写死数值心理学。每项变化应有可检验的后续表现，避免右栏数值变化而台词不变。模型提出原因与变化，程序校验权限/来源/事务；语义是否合理仍需真实文本评测。

## 5. 需要与用户讨论，而非由编码者默定

### 2026-10-03补充：已确认要求

最新用户决策覆盖下文仍保留的旧问题：首版先做角色载入与独立一对一对话核心；长期性格演变默认关闭、降低为P2灵感，暂不深入设计或开放。未来开启时变化自然生效并通知、不打断；关闭后角色卡设定冻结，但记忆、关系与情绪可以变化。允许工坊辅助提炼内核的方向，但提示词及入口均后置P2。首版时间仅使用聊天中明确经过的时间，不混入现实离线时间。首版不要求作者填写内核，不每轮重写原卡；底稿快照与局内记录分离。

当前最小闭环（P1）：选择现有角色卡→建立独立会话→以即时聊天或情景扮演互动→流式显示→最终验证与保存→切换/重进继续；失败、重试、撤回保持记录与状态一致。首版有限来源账本是连续性基础，不等于完整长期心理/记忆模拟。先按22b逐片落实必要安全基础，不以所有远期能力冻结为开聊前置。

- 长期性格以角色卡为底稿；允许作者提供若干“精神内核”描述价值观、思考习惯与行为逻辑，但不是必填字段、不限定数量。只写自由文本人设的角色也必须可用，不强制自动转换成内核。
- 玩家可自由开关“允许角色长期性格演变”。默认值、会话/全局作用域和关闭后的状态语义尚待确认，不能由程序员默定。
- 长期变化考虑重大经历、累积经历与内核变化；短期状态考虑近期事件、休息、压力及作者设定的生理因素，并与长期人格互动。不能把一次情绪直接永久写成人格，也不能套用生理因素决定行为的刻板公式。
- 酒馆/类脑资源兼容是明确需求；具体格式、扩展与行为兼容需样本核对，不宣称所有社区资源都已兼容。

### 心理学边界与候选分层（建议，非已冻结契约）

产品借鉴人格特质与情境状态的区分，不宣称构建了经过验证的心理模拟器。“精神内核”是创作工具，不等同心理学公理；理性旁观等表现可以作为作者给定的应对习惯，不自动诊断精神疾病。

候选层次：创作者底稿（可选内核/自由人设）→会话内长期变化→近期情绪/身体状态→针对不同对象的关系、目标→个人知识/信念/有来源记忆。各层共同影响表现，不要求玩家填写五套表格。关系变好不自动等于性格变顺从；短期愤怒也不必覆盖稳定价值观。能力成长与人格演变是否共用开关仍待讨论。

建议AI可以辅助提炼内核，但只作为可编辑候选，不把推断提升为高于原卡的隐藏硬规则。进口卡保留原文、样例对话和未知扩展；未知内容保留不等于自动执行外部脚本或支持全部宏。

需讨论的关键语义：演变默认开关；重要变化自动生效还是确认；关闭开关是否冻结当前人格（而非还原）；内核彼此/与自由文本冲突如何处理；时间流逝是否导致状态变化及额外调用；玩家如何纠正不合理变化。

### 证据与不确定性

- [Whole Trait Theory](https://pmc.ncbi.nlm.nih.gov/articles/PMC4472377/)支持将稳定倾向和情境表现共同考虑。将此借鉴到游戏是设计推断，不代表它证明本产品能准确模拟人。
- [酒馆官方角色设计说明](https://docs.sillytavern.app/usage/core-concepts/characterdesign/)允许描述使用自由文本等不同组织形式；不能据此推断作者能力。
- 当前未找到足以判断“大多数角色作者缺乏内核—行为—情景创作能力”的代表性统计。不得把用户猜测写成事实；若需调研，先限定社区/样本与评价标准，避免以少量热门卡代表所有作者。
- 核心P1：兼容自由人设、稳定/临时分离、来源记忆、控制权与演变开关语义。P2：工坊辅助提炼、复杂长期成长、可选生理/时间机制。首版不强制临床量表、每轮独立心理分析调用或完整人体模拟。

1. 首版最重要的体验是人物鲜明、长期记忆，还是关系/性格成长？三者都需要，但不能同一版无限扩张。
2. 角色变化默认由故事自然发生，还是重要改变先提示用户确认？尤其稳定性格和能力的变化。
3. 主动消息是否属于首版？关闭页面后是否允许继续活动？后者涉及费用与隐私，不默认开启。
4. “文爱”是同一聊天的用户情景偏好，还是需要独立节奏/表现配置？先不强制加新模式。

这些问题暂不阻塞用户要求优先的流式输出，但会阻塞后续完整角色产品冻结。设计会议结论需回写本节与优先级，不能把“已写文档”当作“用户已同意”。

## 6. 验收：技术正确与活人感分开

- 工程验收：会话/记忆隔离、原文保留、增量预览、失败回滚、撤回、重载、可取消；假API可自动验证。
- 内容验收：同场景不同角色、关系变化前后、误会纠正、承诺兑现、私人知识不泄漏、利益冲突、亲密节奏、用户行动权。人工或评审模型读文本，记录质量/成本，不用JSON通过冒充人格可信。
- 小闭环：选一人→互动→形成一段有来源的经历/关系变化→离开重进→后续回应确实反映经历→纠错/撤回后正确改变。不是一次漂亮回复即验收全部角色能力。
