## 2. 核查到的代码事实

- `core/external_formats/adapters.py::adapt_character_card` 已将 personality/scenario/mes_example 拼入 description；first_mes 写入 starting_scene，原始对象保留在 `_external_import.source`。问题是语义混合，不是信息全部丢失。
- `core/character_chat/models.py::profile_projection` 只返回 name/description/starting_scene；创建保存深拷贝快照。会话 envelope schema 为 1。
- `core/character_chat/context.py` 先过滤 AI 可见账本，再选最多32条（intent最多8），近期最多20完整回合；预算依次移除相关世界条目、最旧回合（保留至少2个现有完整回合）、账本，仍超限则拒绝调用。
- `core/character_chat/contract.py` 只允许运行消息 ID 的逐字证据；模型不能创建 author 来源。示例无需新增来源类型，也不应进入 allowed_messages。
- 编辑器 `AssetEditorModal.vue` 只提交旧 description/starting_scene。全局、局内保存合并已有资产；仅在请求里省略结构字段不会删除旧结构。
- `core/asset_workshop.py` 的 normalize 白名单不含新结构，但 publish 合并 current 与 draft；不处理时，工坊更新 description 后旧 role_fields 会在发布时复活。这是本片必须修复的权威问题。

## 3. 资产字段与版本

新外部角色导入生成以下可选结构；name 继续使用原字段：

```text
role_fields = {
  version: 1,
  description: string,
  personality: string,
  scenario: string,
  dialogue_examples: string,
  first_message: string
}
```

version 必须是整数1（不是 boolean），五项必须全部存在，可空；拒绝未知键、非字符串和未知版本，不能部分激活或把对象强转字符串。对外部缺失/空字段归一为空串，非字符串已知字段明确报导入错误。字段映射为 description/personality/scenario/mes_example/first_mes；沿用适配器文本 trim 习惯，原始完整 source 不改动。

| 字段 | 上限（Python Unicode 字符数） | 新角色运行含义 |
| --- | --- | --- |
| description | 16,000 | 作者人设/背景资料 |
| personality | 8,000 | 作者性格资料，不自动推断精神内核 |
| scenario | 8,000 | 初始情景资料，不宣称用户已作出其中动作 |
| dialogue_examples | 8,000 | 可省略的表达参考，非历史/非经历 |
| first_message | 8,000 | 只保存及资料区预览，不成为本片模型历史或正式开场 |

五项总长 ≤32,000；兼容 description 的合并结果（含标题和分隔符）仍须满足既有32,000限制，starting_scene 仍≤8,000。UTF-8快照/深度/文件上限继续生效。超限不得静默截断：导入预览给出字段名、实际长度和上限，拒绝本次结构导入，保留用户原文件且不写半个资产。用户可先修改原文件；本片不新增修卡工作流。

适配器同时生成与旧版本相同的兼容 description 分段与 starting_scene，供故事及旧读取者使用；角色新语义不重复投影它们。复用一个纯领域帮助模块承担结构校验、兼容派生及写入协调，避免 API/UI 各拼一份。原 source、外部隐藏字段仅归档；不加入模型资料、诊断日志或会话列表摘要。

role_fields 缺失或显式 null 是自由文本资产。null 是保留的清除标记，不能在合并前被过滤掉。旧资产不从 source、描述标题或字段相似性反向猜测升级；本片无批量资产迁移。

## 4. 创建快照：按参与者固定语义，不按当前字段猜测

新建会话时，对含有效 role_fields 的参与者写 `profile_semantics: "role_fields_v1"`；自由文本参与者可写 `profile_semantics: "legacy"`。AI/玩家两人分别确定，允许混合。此标记属于 participant，不由外部卡任意字段传入；创建函数依据已校验结构分配。profile_snapshot 及 source_hash 仍冻结整个资产。

- **旧参与者无标记：永远使用原 name/description/starting_scene 投影，即使历史快照恰有名为 role_fields 的扩展。** 不能因读到新字段自动升级。
- 标记 legacy：同旧投影。标记 role_fields_v1：只用结构白名单；不得再拼兼容 description/starting_scene，不从 source 回填空字段。
- 新建时未知/非法非空 role_fields 拒绝创建并提示编辑/重新导入；不是回落到旧字段“勉强运行”。
- 持久化标记未知，或标记 v1 但结构损坏：只读/安全错误、不运行、不重写；无标记旧会话不受新结构验证规则影响。
- envelope schema 保持1，新增标记只控制投影。旧会话文件不迁移，打开/重载不产生写入；源卡后续编辑、克隆、重导入、删除均不改变已创建会话。
- 新版本能继续读取旧会话；不承诺旧程序理解新会话的 v1 语义。回退程序前需保留数据备份，新包覆盖测试保持 UserData；不得为“降级兼容”重写会话快照。

## 5. 模型投影、来源、预算

在稳定引擎规则中解释结构含义；作者文本继续是 user 数据，不进 system、不覆盖 JSON/玩家行动权/知识范围契约。profile 中保留独立的 description/personality/scenario/dialogue_examples，并明确 semantics 标识。first_message 在本片只作 UI 资料，不发送给 character.reply；这避免把尚未选择的作者话语诱导成已发生对话。

示例整体放在独立字段，固定说明“仅表达参考；非本次历史、非共同经历、不可引用为账本证据”。不给 message_id/turn_id，不解析 `<START>`、角色标签或宏为运行消息，不加入 allowed_messages/projected_entry_ids。对 source 类型的现有限制不放宽。作者资料对人物设定有参考意义，但不直接制造共同经历/知识账本；模型的所有新记录仍须满足现有正式消息证据。

文本冲突不由程序或另一个 LLM 重写：人物设定优先于示例的说话习惯；场景提供起点，不能覆盖已正式发生的后续事件；所有卡片都不能覆盖引擎约束或替玩家行动。资料区分项可查看并注明“字段如有矛盾，请在源卡修订后新建对话”；不开发不可靠的自动语义冲突检测。

外部 system_prompt、post_history_instructions、extensions、脚本、宏、内嵌世界书保持不激活、不联网、不求值；已知资料字段里出现相同文本也只当数据。不给“所有提示词攻击已解决”的保证，以确定性投影和执行面隔离作验收。

预算冻结为最小改动：

1. 权限过滤在相关性选择/预算前完成，既有账本与世界书规则不放宽。
2. name、description、personality、scenario、稳定规则、本轮输入及至少2个现有近期完整回合是必需集合；少于2回合时保留全部，不伪造回合。
3. 预算超限先沿既有次序移除可选相关世界条目，再按稳定参与者顺序移除完整 dialogue_examples 字段（一次整个字段，不逐字截断，不转成历史）；记录仅 participant ID/字段名的 omitted 元数据，不含正文。
4. 再沿旧完整回合→账本顺序缩减；不删必需人设/场景。示例先于历史裁剪，first_message 本就不在模型请求，不耗运行上下文预算。
5. 仍不适配则 CONTEXT_LIMIT、零供应商调用；保留草稿、资产和历史。无压缩/修复LLM或自动重试。字符限额与实际请求token预检是不同保护，不能以通过字符校验宣称一定可发送。

稳定字段排序、source hash与内容无关的省略信息可复用已有请求观测；不新存私聊日志，不承诺缓存命中或真实质量提升。

## 6. 最小编辑权威路径（选择显式退回自由文本）

本片不建设结构化作者工坊。现有编辑器/角色工坊继续编辑兼容自由文本，结构卡在进入编辑时清楚显示：**“此卡含独立字段。修改描述或开场并保存/发布后，将转为自由文本；现有对话不变。原始导入资料仍保留。”** 编辑器先提供分段只读预览，再提供明确“转为自由文本编辑”的用户动作，保留合并全文作为起始草稿，取消不写盘。工坊在编辑/发布位置展示同等提示，应用草稿与正式发布仍分离。

所有写入口共用服务端协调规则（全局保存、局内保存、工坊发布），不能仅靠 UI：

- 请求显式提供有效 role_fields：结构是权威，派生兼容字段覆盖请求中的旧 description/starting_scene；不能让 stale 兼容文本盖过结构。
- 请求提供 role_fields:null：清除结构语义，保留请求中编辑后的自由文本和已有 `_external_import`。
- 请求未提供 role_fields，但真正改变 description 或 starting_scene：若旧资产有结构，则原子写入 role_fields:null。此为兼容旧客户端/既有工坊的确定性协议；不能保留过时结构。
- 仅 tags/portrait/is_player/name 或未实际改变文本：保留结构，不因无关编辑降级。比较须基于当前权威值与正常化后的提交值，不仅看 payload 是否带字段。
- 工坊以 base→draft 实际文本变化判断，undo 回 base 后发布不能误清除。结构信息应进入修订冲突比较或独立冻结指纹，防止工坊期间另一入口更新 role_fields 后被 stale 发布覆盖；不把 source 全文暴露给工坊模型。
- 更新失败、非法结构、冲突时保持原文件/结构，草稿留在UI；不自动转模式或重发模型。既有原子保存与错误机制复用，不借本片扩成通用资产数据库。

编辑转换只影响后续新会话。需要恢复结构时重新导入原文件为独立资产；不从过时 source 自动恢复，不新增撤销历史系统。

## 7. 最短 UI 路径

工坊/资产库导入 JSON 或 PNG→预览显示五项映射、原开场“仅资料”、隐藏能力“不执行”→保存→角色页卡片选择→新建→玩家先发言。无需新建时填写精神内核/开场选择。已有搜索卡片、可选世界书入口和两种表现保留。

当前会话右栏对 v1 参与者显示独立折叠项：人设、性格、场景、对话示例、作者开场；空项可隐藏。示例固定标“非历史”，作者开场固定标“仅资料，未发送”，不出现于聊天气泡、末条预览、未读、水位、turn_count。旧会话继续原资料显示。结构资料来自冻结投影，不读取当前资产库；若 first_message 不在模型投影，应由安全 detail/UI 白名单独立返回，不复用完整 snapshot 或 source 暴露接口。

所有作者文本使用安全纯文本/现有受限渲染，不执行 HTML、远程图片或宏。宽窄屏可展开和选择全文；不新增复制按钮、第二套资产列表或会话中换卡。

## 8. 必须落地的实施与验收

先领域纯函数/创建标记与预算→导入及全部写入口→最小UI→专项、完整回归和包验收。API只映射，service保持动作事务，Workspace只组合。

1. V1/V2/V3 JSON及PNG、缺失/空字段、Unicode、非字符串、未知版本/键、上限与总量/兼容文本边界。确认原 source 保留、预览准确、失败无资产写入。

## 9. 合成角色质量场景（本片准备，不付费评测）

已提供`tests/fixtures/character_quality_i1.json`：两角色、六场景、两表现、自由/结构两形态；`test_quality_fixtures_preserve_profiles_without_claiming_model_quality`检验48组请求资料完整及无伪历史。这是可重复的输入基线，不是对真实模型人格表现的评分。误会纠正与承诺连续的真实多回合质量仍待人工评测。

用可提交的隔离夹具：角色A“谨慎守约的修复师”、角色B“热情但重利益的商人”，各自由文本/结构导入两形态，名字和私密哨兵均为虚构；同场景×两角色×messenger/roleplay。固定scenario和与正式情境无关的示例，避免测试只看关键词复述。

| 场景 | 需要人工判断的行为 | 程序可证明的边界 |
| --- | --- | --- |
| 个人立场 | 两角色有不同但可理解的选择 | 独立persona字段、正确参与者快照 |
| 利益冲突 | 不因玩家要求立即放弃自身目标 | 输入保留性格且不被示例覆盖 |
| 未公开知识 | 不凭空得知未公开秘密 | 权限过滤和隐藏哨兵缺席 |
| 误会纠正 | 区分曾听闻、相信和纠正 | 正式来源、supersede及undo可逆 |
| 承诺连续 | 后续自然记住正式承诺，非样例承诺 | 引用仅正式消息、无示例记忆 |
| 用户控制权 | 不代写玩家对白/决定/动作 | 开场不入turn，规则与history隔离 |

自动夹具验证模型实际收到什么及存储事务，不用固定假回复证明人格可信。记录样例输入、预期失败模式、引擎版本和合成结果；真实评测日后需单独授权，记录模型/参数/提示词版本、费用和逐条反例，不以拒绝率/字段数量做“活人感”分数。

## 10. 后续 M：复用基础设施，不复制故事全知语义（仅方向）

可复用的是预算/完整片段选取思路、存档与工作集分离、原子提交基础及低频调度经验；先适配纯帮助函数，不在I1抽通用父类。不可直接把 StoryMemoryManager 的全知章节脊柱、裸字符串核心记忆、故事任务事件或全文trace搬进角色会话。

M设计门仍需冻结：
