# 46 多世界书捕获归属

2026-10-23；P1 功能升级；设计冻结，实施中，目标 dev.28 实际打包发布。

## 玩家目标与边界

新知识进入合适的局内书，修改与废止回到原书，不再按文件名选择第一本。继承24/35/45，不开发世界融合、跨书移动、主动扩写或全局同步。

## 分工与一次请求

- Python 提供启用书的文件标识、主书身份、收录主题、概述、公理与条目；不提供捕获历史。现有后台捕获一次请求同时识别变化和归属，不另加分类请求。
- AI 为每个候选输出 target_book_id、target_entry_id（修改/废止）、归属理由。基础规则优先主书，明确专门知识进入对应知识书；交叉、同等匹配或不确定新增用空目标进入本局自动设定。
- Python 只接受目录内的目标；修改/废止必须精确匹配书和条目，不能靠同名猜测。无效修改跳过并记录，绝不转成新增。无效新增目标退到自动书并待审。
- 单书保持原请求格式和验证链；多书不静默删减目录，超出模型预算由现有请求层报错，不声称已完成。

## 数据与生命周期

收录主题是可选的书籍元数据，用于分类，不是世界公理；旧书留空仍可根据概述分类。只写存档副本。沿用条目审阅、来源回合指纹、历史投影与人工编辑保护。

请求前冻结各书版本和主书选择；写入前核对。主书选择变化则整批弃用；目标书变化则该书不写，其余书独立提交并分别报告。不引入跨文件事务系统。撤回后迟到结果不写。自动书仅在需要兜底时创建；玩家关闭自动书时不重新启用，相关候选跳过并记录。

## 界面

世界书编辑的概述附近提供可选“收录主题”及简短说明。现有局内书条目和待审列表显示结果；后台日志逐书记录目标、自动加入、待审和跳过，不把部分成功宣称为全部成功。无需新增常驻面板或弹窗。

## 顺序与证据

1. 纯归属验证与一次调用编排；准确原书修订、兜底与关闭策略。
2. 收录主题编辑和旧数据保留；接入后台调度。
3. 单元、真实HTTP假模型与浏览器验证：主书与知识书不同新增、同名条目定位、非法目标、人工编辑、撤回、单书兼容。
4. 回归、分类更新日志、升版、EXE/ZIP、Git与Release附件验证后收口。
