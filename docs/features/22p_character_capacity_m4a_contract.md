# M4a：有界容量可见与生命周期说明

2026-10-05，Astra设计，承接22n/22o。原设计门已冻结；用户随后启用目的模式，本最小片源码与验收已完成：Python581/Node102/可见性/155模块构建/Edge37，专项与宽窄视觉通过。详细证据见TESTING/ACTIVE，不以合同本身证明实现。不是扩容/迁移，不升版本、打包、改玩家数据或发布。

## 1. 结论、主线与玩家价值

现有单文件持久化足以交付一个独立可验收切片：**玩家能看到当前公开聊天容量、接近限额时提前获知、知道哪些操作确定受限，以及为什么撤回/取消高光不是清理空间**。不需要新存储格式、后台线程、模型调用或用户重大产品选择。

它不能把当前角色模式变成无限长期聊天，不能解除128活动记忆/2048账本/512正式回合，也不能保证临界点后的模型结果一定能提交。M2完成→M4a容量可见→后续已冻结切片；真正M4b扩容另过下面的生命周期工程门。不要因完成一个容量面板宣称长期记忆容量已解决。

已复核22n记录：OOC使用台词框上方按钮展开的小文本框，不用符号；主动联系仅当前会话授权，同卡其它会话仍关闭。两项产品门已闭合，C3/C5工程门独立，本片不改M2协议或提前实现这些功能。

## 2. 源码事实与不能误导的地方

读取了repository.py、models.py、service.py、contract.py及errors.py：

- 一个会话一个JSON，读取最多32MiB+1字节，完整验证，候选深拷贝后同目录临时文件/fsync/replace。不是数据库或分段档案。
- 正式turns≤512、ledger总条目≤2048、requests≤2048、attempts总数≤4096、active ledger≤128、extensions≤32KiB、整个文件≤32MiB。M2注解也计入现有文件，手动重要8、取消根128另有设置上限。
- 每个请求最多6 ledger ops，supersede追加一条并使旧条失活；active数可能不增，但ledger总数仍增长。删除/失效注解或取消自动重要不删除原账本。
- 撤回/重生成保存archived_turn及inverse；撤回可能降低当前turns/ledger，但会新增action/attempt，不能保证文件更小或释放总生命周期容量。旧attempt不能从计数中偷偷消失。
- service在provider调用前已检查requests2048、attempts4096；到顶会影响send/retry/regenerate/undo。512只阻止新的send，不能据此禁止合法末轮regenerate/undo。
- active128或ledger2048处仍可能提交ledger_ops为空的回复；不能把“一个记忆维度到顶”误报成所有发送都不允许。反之，不得强制模型返回空ops来伪装解决容量、丢弃合法新增记忆后只保存正文。
- 文件保存失败或终态保存失败仍有原子替换/只读恢复边界。容量面板不是文件系统可写保证，更不是备份。超过大小/损坏/未知schema的文件不能靠诊断绕过原读取保护。

## 3. 最短UI与非目标

当前会话设置新增折叠“容量与保存”区：显示公开正式回合数/512；技术记录可展开查看请求数/2048、尝试数/4096；列出固定上限说明。常规聊天无需配置。

接近任一容量时显示一个不抢焦点、不弹窗的提醒，链接到该区。只描述“接近当前版本的保存上限”或“部分操作已达到上限”；不出现“角色即将忘记你”、精确剩余可聊轮数或“删高光就能解决”。normal时不常驻警告条。提示随当前服务端状态变化，重载不累积通知，不追加独立通知确认账本。

内部记忆/文件/扩展只呈现合并的空间压力状态，不展示私有记忆数量、剩余条数、分项百分比、精确文件字节或可反算私有内容的明细。已存在公开记忆仍在原面板查看，不拿公共面板条数冒充总账本使用率。

非目标：清理按钮、自动归档/摘要/付费压缩、提高常量、私聊扫描、跨会话搜索、续聊记忆自动搬运、直接导出全部内部JSON、关闭记忆强行续聊、改变撤回范围。本片不增加“删除旧记忆腾空间”操作。

## 4. 确定性报告与接口冻结

新增只读`GET /api/v1/character-sessions/{sid}/capacity`，不接收正文/任意文件路径/额外query参数。使用该sid当前合法权威快照，禁止枚举其它会话或读取玩家数据目录作统计；load/验证仍沿repository，未知schema按现有只读错误返回，不自行解析未来字段。

响应严格为：

```json
{
  "session_id": "UUID",
  "revision": 0,
  "version": 1,
  "public_counts": {
    "formal_turns": {"used": 0, "limit": 512, "state": "normal"},
    "actions": {"used": 0, "limit": 2048, "state": "normal"},
    "attempts": {"used": 0, "limit": 4096, "state": "normal"}
  },
  "recording_pressure": "normal",
  "operation_capacity": {
    "send": "not_known_blocked",
    "retry": "not_known_blocked",
    "regenerate": "not_known_blocked",
    "undo": "not_known_blocked"
  }
}
```

所有count/state来自同一冻结快照；版本1为只读响应格式，不写入会话扩展。used/limit为非布尔整数；state和recording_pressure枚举normal/near/at_limit。使用整数比较`used*100 >= limit*80`为near，`used >= limit`为at_limit；80%是可逆UI预警阈值，不是自动维护触发器。仅各项现有硬限额校验通过的会话可返回。

recording_pressure取active ledger128、ledger总2048、序列化会话32MiB、extensions32KiB的最高压力档，**只返回合并枚举，不返回来源维度或私有计数**。序列化复用json_bytes规则，只对已读的有界会话做一次，不额外扫描来源、分支、历史或磁盘；只是当前规范化保存体积，非剩余磁盘容量。实现可以重用本次读取/验证已有计数，但不能跨revision缓存成权威。

operation_capacity仅两种值：`not_known_blocked`、`blocked`。blocked规则只复用当前确定性硬门：requests或attempts达到上限时四种都blocked；否则正式turns达到512仅send blocked。not_known_blocked不是允许/保证成功，也不代替pending/busy、目标回合、token预算、权限和协议验证；不因recording_pressure=at_limit额外硬禁发送。

actions/attempts是会话技术操作记录，只返回总计，不返回请求ID、操作内容、失败草稿、时间或私有来源。私有记录不影响公开formal_turns计数；pressure只透露必要的操作性容量状态，不是私有记忆统计接口。若后续数据模型改变这些计数的隐私性质，必须重过投影门。

成功新会话/正式提交/撤回/记忆设置改变后，前端按需刷新该GET；在区块打开或已有容量警告时刷新即可，不每秒轮询、不每token刷新。请求开始、SSE预览、失败attempt同样可能改变技术计数，生成终态后重取。请求/attempt状态改变可能不推进领域revision，所以**不能仅用revision缓存失效**；每次GET现算，客户端以session_id与本地fetch序列丢弃迟到响应。

## 5. 生命周期与错误体验

现有hard-limit守卫保留，确定被挡的请求零provider调用。服务端仍是权威；UI不能把旧report当永久许可或永久禁止。不要只禁按钮而不给理由；show blocked后提供“刷新状态/查看容量”，保留输入草稿、来源查看、既有记录阅读及合法删除入口。

`SESSION_LIMIT`说明更新为中性且真实：“已达到当前会话的某项记录或保存上限，本次未完成；原有内容保留。可查看容量说明。”不一律宣称所有原文可读（损坏/超大文件另有读取失败），不以“新建对话继续”暗示记忆自动继承。只有当前合法session可打开时附加可查看的UI入口；错误信封仍不返回原始路径/正文/私有容量原因。

容量片不得改写ledger_inverse、删requests、重编号消息或回收superseded证据。撤回使public_count降低时正常刷新，但提示明确归档及操作记录仍占空间；取消自动高光和手动重要最多改变其设置空间，不宣称释放记忆槽。到限额仍保留数据，绝不自动新建会话或复制私聊。

保存/终态失败仍沿既有原子事务恢复，不新增“忽略容量保存”的旁路。靠近32MiB时是否需要保留终态/撤回专用字节与记录余量，是M4b工程门；本片不承诺所有满载会话均能再撤回或恢复写入，也不擅自提早降低业务硬上限。若合成验收发现真实不可恢复的pending，应作为P0另开修复，不把它藏在正常容量提醒里。

## 6. 模块边界、性能与验收

独立capacity纯函数从已验证快照派生报告；API只映射白名单，repository保持存储职责。允许提取既有限额为共享常量，但数值不变，不复制“UI上限”和“真正上限”两套来源。前端api/store负责GET与迟到隔离，独立小面板负责解释；不新增provider路由或提示词。

合成测试至少：

1. 0/80%阈值前后/等于上限，中文UTF-8与JSON转义体积；每个维度独立触发near/at_limit，公共响应无内部维度和私有计数。
2. 正式512时仅send blocked，regenerate/undo仍由既有条件决定；requests2048/attempts4096四种blocked且实际provider为0；active128或ledger2048仅pressure，空ops仍按原契约可提交，非空超限仍整轮失败。
3. supersede总数增长、取消高光不减少账本、撤回/重生成归档仍占空间；failed/cancelled/retry增加技术记录但领域revision可能不变，打开面板/终态刷新不呈现旧缓存。
4. 只读GET前后文件hash、mtime、revision相同；不迁移v1/v2、不扫描别的会话、不读取私聊夹具；未知schema/坏文件/已删除/未来memory版本遵循既有错误。
5. 迟到响应/切会话/删除、区块折叠与网络错误，失败显示“暂时无法读取”而非0/正常；保留用户草稿；宽窄布局与键盘入口。
6. close-to-limit合成大文件只做有界读取/计数，无额外模型调用和后台任务；正常路径每次GET最多一次规范化整会话序列化，不在会话列表批量统计全部文件。

窄测后运行项目Python/Node/build/完整Edge，主代理更新实际证据。原设计阶段没有运行以上验收；实施后仅引用M4a实际证据，不引用M2专项冒充本片通过。满足容量可见/解释和守卫回归即停止本片，不扩展成存储重构。

## 7. M4b真正扩容的下一门与重大产品选择

后续需要工程冻结：正式原文分段/索引与当前工作集分离、版本化manifest或事务数据库、原子提交/恢复、旧格式保全与迁移回滚、撤回源与active状态、失败attempt档案、删除墓碑、可重建索引、磁盘预算与临界点终态余量。这些可以由工程设计选取实现，不把数据库选择本身甩给玩家。

以下才是不能擅定的产品行为：

- 是否仍只允许末轮撤回，还是要求跨归档历史撤回/分支；本阶段保持现有末轮语义，不自动扩展。
- 原文/失败attempt保留期限与磁盘预算达到后怎么办。现有方向是原文不丢；未经授权不能以过期清理、裁剪旧回合或转移到新会话解决。
- 若需要LLM摘要，是否允许额外收费及预算/触发；尚未批准，默认无自动付费压缩。纯确定性索引不需要新增收费授权。
- 若提出“续聊新会话继承记忆”，必须明确身份、范围与授权；同卡默认不共享，新会话不自动继承主动联系权限。

这些未决点不阻止M4a，不表示必须立即问完才继续C3等独立片；M4b若能保持原文、末轮撤回、单会话身份和零新增模型调用，则可进一步形成工程合同而无需凭空制造产品问题。当前只冻结M4a，不据此提高上限或宣布M4b已批准。
