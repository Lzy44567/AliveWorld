# 世界包与一键游玩

## 为什么现在做

AliveWorld 已经具备世界书、角色、文风、实体、因果账本、记忆、偏好、工坊和生图，但这些能力首先以“可自由配置的工具”出现。自由度越高，空白页负担越重；新玩家既不知道应该创建什么，也未必知道普通 AI 故事常见的平庸化、遗忘和世界停滞问题，因此无法仅凭功能名称理解 AliveWorld 的价值。

下一阶段不继续横向增加编辑器，而是把现有能力组织成可以导入、预览、安装和一键开玩的完整内容。首版不建设账号、评分、评论、审核或推荐算法；世界包先作为本地文件通过 QQ、Discord、GitHub Release 等渠道分享，等创作者和内容规模真实出现后再建设社区中心或 Steam 创意工坊。

## 玩家闭环

### 使用已有内容

1. 玩家打开“世界包”页，看到已安装世界和随包演示内容。
2. 选择一个世界包，阅读面向体验的简介，而不是先理解世界书、实体或账本术语。
3. 点击“一键开始”，系统从包内起点创建独立故事，并载入推荐资产与局内设置。
4. 玩家可以稍后进入高级资产栏检查或微调；不要求第一次开始前逐卡配置。

### 创作与分享

1. 创作者在现有工坊中完成世界书、角色、文风和实体。
2. 点击“创建世界包”，勾选要包含的资产；系统自动补全被引用的依赖。
3. 系统显示内容、缺失依赖、同名风险、成人标签、许可证和隐私扫描结果。
4. “导出世界包”只生成本地文件；“发布”属于未来社区动作，必须独立按钮和再次确认，不能把本地导出等同公开上传。

## 首版包结构

建议扩展名暂定为 `.aliveworld`，物理格式使用 ZIP，但玩家不需要手工解压。

```text
manifest.json
worldbooks/
characters/
styles/
entities/
images/
workflows/
starter/
```

`manifest.json` 至少包含：

- 稳定的 `package_id`、包版本、名称、作者和简介；
- 标签、成人内容标记、许可证与最低 AliveWorld 版本；
- 资产的稳定 ID、类型、相对路径、内容哈希和引用关系；
- 主世界书、默认角色、默认文风与可选实体组合；
- 可选故事起点、推荐局内设置和可选状态面板定义；
- 原始下载/更新来源；不保存作者本机绝对路径。

首版明确排除：

- API Key、模型连接密钥和账号信息；
- 玩家偏好卡、私人日志、已有游玩存档和记忆切片；
- 未经明确审计的可执行脚本、插件和二进制文件；
- 创作者 `UserData` 中未被选择的任何内容。

ComfyUI 工作流属于可选高级资源。导入时必须说明可能依赖外部模型和自定义节点，缺失时不阻止纯文字世界启动。

### dev.1 已冻结的技术契约

- YAML 资产首次参与打包时写入 `_aliveworld.asset_id`；重命名保留 ID，克隆必须生成新 ID。ID 不再依赖显示名称或文件名。
- `manifest.json` 使用 `schema_version: 1`，入口与依赖只引用包内稳定资产 ID；缺失依赖、循环依赖、重复 ID 和重复路径均拒绝导出或导入。
- 导出格式是确定性 ZIP：固定时间戳、规范 POSIX 相对路径、逐文件大小与 SHA-256。相同 `package_id + version` 但内容不同的包拒绝静默替换。
- 隐私扫描同时检查源路径、资产正文和 manifest；密钥、用户绝对路径、存档、日志、偏好、工坊草稿、模型目录和可执行文件不能进入首版世界包。
- 导入先完整检查路径穿越、文件数、大小、异常压缩比、清单一致性和哈希，再原子落盘到 `data/world_packages/installed/<package_id>/<version>/`。
- dev.1 导入只建立本地已安装内容与安装账本，不把包内卡片静默复制成个人全局资产，也不启动故事。冲突预览、实例化局内副本、一键开始和安全卸载属于 dev.2。
- 安装账本记录包哈希、manifest 路径、资产 ID、类型、原始哈希、落盘位置和修改标记；后续卸载只能依据账本与引用关系，不能按名称猜测所有权。

### dev.2 已实现的玩家闭环

- 游戏右侧默认入口调整为“开始与世界包”；没有安装内容时仍明确保留“空白故事”，不会强迫老玩家使用世界包。
- 导入前先显示名称、版本、内容数量和版本关系。不同来源的同名包允许并存但明确提醒；相同包 ID 与版本却内容不同则拒绝覆盖。
- “一键开始”把包内非可选世界书、角色、文风和实体复制到新故事自己的目录，再创建会话；故事保存 `world_package.json` 溯源，但以后不依赖安装目录继续运行。
- 起点 JSON 可以给出梗概、开场和推荐局内设置。玩家创建的故事仍使用完整现有游戏循环，不共享作者聊天记录。
- 默认安全卸载会把安装目录移入本机恢复区，并把玩家改过的资产另存为个人资产；已经创建的故事不会随包删除。另有“仅移除记录”和需要明确确认的彻底移除协议，玩家界面首版只开放安全卸载。
- 包详情会报告已修改与丢失的安装资产；一键开始前重新校验实际文件哈希，损坏内容不能进入新存档。

## 世界包不是存档

世界包描述“如何开始和运行一个世界”，存档描述“某位玩家已经玩到哪里”。一键开始必须从包生成新的独立故事，不能让多个玩家共享同一个可写存档目录。

首版可包含故事梗概、开场场景、推荐设置和初始状态，但不包含作者的聊天历史。以后若允许发布示例回放，也应作为只读演示资产单独标记。

## 安装记录与安全卸载

需要提供“一键卸载世界包”，但不能按名称粗暴删除所有同名文件。系统必须为每次安装建立安装账本，记录：

- `package_id` 与安装版本；
- 每个安装资产的稳定 ID、原始哈希和落盘位置；
- 资产是否被玩家修改；
- 是否被故事、其他世界包或局外资产引用；
- 世界包更新产生的版本关系。

卸载提供三个语义清晰的选项：

1. **安全卸载（默认）**：删除仍保持原始内容且没有外部引用的包资产；保留玩家修改过或仍被引用的资产，并将其转为个人资产。
2. **仅移除世界包记录**：保留全部已安装资产，只取消包的安装/更新关系。
3. **检查后移除关联资产**：显示逐项清单和影响范围后再删除；现有故事存档默认永不随包卸载删除。

多个包共享同一依赖时，只有最后一个引用解除后才允许删除。任何卸载都先生成可恢复清单；不能用文件名或显示名称作为唯一删除依据。

## 导入冲突与更新

- 相同 `package_id` 且版本更高：作为包更新，先显示变更摘要。
- 不同 `package_id` 但资产同名：默认并存并提示重命名，不静默覆盖。
- 相同资产 ID 且本地未修改：允许升级。
- 相同资产 ID 但本地已修改：保留本地版本，提供对比、另存副本或显式覆盖。
- 包更新不能重写由该包创建的玩家存档；存档持有自己的局内副本和状态。

## 与酒馆生态兼容

兼容层与 AliveWorld 内部格式分离。首版优先支持：

- Character Card V2/V3 的 PNG/JSON 导入；
- 卡内 `character_book` 与常见 Lorebook JSON；
- 角色基础字段、标签、首条消息、系统提示和附加图片的可解释映射；
- 无法映射的扩展字段保存在导入报告中，不假装已经生效。

酒馆角色卡可以成为世界包的一部分，但“导入一张角色卡”不自动生成暗流实体、因果账本或完整世界。需要由创作者或工坊明确升格和补全。

## UI 信息架构

不在世界包 MVP 前重写全部三栏界面。先调整首次入口和信息层级：

- **开始/世界包**：默认面向玩家，展示已安装内容、演示世界、继续故事和导入世界包。
- **游戏模式**：保持当前正文与局内资产三栏工作区。
- **工坊模式**：面向创作者，负责制作资产和导出世界包。
- **高级资产管理**：保留逐卡编辑、局内/全局作用域和调试能力，不在新手首屏展开。

世界包卡片首先回答“会获得什么体验”：角色是否具有长期行动、世界是否会在幕后变化、是否含生图/成人内容、故事规模和预计配置难度。不要用 Overseer、RAG、贝叶斯等内部术语作为卖点标题。

真正需要重排的是入口与渐进披露，不是立刻更换配色或重写所有卡片。等两套官方世界完成后，再以真实世界包内容检验首页、包详情和一键开始布局。

## 新手教程的职责

教程不要求玩家先学会创造世界。首个闭环只包含：

1. 配置并测试一个正文模型；
2. 选择演示世界包；
3. 一键创建故事并发送第一回合；
4. 认识“继续故事、查看日志、保存位置”三个入口。

角色、世界书、文风、实体、记忆和 ComfyUI 分别提供按需短教程。介绍 AliveWorld 价值时使用可观察结果，例如“角色会根据过去改变计划”“玩家未到场时世界仍会发展”，而不是只列模块名称。

## 首版验收

- 全新 `UserData` 可以导入一个世界包并在三分钟内开始第一回合；
- 包内资产依赖完整载入，重启后仍可继续；
- 相同包重复导入不会静默制造重复或覆盖修改；
- 安全卸载不删除玩家存档、玩家修改资产或其他包共享资产；
- 导出的包不含密钥、日志、私人存档、偏好和绝对路径；
- 无 ComfyUI 的电脑仍能运行含可选工作流的文字部分；
- 酒馆格式导入给出成功、降级和未支持字段报告；
- 自动验收覆盖导出、导入、一键开始、更新冲突、重启恢复和安全卸载。
