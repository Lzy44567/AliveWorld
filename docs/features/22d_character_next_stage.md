## 顺序与停止门

1. P1质量基线：准备自由文本和兼容卡的合成样例，覆盖个人立场、利益冲突、未公开知识、误会纠正、承诺连续、用户控制权。同场景比较两角色和双表现。程序验证输入/来源/持久化，实际输出内容由玩家或另获授权的评审判断；不以拒绝率、人设字段数量或假模型固定回复衡量活人感。不自动发起付费调用。
2. P1设计候选I1：人设、场景、示例、开场语义分离，保留原文和自由文本支持；不强迫作者填写精神内核。先冻结下面的产品选择和迁移/预算，再编码，不悄悄改已有会话快照。
3. P1长期记忆设计：证据原文永久保留，取材不等于存储；区分事实、他人声称、信念、经历、承诺与关系。确定检索、合并、纠错、撤回、预算及失败降级。不能直接套用故事摘要，也不默认每回合增加分析模型调用。
4. P2继续后置：长期性格演变、内核提炼、语音图片、群聊、故事NPC复用。优先解决实际验收P0/P1，不借新增灵感替换本主线。

## I1仍需设计的产品决策

- 导入卡开场：是否允许用户选择采用原开场；若采用，如何标记非真实玩家行动，如何撤回，是否触发账本，即时聊天与情景扮演分别如何呈现。原开场不得默认替用户确认其动作。
- 示例对话：是表达参考而非已发生历史，不为示例建立关系/记忆。宏只允许明确白名单的纯文本替换，不执行脚本，不自动提权。
- 可选内嵌世界书：显式载入与知情范围、预算、来源标签；不自动将全部隐藏规则暴露给角色。
- 冲突：引擎操作契约不能被卡覆盖；人设/场景/示例矛盾需要可见提示或明确优先规则，不由模型静默重写原卡。

## 数据与工程边界

源卡属于资产，运行资料属于创建快照；新结构以可选字段/明确版本演进，不直接批量改写旧卡。旧会话继续旧快照，任何升级需预览/备份/失败保原件。适配器只管归一化，角色上下文只管模型投影，服务只管动作事务，UI不承担新记忆权威；不抽象成通用agent平台。

费用、隐私及恢复不改变：本轮仅设计/合成夹具规划，不访问玩家私聊，不上传卡，不运行真实付费评测。后续最短验收路径仍为角色→选卡→聊天；高级语义与记忆不能成为新手必填表格。

完成证据要求：冻结字段映射和兼容样例、输入投影与预算测试、示例不冒充历史、开场不越权、旧快照不变、失败/撤回和流式回归。内容评测单独记录模型/参数/成本和具体反例，不宣称代码测试证明人格可信。
