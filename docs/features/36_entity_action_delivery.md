# 暗流实体行动与账本一致性：实施范围

日期：2026-10-17。依据30/31及既有01/02。35已完成，本轮另开板块，不重做世界书。

## 玩家目标与边界

幕后实体依据自己的认知、资源、目标行动；计划不等于成功事实。角色改名或死亡不抹去身份历史，已派出车队等布置按依赖继续。玩家仍在已有暗流实体详情/账本入口查看；默认不新增幕后弹窗。

本轮不增加每人独立调用、不做复杂跨日调度、普通路人自动补全或完整图谱；不改变重大角色死亡的既有授权策略。新死亡保护默认值待后续产品确认，不能用这次结构升级默认授权随机杀死重要角色。不打包/升级/推送、不读取玩家存档。

## 现状证据

- entities.py有动机、计划、近期行动等；entity_repository按名称存文件。
- undercurrent.py通过名称找行动对象，delete_entities物理移除模型中的实体。
- causal_ledger已有稳定影响ID与remove/release/keep来源死亡策略，来源仍是名称。
- shadow_ledger记录tick、名称和文字，未明确计划/事实和故事时间。
- GameSession正常及重生成均已有单次暗流调用、状态导出与回退路径，优先复用。

## 模块与阶段

1. 身份与生命周期：Entity拥有稳定ID及生命周期；既有无ID数据按旧身份生成可重复ID，真正保存后持久化。改名保持身份，克隆必须新身份。账本逐步引用ID，名称保留用于显示。死亡/停用不等于玩家删除。
2. 行动结果：模型输出区分计划、已执行行动/布置、事实，并给简短依据与信息来源；程序维护引用、一次应用和保存，不将模型倾向称为校准贝叶斯概率。复用因果账本，不新建第三套计划库。
3. 上下文：实体只读取自己的知识和必要世界约束；GM裁定材料与角色已知分区，上帝视角只影响显示。既有计划摘要不被当作已完成事实。
4. 玩家流程：现有实体与账本UI显示当前状态、计划/事实、来源；假模型真HTTP验证改名、行动、死亡后影响存续、存取/撤回/重生成；浏览器核对权限显示。

每阶段先专项验证；整块完成时一次风险相称的广泛回归。不得用新增字段/单元测试代替玩家闭环交付。

## 存储、失败与迁移

本局实体和账本随故事保存，模板不自动回写。稳定身份只在所属故事解释，不跨故事自动合并人物。旧字段保留兼容，不猜未记录的知识或事实。模型外部输入在暗流入口校验，领域代码不铺重复防御分支。失败或撤回复用故事事务恢复，不引入另一个后台写盘通道。实体删除与依赖处理必须保留可追查来源，不连带抹去其他参与者事实。
