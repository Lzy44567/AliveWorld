# 提示词分层、变量注册表与 v1.5—v1.6 遗留审计

更新：2026-09-13  
状态：设计完成，尚未授权实施提示词重构

## 本轮边界

本轮只修复特殊气泡复制按钮和多行文本全屏编辑，并完成提示词架构审计。不得在没有等价性测试和迁移清单时直接删改正文提示词，也不得让新想法取代已确认的玩法主线。

## 当前代码事实

1. `core/prompt_studio.py` 目前登记 10 个切片，只有近期未来、正文结算、玩家行动权和连续性共 6 个切片可覆盖。
2. 状态栏并未丢失：`system_prompts.yml` 的 `settlement_prompt` 同时包含 `dynamic_bars`、`status_updates`、`npc_states`、Buff 和删除字段的说明及 JSON 结构。但它仍被包在 `story.settlement.core` 内，没有独立分区，因此开发者工作台无法单独查看、估算或覆盖状态栏协议。
3. 世界书捕获、工坊、暗流、记忆、偏好和生图提示词仍由各自模块拥有；注册表目前只显示其中两个“尚未迁移”的占位项，不是完整总入口。
4. “警察、保安、公序良俗”等文本同时出现在未来核心、正文核心和连续性切片中。它来自真实游玩缺陷修复，但重复且过于贴近单一案例。
5. 当前变量只使用 `world_info`、`character_info`、`style_info` 等少量字符串名；没有统一描述变量来源、类型、敏感性、空值语义和可用任务的注册表。

## 目标分层

提示词按职责分五层，分层不增加模型请求：

| 层 | 内容 | 可否被普通预设关闭 |
| --- | --- | --- |
| A. 引擎契约 | 输出结构、字段类型、玩家与系统权限、状态事务、后端依赖的不变量 | 否 |
| B. 玩法模块 | 状态栏、随机未来、暗流兑现、世界书捕获、快捷行动、偏好、记忆 | 对应玩法关闭时整片移除；必需校验仍由 Python 保留 |
| C. 体验预设 | 节奏、反套路、避免重复执法介入、描写倾向、俗称“预设/破限”的自定义内容 | 是，关闭后不得继续拼接 |
| D. 世界与角色资产 | 世界书、角色卡、实体、文风、已确认偏好和世界包建议 | 随载入状态决定 |
| E. 本回合数据 | 历史热窗口、记忆摘要、玩家行动、选中未来、待兑现影响、当前状态 | 每回合动态生成 |

玩家行动权的“不得替玩家做重大决定”属于 A 层权限契约；“不要反复引入警方”属于 C 层体验优化；“外部介入必须存在信息通道”属于 A/B 层通用连续性约束。这样可以删除案例重复而不撤掉真正的因果规则。

## 变量注册表

新增唯一 `PromptVariableRegistry`，提示词切片只能引用已登记变量。每个变量至少记录稳定 ID 与中文名称、值类型及渲染器、数据所有者和允许任务、空值语义、必需性、敏感级别、可用状态与 token 粗估；示例只用于编辑器帮助，不进入正式请求。

首批命名空间：

| 命名空间 | 示例 |
| --- | --- |
| `story.*` | `story.premise`、`story.history.hot`、`story.memory.summary`、`story.player_action` |
| `assets.*` | `assets.worldbook`、`assets.characters`、`assets.styles`、`assets.entities` |
| `player.*` | `player.character`、`player.preferences.confirmed` |
| `runtime.*` | `runtime.state`、`runtime.selected_future`、`runtime.causal_influences` |
| `rules.*` | `rules.output_schema`、`rules.story_length`、`rules.action_suggestions` |

编辑器后续提供可搜索变量表：显示名称、来源、类型、当前可用状态和用途，点击即可插入占位符；未知变量、必需变量缺失和跨任务越权都在保存前阻止。

### 面向非专业用户的解释层

变量不能只显示类似 `assets.worldbook` 的工程名称。编辑器同时提供两层信息：

- 默认显示中文短名，例如“本回合适用的世界书内容”；
- 悬停问号显示一句话解释、何时有值、空值意味着什么和适用任务；
- 点击变量打开固定说明卡，兼容触屏和无法稳定悬停的环境；
- “查看技术信息”才展示稳定 ID、值类型、来源模块和 token 粗估；
- 点击“插入”把变量写入当前光标位置，不要求玩家手打；
- 当前故事真实内容默认不出现在悬停气泡中，避免侧栏窥视和超长内容；只有开发者主动打开“预览本次渲染值”时才显示，并按敏感级别脱敏。

建议采用 `{{assets.worldbook}}` 作为新模板语法，使变量与普通 JSON 花括号明确区分。迁移期继续识别现有 `{world_info}` 等别名，但保存新覆盖时规范化并提示旧别名对应的新变量。

### 注册信息草案

```text
id                  稳定变量 ID
label               中文短名
description         非专业用户解释
value_type          text / json / list / number / boolean
owner               唯一数据所有者
allowed_tasks       允许进入的模型任务
required            是否为该切片必需
empty_behavior      omit / empty_text / empty_json / error
sensitivity         public / story_private / hidden_system / secret_forbidden
renderer            受控渲染器 ID
cache_class         static / configuration / asset / session / turn
legacy_aliases      迁移期旧占位符
```

API Key、访问令牌和原始密码一律为 `secret_forbidden`，不能注册为提示词变量。注册表只能引用数据所有者提供的只读快照，不能让提示词编辑器直接访问或修改资产文件。

## 模块协作契约

每个模块不再直接向最终字符串随意追加文字，而是贡献声明式 `PromptContribution`：

```text
slice_id / task / layer / slot / priority
requires / provides / conflicts_with
variables / enabled_when / required
editable / cache_class / source_version
```

组装器只负责解析依赖、稳定排序、变量渲染、预算和来源记录；世界书、状态栏、偏好等模块仍各自拥有其数据和规则。模块关闭后，它贡献的可选切片必须完全消失，而不是只在文本中写一句“已关闭”。必需引擎契约缺失、依赖不满足或槽位冲突时，组装阶段直接失败并指出来源，不能带病调用模型。

这保持高内聚低耦合：模块知道自己提供什么，不知道其他模块如何拼接；组装器知道契约，不拥有世界书、角色或状态业务。

## 预设、模型适配与引擎提示词的权限

“模型适配预设”和“内容/破限预设”必须分开：

- **模型适配预设**属于连接层，负责消息角色、JSON mode、prefill、stop、采样参数及供应商能力，不改变世界事实；
- **内容预设**属于体验层，负责节奏、文体倾向、题材表达和可选反套路规则；
- **引擎契约**负责玩家权限、输出 schema、状态事务和模块交互，不允许普通预设替换；
- **世界包建议**只是内容预设候选，安装时显示并由玩家确认，不能静默取得更高权限。

同一体验槽位的确定性优先级为：官方默认 < 世界包建议 < 用户全局预设 < 本故事覆盖 < 本次明确指令。高优先级可以补充或替换同一体验槽位，但不能删除 A 层引擎契约。多个预设若声明互斥槽位，必须让玩家选择，不靠最后拼接者偶然获胜。

开发者可以创建引擎覆盖用于调试，但 UI 必须标记“可能破坏存档协议”，保留版本、差异和一键恢复；Python 侧仍验证 JSON、状态字段、世界书操作和玩家权限边界。

## API 缓存友好的组装方式

缓存是性能优化，不是正确性依赖。当前 AliveWorld 没有供应商无关的提示词缓存契约，因此采用以下结构：

1. 最稳定的引擎契约放在请求最前；
2. 启用周期较长的玩法与模型适配内容随后；
3. 用户预设和载入资产放在中部；
4. 会话记忆与近期历史靠后；
5. 本回合行动、选中未来和临时影响始终位于末尾。

所有切片使用稳定 ID 和确定性排序；静态区禁止加入当前时间、随机 ID、trace ID 或顺序不稳定的字典。相同配置下，动态内容变化不应改变前面静态前缀的字节序列。供应商若支持自动前缀缓存或显式缓存标记，由连接适配器利用；不支持时仍发送相同语义的普通请求。

manifest 增加 `cacheClass`、切片哈希、稳定前缀指纹和估算 token。供应商返回缓存 token/命中信息时记录实际值；没有返回时显示“不可得”，不能伪造命中率。修改引擎、玩法开关、预设或资产会在对应层之后自然失效，而只改变玩家本回合行动不应破坏更早的稳定前缀。

准确性优先于缓存率：如果某模型需要把关键指令放到末尾强化执行，应由模型适配预设声明重复一个短的契约摘要，而不是移动或复制整份引擎提示词。该摘要也必须有独立切片、token 统计和回归测试。

## 状态栏拆分

状态栏继续与正文共用一次结算请求，但拆为三个可观察切片：

1. `story.state.contract`：字段 schema、事务和 Python 校验依赖，不可由内容预设关闭；
2. `story.state.guidance`：何时新增、更新、删除状态条，开发者可版本化覆盖；
3. `story.state.world_defaults`：世界包或内容预设提供的初始展示建议，可关闭。

状态栏结果仍由 `state_manager.py` 验证和提交。提示词编辑不能绕过字段校验，也不能直接写存档。

## 迁移顺序与验收

1. **注册表只读切片**：建立变量注册表、中文解释、旧别名、API 查询和编辑器变量面板；仍用旧变量渲染，不改变最终提示词。
2. **层级与缓存观测**：加入任务/层/槽位枚举、缓存级别、稳定前缀指纹和旧组装结果快照；仍不移动文本。
3. **状态栏垂直迁移**：从 `settlement_prompt` 抽出状态栏契约与指导，同时保持一次正文结算请求和字节级可解释差异。
4. **正文职责迁移**：拆出正文叙事、玩家行动权、连续性和世界变化短信号；去除重复案例，把可选体验规则移入内建预设。
5. **其他任务族**：迁移世界书捕获，再依次登记暗流、记忆、偏好、工坊和生图；每次只迁移一个任务族。
6. **预设产品化**：实现内容预设/模型适配预设的选择、导入导出、冲突说明和关闭即零拼接。

每一步必须验证：组装顺序稳定；必需变量不遗漏；未知变量和跨任务变量被拒绝；悬停与点击说明可访问；关闭功能后相关切片 token 为零；状态栏 JSON、玩家行动权和世界变化评测通过；模型调用次数不增加；日志 manifest 能解释每段文本来源；只改变回合尾部数据时稳定前缀指纹不变。

## 下一主线判断

本轮 UI 修复完成后，下一开发重点不是给角色卡、实体或文风再增加孤立功能，而是：

1. **提示词架构第二阶段（前置）**：变量注册表、状态栏独立切片、底层契约与体验预设分层；
2. **世界书玩法主线（P0）**：题材无关的世界变化短信号与按需详细捕获；
3. **回合重演与分支（P1）**：待世界状态/修订边界稳定后实现，避免分支复制不一致状态；
4. 角色提取、深层偏好、云生图与移动端保持后置。

因此，对“游戏模式、角色卡、世界书、实体库、文风、提示词”的直接回答是：**先完成提示词基础设施，再回到世界书通用捕获；其余资产域不是下一轮主线。**
