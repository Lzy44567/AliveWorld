# 功能实现方式与编码前设计清单

更新：2026-10-13。用户要求功能设计标明实现方式。本文件是设计标注规范与当前主线初表，不是代码审计结果；未给全部历史条目完成逐项补标。

## 标注方式

一个功能可以组合多类实现，不强迫贴唯一标签：

- 提示词/AI判断：理解自然语言、创作、判断相关性与行为动机。结果是模型判断，不因结构化输出就变成客观保证。
- Python确定性逻辑：存取、计数、明确规则计算、随机抽取、身份引用、状态应用和任务归属。规则本身需要有来源，不能用关键词硬判断所有语义。
- AI选择＋Python执行：AI从已支持操作中选操作/对象/参数，Python检查允许范围后执行并返回结果。可用同次结构化输出实现，不一律增加工具往返或自主agent循环；不等于执行任意AI生成代码。
- 前端交互：呈现、编辑、选择、复制、流式显示和反馈；不应单靠前端守住保存/权限规则。
- 外部能力：模型、图片、语音等供应商接口；明确本软件与外部服务责任。

以后新增或重整一个功能时，记录：玩家目标；设计状态/优先级；实现方式组合；AI负责什么；代码负责什么；权威数据写在哪里；触发与额外调用/等待；验证方法。实现方案另标“已决定／建议／需小实验”，不能把用户确认玩法当成用户确认技术选型。

不为每个微小按钮填完整模板。按可独立验收的功能粒度记录，在模块设计中维护一份权威说明，索引链接过去。开发前对本批功能补齐，远期灵感只记候选类别与未知项。

## 当前主线责任表（目标设计，非现状承诺）

| 功能 | 实现方式 | AI职责 | 程序/前端职责 | 调用与验证 |
|---|---|---|---|---|
| 正文人物行为与玩家控制 | 提示词＋状态取材 | 按人物认知动机表现，不代玩家选择 | 正确取材和角色归属；不能声称代码完全验证自然语言无越权 | 同GM请求；用多场景质量评价验证，不靠关键词禁词表 |
| 未来候选 | 提示词＋Python | 候选、语义可行性及依据 | 结构检查、已知硬条件、权重归一与抽取记录 | 原有未来请求；候选质量与抽样测试分开 |
| 数值/骰子 | AI选择＋Python执行 | 从已设规则选适用项、给情境依据 | 冻结参数、算数、掷骰、记录；不投后改难度 | 不默认另开骰子AI；公式与边界可单测 |
| 状态栏更新 | AI选择＋Python执行＋前端 | 提出变化操作及对象 | 对象/操作边界、保存与回退；前端投影当前状态 | 同正文请求附操作；状态差异与UI验收 |
| 世界书捕获/修改 | AI判断＋受限执行 | 识别可复用事实、归属、增改废止 | 校验目标/来源/范围、审阅选择、应用修订 | 短信号同正文；详细整理按需额外调用 |
| 卡片积累 | Python＋AI筛选 | 判断语义重要性 | 计数已提交变化、去重、归档与触发 | 计数不收费；语义整理批量按需 |
| 实体推演/账本 | AI判断＋受限执行 | 按私有认知推演计划和行动 | 持续保存事件、身份关联、时间与依赖、单次执行 | 暗流按需调用；独立性质量与生命周期分测 |
| 记忆压缩 | 提示词＋Python | 摘要与重要事实提取 | 分段、容量、来源、版本切换、取材 | 达条件时额外调用；事实保真与容量分别验证 |
| 撤回/分支 | Python为主＋前端 | 微调重演重新生成受影响内容 | 恢复分支状态、隔离旧结果、非正式参考选择 | 普通撤回不需AI；重演按所选方式调用 |
| 工坊创作 | 提示词＋受限执行＋前端 | 澄清目标、构思与结构化草稿 | 草稿保存、逐项/批量审阅、引用与发布范围 | 用户对话触发；意图契合与操作正确性分别验收 |
| 知情范围/上帝视角 | Python取材＋提示词＋前端 | GM区分隐藏事实和角色认知 | 分别组织视角数据，显示授权内容，不把幕后消息作为角色历史 | 不为每条消息默认另调审计AI；泄漏仍需模型样例评估 |
| 生图 | 提示词可选＋Python＋外部能力＋前端 | 启用时转写提示词 | 工作流参数、请求、结果保存、分阶段错误提示 | 模型/图片调用分别说明，转写可关闭；不回滚成功正文 |

特别注意：自然语言规则冲突、角色动机、记忆真假不是只写Python就能精准判断；数据权限、计数、抽样、身份和持久化也不能只靠提示词提醒。

## 编码前仍需完成的五项设计

1. **版本范围与优先级**：从总设计选择一个可玩闭环，明确本批必做、后续与不做。不是一次把所有功能重写。当前故事/实体/工坊的产品流程已有整合稿，完整发行范围尚未选定。
2. **关键UI与默认设置**：新建故事、故事主界面、工坊审阅的具体页面安排；简单/高级/作者配置；值来源、保存和作用范围。已有原则，尚未完成原型和集中审阅。
3. **关键玩法分歧**：微调重演保持什么、无法裁定的规则冲突如何提示、重要离场事件的介入边界、未来与数值开关组合。给有限方案和案例，只问用户体验取舍。
4. **本批模块输入输出与数据生命周期**：按本表落实稳定身份、事实/信念/计划区分、回合和后台提交归属、撤回覆盖范围、全局/局内资产及旧存档兼容。写必要样例，不搭通用框架；代码层接口由实现前定向审查决定。
5. **提示词装配与验收方案**：复核已有提示词架构而非从头重构；列本批任务读什么/输出什么、稳定前缀/动态资料/可选片段/预设界限、额外调用。固定回答测试查交互与数据，模型样例评估查语义质量，记录成本和等待。不要求生产提示词每句话提前定稿。

以上满足选定开发范围即可编码。群聊全引擎、故事内私聊、任意小游戏、路人完整人生与社区无需全设计完。大游戏设计案负责统一方向和模块依赖，不是承诺未来不再迭代。

## 哪些由谁决定

AI可自主整理责任表、必要数据约定、默认候选、验收例与开发切片；需用户集中审阅主要界面、玩法取舍和首批版本范围。没有答复不升级为确认。实际付费实验和编码仍遵守任务授权，不因本清单自动启动。

近期下一步保持原计划：先做设置分层与主要页面的信息架构方案，同时给所涉及功能补本表标注，再提交集中审阅。避免因新增文档规范打断设计主线去批量机械改写全部历史资料。
