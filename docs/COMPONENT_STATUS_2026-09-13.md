# AliveWorld 组件与耦合审计（2026-09-13）

## 结论

当前架构保持了较好的领域分层和可控耦合，但不是、也不应该是“每个功能完全独立一个文件”。UI、状态、API 和领域逻辑需要通过明确契约协作；高内聚低耦合的判断标准是状态归谁所有、修改是否局部、依赖方向是否稳定，以及失败会不会污染其他领域。

本轮没有为了形式上的独立拆出空壳文件。关键改动都建立了真实所有权边界：提示词组装、开发者鉴权、故事会话、工坊上下文、日志呈现和持久历史各自由专门模块负责，页面组件只组合这些能力。

## 当前边界

| 领域 | 状态与核心逻辑 | 接口边界 | UI/客户端边界 | 审计结果 |
| --- | --- | --- | --- | --- |
| 应用壳与导航 | `App.vue` 只负责页面组合与模式切换 | 各 API 模块按领域拆分 | `TopNav`、左右侧栏和弹窗分开 | 合理的组合根，不应拆成互不通信的页面 |
| 故事会话与并发 | `core/session_manager.py` 按存档路径注册会话并锁定聚合写操作 | `game_routes.py` 负责 HTTP 映射，冲突返回 409 | `gameStore.js` 按 session 保存独立消息、状态、输入和任务 | 所有权清晰；不同故事并行、同一故事不竞态 |
| 工坊 | 各领域工坊保留自身规则与仓储 | 各工坊路由共享薄的冲突保护器 | `workshopStore.js` 按类型/作用域/故事/资产保存上下文 | 共享生命周期，高风险领域规则仍独立，属于适度复用 |
| 工坊历史 | 已发布工坊文件是持久事实来源，安全投影只读取玩家/助手消息 | start 接口返回匹配历史 | 当前草稿与只读历史分区呈现 | 发布、重启、回看、新草稿生命周期已分离 |
| 提示词 | `core/prompt_studio.py` 注册、排序、校验、覆盖和 manifest；原领域仍拥有官方文本 | `developer_routes.py` 受短期令牌保护 | 设置中的开发者工作台 | 首批正文切片闭环；不是所有提示词都已迁移 |
| 开发者鉴权 | `core/developer_access.py` 保存盐化哈希和进程内令牌 | 开发者接口统一校验 | 普通设置默认不显示工作台 | 防误操作边界清楚，不宣称强加密或 DRM |
| 资产导航 | 资产仓储与世界包服务保持独立 | 资产、局内资产、世界包 API 分开 | 高频卡片在右侧栏，低频图片/世界包在资源库 | 玩家路径与领域归属一致 |
| 日志 | 后端结构化分类与脱敏 | 日志接口只返回安全记录 | 日志弹窗负责筛选、复制和导出 | 展示层没有获得写日志或上传权限 |
| 滚动与复制 | 无领域状态 | 无额外后端接口 | `useBottomAnchoredScroll` 复用初始定位；各视图决定跟随策略 | 复用机制但保留场景策略，耦合合理 |

## 仍需治理的热点

1. `AssetPanel.vue` 和 `AssetEditorModal.vue` 同时覆盖多类资产，体积较大。它们目前共享的确实是同一种目录/编辑流程；只有当某一资产出现独立状态机或明显不同交互时才继续拆分。
2. `game_session.py` 是故事聚合根，必然协调未来、正文、状态、记忆、偏好和暗流。后续应继续把规则留在领域模块，通过返回值组合，避免把新算法直接写进聚合根。
3. `workshopStore.js` 体积增加，但新增代码主要用于统一的 keyed-context 生命周期。下一次拆分应优先抽出无 UI 状态的 API 适配器或任务上下文工具，不能让多个子 store 各自复制竞态处理。
4. 提示词工作台只迁移首批真实正文切片。世界捕获、工坊、偏好、记忆和生图仍要逐域迁移；在完成前必须继续显示“只读/未迁移”，不能制造全覆盖假象。
5. 运行中请求只保证当前应用进程内并发；关闭程序会中断尚未提交的网络请求。若未来需要跨重启恢复，应新增持久作业队列，而不是把 Promise 或半成品存档写盘。

- 并发：不同键可同时进入、同键冲突、重复故事会话复用；两个故事、两个工坊、故事与工坊重叠及失败隔离均由浏览器验证。

## 下一次开发门
