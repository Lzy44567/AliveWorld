# AliveWorld 发行与打包方向

## 不应提交到Git的内容

- `.venv/`、`node_modules/`：体积大、平台相关、不可复现。
- `config.yml`：包含私人API凭据。
- `data/`中的个人资产、存档、工坊草稿、模型和缓存。
- 运行日志。

## 源码试玩版

源码版使用 `install_windows.bat` 在项目内创建环境。它适合开发者和早期测试者，但仍要求玩家预先安装Python和Node。

## GitHub Release便携版

正式便携版应在CI或干净构建机上生成，不把运行环境直接提交进Git：

1. 前端执行生产构建，输出静态文件。
2. FastAPI后端负责同时托管API和前端静态文件。
3. 使用Python应用打包工具封装解释器、后端代码和依赖。
4. 生成单独的用户数据目录，程序升级不得覆盖存档和资产。
5. 输出ZIP或安装程序，并附带校验值和版本说明。

### 当前实施状态

`v1.5.0-dev.8` 已完成便携版所需的运行底座：

- 前端生产构建可由 FastAPI 同源托管，玩家端不需要 Node.js。
- 所有浏览器 API 请求使用相对路径。
- 源码模式继续使用仓库内现有 `data/`；ZIP 便携版使用 `AliveWorld.exe` 同目录的 `UserData/`。
- 首次运行自动建立个人目录，只复制模板和安全配置示例，不覆盖个人数据。
- 默认关闭跨域访问，配置读取不再回传密钥。

`v1.5.0-dev.9` 已加入 Windows 启动器、PyInstaller `onedir` 规格、便携 ZIP 构建脚本和校验值生成。启动器不显示命令行，会自动选择端口、等待健康检查并使用 WebView2 打开完整游戏窗口；关闭游戏窗口会同时退出后台。WebView2 不可用时才降级为系统浏览器与轻量退出控制窗。

`v1.5.0-dev.11` 已在另一台普通玩家电脑成功启动 EXE，并通过本机存档重启保留与旧资产同步测试。`v1.5.0-dev.12` 将 ZIP 内部根目录固定为 `AliveWorld/`，构建后自动检查结构、私人数据和覆盖升级时的 `UserData/` 哨兵。真正的 `v1.5.0-beta.1` 仍要求在外部电脑完成 API 配置、正文生成与重启读取闭环。

### 启动与旧数据迁移

- WebView2 窗口必须先显示本地加载页，再异步导入后端并切换到游戏，不能让玩家在模型和路由导入期间面对无反馈桌面。
- 源码版继续使用仓库 `data/`；便携版使用程序同目录的 `UserData/`。ZIP 文件名带版本号，但内部根目录固定为 `AliveWorld/`；升级时关闭游戏，把新版覆盖解压到原位置，只替换程序文件并保留 `UserData/`。
- 当便携包位于旧源码仓库的 `release/` 等子目录下时，首次启动只沿 EXE 的祖先目录寻找旧源码数据，并在主界面显示后请求确认；不会扫描整块磁盘或任意用户目录。
- 迁移采用复制而不是移动：只复制存档、角色、实体、世界书、文风、图片、偏好和工坊草稿；不删除旧目录，不覆盖新目录同名冲突，不复制缓存、模型下载和日志。
- 对于放在其他位置的旧版本，设置已提供“从旧版目录导入”入口，不能依赖硬编码电脑路径。
- 便携包必须解压到用户可写目录（例如非系统盘的游戏目录），不要放进 `Program Files`。未来若制作标准安装版，再切换到每用户数据目录。
- 开发机必须通过 `build_windows_portable.bat` 构建。脚本会在 PyInstaller 重建 `dist/AliveWorld` 前后备份并恢复本地冒烟测试的 `UserData/`，同时在制作公开 ZIP 时明确排除该目录；不要裸跑 PyInstaller 作为日常构建命令。

## 多平台发行边界

共享层继续使用 Python 领域逻辑、FastAPI API 和 Vue 前端；发行壳按平台分别构建：

- Windows：PyInstaller `onedir` + WebView2。
- Linux：在 Linux CI/构建机上生成独立包，使用 GTK/QT WebView；Windows EXE 不能直接复用。
- Android：需要 Android WebView 壳、应用沙箱路径、文件选择、后台任务与权限适配；不能由 PyInstaller EXE 转换得到。

因此“源码跨平台”与“一个安装包跨平台”是两回事。首个 Beta 先验证 Windows，不在同一轮同时承担 Android/Linux 的打包风险。

## Steam/商业桌面版

Steam版需要在便携版基础上增加：

- 桌面窗口壳和单实例管理。
- Windows代码签名、崩溃日志和自动更新策略。
- 将存档放入稳定的用户数据目录，而不是安装目录。
- API Key安全存储与隐私说明。
- 可选本地模型的下载许可、来源、卸载和磁盘空间管理。
- 第三方模型、依赖、字体和素材的商业许可证审查。

正式打包是独立发行阶段，不应通过把当前开发机的Python或Node目录复制进仓库来完成。

## 更新机制

Beta 首先提供非阻塞“检查更新”：显示官方版本、更新摘要和下载入口，不强制升级。自动下载与安装列为 P1，必须具备 Release 清单、SHA-256 校验、独立更新进程、程序备份、健康检查和失败回滚；更新程序永远不得写入 `UserData/`。详见 [`features/09_updates_and_onboarding.md`](features/09_updates_and_onboarding.md)。
