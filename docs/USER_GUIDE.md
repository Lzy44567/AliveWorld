# AliveWorld 玩家指南

> 本指南面向第一次接触 AI 故事游戏的玩家。便携版不要求安装 Python 或 Node.js。

## 一张图看懂 AliveWorld

```mermaid
flowchart LR
    A["故事线与状态"] --> B["正文与玩家行动"]
    C["角色 / 世界书 / 文风 / 实体"] --> B
    B --> D["动态未来与物理投掷"]
    D --> E["生成本回合正文"]
    F["暗流实体与因果账本"] --> E
    E --> G["存档、记忆与画廊"]
    G --> B
```

AliveWorld 会永久保留完整故事原文。记忆压缩只改变发送给模型的工作上下文，不会删除玩家看到的历史正文。

## 五分钟开始

### 工坊连续创作（dev.23）

工坊的“发布草稿”保存当前版本，不代表结束设计。发布后可直接发送下一条消息，继续讨论同一资产；新的修改仍须发布才进入正式资产，旧讨论可展开查看。

阅读空间不足时，点击标题旁的“专注阅读”，再点“退出专注”或按Esc恢复。方案的批量接受/拒绝位于末尾。

输入区“创作记忆”控制是否参考同资产的已发布讨论。它按本次问题选取有限的原文，不额外调用总结模型，但会增加本次输入token，也不保证每个细节都被记住。长期重要约束建议保存到“创作目标”。偏好工坊默认不参考已发布讨论，主动开启后可能发送包含敏感内容的旧片段；刷新页面后恢复默认设置。

### 1. 解压并启动

1. 把 ZIP **完整解压**到一个可写目录，推荐放在非系统盘。
2. 保持 `AliveWorld.exe` 和 `_internal/` 在一起，不要只复制 EXE。
3. 双击 `AliveWorld.exe`。启动页会先出现，再加载游戏核心。

首次运行会在程序旁建立：

```text
AliveWorld/
├─ AliveWorld.exe
├─ _internal/
└─ UserData/        ← 你的配置、故事、资产、图片和日志
```

### 2. 配置文本模型

1. 点击右上角“设置”。
2. 打开“API 配置”。
3. 填写同一家服务商提供的 Base URL、API Key 和模型名。
4. 点击“保存并测试连接”。
5. 看到连接成功后关闭设置。

API Key 只保存在本机 `UserData/config.yml`。不要把这个文件、完整日志或带密钥的截图发给别人。

### 3. 创建第一条故事线

1. 右侧打开“故事线”。
2. 点击“新建”。
3. 输入故事名称。
4. “宇宙主导向简述”可以只写一两句话，例如：

   > 一座漂浮在云海上的魔法城市，玩家是刚到这里的旅行者。

5. 创建后，在中央输入你想做的行动并发送。

如果开启了“快捷行动按钮”，正文下方会给出 2–4 个可直接点击的下一步行动。

### 4. 验证保存

完成一回合后关闭 AliveWorld，再重新打开并载入同一故事。正文、局内资产和设置应继续存在。

## 主界面区域

### 独立角色对话

顶部“故事”用于RPG，“角色”用于与一个角色独立聊天，“工坊”用于制作卡片。

1. 先在现有角色资产中准备或导入一张有描述的角色卡。
2. 切到“角色”，新建对话并选择由AI扮演的角色；默认自己以“我”参与，也可选择玩家卡。
3. 选择“即时聊天”或“情景扮演”后开始。前者偏聊天消息，后者允许角色自己的场景动作描述；二者不会让AI决定你的言行。
4. 等待时显示“对方正在输入中”，流式内容在正式保存前是临时预览。切换会话不需要重复发送。
5. 关闭重进后继续同一对话；需要换一个角色时新建会话。修改原资产不会悄悄改写已经开始的会话。

首版保留近期对话和有限局内记录，不承诺无限长期记忆；不开放长期性格演变、群聊、语音、图片或离线后台活动。模型服务失败时保留原记录，重试由你决定，不自动追加收费请求。文本模型接口沿用已配置的主接口，高级用途配置可为角色单独选择。

#### 世界、偏好与记忆

- 新建对话时可选择世界书。会话保存创建时快照，普通条目参考本次输入及最近4个公开正式回合；改原资产不会改变旧会话。世界规则不代表角色已经知道全部秘密。
- 打开“会话资料 → 会话设置”可启用用户偏好卡，默认关闭；敏感内容另有授权开关。只参考已确认或明确声明的偏好，不分析私聊，也不将偏好直接当作角色知道的事实。
- “共同经历与记忆”显示公开局内记录。可“标为重要”，最多8条；重要提高取材优先级，但不确认真实性，预算不足仍可能省略。“本次记忆取材”说明哪些公开项实际送入本次请求，不代表模型一定正确理解。
- 展开“来源证据”可查看引文和关联正式原文。“纠正记忆”只创建可编辑草稿，需你自行发送；已有未发送内容不会被覆盖。只有记录实际被更新后才生效。
- 撤回末轮会同步撤回对应记录；重要标记随合法更新继承、撤回恢复。失效标记不会召回旧内容，可手动取消释放名额。
- 当前源码一次参考最多20个近期回合、32条记录（其中意图最多8条），关联旧原文最多4条完整消息/共4000字符。会话仍有512个正式回合、128条有效记录及文件/请求上限；角色长期压缩及扩容尚未开放。不要将其当作无限记忆。
- 当前源码新增自动重要/高光、公开认知筛选和容量说明；新会话启用自动选取，旧协议需显式开启。可以取消/恢复选取并查看来源；高光不是事实确认或心理诊断。旧dev.19/M1验收ZIP尚未重新打包，不包含后续源码功能。

#### 本轮场外提示（C3源码功能，尚未打入旧ZIP）

点击输入框旁的小“场外提示”按钮，在台词框上方写节奏或表达说明；最多1000字，只随本轮非空台词生效。普通括号仍是角色动作，不需要输入特殊符号。收起保留草稿并显示本次会附带的字数，可点击“清空场外提示”取消附带；场外框的Enter只换行。

说明会发送给当前回复模型，并与回合一起保存在当前会话中，但不作为角色对白/经历来源，不修改角色卡或全局偏好。历史可折叠查看。重试使用原台词与说明，重生成沿用原回合说明，不发送新草稿；失败保留草稿，成功时若任一草稿已有新编辑，两框都不清空。撤回仅在双框全空时回填原输入。

未发送的双草稿只在当前页面按会话保留，刷新页面可能丢失。已接受但失败的输入可从服务器核对恢复；不自动重新调用收费模型。撤回保留技术档案，清空草稿不删除历史说明。暂不支持只发送场外提示、持续规则或主动联系。

```mermaid
flowchart TB
    T["顶部：故事 / 角色 / 工坊、偏好、画廊、日志、设置"]
    L["左侧：故事状态、场景与实体感知"]
    M["中央：正文、未来、图片与输入框"]
    R["右侧：故事线和各类资产"]
    T --> L
    T --> M
    T --> R
```

- **游戏模式**：游玩正文、发送行动和观察故事状态。
- **工坊模式**：与 AI 讨论并编辑世界书、角色、文风、实体和偏好卡。
- **日志**：检查实际发送给模型的上下文和错误原因。
- **画廊**：统一管理本局或全局生成图片。

## 全局资产与本局专属

在工坊中，“当前故事”只显示并编辑当前载入故事线的资产副本，界面会同时显示故事线名称。切换故事线后，工坊会重载新故事的资产；这些修改不会污染全局资产。

世界书条目检索并非只看玩家刚输入的一句话。关键词和语义检索会共同读取近期故事工作上下文与本回合玩家输入，因此连续场景中的设定仍可命中；带“常驻”标签的条目无须关键词命中，也会始终加入正文上下文。

- **全局资产**是可复用的原始卡片。
- **载入本局**会创建当前故事使用的副本。
- 局内变化不会自动污染全局原卡。
- 卡片关闭后仍保留，但不再参与对应的正文或推演请求。

### 世界书

多本书一起玩时，在故事右侧「世界书 → 本局专属 → 世界书协作」点击一本书设为主书，其余提供补充知识。未指定主书的旧多书存档不会被自动改优先级。

正文发现有依据的冲突时，默认只在本局暂停使用次书的具体条目。角落会提示数量；在协作面板展开冲突记录，可看双方依据、恢复条目，或在折叠设置中选择人工确认。模型可能判断错误，原条目与全局资产不会被删除。撤回来源回合或修改依据后，旧停用自动失效；修改局内文件名后请重新选择主书。

世界书负责规则、背景和可触发设定：

- 概述：帮助 AI 快速理解世界。
- 公理：世界底层必须遵守的规则。
- 条目：地点、制度、魔法、习俗等具体知识。
- 常驻条目：无论当前场景如何都进入正文上下文，应谨慎使用。

### 角色卡

角色卡负责人物设定。全局角色可生成立绘，载入本局后可以形成当前故事中的人物状态。

### 文风卡

文风卡控制正文的视角、节奏、句式、描写重点和禁忌。关闭后不再拼接相应文风要求。

### 暗流实体

暗流实体只用于能够长期行动并持续影响世界的对象，例如组织、幕后人物、灾难或“世界推演”。普通路人不需要全部进入实体库。

## 工坊协作

1. 顶部切换到“工坊”。
2. 右侧选择资产类型和具体卡片。
3. 默认保持“先讨论方案”，让 AI 分析问题、依据和取舍。
4. 审阅提案后再允许 AI 修改草稿。
5. 在左侧直接检查和微调草稿。
6. 发布前，高风险操作会要求逐项确认。
7. 点击发布后才会写入正式资产。

关闭工坊或切回游戏不会丢失未发布草稿，也不会让草稿提前污染正式资产。

## 暗流因果账本

账本记录尚未在正文中公开、但可能在未来影响玩家的因果，例如陷阱、通缉、诅咒和持续机制。

- 条目可以持续或一次性触发。
- 可以记录存在回合、触发次数和来源实体。
- 取消后可恢复，也可以删除。
- 撤回故事回合时，账本状态会随故事一起回滚。

该界面默认更偏向调试，不要求普通玩家频繁手工维护。

## 记忆压缩

- 完整正文永久保留在存档中。
- 达到上下文水位后，只总结较早的一段历史。
- 最近完整回合、未解决线索和重要记忆继续发送给正文模型。
- 压缩失败时会回退到旧的有效记忆，不应阻止正文继续游玩。

记忆模型配置可以留空，此时复用正文模型。

## 用户偏好卡

偏好系统记录行为证据，再用低频分析提出多个可能解释；Python 根据证据强度计算后验，避免模型一句话把猜测当事实。

- 偏好用于倾向性引导，不要求每回合机械重复同类内容。
- 敏感内容分析可以独立关闭。
- 可以按剧情发展、角色互动、动作、视觉和敏感内容等分类关闭消费。
- 输入 `/偏好 你的说明` 可以明确告诉系统一个高先验方向，但后续仍可修正。

## ComfyUI 生图

1. 在设置中填写 ComfyUI 地址，默认通常是 `http://127.0.0.1:8188`。
2. 点击检查连接，读取可用模型。
3. 在正文回合下点击生图，或在角色卡中生成立绘。
4. “AI 整理并开始生成”会把自然语言和当前可见内容整理为生图提示词。
5. 任务异步执行，完成后进入正文和画廊。

基础版只保证纯文生图。上传参考图可以保存和关联，但是否真正进入工作流取决于所选工作流是否包含对应图生图节点。

## 更新、备份与迁移

### 覆盖更新

1. 关闭 AliveWorld。
2. 建议先复制一份旧 `UserData/` 作为备份。
3. 把新版 ZIP 解压到旧版所在位置，允许覆盖 `AliveWorld/` 中的同名程序文件。
4. 不要删除原来的 `UserData/`。
5. 启动新版并载入一个故事检查。

公开 ZIP 不包含 `UserData/`，正常覆盖更新不会删除个人内容。

### 换到全新目录

如果把新版解压到了另一个位置，可在“设置 → 数据与迁移”选择旧版的 `UserData/`。同步采用复制，不删除旧数据，也不静默覆盖同名冲突。

### 手工备份

关闭 AliveWorld 后，复制整个 `UserData/` 即可完成完整备份。

## 常见问题

### 模型连接失败

在“设置 → API 配置”点击“保存并测试连接”，根据提示检查：

- Base URL、API Key、模型名是否属于同一家服务商。
- 模型是否真实存在并允许当前账号调用。
- 余额、网络、系统代理/VPN 和 DNS。

### 双击后暂时没有游戏画面

启动器会立即显示加载页，首次启动可能需要更长时间。如果长期停留，查看 `UserData/logs/launcher.log`。

### 换了目录后看不到旧故事

旧内容通常仍在旧目录的 `UserData/`。不要删除旧目录，使用“设置 → 数据与迁移”复制到新版。

### ComfyUI 错误

AliveWorld 只会在玩家主动点击检查或生成时连接 ComfyUI。确认 ComfyUI 已启动、地址正确、工作流所需模型和节点存在。
