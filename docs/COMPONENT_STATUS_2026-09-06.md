# AliveWorld 功能组件状态审计（2026-09-06）

## 审计口径

本表来自当前工作区实际模块、API、前端组件、测试文件和设计文档，而不是根据对话印象推断。状态含义：

- **已闭环**：领域、接口、主要 UI 与自动回归均存在；仍可能需要真实模型/设备人工抽查。
- **可用但需收口**：功能已运行，但协议、入口、可观察性或边界仍有明显债务。
- **设计完成**：已有可执行设计门，尚未落地或只完成前置。
- **未实现**：当前没有完整运行链路。

本次只做审计和规划，没有把文档设计描述成已完成代码。

## 耦合热点

### 1. 提示词来源碎片化（P0）

同一个剧情结算请求由 YAML 基线和多个 Python `instruction()` 字符串拼接而成；其他模型任务各自硬编码。旧 `/prompts` 接口只能编辑少量内容，而且可绕过版本与验证。继续新增世界变化、预设或插件提示词会使来源更难解释。

行动：实现 `PromptSliceRegistry` + `PromptAssembler` + manifest；优先迁移动态未来和剧情结算，保持模型调用次数不变。

### 2. “运行”与“显示”混用（P0/P1）

当前候选显示、投掷显示、实体可见性和实体运行并非同一类开关。用户希望“关闭随机未来”意味着停掉该机制，而不是只把候选藏起来。

行动：整理每个功能的 `execution / visibility / disclosure` 三类设置。短期先给随机未来明确运行模式，长期由插件生命周期统一。

### 3. 正文提示词承担过多职责（P0）

剧情、状态、世界书短信号、偏好证据、行动建议、暗流兑现和玩家行动权共用一次请求是节省 token 的正确方向，但不应该因此成为不可观察的大文本。

行动：同一次调用内切片化，并让每个输出字段拥有 schema 与 Python 校验；“拆切片”不等于“拆模型请求”。

### 4. 插件化的执行安全（P2）

现有系统没有代码沙箱、插件权限、资源配额和崩溃隔离。直接让工坊 AI 生成 Python/JS 会把本机文件、密钥和存档暴露给远程代码执行风险。

行动：先支持声明式 manifest、提示词切片、状态 schema 与规则 DSL；超出原语时只生成协议扩展提案。

## 建议的下一开发轮

### 最终目标

让 AliveWorld 的每一次模型调用都可追踪、可开关、可回归，并以此修复“外部力量无信息通道仍介入”和“替玩家决定投降”等真实体验问题，同时为通用世界变化捕获、内容预设和插件协议建立统一入口。

### 阶段目标（第一个可验证切片）

1. 建立只读提示词切片注册表和组装 manifest，不做编辑 UI。
2. 迁移动态未来与剧情结算的现有拼接，确保请求次数和输出 schema 不变。
3. trace 展示切片 ID、版本、来源、启用理由和 token 估算。
4. 把现有玩家行动权、信息通道、快捷行动、正文长度和世界变化信号登记为独立切片。
5. 增加警察/保安介入、玩家拒绝投降、局部未发现和关闭功能不注入的自动回归。

### 完成证据

- 单测证明必需切片不可缺失、可选切片关闭后不进入请求、顺序稳定、变量缺失会失败。
- 假模型记录的请求 manifest 与正文行为一致。
- 现有 Python 测试、前端生产构建和 Edge 正文主循环通过。
- 文档、路线图和 changelog 同步；不在这一切片声称提示词编辑器或插件工坊已完成。
